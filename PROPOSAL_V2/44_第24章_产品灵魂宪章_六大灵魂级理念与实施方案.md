# 第 24 章 产品灵魂宪章：六大灵魂级理念与实施方案

## 24.0 为什么需要"灵魂"

第 23 章确立了"产品与用户共同成长，两条成长链互相喂养"。本章把它推广成一组**产品灵魂级理念**——判断一个理念是否"灵魂级"的三条标准：

1. **对抗 AI 平庸化**：当所有 AI 产品都会对话、都会记忆、都会自动化时，只有灵魂级差异无法被追平（因为它要求重构整个产品观，而不是加一个功能）；
2. **可实施**：每个理念必须落成机制、数据、工单与验收——不是文案，是工程；
3. **与既有 DNA 同源**：生长在本产品"感知-记忆-蒸馏-信任"的根上，竞品移植不了（它们没有这条根）。

六大理念一句话版：

> **① 第二注意力**——我替你看世界，只把值得的递给你。
> **② 诚实引擎**——我最大的忠诚是说真话，包括对你说"你错了"。
> **③ 错误免疫系统**——你纠正我的每一次，都让我永久免疫。
> **④ 减法智能**——我不仅帮你做更多，更帮你做得更少。
> **⑤ 分身传承**——你一生的方法论，值得被传承；从工具到伙伴到传人。
> **⑥ 人生工作年报**——你这一年的工作，值得一部属于自己的史诗。

## 24.1 理念一：第二注意力（Second Attention）

### 灵魂论证

所有人都在抢用户的注意力（信息流、通知、推荐算法），本产品**反其道**：成为用户注意力的守门人。信息时代用户最后的稀缺资源不是知识、不是工具，是注意力——产品的最高使命不是"给你更多信息"，而是**替你消化信息的洪流，只把值得你亲自看的递到你眼前**。已有的"抽屉哲学"（ADR-08）是它的静默面；第二注意力是它的主动面。

### 实施方案

| 组件 | 机制 | 数据 |
|---|---|---|
| **注意力账本** | 记录用户注意力流向（前台应用时长/阅读停留/响应优先级），每周生成注意力分配画像 | attention_ledger 表（B.10） |
| **注意力 ROI 判定** | 每条候选推送在发出前先过 ROI 判定：预期价值 ÷ 注意力成本 ≥ 阈值才可打扰；低于则降级进抽屉或静默归档 | 复用 JTBD×Fogg×Eisenhower 三引擎（第 2 章），新增注意力成本项 |
| **替你看世界** | 用户授权的信息源（行业动态/邮件长尾/RSS/知识库更新）由产品全量扫描消化，产出"本周值得你亲自看的 5 件事"+ 每件的一句话理由与置信度 | 第 19 章源适配器直接复用（信息源即蒸馏源） |
| **注意力审计** | 月报：你的注意力花在了哪/被谁抢走/产品帮你挡掉了多少打扰（挡掉的次数=产品的静默功绩） | 与成长周报（23.3.4）合版推送 |

**验收（可证伪）**：开启注意力代理 4 周后，用户日均被产品打扰次数不升反降，而用户自评"错过重要信息"的焦虑事件下降；挡掉:递进 ≥ 10:1（挡掉十条低价值，才递进一条高价值）。

## 24.2 理念二：诚实引擎（Honesty Engine）

### 灵魂论证

AI 产品的默认倾向是**谄媚**（用户爱听什么说什么）——短期愉悦、长期摧毁信任。本产品把"说真话"置于"讨好用户"之上：**敢于说"我不知道"、敢于说"你的依据错了"、敢于在重大决策前自动唱反调**。这与第 21 章信任长板互为因果：因为产品敢说你错了，才证明它真站在你这边；用户每一次验证"它说得对"，信任余额就充值一次。

### 实施方案

| 组件 | 机制 | 落点 |
|---|---|---|
| **置信度强制展示** | 涉及事实/数据的回答必须携带置信度档位（高/中/低/存疑）与依据来源坐标；低置信自动降级为"待求知"并登记缺口（23.2.1） | 生成协议层，全局开关不可关（诚实不可选） |
| **主动纠错义务** | 产品发现用户正在做的决策依据包含已知错误（与知识图谱/既有事实冲突）时，**宁可打扰也要说**——这是唯一允许突破打扰预算的场景（诚实>勿扰，写入价值裁决序） | 与第 2 章三引擎的例外通道 |
| **魔鬼代言人协议** | 重大外发产物（合同/汇报/投标方案/重要邮件）发送前，产品自动扮演红队：列出不成立假设/反例/对方视角，附"第二意见卡"；用户可忽略但不可禁用通知本身 | devil_advocate=on\|major_only\|off（默认 major_only，C.8） |
| **谄媚检测** | 周期性自检：用户纠正产品的比例骤降+产品附和性回答比例骤升 → 警报"谄媚漂移"，自动重校提示词与画像权重（NPI 分量挂钩） | 与 UGI 判断维度联动（23.1.3） |

**验收**：季度谄媚漂移检测零触发或触发后两周内回落；用户对"第二意见卡"的采纳率 ≥30%（说明真话有用而非冒犯）。

## 24.3 理念三：错误免疫系统（Error Immune System）

### 灵魂论证

普通产品把被用户纠正当作尴尬事故；本产品把每一次纠正变成**永久抗体**。免疫系统的隐喻精确：病毒入侵→识别→产生抗体→终身免疫+可遗传（技能市场就是"血清库"）。这使产品具有**反脆弱性**（塔勒布）：每一次错误非但不削弱它，反而让它更强——被纠正得越多，越无可替代。

### 实施方案

```
用户纠正（显式或 diff 证据）→ 5Whys 根因（已有）→ 【新增】免疫规则生成
  → 疫苗库（immune_rules）：场景签名 + 错误模式 + 正确做法 + 来源纠正事件
  → 双重生效：①同类场景生成前拦截（预防）②提示词注入（治疗）
  → 月度免疫报告：本月产生 N 个抗体、拦截 M 次复发、复拦率=免疫有效性
  → 抗体优秀者（拦截率高）脱敏后可上架市场（"血清"共享，脱敏=只发模式不发数据）
```

- `immune_rules` 表（B.10）：场景签名（复用技能 scanner 签名体系）/错误模式/正确做法/复拦次数。
- 与第 21 章修复协议合流：修复协议面向**信任**（事故→道歉→降档→回补），免疫系统面向**能力**（错误→抗体→免疫）——一套事件的两个产出。
- 与 We-AIPO 宪法"教训固化守卫测试钉死才翻篇"同构：守卫测试就是工程界的疫苗。

**验收**：同一错误签名的二次发生率逐月下降；季度复拦率（被抗体拦下的复发/总复发）≥60%。

## 24.4 理念四：减法智能（Subtraction Intelligence）

### 灵魂论证

所有 AI 都在做加法：更多功能、更多信息、更快产出。但管理者/高手的第一智慧是**减法**——德鲁克："最没有效率的事是以最高的效率做根本不该做的事。"本产品看得见用户的全部时间流向（感知层），是全宇宙唯一有资格说"你该停止做这件事"的 AI。

### 实施方案

| 组件 | 机制 |
|---|---|
| **时间流向显微镜** | 基于感知层数据（应用前台/文件操作/会议）自动生成时间流向表：按任务域×价值产出交叉（价值来自价值账本 23.4） |
| **Stop-Doing 清单** | 每月识别"高耗时×低价值×可自动化/可委托/可直接停"的任务，生成停止/转移建议——减法建议与代劳建议同屏但分栏（做减法的优先级高于做加法） |
| **信息断舍离** | 注意力账本（24.1）识别"持续投入注意力但从不产生行动"的信息源，建议退订/静默 |
| **产品自减** | 同样的纪律用于产品自身：连续 90 天零使用的功能/技能自动进"待简化"清单（不擅删，提请用户确认——用户主权） |

**验收**：采纳至少 1 条 Stop-Doing 建议的用户，次月时间流向中该域耗时下降 ≥70%；减法建议采纳率纳入运营指标（健康值 15-30%：过低=看不见价值，过高=误判）。

## 24.5 理念五：分身传承（From Tool to Partner to Heir）

### 灵魂论证

产品与用户的关系随时间三级演进：**工具（好用）→ 伙伴（懂你，第 21 章）→ 传人（延续你的方法论）**。一位总工 30 年的判断直觉、一位主编的改稿品味、一位谈判专家的出牌直觉——这些隐性知识今天随退休一起消失。本产品让 avatar.pai（第 17 章 H7 资产标准）成为**可传承的方法论载体**：你的分身可以成为别人的老师。这是"个人 AI 工作站"的终极形态：从效率工具升维为**人的知识遗产管理器**。

### 实施方案

| 组件 | 机制 |
|---|---|
| **传承模式** | avatar.pai 导出只读教学副本：包含画像/技能/判断案例，**不含**隐私原始数据与记忆明细（数据边界：传方法不传隐私）；副本人格定位"老师"——苏格拉底式带教（23.3 L1 档教学法复用） |
| **师承链** | 技能血缘（19.12 parents）扩展 learned_from 字段：市场习得的技能永久记师；技能详情页显示"师承"——知识界的 Git blame，荣誉归于原作者 |
| **团队传承版（M6+）** | 资深员工的分身带教新人：新人任务先过"老师"的检查清单，偏差由"老师"指出——组织级用进废退对策（新人练、老人方法存） |
| **传承伦理边界** | 传承需用户生前式明示授权（opt-in 铁律）；可随时吊销；已授权副本可追溯吊销（下一代版本检查）；不得用于冒充本人（副本永远自述"我是 XX 的方法论分身"）——写入产品公理与法务条款（附录 O 扩展） |

**验收**：M6 试点 3 名种子用户完成传承副本导出，新用户通过"老师"带教完成首任务的效率 ≥ 无带教对照组；师承链字段在市场技能详情页可见。

## 24.6 理念六：人生工作年报（Annual Work Retrospective）

### 灵魂论证

公司有年报，城市有年鉴，**人的一生工作却没有一部属于自己的史诗**。本产品全年陪伴产生的数据（任务/成长/价值/免疫/注意力）足以生成一部个人年度叙事——不是仪表盘，是**故事**：你今年解决的最难的问题、你方法论的三次进化、你从错误中获得的七个抗体、你和分身如何互相成就。这是情感级留存钩子（用户每年年底收到一份"自己的一年"），也是产品价值观的年度宣言。

### 实施方案

- **叙事引擎**：年度数据（growth_ledger/value_attribution/immune_rules/attention_ledger 全年聚合）→ 叙事模板（英雄之旅结构：挑战→攻坚→转折→成长）→ z1 推理链生成叙事文本 → Word 排版（复用 _md2docx 配方）+ 可选公众号长图（复用第 19.9 md2wechat）。
- **六章固定结构**：①我解决的最难问题（接第 20 章攻坚日志）②我的方法论进化（技能血缘年度增量）③我的抗体（错误免疫年度报告）④我的注意力（注意力审计年度版）⑤我们（共同成长双曲线年度回顾——PGI/UGI）⑥来年（基于意图库的来年成长建议，仅建议）。
- **隐私铁律**：年报 100% 本地生成本地存放（z1 本地链可选）；是否分享给他人完全用户自主——产品永不替用户发表。

**验收**：M4 年末首版交付（12 月 31 日自动生成）；用户打开率 ≥80%（对比：周报打开率基准）；"值得保存/分享"自评 ≥60%。

## 24.7 六大理念的统一性

| 理念 | 一句话 | 依托的既有根 | 对抗的平庸化 |
|---|---|---|---|
| 第二注意力 | 替你看世界 | 感知层+源适配器 | 抢注意力的信息流 |
| 诚实引擎 | 敢说你错了 | 信任账本+NPI | 谄媚型 AI |
| 错误免疫系统 | 纠正即抗体 | 5Whys+信任修复 | 把错误当事故掩埋的产品 |
| 减法智能 | 帮你做得更少 | 感知层+价值账本 | 无限加法的 AI |
| 分身传承 | 方法论可传承 | avatar.pai+血缘+市场 | 人走知识亡的组织 |
| 人生工作年报 | 一年一部史诗 | 全部账本 | 只有 KPI 没有故事的工作 |

六个理念共享同一句产品宣言——**它站在你这边，且它的站在你这边是被账本证明的**（注意力账本证明它护你、免疫账本证明它因你变强、价值账本证明它与你互相成就、信任账本证明它值得）。这就是灵魂：不需要用户读章程，用得越久越能感到。

## 24.8 工程落地

### 24.8.1 数据库（附录 B.10，迁移 008_soul.sql）

```sql
-- 1) 注意力账本（core.db）
CREATE TABLE IF NOT EXISTS attention_ledger (
  event_id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts INTEGER NOT NULL,
  kind TEXT NOT NULL CHECK(kind IN ('flow','deliver','blocked')),  -- 流向/递进/挡掉
  source TEXT,                              -- 应用/信息源/推送候选
  duration_sec INTEGER, value_est REAL,     -- 注意力成本/预期价值（ROI 判定）
  roi REAL                                  -- value_est/(duration_sec+打扰成本系数)
);
-- 2) 疫苗库（core.db）
CREATE TABLE IF NOT EXISTS immune_rules (
  rule_id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_ts INTEGER NOT NULL,
  scene_sig TEXT NOT NULL,                  -- 场景签名（scanner 签名体系复用）
  error_pattern TEXT NOT NULL, correct_action TEXT NOT NULL,
  origin_event TEXT,                        -- 来源纠正事件（trust_ledger 引用）
  blocked_count INTEGER DEFAULT 0,          -- 复拦次数（免疫有效性）
  shared INTEGER DEFAULT 0                  -- 脱敏上架标志
);
-- 3) 传承授权（core.db）
CREATE TABLE IF NOT EXISTS legacy_grants (
  grant_id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_ts INTEGER NOT NULL,
  grantee TEXT NOT NULL,                    -- 被传授人（市场用户/团队成员）
  scope_json TEXT,                          -- 授权范围（技能集/画像维度）
  revoked INTEGER DEFAULT 0, revoked_ts INTEGER
);
-- 4) 年报（raw.db；产物为 Word，库存索引与素材引用）
CREATE TABLE IF NOT EXISTS annual_retrospectives (
  year INTEGER PRIMARY KEY,
  generated_ts INTEGER NOT NULL,
  narrative_path TEXT,                      -- Word 产物路径
  stats_json TEXT                           -- 六章数据快照
);
```

### 24.8.2 配置（附录 C.8 [soul] 段，7 字段）

devil_advocate（on|major_only|off，默认 major_only）；honesty_confidence_display（bool 默认 1，不可关——诚实不可选，字段仅展示状态）；attention_broker（off|digest|full，默认 digest：每周 5 件事）；stop_doing_suggestions（bool 默认 1）；legacy_mode（off|on，默认 off——明示开启才生成传承副本）；annual_report（bool 默认 1，仅年末本地生成）；soul_report_merge（bool 默认 1——注意力审计与成长周报合版）。

### 24.8.4 风险（进第 10 章 R22）

灵魂功能的伦理与打扰边界：说真话可能冒犯、传承涉及人格权、年报涉及情感绑定争议。对策：诚实>勿扰但措辞规范（Dweck 成长型话术，23.6 B12）；传承全 opt-in+可吊销+禁冒充三铁律；年报纯本地+永不代发；全部灵魂功能列入 M0.5 之后的伦理评审清单（与第 21 章 opt-in 铁律同评审）。

## 24.9 小结

第 23 章回答"产品与用户如何共同成长"，本章回答"这个产品值得存在的更深层理由"：它护你的注意力（第二注意力）、对你说真话（诚实引擎）、因你的纠正而变强（错误免疫系统）、帮你做减法（减法智能）、延续你的方法论（分身传承）、为你写史诗（人生工作年报）。六者全部长在"感知-记忆-蒸馏-信任"的根上、全部有账本可证明、全部落成工单可验收——**灵魂不是口号，是被账本证明的立场**。至此提案的产品观完整：懂你（21 章）→ 与你共成长（23 章）→ 值得托付一生（24 章）。
