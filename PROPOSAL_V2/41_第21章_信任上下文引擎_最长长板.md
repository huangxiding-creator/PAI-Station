# 第 21 章 信任-上下文引擎：最长长板的最大化（V3.2）

## 21.0 用户判断原文与升维声明

> 用户 2026-09-07："我觉得本项目产品与竞品的最大区别在于：**它以信任它的用户为基础，可以最大限度地自动获取到有关用户本人及其工作任务的上下文，从而能进行多维度、多层次的深度分析研究，更懂用户和用户的待办任务，这样就能实现最大程度地贴近用户的真需求。请你一定要把这个最长的长板最大化地实现和运用起来。**"

**升维声明**：本章把这句产品判断升维为**一等架构——信任-上下文引擎（Trust-Context Engine）**，并给出十个可落地的工程件：TCN 四环飞轮、信任账本、信任预算、信任阶梯、三层上下文模型、全维度上下文矩阵、需求三角定位法、五维画像×四层任务解析、需求逼近指数（NPI）、信任修复协议。**信任是因，上下文是果，理解是复利**——这条因果链是 PAI-Station 与一切竞品的分水岭，本章把它从"愿景"变成"可度量的系统"。

## 21.1 TCN 四环飞轮：信任→上下文→理解→真需求

```
      ┌────────── ① 信任 Trust ──────────┐
      │  用户授予感知权（信任账本记账）      │
      ▼                                  │
 ② 上下文 Context                        │
  显式 L0 / 行为 L1 / 环境 L2 三层全采集   │
      ▼                                  │
 ③ 理解 Comprehension                    │
  五维画像 × 任务四层解析 × 三角定位       │
      ▼                                  │
 ④ 真需求 Need                           │
  主动服务命中 / 初稿一次通过 / 预测下一步  │──价值兑现──┘
      └── 每次命中都让用户更信任 → 回到 ①
```

飞轮的四个咬合点：①→② 用户每多授一格感知权，上下文覆盖度+1；②→③ 上下文三层交叉验证才产出高置信理解（单层都会骗人）；③→④ 理解深度决定需求逼近度；④→① **价值兑现是唯一可信的信任充值方式**——不是话术，是"它又猜对了"。反向同理：任何一次事故/误发/越界都在透支信任账本，飞轮降速（21.2 信任修复协议负责止损）。

**与既有理论的关系**：这是第 15 章智能复利在"信任-数据"维度的展开——diff 是复利燃料（15 章），而 diff 之所以存在，是因为用户信任到愿意让 AI 写初稿；TCN 环比复利环更靠前，是**复利的前置发动机**。

## 21.2 信任的一等资产化（把"信任"从口号变成库表）

### 21.2.1 信任账本（Trust Ledger）

每次信任相关事件入账（DDL 见附录 B.8）：授权（grant）/撤回（revoke）/升档（upgrade）/降档（downgrade）/事故（incident）/修复（repair）。月度**信任报告**推送给用户（第 16 章隐私报告的升级版）：本月动了哪些感知源、每次出境的 payload 哈希、采纳了几次建议、信任余额变化曲线——**看见即安心**（R10 对策的深化）。

### 21.2.2 信任预算与渐进信任阶梯

信任是有限预算，产品必须像管钱一样管它：

| 阶梯 | 感知范围 | 升阶条件（用户确认） | 典型 earn-trust 时刻 |
|---|---|---|---|
| T0 观察员 | 仅 Documents 只读+摘要 | 默认起点 | "我已读完你 3 个月的周报文件夹" |
| T1 助手 | +邮件/日历/IM 收件 | 连续 14 天无事故+采纳 ≥3 次 | "要不要我提前准备下周一的周报初稿？" |
| T2 代办 | +屏幕/音频/会议（分域） | 周报域跨 60 分奇点（15 章） | "这个域我可以独立交活了" |
| T3 搭档 | +内网/全上下文 | 多域 L2+用户主动升档 | 分身资产年度报告 |

**铁律**：升阶永远由用户确认、产品只发起建议（第 17 章自主四态 ask）；**任何"默认开启再让用户关"的设计违宪**——Microsoft Recall 的教训（21.7）。

### 21.2.3 信任修复协议

事故后四步：透明通告（48h 内全事件披露）→ 权限自动降一档（不必等用户动手，主动示弱）→ 修复期（高敏感动作全部 ask）→ 复盘报告入账。目标不是"不出事"而是**事故后信任余额可恢复**——账本上有修复记录的信任，比从未出事的沉默信任更稳固。

## 21.3 上下文获取最大化（长板的第一物理量）

### 21.3.1 三层上下文模型

| 层 | 定义 | 采集面 | 特性 |
|---|---|---|---|
| L0 显式 | 用户**说出来**的 | 指令/纠正/反馈/偏好声明 | 最准但最稀疏，且常与真实行为不符 |
| L1 行为 | 用户**做出来**的 | 初终稿 diff/采纳-拒绝/编辑轨迹/工作节律 | **因果性最强**（P2 蒸馏的燃料） |
| L2 环境 | 用户**所处**的 | 文件系统/邮件流/日历/会议/浏览器/IM/内网/GitHub | 覆盖最广但噪声最大 |

三层缺一不可：只有 L0=普通 chatbot；只有 L2= Recall 式监控（无行为理解，纯记录）；只有 L1= 编辑器插件。**三层交叉才有真理解**。

### 21.3.2 需求三角定位法（Need Triangulation）

单一来源都会骗人：用户说的未必做（L0 偏差）、做的未必是想要的方向（惯性）、环境信号有噪声。真需求=三层的交汇点：

```
L0 说要"更简洁的汇报" ──┐
L1 diff 里删了 40% 形容性段落 ├──▶ 三角定位："领导只看结论" → 汇报技能=结论先行
L2 环境里领导批复平均 3 行 ──┘
```

引擎实现：每个需求假设必须收集 ≥2 层证据才进入意图库（intents 表 evidence 升级为 evidence_json 多源数组，附录 B.6 兼容扩展）；置信度=层间一致度函数。**这是"更懂你"从比喻到算法的关键一步**。

### 21.3.3 全维度上下文矩阵（18 源×4 态）

本地文件/邮件/日历/IM 四通道/浏览器历史/屏幕感知/音频/会议转写/企业内网/GitHub 仓库/云盘同步/剪贴板流/文档版本库/日程习惯/通讯录关系/位置时区/硬件状态（在线/演示模式）/第三方 MCP 源——每源 4 态：dormant（未授权）→ granted（已授权未活跃）→ active（采集中）→ deep（已建索引可查询）。**上下文覆盖度仪表盘**：用户一眼看到"我打开了多少格、每格最后活跃时间、每格贡献了多少次命中"——覆盖度即长板长度的可视化。

### 21.3.4 新鲜度工程

上下文是有半衰期的资产：文件事件秒级（H8）、邮件/IM 分钟级、画像周级、偏好月级。引擎按半衰期分层刷新（1AM 增量窗口+事件驱动+周度画像收敛），过期上下文自动降权——**"懂三年前的你"不如"懂今天的你"**。

## 21.4 多维度多层次深度分析（长板的第二物理量）

### 21.4.1 用户五维画像

| 维 | 回答 | 输入 | 输出 |
|---|---|---|---|
| 认知 | 他怎么思考 | 写作结构/决策模式/思维模型偏好（第 3 章 32 模型反推） | 提示词适配策略 |
| 行为 | 他怎么干活 | 工作节律/工具序列/黄金时段 | 调度与主动时机 |
| 社会 | 他和谁协作 | 通讯录/往来文风/相关方期待（领导画像=4 章既有） | 受众适配 |
| 情感 | 他现在状态如何 | 日程密度/深夜工作/语气变化 | 强度调节（Fogg 动机维度） |
| 进化 | 他在长出什么 | 技能卡增长曲线/diff 复杂度趋势 | 成长建议+分身资产报告 |

三模型收敛法（既有）扩展为五维流水线；画像分层 TTL（17 章）适用。

### 21.4.2 任务四层解析

| 层 | 回答 | 方法 |
|---|---|---|
| 事实层 | 这是什么任务 | 任务分类器（JTBD 场景库） |
| 结构层 | 怎么拆解、依赖谁 | 依赖图+同类任务历史（技能卡复用） |
| 意图层 | 为什么做、成功标准 | JTBD 三维（功能/情感/社会）+三角定位 |
| 战略层 | 在他目标体系的位置 | Eisenhower×OKR 映射+画像长短期目标 |

四层齐了，"更懂用户的待办任务"落成可查询结构：任何任务先过四层解析再调度——**理解先于执行**。

## 21.5 真需求逼近的度量：需求逼近指数（NPI）

长板要最大化，先要可测量。NPI 四指标（月度，进复利仪表盘与运营周报）：

1. **主动建议采纳率**（既有北极星族）；
2. **下一步预测 Top-3 命中率**：预测用户接下来打开的文件/联系的人/启动的任务（离线回测，不上传）；
3. **初稿一次通过率**：AI 初稿被用户"零修改"采纳的比例（L1 因果质量的最直接读数）；
4. **纠正频率下降曲线**：同域任务每千字用户纠正次数的斜率（理解深化速率）。

基线与目标：M4 首版 NPI ≥60%（"明显比通用助手懂我"），M6 ≥85%（"它就是懂我"）。**NPI 是本产品对外可讲的唯一核心指标**——一切长板投入最终都汇到这里。

## 21.6 长板运用全景（"运用起来"：长板驱动一切）

| 被驱动者 | 长板怎么用 |
|---|---|
| 主动服务引擎（P6） | NPI 直接决定主动质量：上下文覆盖度×理解深度=主动时机与内容的置信度 |
| 技能蒸馏（P2） | L1 行为上下文是蒸馏燃料；L0 纠正信号是技能改进信号 |
| 技能铸造厂（19 章） | 交叉铸造的第三亲本就是用户画像（方法论×组织文风×**个人五维**） |
| 画像系统（P4/P5） | 本章的五维模型即画像系统的规格书 |
| IM 通道（5 章） | 有上下文的 IM 对话免背景交代——"直接说'把它发给老张'" |
| 分身资产（avatar.pai） | 上下文资产的沉淀形态=可携带的"被理解权" |
| 技能市场（6/7 章） | 群体层：匿名画像模式库（本地聚合、k-匿名、不出原始数据）反哺技能推荐 |
| 九大难点（20 章） | H1/H2/H3/H6 的共同上游：没有最大化上下文，四者全部降级 |

## 21.7 为什么这是结构性长板（竞品实证）

| 产品 | 上下文能力 | 结构性缺口 |
|---|---|---|
| [ChatGPT Memory](https://lumichats.com/blog/chatgpt-memory-vs-claude-memory-vs-gemini-personal-intelligence-2026-which-ai-actually-knows-you) | 双层记忆（显式保存+推断）最成熟 | 云侧：拿不到本地文件/内网/屏幕；数据出境换记忆 |
| [Gemini Personal Context](https://www.notebookcheck.net/AI-that-remembers-ChatGPT-Gemini-and-Claude-compared.1336513.0.html) | Gmail/Docs 生态内上下文 | 圈定 Google 生态；跨生态工作流断链 |
| [Claude Memory](https://www.xda-developers.com/claude-memory-beats-gemini/) | 用户控制最好（可查可删） | 项目工作区制，无全盘行为/环境层 |
| [Microsoft Recall](https://www.bbc.com/news/articles/c869glx8endo) | Windows 全屏截图"photographic memory" | **信任反噬样本**：默认开启引发"[privacy nightmare](https://www.computerworld.com/article/2140187/makes-windows-recall-opt-in-after-privacy-security-backlash.html)"全球声讨，被迫改 opt-in+加密+Windows Hello——先抢上下文后补信任=逆序失败 |
| OpenClaw/openhuman/QwenPaw（18 章源码级） | 通道/治理/工作流 | 无全盘感知管线、无 L1 diff 因果数据、无信任运营层 |

三条结构性论证：①**云侧拿不到**——用户主权时代，全量个人上下文出境的信任成本无限高（Recall 证明了连本地截图都会被声讨，何况上云）；②**本地侧没做全**——现有本地产品无三层模型（多止于 L2 记录或 L0 对话）；③**信任无法后补**——Recall 的失败顺序（先上下文后信任）不可逆，我们的顺序（先信任后上下文，T0→T3 阶梯）是唯一可行路径。**长板不在"能拿到上下文"，在"被信任地拿到"**。

## 21.8 工程落地

- **DDL**（附录 B.8 增补）：`trust_ledger`（事件流）+ `context_sources`（18 源×4 态矩阵库化）+ `intents.evidence_json` 升级（三角定位多源证据）；
- **里程碑映射**：M1=L2 环境层+覆盖度仪表盘 v1；M2=IM 通道上下文注入；M2.5=铸造厂用画像亲本；M3=L1 行为层全量（diff）+任务四层解析；M4=五维画像+NPI 首版（≥60%）+信任报告月推；M5=群体匿名模式库+k-匿名发布；M6=NPI ≥85% 公开对表；
- **验收**（附录 D 对齐）：覆盖度仪表盘 18 源状态实时准确；NPI 四指标全部可离线回测；信任报告月度送达率 ≥95%；升阶确认交互零"默认开启"违例（自动化测试扫描）；
- **风险 R20（风险登记册新增）**：信任反噬——过度索取/一次事故摧毁长板。对策：本章信任四件套（账本/阶梯/预算/修复）+Recall 三教训入设计评审清单（opt-in 铁律/默认最小/透明可见）；触发器：月度信任余额降幅 >20% 或撤回事件环比翻倍。

## 21.9 小结

用户指出的"信任→上下文→深度分析→真需求"不是四个口号，是一条可工程化的因果链。本章交付十个工程件把它钉进系统：TCN 四环飞轮（因果模型）、信任账本+预算+阶梯+修复（信任的资产化）、三层上下文+18 源矩阵+新鲜度（获取最大化）、需求三角定位+五维画像×四层解析（分析深度）、NPI 四指标（逼近真需求的度量）。竞品实证（Recall 反噬/三大助手记忆格局/五竞品源码）证明这块板的结构性：**云侧拿不到、本地侧没做全、信任无法后补**。长板的最大化不是"采集更多"，而是"被信任地拿到更深、运用到每一个输出面"——它最终凝结为一个对外可讲的数字：NPI ≥85%，"它就是懂我"。
