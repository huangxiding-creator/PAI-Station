## 19.6 知识原料湖（100× 新增：原料即资产）

四源原料统一落 `知识原料/` 目录（第 17 章数据自由：任意位置）：

```
知识原料/
  电子书/{书名}/       章节.md + book.json（目录指纹+来源坐标）
  混沌学园/{课程名}/   简介.md + 小节文稿.md + 幻灯片.pdf + course.json
  飞书知识库/{库名}/   节点树.md + node.json
  企业内网/{簇名}/     成果样本/ + cluster.json
```

三个字段撑起全部高级能力：**章节指纹**（增量定位：源更新→只重蒸馏受影响章节，成本降 90%+）；**来源坐标**（每张技能卡可追溯"出自哪本书第几章/哪门课第几节"——版权审计与信任基础，技能卡展示溯源徽章）；**版权标记**（self_only/market_ok/rewrite_ok 三态，自动执行 19.11 分层策略）。

## 19.7 交叉铸造：杂交技能引擎（100× 新增：从加法到乘法）

单源蒸馏是加法；**跨源杂交是乘法**——这是铸造厂区别于一切"书摘要工具/课程爬虫"的灵魂：

| 杂交配方 | 产物示例 | 复利本质 |
|---|---|---|
| 混沌方法论 × 个人 diff | "第一性原理拆解法"×你的周报写法=「周报重构技能」 | 理论落地个人 |
| 教材方法 × 企业文风 | 金字塔原理×领导偏好=「汇报材料技能」 | 通用方法组织化 |
| 课程更新 × 既有技能 | 新课程"AI 组织学"→自动升级你的「会议纪要技能」 | 知识保鲜 |
| 内网聚类 × 教材模板 | 同类方案簇×方案写作教材=「技术方案技能」 | 组织知识显性化 |

实现：蒸馏层输出的是带语义标签的方法单元（方法名/适用场景/步骤/反例），交叉铸造器按"场景互补/风格叠加/知识升级"三类组合子生成杂交卡，过质量闸后入库。与第 15 章智能复利引擎共用仪表盘——**交叉铸造是知识供给侧的复利轨道**。

## 19.8 信息源即配置 + 铸造配方（第十一维灵活性：知识源自由）

```ini
[info_sources.混沌学园]
type     = web_course          ; web_course|feishu_wiki|ebook_dir|intranet
url      = https://...
auth     = secretref:hundun    ; 凭据只存 DPAPI 保险箱引用
schedule = weekly MON 08:00     ; 增量调度

[info_sources.我的电子书]

[info_sources.一堂]
type     = feishu_wiki
url      = https://xxx.feishu.cn/wiki/...

```

用户全程只需说清两件事（用户原话）："**参考资料在哪、要求文档在哪**"→铸造厂自动出技能。**每源仅 6 字段**（用户："没必要的不搞"）；IM 对话式增改源（第 17 章 17.7 界面自由）；选择器/翻页规则同文件存放，源站改版→告警+提示用户改一行配置（heal 接口预留自动重定位）。

**铸造配方（recipe）**：蒸馏过程本身可配可分享——`recipe.ini`（分章策略/抽取目标/质量阈值/杂交开关）。默认配方开箱即用；高级用户可在市场发布配方（如"法规类教材专用配方"）——**配方市场是技能市场的二阶供给**（19.10）。

## 19.9 学习笔记与内容运营飞轮（复用 We-AIPO 成熟配方）

增量课程提取后自动触发**学习笔记流水线**：新课程材料+我们自己的 AI 开发实践（GitHub 仓库/本提案/开发日志）→ 写"结合自身体会的心得"（二次创作，非课程摘要）→ 静态排版 → 发布**总包之声**公众号（直接复用 We-AIPO 已验证的 md2wechat 配方与定时发布管线）→ 同步上传工程行业大脑·创新理论实践库（复用已开发项目的上传方法；上传目标配置化，可回流任意组织库）。

三重收益：①内容运营=获客漏斗（第 7 章 CAC 对策）；②混沌材料合规利用（公开发布的是自写心得，版权安全）；③组织知识库持续增新。**运营飞轮与供给飞轮在此咬合**：公众号读者=潜在用户=新技能需求=反哺铸造。

## 19.10 技能定价与 token 经济（第 7 章具体化）

- `skills.price_tokens` 字段（附录 B 增补）：**自铸技能=0（永远免费自用）**；上架市场才定价；
- 定价公式：`price = 铸造成本(兜底) + 稀缺度系数 + 采纳率溢价`（首发期统一 1 倍铸造成本价，市场数据起来后动态）；单位=token，购买即扣，作者分账 85%（平台 15%，对齐附录 O）；
- 冷启动：前 100 名作者技能全部 0 价上架（第 16 章 16.8 自营先行互补）；
- **配方市场**：铸造配方独立定价（低价高频），与技能市场共用 token 结算——供给的二阶曲线。

## 19.11 质量闸与版权合规边界（红队预埋）

**质量闸**（铸造≠上架）：①skill_scanner 签名规则（QwenPaw 吸收，18.3 #12）扫恶意/低质；②每卡 5 样本 Prove 验证（OpenClaw 纪律，18.3 #2）——照卡执行 5 个真实小任务，≥4 个达 Prove 才可上架；③<5 样本标"学习期"不可上架（既有 Q5 条款）；④交叉铸造卡双亲质量继承（双亲均过闸才可杂交）。

**版权分层策略**（Q14 详答）：

| 场景 | 策略 |
|---|---|
| 个人自用（电子书/课程/内网→自己技能仓） | 全功能——合理使用范畴 |
| 市场分发 | 只分发"方法结构"（步骤/模板/触发条件），原文摘录≤合理引用；版权方授权通道（收益分成邀请版权方上架官方技能卡） |
| 混沌学园课程原文 | 仅个人/组织内部学习库，不上市场（原料湖版权标记自动拦截） |
| 公众号学习笔记 | 只发自写心得（二次创作），配课程官方链接导流 |

## 19.12 活技能生命周期（100× 新增：技能是活资产）

技能不是静态文件，是有生命周期的资产：

- **进化**：使用反馈（Prove 成功率/采纳率/用户改写 diff）→ 月度过闸技能自动生成"改进版提案"（用户一键采纳或否决——第 17 章技能自由）；
- **血缘图**：每张卡记录 parents（源章节/父技能/杂交配方），形成知识血缘 DAG——可视化"我的能力族谱"（与第 15 章复利仪表盘合流）；
- **衰减检测**：源知识更新（原料湖指纹变化）→ 相关技能标"可升级"；连续 30 天 0 采纳 → 标"休眠"（不删，降权）；
- **度量**：SkillYield（每 GB 原料产出可用技能数）/技能采纳率/技能创收额，进运营周报（附录 I）。

## 19.13 工程落地与验收

- **里程碑 M2.5**（M2 通道完成后插入）：三验收全过→M3 全量+增量调度上线——①混沌学园 PoC：2-3 门课程全要素提取（简介+全部小节文稿 Word/MD+PPT 合并 PDF）；②1 本教材 ≥10 张技能卡（人工抽检 ≥4/5 可用）；③1 篇学习笔记排版发布+1 次组织库回流；

- **风险登记**：R16 版权与平台条款（对策=19.11 分层+原料湖标记）；R17 源站改版脆弱（对策=选择器全配置化+heal 告警）；R18 垃圾技能供给（对策=质量闸四条+学习期制度）。

## 19.14 小结

技能铸造厂回答了技能市场的第一性问题——**供给从哪来**：四源蒸馏（46 项开源调研打底的适配层）让每个用户"给本电子书、给个网址"就能铸技能；知识原料湖让原料变资产（指纹增量/全程溯源/版权标记）；交叉铸造让蒸馏从加法变乘法；活技能生命周期让技能自进化；token 计价+配方市场把供给变成经济体；学习笔记+公众号让铸造厂同时是增长引擎。用户想法的每一个要素（双格式/PPT 合并/首测 2-3 门/周增量/简洁配置/自动部署/售价扣 token）都落进了工程方案——并加上五件用户没提但决定成败的东西：知识原料湖（资产化）、交叉铸造（复利乘法）、质量闸（防垃圾）、版权分层（防法律风险）、活技能生命周期（防腐化）。
