# 附录 F 安全威胁建模（STRIDE）与应急响应

## F.1 资产清单与信任边界
资产：memory.db（最高）、avatar.pai、skills 目录、INI 凭据、IM 通道令牌。信任边界：本机进程间（主程序↔sidecar）、本机↔云（智谱 API）、本机↔IM 平台。原则：**凭据永不入库入 git（.gitignore 已列 *.secret.ini）；密钥用 Windows DPAPI 派生加密存储**。

## F.2 STRIDE 威胁矩阵（逐威胁×对策×验证）

| 威胁 | 场景 | 对策 | 验证方式 |
|---|---|---|---|
| Spoofing 仿冒 | 他人向机器人发指令操控电脑 | IM 指令白名单（仅配置的 user_id）；通道级鉴权 | 白名单外用户发指令→audit 记录 denied |
| Tampering 篡改 | 市场技能被植入恶意代码 | Skill Scanner 静态扫（密钥/eval/exec/反连/提权）+ 人工抽检 + 技能沙箱 | 恶意样本测试集（预埋 20 个坏技能）全部拦截 |
| Repudiation 抵赖 | 技能执行了危险操作无凭据 | audit.db 只追加全留痕 + 操作哈希链 | 篡改检测：重算哈希链断裂即告警 |
| InfoLeak 泄漏 | 敏感内容上云（截图/凭据） | never_send 黑名单 + 发送前 NER 二次扫描 + 脱敏 | 隐私断言测试（D.1）+ 人工红队 50 样本 |
| DoS 拒绝 | 智谱 429/断网导致系统假死 | pacer+队列降级+本地兜底 | 异常注入（D.6） |
| Elevation 提权 | 技能脚本越权写系统目录 | 沙箱白名单目录 + Tool Guard 二次确认 | 沙箱逃逸用例集（预埋 10 个逃逸尝试） |

## F.3 微信纯视觉四铁律的威胁面复核
攻击面分析：不注入→不触发微信进程完整性校验；不发送→不产生非人类行为指纹；原文不存→即使本机被入侵也无微信明文库；默认关→默认攻击面为零。残余风险仅"截图中含敏感信息被 VLM 处理"——黑名单+裁剪+脱敏三层缓解，且 VLM 响应不回传原文（只存摘要）。

## F.4 应急响应流程（SOP）
1. 发现（audit 告警/用户报告）→ 冻结：暂停感知与通道（托盘一键）；
2. 取证：audit.db + 哈希链导出（只读副本）；
3. 止损：撤销通道令牌、Skill 下架/ban、必要时全网市场熔断（index 仓库 revert）；
4. 通告：24h 内 GitHub 安全公告 + 企微用户通告（模板预写）；
5. 复盘：5Whys 入 PDCA，威胁矩阵更新（F.2 为活文档）。

## F.5 合规映射
PIPL：本地处理为原则、上云内容脱敏、用户可导出可删除（数据主权三件套）；AIGC 管理办法：生成内容显式标识"由 PAI-Station 生成"；未成年人/特殊数据：不采集（黑名单兜底）。企业版附加：算法备案指引、数据出境评估材料清单。
