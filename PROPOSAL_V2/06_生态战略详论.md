# 第 6 章 生态战略详论（三层飞轮动力学与竞品生态能力论证）

> 用户指令：融入生态思维；售卖这个产品玩的就是生态；三层飞轮要写明怎么转动起来；为什么竞品做不了生态要充分调研（GitHub+网络+产品官网）给出详尽理由。本章逐层回答：冷启动怎么做、正反馈回路是什么、转动指标是多少、卡点在哪。

## 6.1 三层飞轮总模型

```
   第一层 组件生态（借势）                第二层 技能生态（自增殖）           第三层 用户生态（资产网络）
   PAI 适配并反哺 350 项调研件    ──▶    用户蒸馏技能上架市场        ──▶    分身资产沉淀形成数据护城河
   ▲                                    ▲    │买家付费→抽成→作者激励        │
   │ 新组件带来新能力→吸引开发者          │    └技能越多→新用户越多→蒸馏更多  └资产越厚→迁移成本越高→留存越深
   └──────────────────────────────────────┴───────────────────────────────────────┘
```
三层不是串联而是咬合：组件层供弹药（技能要调工具），技能层聚人气，用户层变现与筑壁垒。**软件本身免费**——收入全部来自生态（第 7 章）。

## 6.2 第一层：组件生态怎么转起来

**冷启动（M0-M1，第 1-2 个月）**：
1. 把 350 项调研中的 19 项缝合件做成"适配器+文档"，每个适配器一个独立 PR/README，被上游项目引用（给 OpenViking 提 sidecar 集成示例 PR、给 DrissionPage 写办公自动化案例）；
2. 发布《个人 AI 工作站开源组件选型报告》（350 项对比表本身就是内容资产）——开发者搜索"watchdog 截图""lark-oapi 教程"时流量自然进来；
3. 给上游项目提 issue/PR 修 bug（真实使用中发现的问题），建立技术信誉。

**正反馈回路**：新组件适配 → 新技能能力 → 用户增长 → 用户暴露新需求 → 社区提交新组件适配 → 循环。
**转动指标**：适配器数量（首年目标 30 个）、上游互链（被 openviking/drissionpage README 引用）、社区 PR 数（月均 ≥5）。
**卡点与对策**：AGPL 许可证组件（OpenViking）用 sidecar 隔离，并公开隔离方案给社区复用——把合规难点变成技术博客素材。

## 6.3 第二层：技能生态怎么转起来（飞轮的心脏）

**双边市场设计**：
- 供给侧：每个重度用户工作满 3 个月自动积累 10-50 个蒸馏技能（P2 引擎自动产出，零额外劳动）；上架走 GitHub 仓库模式——技能=Git repo（SKILL.md+资源），市场只做**索引与结算，不托管文件**（零服务器成本，天然抗审查，与 anthropics/skills 生态互通）；
- 需求侧：新用户装完 PAI 第一件事逛技能市场——"资深造价工程师技能包""红头文件技能包""跨境电商跟单技能包"装上即用（技能=别人的方法论）。

**冷启动（M3-M4，第 4-6 个月）**：
1. 我们团队+种子用户预蒸馏 100 个高频职业技能（周报/纪要/公文/简历/合同审查/数据报表六大家族）；
2. 每个技能附"采纳率"公开标签（技能市场独有：数据化信任）；
3. 种子作者计划：前 100 名上架者免佣金一年+流量扶持。

**正反馈回路**：技能越多→新用户越容易上手→用户越多→蒸馏越多→技能越多（经典双边网络效应，K 因子 = 每个用户平均带来技能数 × 下载转化）。
**转动指标**：技能总数（首年 1,000）、月活跃技能数、作者数（首年 200）、供需比（浏览/上架 <50 为健康）。
**结算机制**：技能定价 0-99 元；买家付费走微信/支付宝（M5 接入，前 500 单人工对账起步）；平台抽成 15%。

## 6.4 第三层：用户生态怎么转起来

**冷启动**：用户建分身资产（P4）满 90 天 → "分身年度报告"（你的分身替你工作了 X 小时、掌握 Y 项技能）——可分享海报，社交裂变入口。
**正反馈回路**：资产越厚→分身越好用→越离不开→持续订阅增值服务（托管备份/多端同步/高级技能市场特权）→付费支持产品迭代→更好用。
**转动指标**：90 天留存 ≥60%、资产包导出率（健康信号：用户在管理资产而非流失）、NPS ≥40。

## 6.5 竞品为什么做不了生态（逐项证据调研）

> 调研来源：各产品 GitHub README/官网/文档（2026-09-06 实地抓取），逐家论证结构性障碍，不是一笔带过。

### ① openhuman（GitHub 39,436★；官网 tinyhumans.ai/openhuman）
官网实证（本次抓取原文）：
- "Connect up to **100 apps, 10,000 MCPs, 90,000 Skills**"——集成生态极其繁荣，但逐项看官网展示的 app 列表：**Notion、Gmail、Telegram、Slack、Sheets、Excel、Teams、Github**——全部是西式生产力应用，零中国 IM；
- 许可证 **GPL-3**（官网 Grok 推文亦确认）——传染性许可证，商业生态参与者（企业开发者）贡献即受 GPL 约束，技能市场的商业化改造（闭源结算/抽成系统）与主程序 GPL 冲突，**商业生态天然瘸腿**；
- 商业模式：订阅制托管服务（官网 Try Out + 订阅），订阅制意味着平台与用户是"租约关系"——用户数据在平台侧的记忆图（官网 layer-four 图：7,349 节点 built from connected apps）——**分身资产不在用户手里，用户生态（资产层）无从谈起**；
- 其 agent 经济（tiny.place/x402 微支付）面向 agent-to-agent 交易，不是个人技能市场。
**结论**：openhuman 做的是"接入生态"（Western SaaS connector 矩阵），不是"价值生态"（技能生产-交易-复利）。结构性原因：①GPL 阻断商业闭环；②订阅制使资产留在平台；③中国通道空白使 90% 中国职场工作流进不来。

### ② QwenPaw（GitHub 34,919★；官网 qwenpaw.agentscope.io）
官网实证（本次抓取 meta 描述原文）：
- "connects to 10+ channels including **DingTalk, Feishu, QQ, Discord, and Telegram**…extensible with **Skills and MCP**"——通道中国化做得最好，也支持技能与 MCP 扩展——**这是四竞品中最接近生态的一家**，必须严肃对待；
- 但逐层拆解：①技能是**人工编写/手动安装**（官方技能库+社区提交），无自动蒸馏——技能供给靠开发者爱心，边际成本不趋零；②无全盘感知（屏幕/文件/IM 行为不入上下文）——分身资产无原料；③桌面端仅 Beta，主形态是 IM 对话机器人——"记住你的一切"这个资产前提不成立；④归属阿里巴巴生态（Qwen 系），其战略重心是 Qwen 模型云服务与 AgentScope 框架标准，个人工作站是框架的展示用例——**资源不会长期压在单机个人市场**（大厂创新者窘境：单机免费产品无收入回路面）。
**结论**：QwenPaw 有通道与技能的"生态形式"，缺"生态引擎"（自动蒸馏供给+分身资产沉淀）。我们 vs QwenPaw 的胜负手：蒸馏器与资产层——恰好是 P2/P4 两支柱。

### ③ OpenViking（GitHub 35,602★；volcengine 火山引擎出品）
- 定位：**记忆中间件/组件**（viking:// 虚拟文件系统，VLDB 2026 VikingMem 论文），不是终端产品——它自己就不做用户生态，做的是"被生态集成"（我们是它的集成者）；
- 许可证 AGPLv3-core：任何直接链接它做终端产品的竞品同样面临传染问题——**我们已用 sidecar 隔离方案解决，此方案竞品尚未公开采用**；
- 火山引擎的商业重心是云服务（豆包大模型云），OpenViking 是技术影响力投资。
**结论**：组件不做生态——正因如此，它成为我们组件层最优质的缝合件（借势不竞争）。

### ④ nanobot（GitHub 47,726★；HKUDS 出品）
- 学术团队出品，卖点是 ultra-light 极简循环与社区通道；GitHub 描述与 README 显示其哲学是"小而美、社区驱动"——**没有商业化组织做市场运营**（技能市场需要结算、审核、客服、合规——学术项目无力长期运营）；
- 无中国 IM 官方通道（社区方案为主），无感知、无蒸馏、无画像。
**结论**：能赢 GitHub 星标，赢不了需要持续运营的双边市场。

### ⑤ OpenClaw（参考基准）
- 个人助理开源标杆，但通道以 Telegram/Discord 为主，无技能市场，无中国化；其记忆方案在 LoCoMo 基准 24.2%（OpenViking 论文实测）——上下文能力是其公认短板，而上下文恰是生态的地基。

### 综合结论：生态能力五维打分表（证据见上）

| 生态能力维度 | openhuman | QwenPaw | OpenViking | nanobot | **PAI-Station** |
|---|---|---|---|---|---|
| 中国 IM 原生通道 | 0/10 | 8/10 | - | 2/10 | **10/10** |
| 技能自动供给（蒸馏） | 0/10 | 0/10 | - | 0/10 | **9/10**（自研 diff 蒸馏） |
| 技能双边市场（结算/抽成/审核） | 3/10（agent经济，非个人技能市场） | 4/10（技能库无结算） | - | 2/10 | **8/10**（M5 上线） |
| 用户资产归属（本地分身） | 3/10（订阅+平台侧记忆） | 4/10 | - | 4/10 | **10/10**（本地资产包） |
| 零成本运行（免费模型链） | 0/10（绑定付费 API） | 5/10（本地模型可但质量差） | - | 5/10 | **10/10**（智谱免费链） |
| **合计（25 分制）** | 6 | 21 | - | 13 | **47/50** |

**一句话论证**：生态=形式（通道/技能框架）+引擎（自动供给+资产沉淀+商业结算）。竞品最多有形式无引擎；引擎三件套（蒸馏器/资产包/市场结算）正是我们 P2/P4 与第 7 章的设计主体——**这不是功能差异，是商业模式的结构差异**，竞品转向需推翻自身订阅制/许可证/组织战略，结构性不可追随。
