# 第 4 章 系统架构详设（工程师照此实现）

## 4.1 进程与线程总拓扑

```
┌──────────────────────────────────────────────────────────────┐
│ PAI-Station.exe（pywebview 桌面宿主 + pystray 托盘，用户唯一可见窗口）│
│  ├─ 主循环 scheduler_loop（APScheduler）：20 分钟节拍 OODA      │
│  ├─ 感知线程：watchdog 事件 / mss 截图 / 前台窗口轮询            │
│  ├─ 通道线程×N：lark-oapi WS / dingtalk-stream / 企微 WS       │
│  ├─ 视觉线程：截图→GLM-4V-Flash→结构化事件（断网→PaddleOCR）     │
│  └─ LLM 适配器：pai/llm/（fast/deep/vision 三通道）             │
├──────────────────────────── IPC（localhost HTTP/stdio）────────┤
│ openviking-sidecar.exe（AGPL 隔离）：viking:// 分层记忆检索      │
├──────────────────────────────────────────────────────────────┤
│ WinSW 包装为 Windows 服务：开机自启、崩溃自动重启、7×24          │
└──────────────────────────────────────────────────────────────┘
数据面：memory.db / rules/ / skills/ / outbox.db / audit.db（全部 %LOCALAPPDATA%\PAI-Station\）
```

关键设计决定：
1. **单主进程多线程**（不是微服务）——个人电脑单用户场景，进程间通信只用于 AGPL 隔离这一处硬需求；
2. **Sidecar 模式隔离 OpenViking**——进程边界阻断许可证传染，协议走本地 HTTP（127.0.0.1:17777）；
3. **WinSW 守护**——Windows 服务化后断电重启自动拉起，满足 7×24 要求；
4. **断网降级链**——云端 glm-4v-flash 不可用时截图转本地 PaddleOCR，云端 chat 不可用时任务入队延迟执行，感知与存储永不中断。

## 4.3 模块间接口契约（关键 5 个）

```
① LLM 适配器（全项目唯一模型入口）
   fast(prompt, ctx=128K) -> {text, confidence, usage}
   deep(prompt, reasoning=True) -> {text, chain, confidence}
   vision(image_path, schema) -> {json}        # schema 约束输出结构

② 记忆写入 ingest.capture(event) -> memory_id
   event = {type, source_path, content, ts}
   处理：抽取→摘要→实体→打分→写库→（若高价值）同步 viking sidecar

③ 记忆召回 recall.query(nl_question, top_k=8) -> [{mem, score, path}]
   三路召回→RRF 融合→返回带出处

④ 主动评分 timing.evaluate(trigger_event) -> {B, quadrant, action}
   action ∈ {push_wecom, drawer, folded_reminder, drop}

⑤ 技能执行 executor.run(skill_id, task) -> {draft_path, usage}
   初稿落盘后监听用户编辑，diff 回写 distiller.feedback()
```

## 4.4 数据库 Schema（四库，全部 SQLite）

```sql
-- memory.db：记忆库（P1）
CREATE TABLE memory (
  id TEXT PRIMARY KEY,          -- UUID
  ts INTEGER NOT NULL,          -- 事件时间
  created_at INTEGER,           -- 入库时间
  type TEXT NOT NULL,           -- doc/screen/im/commit/calendar/browse
  source_path TEXT,             -- 出处（可溯源）
  source_hash TEXT,             -- 内容指纹（去重）
  summary TEXT NOT NULL,        -- ≤200 字事实摘要（L1）
  entities TEXT,                -- JSON 数组：人/项目/客户/日期
  tags TEXT,                    -- 主题标签
  weight REAL DEFAULT 1.0,      -- Ebbinghaus 权重
  links TEXT                    -- Zettelkasten 互链 id 数组
);
CREATE VIRTUAL TABLE memory_fts USING fts5(summary, entities, tags, content=memory);

-- outbox.db：主动成果（P3）
CREATE TABLE outbox (
  id TEXT PRIMARY KEY, ts INTEGER, trigger TEXT,   -- 触发事件
  content_path TEXT, score REAL, quadrant INTEGER, -- B 分与象限
  action TEXT, status TEXT,                        -- pending/adopted/rejected/expired
  adopted_diff REAL                                -- 采纳率（编辑距离比）
);

-- skills.db：技能注册表（P2）
CREATE TABLE skills (
  id TEXT PRIMARY KEY, name TEXT, version TEXT,
  level INTEGER,          -- Bloom 层级
  adopt_rate REAL,        -- 滚动采纳率
  sample_count INTEGER,   -- 蒸馏样本数（<5 标"学习中"）
  origin TEXT,            -- distilled/market/builtin
  updated_at INTEGER
);

-- audit.db：审计日志（安全层）
CREATE TABLE audit (
  id INTEGER PRIMARY KEY, ts INTEGER, actor TEXT,   -- engine/skill/user
  action TEXT, target TEXT, detail TEXT, result TEXT
);
```

规则与技能本体是文件不是表：`rules/*.ini|json`（用户可直接编辑）与 `skills/<id>/SKILL.md`（git 化）。

## 4.6 关键数据流走查（三条端到端用例）

**用例 A：文件感知→记忆**
新合同落 Desktop → watchdog 事件（去抖 3 秒合并）→ MarkItDown 转 MD（失败则 MinerU）→ ingest.capture() → glm-4-flash 摘要+实体（glm-4.7-flash 若 >50 页）→ 打分（合同类 source 高权重）→ 写 memory.db + FTS5 索引 → 实体链接（同供应商旧记忆互链）。全程 ≤90 秒，audit.db 记录每步。

**用例 B：主动服务→抽屉**
周五 15:40（周期触发器）→ timing.evaluate：M=5×4×3=60，A=技能库有"周报"技能（sample≥5, adopt 0.62）→A 高；P：前台是浏览器=可用 → B=高 → Eisenhower：重要不紧急 → 抽屉。executor.run 生成初稿 docx → outbox 状态 pending → 托盘图标轻闪（非弹窗）。用户 16:00 打开抽屉→采纳/编辑→diff 回写→adopted。

**用例 C：IM 命令→执行**
飞书消息"把上季度供应商合同账期整理成表"→ lark-oapi WS 回调 → 权限校验（仅白名单用户可指挥）→ recall.query("供应商 合同 账期") → 8 条记忆 → executor 用表格技能生成 xlsx → 回传飞书文件。全链路 <60 秒，audit 全留痕。

## 4.7 安全架构（五层，QwenPaw 范式中国化）

| 层 | 机制 | 中国化/强化点 |
|---|---|---|
| 1 沙箱 | 技能脚本在受限解释器跑（禁 import os 直接写盘） | 白名单目录外全拒 |
| 2 Tool Guard | 危险命令（删/网/发）二次确认 | 企微审批卡片确认 |
| 3 File Guard | 路径白名单+黑名单双控 | 微信进程内存零接触 |
| 4 Skill Scanner | 市场技能静态扫描 | 硬编码密钥/反连/提权命令一票否决 |
| 5 Access Policy | IM 通道指令仅限白名单用户 | 通道分级：飞书全指令/微信只读 |

铁律：**原始截图与凭据类内容永不上云**（vision 调用前先黑名单过滤+敏感区域打码重截图）；数据默认不出本机，云调用仅发送脱敏摘要文本。
