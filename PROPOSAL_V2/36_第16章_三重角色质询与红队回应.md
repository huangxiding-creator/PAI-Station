# 第 16 章 三重角色质询与红队回应（V2.2）

## 16.0 本章缘起与方法

一份从不被攻击过的提案不是提案，是愿望清单。本章按用户指令进行**结构化红队评审**：邀请三个立场根本不同、且都以"杀死这个项目"为职业本能的角色，对 V2.1 全文做最深的质询；随后用**平台官方一手数据**做调研补强（本章所有引用均标注来源与核实日期），逐条给出工程化解法，并把解法**直接落进既有章节**（修订清单见 16.9）。

> 方法对应第 3 章模型库 M9（红队思维）与 M7（风险反转）。质询不设"软问题"——每个角色的问题都按"若答不出，项目即死"标准设计。

三个角色画像：

| 角色 | 身份设定 | 职业本能 | 攻击面 |
|---|---|---|---|
| 甲 | 硬科技基金合伙人，投过 3 个死掉的 AI 项目 | 识破故事，保护本金 | 商业地基、市场、竞争 |
| 乙 | 个人数据安全研究员（前红队，现个保法合规顾问） | 假设系统已被攻破 | 隐私、合规、攻击面 |
| 丙 | 超级个体用户兼一线交付者（We-AIPO 作者型：一个人维护过 290 commits 的自动化系统） | 装不上/用不起/修不动 = 差评 | 交付现实、可用性、准入门槛 |

## 16.1 质询人甲：硬科技基金合伙人

**甲 Q1（免费地基）**：你整份商业计划的成本结构建立在"智谱免费模型链永久 ¥0"上。免费是厂商的**获客补贴**，不是合同义务——智谱自己已经证明了这一点：它的 GLM Coding Plan 就是收费分层的（Lite/Pro/Max，套餐决定并发，来源：智谱官方文档《速率限制》页，2026-09-06 核实）。补贴一停、额度一降、模型一下架，你的"零成本推理"卖点当场归零，400 万 DAU 的服务器账单你付得起吗？**把公司命运押在别人的定价权上，这本身就是不合格的商业设计。**

**甲 Q2（限流现实）**：官方速率限制机制写得明明白白：并发数按"用户权益等级"分档，免费档最低；1302=你被限流，1305=平台过载，"稍后再试"。你的第 15 章要 7×24 复利飞轮、附录 E 自己测算日均 133 万 token——一个免费账户的并发上限，凭什么撑住"白天感知摘要+夜间批量蒸馏+随时主动服务"三路并发？这还没算你的免费模型清单是不是还真实存在（见 16.4，确实已经过时了）。

**甲 Q3（双边市场冷启动）**：技能市场 15% 抽成是你收入模型的核心引擎。双边市场的死亡谷你打算怎么过？没有买家，作者不来；没有作者，买家不来。历史上 90% 的开发者市场死在这里。何况个人收款、分账合规，你一个自然人主体怎么解决？

**甲 Q4（巨头碾压）**：字节、腾讯、阿里、微软都在做个人 AI 助手，资金是你的 10000 倍。他们哪天把"全盘感知+技能蒸馏"做一个阉割版塞进自家 IM 客户端，你的窗口期就关了。你说数据壁垒，巨头拿到的数据只会比你多。

## 16.2 质询人乙：个人数据安全研究员

**乙 Q1（敏感信息大规模处理）**：你们的感知层设计 = 屏幕每 10 分钟截图 + 全盘文件索引 + IM 会话读取。聊天记录、健康信息、金融信息是《个人信息保护法》下的**敏感个人信息**；屏幕上随时可能出现你的领导、同事、家人——**第三方个人信息**。本地处理不等于免于告知同意义务。更致命的：用户在**公司电脑**上装它，员工个人授权根本覆盖不了公司数据的处理权限——这台机器变成一个合规黑洞。

**乙 Q2（"数据不出本机"是虚假承诺）**：你们满篇承诺"数据不出本机"，但视觉理解走 glm-4v-flash——**每一张截图都发到了智谱的服务器**。这不叫数据不出本机，这叫数据出了本机但你不告诉用户。个保法下向境外机构提供个人信息尚有单独同意条款，向境内云厂商传输也应如实告知。审计链？本地自建哈希链在法律上**自证效力为零**——它只能证明"你没改日志"，证明不了任何对外事实。

**乙 Q3（微信纯视觉的合规残余）**：技术上"与人看屏幕等价"不等于平台合规。微信软件许可协议禁止未经授权的自动化数据采集，风控对自动化行为的识别在升级；"只读"降低的是民事侵权烈度，不是封号概率。你们把整个感知故事的一半押在一个随时可以让你产品失效、还可能让**用户账号**受害的通道上。

**乙 Q4（凭证集中 = 人生裸奔）**：一台家用 Windows（大概率无 TPM 磁盘加密、可能多人使用）上集中存放：智谱 API key、四个 IM 的会话凭证、全部工作文件索引、行为画像、技能库。这台机器被入侵一次，受害者失去的不是密码，是**整个数字人生**。你们的四铁律防的是"AI 乱来"，防不了"人来偷"。

## 16.3 质询人丙：超级个体用户兼一线交付者

**丙 Q1（22 周排期）**：我维护一个只做"公众号自动发布"单一域的系统就写了 290 个 commit、修了 78 个问题。你要 1 个人 22 周交付六大引擎+四库+四通道+技能市场？第 8 章的 Gantt 图很漂亮，问题是它没有"砍功能"的分支——排期只会整段延期，不会优雅收缩。

**丙 Q2（免费小模型达不到验收线）**：第 15 章奇点判据要求端到端 ≥95%——在免费 flash 级模型上，复杂公文/合同的端到端完成率连 60% 都悬。你的整个"60 分上岗"叙事建立在旗舰级能力上，但你的成本结构只买得起免费档。这两个承诺互相矛盾。

**丙 Q3（终稿采集率是飞轮的暗断点）**：diff 蒸馏假设"终稿可得"。现实是：终稿出现在微信对话里、会议上口头定了、领导在纸质件上画了圈——文件系统里只有初稿。采集率不到 30% 的话，G=T×Q×C 里 Q 和 C 双低，第 15 章的复利飞轮根本转不起来。你测算过真实采集率吗？

**丙 Q4（Windows 7×24 的物理现实）**：锁屏、休眠、系统更新强制重启、内存泄漏、杀毒软件拦截——"7×24 工作站"在这台笔记本合盖的一刻就结束了。感知层依赖屏幕，锁屏时它全瞎，还谈什么主动服务？

**丙 Q5（通道准入门槛被严重低估）**：企微自建应用需要**企业主体**；飞书开放平台、钉钉应用都要开发者注册审核。你的目标用户是个人，他们没有企业。第 5 章写的"四通道"对小白用户第一天可用的只有几个？如果答案是 0，冷启动就是空转。

### 16.4.2 低估一：限流机制的官方口径（来源：https://docs.bigmodel.cn/cn/api/rate-limit.md ）

- 并发限制按**账户权益等级**分档，免费档最低；并发数=同一时刻处理中的请求数；
- 错误码 **1302**（账户触发速率限制）→ 官方建议：降低并发、加请求队列、提升权益等级；
- 错误码 **1305**（平台服务过载）→ 官方建议：稍后重试、拉大重试间隔、降级或延迟处理；
- **低峰期享有更高速率**（动态提升）——夜间批量任务的合法性有了官方依据；
- 提额通道：通用 API 用户可在控制台申请速率限制调整，**10 个工作日审核**。

### 16.4.3 低估二：官方已在售卖 Coding Plan 订阅

GLM Coding Plan 分 Lite（单项目）/Pro（1-2 项目）/Max（2+ 项目）三档，按订阅决定并发——印证"免费是补贴"的判断，也给出了**付费兜底的价格锚点**（Lite 档≈一杯咖啡/月级别）。免费链不是永动机，是**起跑器**。

## 16.5 解法一：模型韧性栈（回应甲 Q1/Q2、丙 Q2）

**原则改写：不承诺"永久 ¥0"，承诺"默认 ¥0 起步、永不锁定"。** 把免费链从"地基"降级为"起跑器"，把可迁移性做成架构属性：

### 16.5.1 三层韧性设计

| 层 | 机制 | 落点 |
|---|---|---|
| L1 抽象层 | 全部模型调用走统一适配器（OpenAI 兼容协议），`pai.ini [models]` 支持任意端点/模型名/降级序，换供应商=改 3 行配置 | 第 4 章适配器设计（已有，V2.2 强化为"降级序"原生支持） |
| L2 免费链 | 现行族谱：主力 GLM-4.7-Flash（含思考模式）→ 高速 GLM-4-Flash-250414 → 视觉 GLM-4.6V-Flash / 轻扫 GLM-4V-Flash；**启动探针**自动探测清单可用性并落库，模型下线自动降级，用户无感 | 附录 E E.1（V2.2 已勘误重写） |
| L3 兜底层 | 最坏情景（免费链全取消）：智谱付费按量档（¥19/月 Pro 定价已含模型成本缓冲，附录 E E.3）；完全断网/极端隐私档：本地 Ollama + qwen 系开源模型（L2 隐私档联动，见 16.6） | 第 7 章定价与 16.6 |

### 16.5.2 限流工程五件套（每条都有官方依据）

1. **错峰调度**：夜间批量任务（蒸馏/索引/画像）排 00:00–08:00——官方明示低峰期速率更高；
2. **全局队列+并发池**：感知/服务/夜间三路任务统一排队，绝不瞬时洪峰（官方建议原文："使用请求队列或并发池"）；
3. **指数退避+抖动**：1302 退避并降并发，1305 拉大间隔重试（官方建议原文："增加重试间隔，避免立即高频重试"）——沿用 We-AIPO `_AdaptivePacer` 已验证实现；
4. **降级链**：4.7-Flash→4.5-Flash→4-Flash-250414 逐级降，视觉 4.6V-Flash→4V-Flash→本地 PaddleOCR；
5. **提额通道**：重度用户引导申请速率调整（10 工作日审核）或购 Coding Plan Lite——把限流压力转化为**Pro 档付费动机**（与第 7 章"重度用户溢出"闭环吻合）。

### 16.5.3 对丙 Q2（能力矛盾）的正面回答

承认矛盾，然后用**域分级上岗**化解：奇点判据按任务域分层验收——格式转换/信息整理/定时提醒类**简单域**在免费链上现实可达 95%（先上岗，快速正反馈）；公文拟制/合同审查类**复杂域**起步即 L2 预审级（第 15 章责任协议），靠"规则模板+人工确认"逐步爬坡，且这正是曾鸣"简单任务无复利壁垒"警告的正面用法：**先易后难，用简单域养信任，把复利积累留给复杂域**。验收基准（附录 D）同时新增"免费链分组"：每个 500-facts 基准必须分别在免费链/付费链跑分并公示差距——不隐藏天花板，量化它。

## 16.6 解法二：三级隐私档位与出境审计（回应乙 Q1-Q4）

**原则改写：隐私是滑块，不是开关；"数据不出本机"改为可验证的"出境账单"。**

### 16.6.1 三级隐私档位（`pai.ini [privacy] level=0|1|2`，安装向导首屏必选）

| 档 | 名称 | 行为 | 适用 |
|---|---|---|---|
| L0 | 全感知档（默认） | 感知全开 + 黑名单目录 + 出境前双层脱敏 | 个人电脑、信任云厂商者 |
| L1 | 混合档 | 敏感目录/应用（公司邮箱、网盘、指定 IM）仅本地处理（OCR/嵌入全本地），一般域走云端 | 混合办公者 |
| L2 | 全本地档 | 零云端调用：仅 Ollama 本地模型 + PaddleOCR；主动服务降级为规则模板；数据**物理不出门** | 企业机密/极端隐私者 |

### 16.6.2 出境账单（对乙 Q2 的正面回答）

- **前置双层拦截**：正则（证件号/卡号/密钥格式）+ NER（人名/机构/地名）双层扫描，命中即占位符替换，**出境的永远是脱敏后文本**；
- **出境流水**：每次模型调用在 audit.db 记录 `ts / endpoint / model / payload_sha256 / 脱敏命中数`；仪表盘新增"本月数据去向"页：调用了谁家多少次、拦截了什么——**用户可以亲眼验证"离开本机的是什么"**；
- **视觉不出境开关**：默认开；开启后截图仅本地 PaddleOCR 提取文本，VLM 理解关闭（感知精度换隐私，用户自选）；
- **法律效力补强**（对乙 Q2 后半）：关键自主动作可选接入**可信时间戳（TSA）**存证（联合信任时间戳服务中心，单次几元级），哈希链保留技术自证，TSA 提供司法采信——两条腿走路。

### 16.6.3 凭证保险箱（对乙 Q4）

- 全部密钥/token 经 **Windows DPAPI**（`CryptProtectData`，绑定当前用户）加密落盘，明文只在内存；INI 里的 key 字段写入时自动加密、导出时自动失效；
- 整机安全基线检查（首次运行）：BitLocker 状态、登录密码强度、自动锁屏时间——不达标弹引导，不达标也允许用，但**风险自担声明**必须勾选（知情同意留痕，对乙 Q1 同样适用）；
- 企业电脑场景：L2 档 + 企业域学习默认关闭；企业版路线（M6+）走私有化端点，数据不出企业墙。

### 16.6.4 微信通道降格（对乙 Q3）

微信纯视觉从"常驻感知通道"降格为**"用户触发式辅助功能"**：默认关闭；开启后也仅在用户明确触发（快捷键/指令）时读取当前屏，不做定时轮询、不建行为画像。产品叙事同步改写：四大 IM 通道中，微信是**补充项**而非支柱——支柱是企微/飞书/钉钉官方 API 通道。同时把"通道失效"列入技能健康度监控（技能带 version 字段，接口改版→自动降级→提示用户，不再静默失效）。

## 16.7 解法三：交付收敛与假设检验门（回应丙 Q1/Q3/Q4/Q5、甲 Q3 部分）

### 16.7.1 M0.5 假设检验门（对丙 Q1 的正面回答：排期必须能死）

在第 8 章里程碑序列中插入 **M0.5（第 4-6 周）**：单一场景打穿——"个人周报"任务域端到端闭环（感知→初稿→通道送达→diff 采集→采纳率上仪表盘）。门禁三条件，**任一不达即触发收缩分支**（冻结 M2 多通道，聚焦单场景做到过线）：

| Kill 指标 | 阈值 | 不达标动作 |
|---|---|---|
| 周报域端到端成功率（自用环境 4 周） | ≥80% | 收缩：砍任务域数量，不砍质量 |
| 自用采纳率 | ≥50% | 重做初稿模板与提示词，不进 M1 |
| 单日人工维护时间 | ≤10 分钟 | 自动化体检脚本前置，修运维债 |

北极星指标同步分层（第 15 章 15.8 修订）：北极星⁰=自用已上岗域数（M0-M2）→ 北极星¹=种子用户已上岗域数（M3-M5）→ 北极星²=周活跃已上岗任务域数（生态期）——**每层都有机会被证伪，而不是 22 周后才知道对错**。

### 16.7.3 感知分级与多源终稿采集（对丙 Q3/Q4）

- **感知分两态**：解锁态=屏幕感知全开；锁屏态=降级为文件监视器+日程驱动（不依赖屏幕）；**夜间批量任务恰恰安排在锁屏时段**——物理约束变成调度优势；
- **多源终稿采集协议**（把丙 Q3 的 30% 采集率打上去）：①文件系统 diff（已有）；②**通道回声**——用户把终稿发到企微/飞书，通道消息即采集点；③**每日对账**——17:30 主动问一次："今天这三份初稿的最终版发我，或回复'照发'"；④纸件批注拍照 OCR（实验）；⑤采集率本身成为仪表盘指标，**M3 验收线：终稿采集率 ≥50%**。
- 断供兜底：diff 缺失的任务自动降级为"规则版技能"（只记录模板参数，不蒸馏隐性方法），复利飞轮降速但不空转。

## 16.8 竞争应答：黑洞效应的双向性（回应甲 Q3/Q4）

**曾鸣黑洞效应是双向的**：巨头的黑洞在云——用户数据上云越多，巨头越强，**因此云厂商结构性做不出"数据不出云"的产品**（等于自断算力与数据双臂）。PAI 的黑洞在本机——本机文件、本机行为、本机技能资产随时间复利，**本地资产 + 开源 + 隐私主权是巨头结构性不进入的生态位**。这不是"巨头没看到"，是"巨头看到了也进不去"：微软 Recall 引发的隐私风暴（2024-2025）已示范了"系统厂商做全盘感知"的信任代价——巨头每做一步，都在为 PAI 的定位做广告。

技能市场冷启动（甲 Q3）则用**自营先行 + Git 即上架**破解双边死结：

1. 种子期 100 技全部官方自营（附录 M 清单），供给端不依赖第三方——本质是内容平台冷启动，不是双边平台冷启动；
2. 上架协议=Git 仓库 + README 索引：作者发 repo 即上架，买家 `git clone` 即安装——**零服务器、零支付、零双边依赖**，服务器后置到确有付费需求时；
3. 分成合规后置：种子期全免费，商业化（支付通道/分账）启用门槛=500 周活 + 10 个自营技能采纳率>70%——先用数据证明市场存在，再解决合规复杂度；
4. 护城河叙事不变：采纳率数据（哪些技能真的被用）是买不到的反馈资产——恰好是曾鸣"复杂任务反馈买不到"的又一落点。

## 16.11 小结

三重质询的最大战果不是答辩，是**勘误**：附录 E 的免费链在提案写作期与官方现行族谱之间已经脱节——这从反面验证了甲 Q1 的判断，也验证了"模型抽象层+启动探针+降级链"不是锦上添花而是生存必需。V2.2 的三条主线——**模型韧性栈、隐私滑块与出境账单、交付收敛与假设检验门**——把 V2.1 的三个最软的承诺（永久免费、数据不出本机、22 周交付）改写成三个**可验证的硬承诺**。红队不是一次性动作：M0.5 假设检验门把"被证伪"制度化进了开发流程，每个里程碑都是一次小型红队。
