# 第 1 章 愿景体系与四支柱实施路径

## 1.1 愿景的源头：从"个人电脑"到"个人 AI 工作站"

1980 年，比尔·盖茨提出"让每个家庭、每张办公桌上都有一台个人电脑"。这句话定义了此后四十年的信息产业——计算机从机房走向桌面，成为每个人生产力的延伸。但四十年后的今天，个人电脑面临一个根本悖论：**它存储了你全部的工作痕迹，却对你一无所知**。你的电脑知道你三年里写过 1,400 份文档、开过 3,000 场会、翻过 80,000 次窗口，但它不能替你写下一份文档、不能提醒你上一场会的结论、更不能在你睡觉时替你干活。

PAI-Station 的愿景正是补上这最后一跃：

> **盖茨让每个人都拥有一台个人电脑；PAI-Station 让每个人的电脑变成随时间复利增值的个人 AI 工作站。**

"复利增值"是这个愿景的关键词，它意味着三点：
1. **资产随时间自动积累**：你不需要"喂"它，它自己在感知、在记忆、在学习；
2. **积累产生非线性回报**：第 1 个月它只能提醒你日程，第 12 个月它已经能替你写周报、拟合同初稿、筛简历——能力的增长曲线是指数的，因为技能、画像、记忆三者互相强化；
3. **积累归属于你个人**：全部数据在本地 SQLite，随时可导出、可携带、可继承——它是你的数字资产，不是平台的流量燃料。

## 1.2 四支柱总览：每条支柱都是一个可验证的工程目标

愿景不能只是口号。四支柱每条都拆解为"六段式实施路径"：**①目标定义（含可量化验收标准）→ ②需要感知什么 → ③核心算法/处理流水线 → ④用哪个开源件（绝不造轮子）→ ⑤数据落在哪（Schema）→ ⑥怎么验证**。

| 支柱 | 一句话 | 核心引擎 | 验收标准（可证伪） |
|---|---|---|---|
| P1 记住你的一切 | 电脑里发生的一切自动变成可检索的长期记忆 | 感知层+上下文层 | "上季度和供应商谈的账期是几天？"3 秒内命中出处文件 |
| P2 继承你的方法 | 你的做事方式被自动蒸馏成可复用技能 | 技能层（diff 蒸馏） | 蒸馏出的周报技能在你最近 5 次周报上初稿采纳率 ≥60% |
| P3 放大你的产能 | 在正确时机主动交付正确成果，替你干例行工作 | 规则层+主动引擎 | 每周主动交付 ≥3 项被采纳成果；打扰次数 ≤2 次/天 |
| P4 成为你的资产 | 记忆+技能+画像打包成可携带、可交易的分身 | 画像层+资产包 | 一键导出分身包，换机导入后能力无损失 |

四支柱不是并列功能，而是一条价值链：P1 产生的记忆喂给 P2 蒸馏方法，P2 的技能被 P3 调用放大产能，三者沉淀成 P4 的资产。数据流向见图 4.1 总架构。

## 1.3 支柱一：记住你的一切（长期记忆的实施路径）

### ① 目标定义
让电脑上的工作痕迹——文档、屏幕活动、IM 对话、代码提交、浏览内容——自动转化为**结构化、可检索、带时间线和出处**的长期记忆。验收标准：
- 任意自然语言查询（"上季度和供应商谈的账期是几天？"）≤3 秒命中出处文件与原文片段；
- 记忆库覆盖近 90 天 ≥90% 的工作文档与会议；
- 全量存储 ≤5GB/年（摘要化压缩后）。

### ② 需要感知什么（感知面清单）

| 信号源 | 感知方式 | 频率 | 开源件 |
|---|---|---|---|
| 文件系统（文档/表格/PPT/PDF） | watchdog 监听 + 增量扫描 | 事件驱动 + 每日 1:00 全量 | watchdog、MarkItDown、MinerU |
| 屏幕内容 | mss 截图（10 分钟滚动窗口）→ GLM-4V-Flash 视觉摘要 | 10 分钟 | mss、glm-4v-flash |
| 微信/企微/飞书/钉钉消息 | 纯视觉只读（截图+OCR）或官方通道回调 | 事件驱动 | GLM-4V-Flash、PaddleOCR、lark-oapi、dingtalk-stream |
| 代码/仓库 | git log + diff 解析 | 每次提交 | GitPython |
| 日程 | 系统日历导出/IM 日程消息解析 | 每小时 | icalendar |
| 浏览痕迹 | 剪贴板监听 + 前台窗口标题轮询 | 5 分钟 | pywin32 |

**隐私红线**：微信通道只做"纯视觉只读"——零 Hook、零注入、零自动化操作，只截图识别，杜绝封号风险（详见第 5.5 节）；密码管理器窗口、隐私浏览模式窗口进入黑名单不感知。

### ③ 核心处理流水线（原始信号 → 长期记忆）

```
原始信号（文件/截图/消息/提交）
  ↓ L0 原始层：仅存 10 分钟滚动缓冲 + 文件指纹，不长期保留原文
L1 抽取层（MarkItDown/MinerU 转 Markdown；GLM-4V-Flash 出截图摘要）
  ↓ DIKW 流水线：Data→Information→Knowledge→Wisdom 逐级提炼
L2 摘要层（glm-4-flash 生成 200 字内事实摘要 + 实体/时间/主题标签）
  ↓ Ebbinghaus 衰减：新记忆权重 1.0，30 天未复现 ×0.5，90 天 ×0.25
L3 检索层（SQLite FTS5 + jieba 分词全文索引；嵌入向量备用通道）
  ↓ Zettelkasten 链接：同实体记忆自动互链（人/项目/客户/日期）
MEMORY 表（永久存储，含出处路径/哈希/权重/链接）
```

每条记忆的 Schema（详见 4.4 节）：`id, ts, source_path, source_hash, type, entities, summary, tags, weight, links`。检索时三路召回：关键词（FTS5）+ 实体图（links 扩展）+ 时间线（ts 范围），召回后由 glm-4-flash 拼装答案并强制附出处。

### ④ 用的开源件与理由（对比过才敢用）
- **OpenViking（viking:// 文件系统，L0/L1/L2 分层加载）**：采纳为记忆 sidecar 进程。官方基准 token 节省 34~91%、延迟降低 58~66%，LoCoMo 基准 OpenClaw 24.2%→82.08%。因 AGPLv3-core 许可证，以独立进程 + IPC 隔离，主程序 MIT 不受传染。
- **MarkItDown（微软）**：Office 全家桶转 Markdown，11k+ stars，比自写解析器覆盖面高一个量级。
- **MinerU（上海AI实验室）**：PDF 版面还原，处理扫描件与公式。
- **SQLite FTS5 + jieba**：单文件、零运维、中文分词成熟；对比向量库（Chroma/Milvus）在 10 万条记忆量级下 FTS5 延迟更低且免嵌入成本——等记忆超 50 万条再升级混合检索。

### ⑤ 数据落在哪
`%LOCALAPPDATA%\PAI-Station\memory.db`（单文件 SQLite，用户可一键备份/导出）。原始截图缓冲 `%TEMP%\PAI-Station\rolling\` 只保留 10 分钟。

### ⑥ 怎么验证
- 建立含 500 条已知事实的测试集（从用户真实文档抽取），跑"3 秒召回率"基准，目标 ≥90%；
- 端到端 E2E：投放一份新合同 → 24 小时后问"合同里违约金比例"→ 验证命中；
- 隐私审计：黑名单窗口期间产生的截图必须在缓冲区清理中消失（文件系统断言）。

## 1.4 支柱二：继承你的方法（技能蒸馏的实施路径）

### ① 目标定义
把用户"做事的方法论"自动蒸馏成可复用、可分享、可交易的**技能文件（SKILL.md）**。验收标准：
- 对用户最近 5 次同类工作（如周报），蒸馏技能生成的初稿采纳率 ≥60%（用户编辑距离 <30%）；
- 技能文件人类可读（Markdown），打开就能改；
- 蒸馏全自动：用户正常工作即可，无需"教学模式"。

### ② 需要感知什么
- **成对样本**：同一任务的"初稿→终稿" diff——这是方法论的化石。来源：①文档的本地版本链（.tmp/~$ 临时文件、同名版本号）；②感知层记录的"AI 初稿落地后被人工修改"轨迹；③git 提交历史。
- **过程信号**：用户在任务上的操作序列（打开什么参考资料、粘贴什么模板）。

### ③ 核心算法：初终稿 diff 蒸馏（本项目原创，也是对竞品的核心差异）
```
输入：初稿 D0 与终稿 Dn 的 diff，及任务上下文（分配请求、参考资料）
Step 1 结构对齐：difflib.SequenceMatcher 找出修改块（增/删/改）
Step 2 模式归纳：对 5+ 个同类任务的修改块做聚类（修改是否反复出现？）
        反复出现的修改 = 用户的方法论偏好（如"结论前置""数据必须带出处""称呼用 X 总"）
Step 3 规则抽取：glm-z1-flash（推理链）把高频修改模式转写为 SKILL.md 规则
        规则形式：`当 <触发条件> 时，<动作>`，如"当写周报时，第一段必须是本周结论，≤50字"
Step 4 写入 SKILL.md：frontmatter(name/description/触发器) + 规则列表 + 反例
Step 5 验证环：下次同类任务用新技能生成初稿 → 再 diff → 采纳率进入正反馈
```
理论依据：Kolb 经验学习圈（具体经验→反思观察→抽象概念化→主动实验）+ 刻意练习——diff 是"具体经验"，聚类归纳是"抽象概念化"，下一单任务是"主动实验"。

### ④ 用的开源件
- **anthropics/skills 的 SKILL.md 规范**：直接采用其 frontmatter 结构（name/description），确保与 Claude 生态技能互通——技能市场天然兼容全球最大技能生态；
- **difflib**（标准库）：零依赖做修改块对齐；
- **QwenPaw 的技能扫描器（Skill Scanner）范式**：蒸馏出的技能先过静态安全扫描（禁 API key 硬编码、禁危险命令）再入库。

### ⑤ 数据落在哪
`%LOCALAPPDATA%\PAI-Station\skills\` 目录，每个技能一个文件夹：SKILL.md + 采样样本 + 采纳率统计。目录可直接 git 化，用户技能库即 Git 仓库，一键发布到技能市场。

### ⑥ 怎么验证
- 留出法：用前 4 次周报蒸馏技能，预测第 5 次的采纳率（编辑距离）；
- 消融实验：关掉 diff 蒸馏（只用通用提示词）vs 开启，采纳率差 ≥25 个百分点才算技能生效；
- 案例集：每类任务保留"初稿-终稿-抽取出的规则"三联证据包，人工可审计。

## 1.5 支柱三：放大你的产能（主动服务的实施路径）

### ① 目标定义
从"你问我答"升级为"我知道你该要什么，做好等你拿"。验收标准：
- 每周主动交付 ≥3 项被采纳的成果（周报初稿/会议纪要/资料包/待办清单）；
- 打扰 ≤2 次/天，且每次打扰满足"三问"——为什么是现在？为什么是你？为什么是这个成果？
- 例行工作接管率逐月上升（第 1 月 5% → 第 12 月 30%）。

### ② 需要感知什么（时机感知是本支柱的灵魂）
- **任务信号**：日历事件（15 分钟后的会→预生成议程）、文件事件（日报 18:00 未写→预起草）、IM 事件（领导 @ 你要材料→提醒+代拟）；
- **注意力状态**：前台窗口轮询判断"你在深写文档"还是"你在摸鱼"，深工作时段绝不打扰；
- **周期规律**：从历史行为统计出你的节奏（每周五 16:00 写周报、每月 1 日报销）。

### ③ 核心算法：三层决策（对应 Fogg B=MAP × JTBD × Eisenhower）
```
第 1 层 触发器（Trigger）：事件（日历/文件/IM/周期）触发候选任务
第 2 层 动机×能力评估（B=MAP）：
        动机 M：JTBD 三维度打分（功能/情感/社会，1-5 分）×紧迫度
        能力 A：技能库是否有匹配技能？参考记忆是否召回齐？
        提示 P：当前注意力状态是否允许打扰？
        B = M × A × P → 服务分数
第 3 层 优先级裁决（Eisenhower 四象限）：
        重要且紧急 → 立即推送；重要不紧急 → 排入"成果抽屉"
        紧急不重要 → 折叠为提醒；不重要不紧急 → 丢弃
输出：成果进入"抽屉"（用户下次打开即见，无打扰）或推送企业微信（高价值）
```
**抽屉机制**是防打扰的关键创新：主动成果默认进抽屉不弹窗，只有 Eisenhower 判定"重要且紧急"才推送——把打扰成本从"每次 23 分钟重聚焦损失"（Gloria Mark, UC Irvine 研究）压到近乎零。

### ④ 用的开源件
- **APScheduler**：cron/interval/date 三种触发器，托管周期任务；
- **openhuman 的 auto-fetch 范式**（每 20 分钟自动拉取上下文）改造为"每 20 分钟时机扫描节拍"；
- **nanobot 的 ultra-light loop 范式**：主循环保持 <100ms 心跳，重活全部下放队列。

### ⑤ 数据落在哪
`outbox.db`（待交付成果表：content, score, quadrant, expires_at, adopted）+ 抽屉 UI（pywebview 桌面托盘）。采纳率自动回写，作为第 7 章自学习引擎的输入。

### ⑥ 怎么验证
- A/B 基准：同一用户环境，开启主动引擎 vs 关闭，两周对比采纳成果数；
- 打扰审计：统计每日推送次数与用户静音/关闭动作，目标拒绝率 <10%；
- 响应延迟：从事件触发到成果就绪 P90 ≤90 秒（周报级任务 ≤5 分钟）。

## 1.6 支柱四：成为你的资产（分身资产化的实施路径）

### ① 目标定义
记忆+技能+画像三库合一，打包为**可携带、可备份、可授权交易的个人分身资产包**。验收标准：
- 一键导出/导入：换机后分身能力零损失（迁移测试通过）；
- 画像自动生成并每季度自更新：个人画像（Big Five 收敛式）+ 领导/客户画像 + 企业画像；
- 资产包可选择性脱敏分享（技能市场）而不泄露记忆。

### ② 需要感知什么
记忆库全量统计特征：沟通文风（用词/句长/语气）、协作对象（领导/客户/同事）、行业上下文（产品/竞品/术语）、决策偏好（风险态度/反馈速度）。

### ③ 核心算法：三模型收敛画像
```
个人画像：Big Five 量表题项由 glm-z1-flash 从记忆库行为证据打分（开放性/尽责性/
外向性/宜人性/神经质），每维度附"证据链"（哪些行为支持该评分）→ 可解释
人际画像：对每个高频联系人建"沟通画像"（偏好文风/决策风格/雷区）→ 服务于
向上管理与客户应对
企业画像：SWOT+Porter 五力+PESTEL 框架化爬取与整理解果（内网公开资料+行业报告）
         → 服务于"写出来的东西像这家公司的人写的"
资产包结构（avatar.pai）：
  profile/    三类画像 JSON
  skills/     技能库（可分享部分）
  memory.idx  记忆索引与摘要（不含原文，原文留在本地）
  provenance  资产溯源与授权记录（哈希链）
```

### ④ 用的开源件
- **openhuman 的 Memory Tree + Obsidian wiki-link 范式**：画像与记忆的互链结构借鉴其 7,349 节点记忆图的产品化经验；
- **DPDP（差分隐私思想）**：资产包分享时对记忆摘要做 k-匿名过滤（实体只保留哈希），技能文件分享默认剥离样本数据。

### ⑤ 数据落在哪
`avatar.pai`（zip 容器，AES-256 本地加密，密钥由用户主密码派生 PBKDF2）。技能市场发布仅上传 `skills/` 子集。

### ⑥ 怎么验证
- 迁移测试：导出→清空→导入→跑 P1/P2/P3 全部验收基准，分数差 <5%；
- 脱敏审计：发布到市场的技能包经扫描器验证不含个人实体（NER 扫描零命中）；
- 画像校准：用户每季度对画像做 5 分钟确认，偏差>30% 触发重建。

## 1.7 四支柱的复利闭环（为什么 1+1+1+1 > 10）

```
P1 记忆 ──喂样本──▶ P2 蒸馏技能 ──被调用──▶ P3 主动产能
  ▲                    │采纳率回写              │新工作再入记忆
  └────────────────────┴────────────────────────┘
              └──三者沉淀──▶ P4 资产（画像反哺 P2/P3 更准）
```
第 n 个月的能力 = f(记忆量) × g(技能数) × h(画像精度)，三项都随时间单调增长——这就是"复利"的数学结构，也是竞品（订阅制、无蒸馏、无画像）无法复制的结构性优势。
