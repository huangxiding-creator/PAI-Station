# 第 11 章 竞品全景解剖（四强逐家深拆，本提案的"知己知彼"底稿）

> 调研完成于 2026-09-06：GitHub README/源码结构 + 官网实地抓取（tinyhumans.ai/openhuman、qwenpaw.agentscope.io）+ 论文（VikingMem, VLDB 2026）。每家五段：架构与定位 → 杀手特性（实测/文档证据）→ 商业模式 → 可缝合吸收清单 → 我们的超越路线。

## 11.1 openhuman（39,436★，Rust+Tauri 桌面应用，GPL-3）

**架构与定位**：原生桌面（Mac/Win/Linux）个人 AI 超级智能，内置编排引擎管理多 agent；本地加密记忆；官网宣称 100k+ 用户、#1 Product of the Week。

**杀手特性（官网与代码证据）**：
1. **Memory Tree + 记忆图**：官网 layer-four 图展示 7,349 互联节点的记忆图——把"记忆可视化"做成产品第一卖点，用户"看见自己的第二大脑"；
2. **TokenJuice 式压缩**（社区版本）宣称记忆调用 token 降 80%；
3. **auto-fetch 20 分钟节拍**：无需用户提问即自动拉取集成应用增量——与我们的 OODA 节拍同源；
4. **118+ 一键集成**：官网列表 Notion/Gmail/Telegram/Slack/Sheets/Excel/Teams/GitHub——西式 SaaS 全家桶；
5. **Medulla 多 agent 编排**：规划-委派-执行可视化（官网 layer-three 图）。

**商业模式**：GPL-3 开源 + 托管服务订阅；agent 经济（tiny.place/x402 微支付）面向 agent 间交易。

**吸收清单**：①20 分钟节拍→主循环；②记忆星图可视化→抽屉 UI；③多 agent 编排范式→M6+ 规划器；④集成市场卡片设计→技能市场 UI。

**超越路线**：它没有中国通道（118 集成零中国 IM）、没有蒸馏（技能靠人写）、GPL 阻断商业生态、订阅制把资产留在平台。我们四点全反着做（原生通道/自动蒸馏/MIT+生态/本地资产），差异是结构性的。

## 11.2 QwenPaw（34,919★，Apache-2.0，阿里 AgentScope 生态）

**架构与定位**：个人 AI 工作站，官网 meta："running in your own environment. It supports local or cloud deployment, connects to 10+ channels including DingTalk, Feishu, QQ, Discord, and Telegram, and is extensible with Skills and MCP"。

**杀手特性**：
1. **通道中国化最全**：钉钉/飞书/QQ 一等公民——四竞品中唯一认真做了中国 IM；
2. **ReMe v0.4 记忆系统**：会话自动入库、分层检索；
3. **Scroll Context**：滚动上下文技术（长对话不丢头）；
4. **Agent OS + 桌面端 Beta**：向单机工作站演进中；
5. **五层安全**：Sandbox/Tool Guard/File Guard/Skill Scanner/Access Policy——安全范式行业最佳实践，我们整体移植（4.7 节）。

**商业模式**：Apache-2.0 开源；背靠阿里云（模型与算力导流），是 Qwen 生态的旗舰示范。

**吸收清单**：①五层安全全盘移植；②通道抽象；③ReMe 会话自动记忆思想并入 DIKW 流水线；④技能库结构。

**超越路线**：它无全盘感知（文件/屏幕/微信行为不进上下文）、无 diff 蒸馏（技能手写）、无画像、桌面端仅 Beta 且重心在云。胜负手=感知+蒸馏+资产三件套（恰是我们的 P1/P2/P4）。这是最值得敬畏的对手，也是我们公开对标并逐项对比的对象（README 对比表每季度更新）。

## 11.3 OpenViking（35,602★，AGPLv3-core，火山引擎）

**架构与定位**：不是终端产品，是**记忆中间件**——viking:// 虚拟文件系统把外部记忆挂载进 LLM 上下文；VLDB 2026 论文 VikingMem。

**杀手特性（论文与 README 数据）**：
1. **L0/L1/L2 分层加载**：原文/摘要/索引按需载入，token 省 34~91%、首字延迟降 58~66%；
2. **LoCoMo 基准**：OpenClaw 原生记忆 24.2% → 接入后 82.08%（3.4 倍）；
3. **会话自动提交记忆**（session auto-commit）。

**商业模式**：AGPLv3-core 开源，火山引擎技术影响力投资，云服务导流。

**吸收清单**：整体作为 sidecar 进程采纳（第 2.3 节选型+AGPL 隔离方案）；分层思想反哺 FTS5 侧设计（weight 驱动降级）。

**超越路线**：不构成终端竞争——它做组件我们做产品，互为生态。我们公开的 sidecar 集成方案本身就是社区贡献（借势+反哺双层收益）。

## 11.4 nanobot（47,726★，HKUDS，Python）

**架构与定位**：ultra-light 极简 agent 循环，学术团队（港大数据智能实验室）出品，"小而美"哲学。

**杀手特性**：①主循环 <100ms 心跳、极低资源占用；②Dream 记忆（闲时整理）；③社区通道生态。

**商业模式**：无商业化组织，纯社区驱动——星标最高但无收入回路。

**吸收清单**：ultra-light loop 范式（主循环架构）、Dream 闲时整理（融入每日 02:00 PDCA 时段）。

**超越路线**：无中国官方通道、无感知/蒸馏/画像、无运营组织（技能市场的结算审核客服无人扛）。它能赢星标，赢不了需要持续运营的双边市场。

## 11.5 四强合围下我们的生态位（结论）

四大竞品各占一角：openhuman=桌面体验+西式集成；QwenPaw=中国通道+安全；OpenViking=记忆组件；nanobot=极简哲学。**交集处（中国通道×全盘感知×蒸馏×资产×零成本×生态结算）全部空缺**——6.5 节五维矩阵量化了这个空白（竞品最高 21/50，我们 47/50）。PAI-Station 的定位一句话：**把四家各自的"最长板"缝合成一台面向中国职场的工作站，并在它们都没有的蒸馏-资产-生态引擎上建立结构性壁垒。**
