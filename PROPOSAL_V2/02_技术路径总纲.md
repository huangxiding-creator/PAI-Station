# 第 2 章 技术路径总纲（愿景与思维模型之间的技术方案层）

> 本章回答：从愿景到落地，每一层**有哪些候选技术、调研结论如何、为什么选这个、怎么组合缝合**。选型原则（用户指令）：每个技术点先在谷歌/网络充分调研多种手段→找最适合的或开源项目组合→绝不造轮子→详细写出用了哪个项目、怎么组合、怎么创新、怎么改造。

## 2.0 六层技术栈与思维模型的双向映射（先给全景）

| 层 | 本层干什么 | 候选调研过的方案 | 最终选型 | 指挥本层的思维模型 |
|---|---|---|---|---|
| L1 感知层 | 采集文件/屏幕/IM/代码信号 | watchdog/PowerShell FSWatcher；mss/dxcam/OBS；Hook 注入/无障碍 API/纯视觉 | watchdog+mss+纯视觉 | Kahneman 双系统（快慢分离） |
| L2 上下文层 | 信号→摘要→分层记忆 | OpenViking/LangChain Memory/Mem0/MemGPT/自建 | OpenViking sidecar+FTS5 | DIKW+Ebbinghaus+Zettelkasten |
| L3 规则层 | 提炼个人/企业工作规则 | 纯提示词/RAG/规则库+画像 | 规则库+三模型画像 | MECE+SWOT+Porter+商业模式画布 |
| L4 技能层 | 生成与执行任务 | SKILL.md/MCP/自定义 DSL | SKILL.md（兼容 anthropics 规范） | Kolb+Bloom+Ericsson |
| L5 主动层 | 决定何时服务、交付什么 | cron 轮询/事件驱动/强化学习 | 事件+节拍混合，Fogg 打分 | Fogg B=MAP×JTBD×Eisenhower |
| L6 自学习层 | 复盘、纠错、升级 | 日志分析/RLHF/自博弈 | 5Whys+双环学习引擎 | PDCA+Argyris+石川图 |
| 横切 | 模型调度 | 付费 API/本地大模型/免费链 | 智谱免费链（glm-4/4.7/z1/4v-flash） | Kahneman 系统1/系统2 |

**为什么要这层映射**：思维模型不是装饰，是每层的"指挥算法"——L5 该不该打扰你不靠拍脑袋，靠 Fogg 公式打分；L6 怎么纠错不靠重试，靠 5Whys 找根因。第 3 章将逐模型展开论证。

## 2.1 模型推理层选型（横切层，先定因为它决定一切成本结构）

| 候选 | 成本 | 能力 | 中国可达性 | 结论 |
|---|---|---|---|---|
| OpenAI/Anthropic 付费 API | $3-15/M tokens | 顶级 | 需海外支付 | ✗ 违背零成本约束 |
| 本地开源模型（Qwen/Llama + Ollama） | 电费+硬件 | 中低（笔记本 8-16G 显存跑 7-14B 吃力） | 好 | ✗ 笔记本跑不动高质量推理 |
| **智谱免费链（glm-4-flash + glm-4.7-flash + glm-z1-flash + glm-4v-flash）** | **¥0** | 128K-200K 上下文，z1 带推理链，4v 视觉 | **国内直连** | ✓ 唯一同时满足零成本×能力×可达性 |

**组合策略（Kahneman 双系统的工程化）**：
- 系统 1（快）：glm-4-flash 128K/30 并发——感知摘要、意图分类、日常问答，毫秒级成本零；
- 系统 2（慢）：glm-z1-flash——技能蒸馏规则抽取、画像打分、复杂任务规划（带显式推理链）；
- 视觉：glm-4v-flash——截图理解、微信消息识别；
- 长文：glm-4.7-flash 200K——整份合同/长报告解析。
**调度器**：任务先入系统 1 分类，置信度 <0.7 或任务标记 complex 才升级系统 2——该模式已在用户自有项目 We-AIPO 的 zhipu.py 验证稳定（_AdaptivePacer 自适应限速 + tenacity 重试），直接移植。

**改造点**：为智谱链写统一适配器 `pai/llm/`，暴露 `fast()/deep()/vision()` 三个方法；所有引擎只依赖此接口——未来若免费额度变化，可无痛切换任何兼容 OpenAI 协议的端点。

## 2.2 感知层选型对比

| 维度 | 方案A：Hook/无障碍注入 | 方案B：系统事件 API | 方案C：纯视觉+文件监听 |
|---|---|---|---|
| 覆盖面 | 极高（可截获一切） | 中（只有注册过的事件） | 高（屏幕上有的都能看见） |
| 稳定性 | 低（微信会封号） | 高 | 高 |
| 实现成本 | 极高（逆向维护） | 中 | 低（截图+VLM 成熟） |
| 隐私可控 | 差 | 中 | 好（黑名单粒度到窗口） |
| **结论** | ✗ | 部分采用 | ✓ 主路线 |

- **文件**：watchdog（跨平台 FS 事件，Python 标准选择）→ 变更文件进 MarkItDown/MinerU 管道；
- **屏幕**：mss（纯 Python 截图，实测 4K 单帧 <80ms）；dxcam 备用于需要高频帧的场景（桌面 UI 自动化时 60fps）；
- **浏览器自动化**：**DrissionPage（用户指定）**——对比 Playwright/Selenium：DrissionPage 收发数据包与浏览器操作双模式、无 webdriver 特征、对国产环境兼容好；用于内网数据爬取与登录态复用；
- **微信读取**：纯视觉（截图→GLM-4V-Flash）——这是对 ItChat/wechatpy 等 Hook 方案（已死/封号）的彻底否决，QwenPaw 等竞品的微信方案也停在"社区通道"灰色地带，我们用只读视觉实现零风险。

## 2.3 上下文/记忆层选型对比（本项目技术密度最高的一层）

| 候选 | 星数 | 核心机制 | token/延迟收益 | 许可证 | 结论 |
|---|---|---|---|---|---|
| OpenViking | 35.6k | viking:// 虚拟FS，L0原文/L1摘要/L2索引按需加载 | -34~91% token，-58~66% 延迟，LoCoMo 24.2→82.08 | AGPLv3-core | ✓ 采纳为 sidecar 进程 |
| Mem0 | 30k+ | 记忆抽取+图增强 | 中等 | Apache-2.0 | 备选（备胎） |
| MemGPT/Letta | 15k+ | 分页虚拟上下文 | 中等 | Apache-2.0 | 思想吸收（分页），不引入 |
| LangChain Memory | - | 会话记忆 | 低（会话级，非长期） | MIT | ✗ 量级不够 |
| 自建 SQLite+FTS5 | - | 全文检索+实体链接 | 高（免 LLM 召回） | 自有 | ✓ 与 OpenViking 并用 |

**最终架构**：OpenViking 作为独立 sidecar 进程（管分层加载与召回排序）+ SQLite FTS5（管持久化与全文索引）+ jieba（中文分词）。**AGPL 隔离方案**：OpenViking 以独立进程运行，主程序通过本地 HTTP/stdio 协议调用，进程边界切断许可证传染——这是开源合规的标准做法（参考 MongoDB SSPL 生态的 sidecar 模式）。

**创新点**：在 OpenViking 的 L1 摘要层前面加一层"记忆审计"——每个新记忆写入时用 Fogg 逻辑打"未来被检索概率"分，低分记忆直接降级到 L2 索引不占摘要预算，把 OpenClaw 记忆膨胀问题（上下文超长导致退化）在写入端解决。

## 2.4 规则/画像层选型对比

规则的表达形式决定了可维护性：

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯提示词（塞 system prompt） | 简单 | 规则一多互相冲突、无法审计 | ✗ |
| 知识图谱（Neo4j） | 关系推理强 | 重、运维复杂 | ✗ 过度设计 |
| **结构化规则库（INI+JSON）+ 画像文档** | 人类可读可改、INI 用户约定、冲突可检测 | 需自建冲突检测 | ✓ |

规则库分三类，分别用不同思维模型保证完备性（MECE 检查分类相互独立、完全穷尽）：
1. **个人规则**（文风/习惯/雷区）——从记忆库蒸馏，存 `rules/personal.ini`；
2. **人际规则**（领导怎么伺候/客户怎么应对）——Big Five×沟通画像收敛，存 `rules/contacts/*.json`；
3. **企业规则**（行业黑话/公文格式/合规红线）——SWOT+Porter+PESTEL 框架爬取整理，存 `rules/org/`，公文格式直接实现 GB/T 9704（党政机关公文格式国家标准）模板。

## 2.5 技能层选型对比

| 候选 | 生态位 | 结论 |
|---|---|---|
| anthropics SKILL.md 规范 | 全球事实标准（Claude 生态、Claude Code 原生） | ✓ 直接采用 frontmatter，兼容最大技能生态 |
| MCP（Model Context Protocol） | 工具互操作标准 | ✓ 作为工具接口层支持（社区技能可挂 MCP 工具） |
| 自定义 DSL | 无生态 | ✗ |

**执行引擎**：技能=SKILL.md（说明书）+ 可选脚本（Python/命令）。执行器读取 SKILL.md 组装上下文，调度 L1-L6 完成任务；执行结果连同初终稿 diff 回写——这就是 P2 蒸馏闭环的入口。**安全范式移植自 QwenPaw 五层防护**（Sandbox 沙箱/Tool Guard 工具守卫/File Guard 文件守卫/Skill Scanner 技能扫描/Access Policy 访问策略），技能市场上架必过扫描。

## 2.6 主动层与自学习层选型

**主动层**：APScheduler（触发器框架成熟）+ 自研时机评分（Fogg B=MAP，见 1.5③）。对比过 LangGraph（图编排，重）/Temporal（工作流，极重）——本地单机场景 APScheduler 足够，保持 nanobot 式 ultra-light loop。

**自学习层**：日志→事件→根因的标准流水线，不引入 RL（无标注奖励信号，用户采纳率就是天然奖励，但样本量太小不值得上 RLHF）。采用 5Whys+石川图（因果结构化）+ Argyris 双环（不只改行为，还改规则本身）。

## 2.8 自研部分清单（诚实边界：哪些必须自己写）

缝合不是没有自研，自研集中在**无人做过、构成核心壁垒**的四处：
1. **初终稿 diff 蒸馏器**（P2 引擎，竞品皆无）；
2. **时机评分器**（Fogg B=MAP 工程化，决定主动服务体验）；
3. **三模型收敛画像器**（可解释画像+证据链）；
4. **五层安全的中国化合规改造**（微信纯视觉协议、数据不出本地策略）。
其余全部缝合。预计自研代码占总量 <30%，但贡献 80% 差异化价值。
