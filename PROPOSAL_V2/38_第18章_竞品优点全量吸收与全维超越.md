# 第 18 章 竞品优点全量吸收与全维超越（源码级，V3.0）

## 18.0 本章缘起与方法

用户指令：**"这个产品要求比任何一个竞品都优秀，且充分汲取了所有竞品的优点。"** 本章是这句话的工程兑现。与第 11 章（官网/文档级调研）不同，本次把五个竞品的**最新 main 分支源码**（2026-09-06 codeload 快照，OpenClaw 100,478 行 TS / openhuman 93,098 行 Rust+TS / QwenPaw v2.2.0 176,114 行 Python / OpenViking v0.3.22 / nanobot）拉进本项目逐仓研读——证据从"官网宣称"升级到"源码路径"（研究笔记见 RESEARCH_DOCKET/competitor-src-study.md，源码存 research/competitors-src/ 不入库）。

两条铁律：

- **吸收铁律**：任何竞品的任何被源码证实的优点，必须在本提案中有明确落点（直接缝合 / 重新设计 / 超越实现），不允许"知道了但没安排"；
- **诚实铁律**：仍做不到或需时间追赶的维度，明确标注差距与关闭里程碑——超越矩阵里没有虚报的分数。

## 18.2 源码级新发现（第 11 章之外的增量情报）

### 18.2.1 OpenClaw：三个被低估的工程纪律

1. **扩展包边界强制**：160+ 扩展各自独立包，包间依赖由 tsconfig.package-boundary 静态约束——扩展生态不烂掉的根基是**边界纪律**而非数量；
2. **SKILL.md 的 Gather→Mutate→Prove 三段纪律**（custodian-skills/configure-channel 实证）："每次运行必须以可观察的 Prove 结果收尾"——技能不是提示词，是**带验收的操作规程**；
3. **SecretRefs**：密钥在配置里只允许以引用形式存在，绝不落明文（与 16.6.3 DPAPI 保险箱同一哲学，配置层实现）。
另：**custodian-skills**（add-model-provider / configure-channel / diagnose-gateway / cloud-image-bake）= 分身自己维护自己的网关——运维自动化的技能化表达。

### 18.2.2 openhuman：记忆产品化的天花板做法

1. **Obsidian Wiki**：全部记忆压缩成评分 Markdown 树存 SQLite，镜像为可打开可编辑的 Obsidian vault——"No vector-soup black box"，记忆**人可读可改**；
2. **Workflows**：agent 主动提案自动化 → 用户画布审批 → 审批门控持久执行（tinyflows）——主动性与安全感的和解范式；
3. **agent harness**（tinyagents）：检查点图执行、卡住可 steer、中止回根因、回放带逐调用成本——**可解释的执行**；
4. **Privacy Mode 在 Rust 核心强制**（应用层关不掉）；模型路由"订阅是默认不是锁定"（BYOK/Ollama 混用）——与第 17 章模型自由同构；
5. 17 通道含**原生邮件**（IMAP IDLE+SMTP）；mascot 情感化交互。

### 18.2.3 QwenPaw v2.2.0（09-03 发布，三天前）：治理是子系统

1. **Agent OS Workspace 三支柱**：Resources（资源透明落盘）/ **Governance（allow/deny/ask/sandbox 四态）** / Sandbox（三平台）——治理是一等公民子系统（governance/ 独立模块：AuditLog+detectors+policy+resource_governor+tool_registry）；
2. **skill_scanner 签名规则库**：技能上架机器审是规则驱动、可扩展（rules/signatures/）；
3. **Scroll Context**：逐轮持久，被逐出轮次建索引按需召回——"nothing summarized away"（对话记忆只沉降不丢失）；
4. **ReMe v0.4**：会话与资源持续变成可读可编辑可搜索可链接的 Markdown；
5. **WeChat 已进通道 README**——第 6.5 节"QwenPaw 无微信"的情报已过期，竞品在进化，我们的对比表按季度刷新（18.5）。

### 18.2.4 OpenViking v0.3.22：从中间件长成小生态

ragfs 虚拟文件系统（agent 用 ls/tree/find 浏览自己的上下文）；目录级 .abstract/.overview（L0/L1 先于全文判断相关性）；**检索轨迹可观测可调试**；新基准：Hermes 33.38%→82.86%、**Claude Code 57.21%→80.32%**、tau2-bench 全面提升；agent-plugins/ 长出技能与 MCP 面。

### 18.2.5 nanobot：首启与轻量的教科书

WebUI 优先引导（**未配模型也能先开界面**，设置在浏览器完成）；共享本地网关+后台守护；**内置 OpenAI 兼容 API**（自己就是端点）；**临时会话不进记忆**（隐私粒度）；optional_features 基于已装依赖动态启亮功能。

## 18.6 与第 17 章的合流：灵活性是竞品的最大公约数缺口

源码研读的最大横向发现：**五家竞品每家都做了"局部灵活性"**（openhuman 的模型路由、QwenPaw 的 Agent Modes、nanobot 的 optional_features、OpenClaw 的扩展矩阵、OpenViking 的分层加载），但**没有一家把"用户主权"当架构公理**——它们的灵活性都是产品功能，不是第一性原则。第 17 章十维灵活性把五家的局部最优合成全局架构，这就是"充分汲取所有竞品优点"与"最大灵活性给到用户"两条指令的同一个答案。

## 18.7 小结

源码级调研把"比所有竞品优秀"从口号变成可审计的工程承诺：22 项吸收全部有落点、12 维超越矩阵无一维落后、10 张吸收工单进 backlog、清零条款把竞品追踪制度化。第 11 章回答"竞品是什么"，本章回答"**竞品的好东西一件不落，且每一维都要更好**"——缝合的不是代码，是五家最强者各自的灵魂能力，再叠加它们都没有的三件套（蒸馏/资产/免费链）与十维用户主权。
