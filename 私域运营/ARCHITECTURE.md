## 1. 背景与目标

### 1.1 业务资产

- **总包AI顾问**：已有的工程行业 AI 答疑能力（Claude/GLM 大模型栈），另有微信小程序入口。
- **总包智库**：工程知识库与标准规范内容。
- **自媒体永动机（We-AIPO）**：在跑的内容引擎（另一台机器，9222），日更 3 个公众号 + 1 个视频号。
- **主理人个人微信**：加入了几十个工程建设行业微信群。
- **企业微信**：总包科技主体，可申请官方 API 能力。

### 1.2 目标场景

| 场景 | 内容 | 通道 |
|---|---|---|
| A 群聊守护 | 监听行业群，识别工程问题，AI 答疑 + 智库内容推荐 + 恰当的产品介绍；被 @ 必答，克制主动 | 个微 RPA + 企微 |
| A2 内容分发 | 永动机产出的文章/视频，按"群画像×内容标签"匹配后低频分享进群 | 个微 RPA + 企微 |
| B 朋友圈 | 仅自己内容的发布辅助：系统生成文案素材 → 人工确认 → 辅助发布；**不做**对他人内容的自动点赞/评论 | 企微客户朋友圈 + 个微半自动 |
| C 客户沉淀 | 联系人/群/商机台账与画像，周报复盘 | 本地 |

### 1.3 非目标（红线）

- 不做对他人朋友圈的自动点赞/评论/留言。
- 不做自动加好友。
- 不做未经人工确认的全自动朋友圈发布。
- 不做多租户/云服务，单机自用。

## 2. 总体架构

```
+------------------------------------------------------------------+
|                       总包私域运营台 zb-ops                        |
|                                                                    |
|  +--------------+  +------------------+  +---------------------+  |
|  | 通道适配层    |  | 护栏层 Guardian   |  | 编排层              |  |
|  | 企微官方 API  |  | 频率令牌桶        |  | AI 编排(答疑/推荐)   |  |
|  | 个微 RPA      |  | 内容审核闸        |  | 内容分发 CDM        |  |
|  | worker(独立)  |  | 人工确认队列      |  | (匹配/排期/队列)     |  |
|  |              |  | kill switch      |  |                     |  |
|  +------+-------+  +--------+---------+  +----------+----------+  |
|         |                   |                       |             |
|         +----------+--------+---------+--------------+             |
|                    v        v         v                            |
|              +---------------------------------+                   |
|              | 数据层 zb-data (SQLite/WAL)     |                   |
|              | 台账/画像/队列/审计/频率账本      |                   |
|              +---------------------------------+                   |
|                    |                                               |
|              +---------------------------------+                   |
|              | 运维层：守护/监控/备份/升级        |                   |
|              +---------------------------------+                   |
+------------------------------------------------------------------+
        |                                  |
        v                                  v
  企业微信官方服务器                  个人微信桌面客户端
  (合规 API，主力通道)              (精简 RPA，辅助通道)
```

三条铁律贯穿全图：

1. **队列即唯一出口**：一切对外动作经统一分发队列，依次过护栏闸链（急停→日历→令牌桶→审核→人审路由）后才由 dispatcher 执行；通道适配器只接受 queue_id，架构上不存在旁路直发。
2. **企微优先**：同一能力若企微官方 API 可达，一律走企微；个微 RPA 只承接企微覆盖不了的存量群。
3. **本地数据主权**：数据全部本地 SQLite，最小化采集、可删除、不外传第三方云。

## 3. 与逆向标的（识流AI助手）的对照

用户要求"充分利用逆向产物、达到与标的一致的效果与安全性"。对照结论：

| 维度 | 识流的做法 | 本系统的做法 | 等价性 |
|---|---|---|---|
| 感知 | 截屏→云端 YOLO→豆包视觉 OCR/校验 | 本地视觉：RapidOCR + OpenCV 模板匹配 + Claude/GLM 视觉（自家栈） | 等效（见 §5.7 降级策略） |
| 决策 | 其云端 sees 引擎 + Coze | 自有 AI 编排层 + 总包AI顾问同源 API | 等效且自主 |
| 输入 | robotjs helper + wyhkm 驱动 + CH9329/AtomS3U/NanoKVM 硬件 | robotjs（其公开 fork）拟人化输入；CH9329 硬件后端列为可选升级（公开协议芯片） | 软件级等价；硬件级为可选 |
| 拟人化 | 贝塞尔轨迹/正态延迟/随机点击参数全套 | **参数表全盘照抄**（逆向报告 §6.1 公式级） | 等价 |
| 风控对策 | 不聚焦/红点导航/画面 diff/截图节流 | 同左，参数照抄；外加频率纪律 | 等价 + 频率纪律补强 |
| 行动验证 | 0/1 视觉后验 | OCR/模板置信度后验 + 异常即停 | 等效 |
| 审计 | ReplayLogger（默认关） | append-only audit_log（**默认开**） | 更强 |
| 合规 | 反检测军备竞赛 | 企微主体 + 低频响应式 + 护栏 | 路线不同，风险更低 |

**诚实声明**：本系统不追求与其硬件级反检测能力完全对等（那是无限军备竞赛）；在已确认的克制范围内，软件级拟人 + 频率纪律 + 行动验证的组合，配合企微主体承担主要流量，账号安全实践上优于纯个微 RPA 路线。

## 4. 总体裁定书（对三镜头对抗评审的裁决）

6 份子系统设计 + 内容分发设计经合规/可行性/安全三镜头评审，共提出 34 条问题（2 条否决级、12 条 high）。以下为动工前**必须锁定**的集成裁定，全部子系统的后续详细设计以本表为准：

| # | 裁定项 | 评审问题 | 最终裁定 |
|---|---|---|---|
| 1 | 唯一 AI 大脑 | 企微侧与编排层双大脑、流式与整条发送冲突 | 编排层（AI 编排子系统）为唯一大脑；企微侧只留通道适配；流式仅用于智能机器人通道且每个增量段过闸后下发，个微一律整条 |
| 2 | 唯一咽喉 | 护栏票据无人验，企微组件直发 | 企微全部出站动作（欢迎语/机器人回复/朋友圈任务/群发/客服）收编进 ActionGateway 票据链 |
| 3 | 唯一回调与 token | 双企微客户端 token 互踢 | 仅 wecom-core 持有 access_token；回调唯一入口为单个 FastAPI 服务 |
| 4 | 唯一主数据 | 双台账无映射 | 数据层 schema 为准，企微侧台账降为只读投影；各子系统私有库仅存私有缓存 |
| 5 | 唯一熔断 | 三套断路器互不包含 | 单一权威急停状态机（全局+分通道、版本化），全部触发源写同一状态，执行器与监督者强制读它 |
| 6 | 唯一频控表 | 四层频控数值互相矛盾 | 全局频控参数表（单一 YAML）为唯一真源，多层取严；见第 7 章 |
| 7 | 唯一人审队列 | 双队列规则冲突 | 合并进护栏子系统确认队列；"产品推介 vs 知识资料"判定函数入共享策略表 |
| 8 | 唯一控制台 | 四个管理面碎片化 | 单一本地控制台 + 端口注册表 |
| 9 | 密钥单面 | 三套密钥方案并存 | 全系统唯一密钥面 = secrets.dat（DPAPI）+ zbctl；禁环境变量与明文传密钥；gettoken 类 URL 强制日志脱敏；LiteLLM 关请求日志与遥测 |
| 10 | 个微 RPA 定位 | 合规镜头否决级：自动读取+自动回复属外挂红线本体 | **降级为"纯辅助默认 + 门禁制放权"**：默认模式零触碰微信进程（素材+剪贴板辅助）；群应答主路径迁企微；个微自动应答须过 Go/No-Go 门禁（4.x 探针实测 + 小号 72h 存活 + 主理人书面风险确认）后按三阶段放权，且出站默认逐条人工确认 |
| 11 | 个微内容分发 | 同上（用户核心需求：分享文章到个微行业群） | 保留但半自动优先：系统导航+粘贴、人工点发送；稳定 N 周零风控信号后经书面确认才可对白名单群开免批，仍受最严频率。此为"用户需求驱动、评审保留意见、风险主理人自担"的明示决策点 |
| 12 | 4.x 感知前提 | UIA 空树已实测、唯一文献支持的是被禁视觉栈 | Go/No-Go 门禁前置；推荐解禁**最小视觉栈**（仅控件定位+发送后校验，RapidOCR/OpenCV 本地），与最小采集相容；禁止复活识流式全套视觉理解 |
| 13 | 被动采集合规 | 对未互动群成员画像无告知无退出 | 采集收缩为"与机器人/主理人有直接互动者"；上线前群公告告知 + @机器人退订通道；线索默认只记"群+话题"，人工确认后才落自然人 |
| 14 | 云端 LLM 出境 | 与"不外传"自相矛盾 | 硬规则：个微侧语料一律本地模型或完全脱敏后方可出境；出境内容审计计数 |
| 15 | 工程内容风险 | 高风险域无强制人审、资质无白名单 | 结构/抗震/消防/质量安全验收类强制人审或拒答；资质业绩事实白名单表，事实性主张仅可引用白名单 |
| 16 | 升级与热更 | 回滚撞新 schema、热重载 fail-open | 迁移只加不改不删 + 回滚包带退却脚本 + user_version 断言；热重载改强校验 fail-closed |
| 17 | 备份与恢复 | SQLite 孤岛未枚举、SQLCipher 与备份工具不匹配 | 备份清单枚举全部库文件；备份工具用 sqlcipher 构建；恢复即 paused + 首 24h 保守配额（50%）；主库 RPO 目标 ≤15min（高频热备） |
| 18 | 急停误报 | 看门狗扫窗口文本误触发 | 看门狗只判"未知模态顶层窗口"即 trip，文本匹配仅限 3.9 适配包内；对账不一致降级为暂停+人工复核 |
| 19 | 半自动防漂移 | 确认疲劳滑向全自动 | 发表后只读回读与批准稿哈希比对，不一致冻结排期；人审耗时低于阈值自动降回 L0 |
| 20 | 单人单点 | 主理人失联则系统安全地死 | 备用确认人（第二企微账号，仅白名单动作+re-arm 权限）；心跳提至小时级 |

## 5. 子系统设计（合成后）

六个子系统 + 内容分发子系统。本节为合成要点；完整设计原文存档于 `逆向工程/work/arch_designs.txt`（六份全文）与本文档同目录留档。

### 5.1 企微主通道（合规主干，P0）

全部能力经官方文档逐条核实（2026-10 现行版），关键事实：

| 原语 | 事实 | 用途 |
|---|---|---|
| 智能机器人长连接 | wss 免公网 IP，群@/单聊触发，流式回复 | 群答疑主链路 |
| 消息推送（群机器人） | 只发不收，20 条/分 | 运维告警+商机通知 |
| 客户联系欢迎语 | welcome_code 20 秒仅一次 | 新客户承接 |
| 客户朋友圈任务 | 成员客户端确认后发表 | 朋友圈合规路径 |
| 企业群发 | 成员确认，月上限=当月天数 | 克制触达 |
| 微信客服 | 48h/5 条窗口 | 外部客户咨询 |

组件：wecom-core（唯一 token 面）、aibot-gateway、callback-service（frp 固定域名隧道）、kf-service、message-router、welcome-engine、moment-studio、group-mass-sender、contact-ledger（只读投影）、material-library。智能机器人进客户群的能力待实测，不支持则客户群降级为欢迎语+官方自动回复+群发。

### 5.2 AI 编排层（唯一大脑，P0）

- **管线**：规则预筛（标准号 regex/@检测，零模型成本）→ 意图分类（小模型 T1）→ 上下文构造（20 条窗口+群摘要+画像+去重）→ 智库 RAG（FTS5 前置粗筛+向量精排，sqlite-vec 上限 10 万 chunk，超限换 faiss）→ 答疑生成（T2：Claude 首选/GLM 兜底，max_tokens 群答 400）→ 引用校验（条款号必须来自命中 chunk，difflib 比对，防幻觉）→ 话术护栏 → 治理器终审（全确定性规则，零 LLM 参与发送决策）。
- **克制度**（治理器硬规则）：产品提及每群每日 ≤1、每联系人 7 日 ≤1、仅商机信号明确时触发；同群两次发言 ≥10 分钟（被 @ 除外）；资料卡片每次答疑 ≤1 张。
- **成本**：LiteLLM 网关统一计量，三层预算硬顶+降级链；prompt caching 按保守 30% 命中测算；免费池仅过渡（设截止期）。
- **Prompt 资产**：版本化+评测集回归+灰度，热重载 fail-closed。

### 5.3 内容分发子系统（P1）

与自媒体永动机（9222 机器）以 **append-only JSONL 文件契约**对接（schema 含 content_id/type/title/url/account/tags/video_article_url/product_refs），分钟级轮询、三层去重（id+规范化 URL+标题 SimHash）。群画像半自动构建（AI 候选标签带证据，人工确认）。匹配打分：`0.5×tag_match + 0.2×freshness + 0.3×quality − 0.15×同题密度 − 0.2×群疲劳`，阈值 0.55。统一分发队列（kind=share/qa_reply/manual），三段式：护栏三闸 → dispatcher → 通道适配（个微 RPA / 企微 webhook）。频率默认：每群日 1 周 3、全局日 12、时段早午晚窗口、产品内容周 ≤1/群且占比 ≤20%。效果闭环：24h 讨论量追踪+周报。

### 5.4 数据与画像（P0 骨架）

双库：core.db（台账/审计/账本，SQLCipher+DPAPI）+ msg.db（高体量消息，可整体轮换）。写入即脱敏（手机号/身份证/银行卡不可逆）。联系人唯一键 (channel, ext_id)，双通道人工合并。画像带证据与半衰期，商机阶段升降级只建议不自动生效。保留期：消息 180 天→匿名聚合、AI 交互 90 天、截图 30 天、审计 3 年。与既有微信情报库做 bootstrap 导入（仅本人可见数据）。

### 5.5 合规护栏 Guardian（横切强制层，P0）

- **ActionGateway 唯一咽喉**：固定管线 急停→日历→抑制名单→令牌桶→内容审核→人审路由→落审计（fsync）→签发一次性 HMAC 票据（绑定内容哈希+急停版本，TTL 90s）；三通道执行器无票据即拒发；能力封闭枚举——**"点赞/评论他人朋友圈"不在枚举中，不存在即不可绕过**。
- **内容审核三级词库**：硬阻断（涉政/广告法绝对化/工程承诺类"保证中标/包验收"）→ 强制人审（报价/工期/资质表述）→ 提示。Aho-Corasick+正则，本地词库版本化。
- **KillSwitch 统一状态机**：全局+分通道，版本化，三入口（控制台/热键/企微指令）+自动触发（模态框检测/对账失配/校验连续失败）；恢复人工 re-arm+冷却。
- **个保法套件**：采集 schema 白名单最小化、LLM 出境脱敏代理、告知语模板+退订名单、按联系人删除（tombstone 保审计链连续）。

### 5.6 部署与运维（P0）

三层监督树：计划任务看门狗 → zb-supervisor（Python）→ rpa-worker（独立进程）。**铁律：凡触碰 UIA/微信窗口的进程必须跑在交互式桌面会话，严禁注册 Windows 服务**（Session 0 无桌面）。唯一例外是 frp 隧道进程。开机自启链：BIOS 来电自启 → Autologon（凭据入 LSA）→ 计划任务 → supervisor。告警走专用企微群机器人 webhook（单向，物理上杜绝递归），兜底 Toast+邮件+alerts.log。升级双轨：数据型热更（强校验）+ 版本目录 junction 切换（带 schema 迁移闸门与自动回滚）。备份 GFS+每周恢复演练+恢复即 paused。

### 5.7 个人微信精简 RPA（P2，门禁制）

默认 = **纯辅助模式**（零触碰微信进程：素材生成、剪贴板复制、打开图夹）。升级须过 Go/No-Go 门禁：

1. 本机微信 4.x UIA 能力矩阵实测（本机 2026-10-12 已实测：UIA 树为空 → 预期 DEAD）；
2. 若 DEAD：二选一——最小视觉栈（仅定位+校验，本地 RapidOCR/OpenCV，推荐）或明示"个微群应答不可用"并把迁企微前置；
3. 小号试运行 72h 存活 + 主理人书面风险确认。

放权三阶段（任一阶段可一键降级）：Phase 0 影子（只读感知+草稿+审计，零输入）→ Phase 1 辅助（人工逐条批准后执行粘贴；朋友圈 assisted_fill 止于发表按钮前，"发表"选择器在 FORBIDDEN 清单）→ Phase 2 受限自动（仅被 @ 与白名单私聊免批，限额最严）。回复执行：剪贴板协议（备份→写入→回读校验→Ctrl+V→恢复，随机延时 300-500ms 级，识流实测参数）；"永不做"清单硬编码（不点赞评论他人/不全自动发圈/不主动私聊陌生人/不绕风控验证/被问是否 AI 必须承认等 11 条）。

## 6. 关键流程（时序）

**F1 企微群答疑（主链路，全合规）**：成员 @智能机器人 → wss 长连接回调（msgid 排重）→ message-router 规则链 → AI 编排（意图→RAG→生成→引用校验→护栏）→ ActionGateway 管线（急停→日历→令牌→审核→人审路由→审计→票据）→ aibot 流式回复（每增量段过闸）→ 商机信号写台账+通知 → 全程审计。

**F2 永动机内容到群（个微半自动形态）**：JSONL 契约轮询入库 → 内容加工（标签归一/植入分级/推荐语候选）→ 次日 07:30 排期（打分+频率过滤+时段槽位）→ 到点组装 → 护栏三闸 → dispatcher → RPA worker 导航到群+粘贴 → **人工点发送（或面板一键确认下一群）** → 回读校验卡片渲染 → 审计+24h 效果追踪。企微群走 webhook 直发（同队列同护栏）。

**F3 朋友圈发布（合规路径）**：内容管线生成文案+配图 → 审核 → 人工确认队列 → 企微 add_moment_task（成员客户端一键确认发表）→ 轮询结果入台账。个微朋友圈走纯辅助/L0（复制文案+开图夹，人手动发）。

**F4 风控熔断**：未知模态框出现/校验连续失败 → 统一 KillSwitch trip（epoch+1，在途票据全废）→ 双路通知 → 只读观察 → 人工 re-arm（原因码+冷却）→ 全程审计。

**F5 数据主体删除（个保法）**：控制台发起 → 数据地图跨库清除（审计链 tombstone 保连续）→ 删除报告 → 备份副本同步处理。

## 10. 开放问题（动工前需主理人拍板）

1. 企微主体企业验证状态与四项能力（客户联系/朋友圈/微信客服/会话存档）后台核验；智能机器人能否进客户群实测。

5. 个微侧最终形态：纯辅助 / 最小视觉栈 / 迁企微——待 Go/No-Go 实测后拍板。
6. 保留期数值确认（消息 180 天/审计 90 天正文）；云备份默认关闭是否接受。
7. 备用确认人人选；值守窗口安排。
8. 群公告告知话术与退订机制的落地形式。
