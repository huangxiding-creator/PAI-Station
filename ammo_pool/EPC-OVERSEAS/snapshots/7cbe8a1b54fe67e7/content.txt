# PRA风险分析软件的六步操作指南

原创 zu 2026-07-03 18:25 北京

PRA风险分析操作就六步：导入P6进度、做健康检查、给活动加三点估算、把风险事件映射到活动上、跑蒙特卡洛模拟、看结果定应急储备。每一步具体怎么操作，下面展开说。

1. 导入P6进度计划

1从P6导出XER，在PRA中打开
操作路径：P6中按F9重新计算进度 → 文件 → 导出 → 选择XER格式 → 在PRA中 File → Open → 选择XER文件。

导入后PRA会自动验证，如果早开始/早完成日期与源文件不一致，会报错。这说明P6中的进度是旧的。

最容易踩的坑：导出前没在P6中按F9重算。PRA导入时会检查日期一致性，不匹配意味着分析基础就不对。

导入后PRA会在左侧面板列出所有活动，右侧显示甘特图。确认内容完整后就可以进入下一步。

2. 进度健康检查

2用PRA内置诊断工具检查进度质量
操作路径：菜单栏 Tools → Schedule Check → 勾选四项检查 → Run。

四项检查的内容和修复方法：

检查项

问题说明

怎么修

硬约束

如Must Finish By、Start On等，会锁死活动日期，模拟无法真实推移

全部删除，用逻辑关系驱动日期。如果需要固定节点日期，用里程碑+逻辑关系替代

开口作业

无前置或无后置逻辑的活动，破坏关键路径连续性

补齐逻辑关系，除项目开始和完成里程碑外不留开口

滞后量过大

大滞后量（如30天以上）把活动固定住，无法反映风险

替换为虚拟活动，这样可以为滞后本身分配不确定性

SS/FF关系滥用

这类关系在蒙特卡洛模拟中容易产生不可控的浮动

尽量减少，改用FS关系。必须使用的，检查是否有对应的FF/SS配合

这一步不能跳过。逻辑有问题的进度跑出来的风险分析结果是废的。一般花30-60分钟，修完再进下一步。

3. 分配工期不确定性（三点估算）

3为每个活动输入最小、最可能、最大工期
操作路径：选中活动 → 右键 Duration Uncertainty → 选择分布类型 → 输入三个工期值 → OK。

3.1 选择概率分布

分布类型

形状

什么时候用

Triangle（三角分布）

三角形

只有三个估计值，没有更多数据

BetaPERT（PERT分布）

略偏钟形

最常用，有最可能值，两端概率低

Uniform（均匀分布）

矩形

区间内任何值等可能，没有峰值

Lognormal（对数正态）

右偏长尾

活动只能延误不能提前（如审批、取证）

Normal（正态分布）

对称钟形

提前和延误概率对称

日常用BetaPERT最多。有历史数据的用数据拟合，没数据的找现场工程师逐项讨论。三个数不是拍脑袋出，至少说出"为什么最可能是5天、为什么最长不会超过7天"。

3.2 设置活动相关性

PRA默认所有活动独立变化。现实中不成立——比如下雨同时拖慢多个土建活动。不设相关性，模拟出来的完工日期范围会偏窄。

操作路径：选中多个相关活动 → 右键 Correlation → 输入Pearson系数（0到1）。同类工作（如混凝土浇筑之间）设0.5-0.7，不同类工作设0-0.3。

避免重复计算：每个活动只能分配一种不确定性来源。给活动用了三点估算，就不要再把同一个活动的工期不确定性作为离散风险事件再映射一遍。

4. 映射离散风险事件

4建立风险登记簿并映射到活动
操作路径：Risk Register面板 → Add Risk → 输入风险名称/概率/影响 → 拖拽风险到受影响的活动上（或右键活动 → Assign Risk）。

三点估算和离散风险事件的区别：

三点估算覆盖的是每个活动固有的执行不确定性——100%存在，只是范围不同

离散风险事件是可能发生也可能不发生的外部事件——概率低于100%，发生后产生额外延迟

给风险事件定义时至少包含三项信息：

参数

含义

怎么取值

概率（Probability）

风险发生的可能性百分比

有历史数据的用频率，没数据的用风险矩阵（如5级量表对应5%/25%/50%/75%/95%）

影响（Impact）

发生后延迟多少天

参考历史同类事件，结合受影响活动的工期估算

映射方式

Series（串联）或 Parallel（并联）

多个独立风险可能先后发生选Series，多个并发风险选Parallel

天气风险用PRA的概率日历功能，在活动日历中随机插入非工作日，而不是通过增加工期来模拟。这样更贴近实际——下雨那几天干不了活，不是活变多了。

5. 配置并运行蒙特卡洛模拟

5设置模拟参数后启动运行
操作路径：菜单栏 Run → Risk Analysis → 设置迭代次数/采样方法/随机种子 → Start。

四个关键参数：

参数

推荐值

原因

迭代次数

5,000

少于3,000结果不稳定，超过10,000浪费时间，5,000对于大多数项目足够

采样方法

Latin Hypercube

比简单随机抽样效率高，用更少迭代覆盖概率分布的全空间

随机种子

锁定为固定数字（如1）

保证结果可复现。不锁定的话跑两次结果不同，没法解释

收敛监控

启用

当均值和关键百分位数稳定后自动停止，节省等待时间

常规做法：跑两次。第一次是"减缓前"基准，反映当前风险暴露。加入应对措施后跑第二次"减缓后"。两次S曲线的差距，就是风险应对措施的量化效果。

PRA性能限制：PRA是32位软件，内存上限约4GB。活动数超过5,000个会明显变慢，超过10,000个可能崩溃。超大项目考虑分批分析或换用64位工具。

6. 解读输出结果

6打开五类输出报告，逐个解读
操作路径：模拟完成后自动生成报告面板，左侧选择报告类型 → 双击打开。

6.1 概率分布直方图

显示所有模拟迭代中完工日期的频率分布。横轴是日期，纵轴是出现频率。

图形宽扁 → 不确定性大，工期分散

图形瘦高 → 不确定性小，工期集中

出现双峰 → 可能存在两个不同的风险场景（如"审批通过"和"审批不通过"对应的两条路径）

6.2 S曲线（累计分布函数）

直接读取关键百分位数对应的日期：

P50完工日期 = 2026-12-20（50%把握） P80完工日期 = 2027-03-15（80%把握） P90完工日期 = 2027-06-01（90%把握）  进度应急储备 = P80日期 − P6确定性日期 = 2027-03-15 − 2026-11-30 = 105天

国际EPC项目通常以P80作为风险调整后的基准工期。P50给业主看趋势，P80用来定应急储备，P90太保守用不起。

6.3 龙卷风图

按对总工期的贡献度从大到小排列各风险和活动。排在顶部的就是最需要关注的关键风险驱动因素。

使用方式：取前5-10项作为重点关注对象，输入到项目风险登记簿，制定专项应对措施。

6.4 关键性指数

关键性指数表示每个活动在所有模拟迭代中出现在关键路径上的频率。

P6里不在关键路径上但关键性指数高的活动——这些是容易被忽视的"近关键路径"，浮时小，不确定性稍大就会变成关键路径。列入重点跟踪清单。

6.5 分布分析器

按WBS层级查看各工作包或各活动的概率分布详情。定位哪些WBS包是主要的工期不确定性来源——看哪个包的P50-P80跨度最大。

7. 操作中需要注意的几个问题

7.1 三点估算的数据从哪来

直接让工程师填"乐观/最可能/悲观"三个数，对方通常不知道怎么下手。给一个参考框架：先找历史同类活动的实际工期范围，作为讨论起点。比如"同类土建活动过去两年最短15天、最长35天，你觉得这批活动大概在这个区间里的什么位置"。从对比数据切入比从理论公式切入有效。

7.2 结果怎么跟业主沟通

不要只给一个P80日期。同时给出P6确定性日期、P50、P80、P90及对应的应急储备。业主看到的不是一个数字而是一个决策空间——多留多少天对应多大概率的把握。让业主自己决定愿意接受什么概率水平。

7.3 模拟结果差异很大怎么办

如果P50和P80之间的跨度非常大（比如超过计划总工期的30%），回头检查：

三点估算的最大值是否设得过于悲观

是否有大量活动的高影响风险被映射到了同一条路径上（串联累加效应）

进度逻辑是否本身存在大量开口作业导致分析失真

优先修正输入问题，而不是直接调低分布参数来凑一个好结果。

8. 总结：六步操作清单

步骤

操作

完成标志

1. 导入进度

P6中F9重算 → 导出XER → PRA打开

PRA验证通过，日期一致

2. 健康检查

Tools → Schedule Check → 四项全选 → Run → 逐项修复

无硬约束、无开口作业

3. 三点估算

选中活动 → Duration Uncertainty → 选分布 → 输入数值 → 设相关性

每个活动都有分布

4. 风险映射

Risk Register → Add Risk → 填概率和影响 → 拖到活动上

风险登记簿完整，活动已映射

5. 运行模拟

Run → 设置参数 → 跑减缓前和减缓后两轮

S曲线生成

6. 解读结果

读直方图看分布 → 读S曲线定P80 → 读龙卷风图排风险优先级 → 读关键性指数找隐藏风险

应急储备天数确定，风险优先级排序完成

PRA操作流程不复杂，六步走完就出结果。关键在于每一步的输入质量——三点估算有没有数据支撑、风险登记簿有没有把场景描述清楚、进度逻辑干不干净。操作方法对了，剩下的就是执行。
