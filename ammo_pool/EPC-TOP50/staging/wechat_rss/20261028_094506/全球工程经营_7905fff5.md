# 大语言模型能力越来越强，国际工程合同风险分析还需要 Prompt 吗？

原创 张明宇 麻佩等 2026-10-05 08:00 天津
提示词工程未过时，正从话术技巧转向任务设计与上下文工程。复杂任务需管理上下文、拆解流程、嵌入专业知识，并与RAG、工具调用结合，其目标是稳定、可复用、可复核地辅助专家，而非替代决策。
本文编号：GLOBAL-226
转载请注明出处：微信公众号 gipcenter
大语言模型提示词（Prompt）是用户输入给模型的任何文本内容，是连接人类意图与大模型能力之间的桥梁，决定着模型理解任务的方式以及生成输出的方向。但是随着模型能力的不断增强，过去很多提示词技巧是否还有效？提示词工程是否正在变得不重要？要回答这个问题，需要了解提示词工程是如何演进的。
早在ChatGPT爆火后，全网社交媒体上就涌现出大量的“提示词技巧”分享，本文列举了一些较为经典的提示词技巧，如表1所示。此时的模型对提示词还十分敏感，同一问题换一种问法，结果可能就会差很多，因此这些技巧在激发早期模型的潜力中发挥了很大作用。

但随着GPT-4、Claude、Gemini等更强大语言模型的发布，提示词工程进入了快速成熟的阶段，OpenAI、Anthropic与Google等AI厂商陆续发布官方提示词工程指南，标志着提示词从经验分享走向系统化知识体系。同时，ReAct、检索增强生成（RAG）等一系列高级技术得到深入研究和广泛应用，这一阶段的提示词工程也开始工具化、自动化。进入2025年，大模型能力持续增强，真实任务从单轮问答逐渐转向复杂工作流，长上下文与工具调用也开始普及，提示词工程开始向上下文工程（Context Engineering）演进。上下文工程的核心观点是：优化AI输出质量不仅仅是优化提示词文本本身，而是要系统性地管理整个上下文窗口，包括系统指令、对话历史、动态检索以及工具调用结果等。其中，提示词主要负责说明任务、组织材料、规定规则、约束输出等，以引导模型如何合理地使用进入到上下文中的信息。这一转变反映了提示词正在从单点优化走向系统性设计的更高层次。
早期模型能力有限，提示词技巧对输出质量影响很大。用户需要通过诸多提示词技巧与方法，尽可能地激发模型能力。当时的一些“咒语式”提示词之所以流行，是因为模型对指令的理解和执行还不够稳定，用户不得不用更详细甚至更夸张的语言去引导模型。当前，主流大语言模型对自然语言指令的理解能力已经明显提升。很多过去需要反复强调的任务，模型现在已经能够自动完成。例如一般总结、简单改写，通常不再需要复杂提示词，模型就可以给出不错的初步结果。因此，一些过度的角色设定、机械要求逐步思考、迷信固定话术的提示方式，其边际价值正在下降。
但是，提示词技巧的弱化，并不意味着提示词工程不再重要。真正变化的，是提示词正在从话术技巧转向任务设计。过去用户关心的是如何提问，模型才会答得更好；现在，则是关注于如何把复杂的任务拆解成模型可以稳定执行的流程。因此，当前更有效的提示词，其实是写得更清楚、更结构化、更贴合专业流程。以国际工程合同风险分析任务为例，提示词需要明确分析视角、合同模板、风险清单、判断标准、输出形式和限制条件。对于风险的分担打分，会要求模型先识别责任主体，再进行风险分担，最后给出这样处理的理由，相当于是把合同专家的工作流程固化后交给模型去执行。
更进一步看，当模型上下文窗口越来越长、工具调用能力越来越强时，提示词工程自然会走向上下文工程。如果模型上下文窗口较短，用户首先关心的是模型能不能装下合同文本。而随着主流大模型已经能够处理较长文本，装下合同文本已不再是问题。相反，哪些合同文件应该进入上下文，通用条件和专用条件的优先顺序该如何表达，合同数据表中的关键信息如何被模型正确利用，哪些无关内容可能干扰模型的判断，这些又构成了新的问题。
以国际工程合同风险分析任务为例，天津大学全球工程经营团队按照业务逻辑将其拆分为不同部分并设计了国际工程合同风险分析系统。关于合同风险识别与风险分担的技术，本服务号往期文章进行过部分介绍（详见往期文章“大语言模型国际工程合同风险识别初筛方案”和“大语言模型国际工程合同风险分担预处理方案”），更多内容将在后续继续分享。
回顾国际工程合同风险分析系统的设计，其实更多的是业务逻辑的拆解与组织，上下文工程与提示词工程只是实现既定目标的手段，而非全部。从这个意义上说，提示词并没有过时，而是从提问技巧转为了任务接口，从关注单次回答效果转向关注稳定性与可复用性。对于国际工程合同风险分析任务而言，企业使用大语言模型的目标并非让其生成一段看似专业的文字，而是希望模型能够接近合同专家的实际判断，并在针对不同项目、不同合同、不同人员使用时在效果上保持相对稳定。
未来，随着模型能力继续增强，某些提示词技巧可能会继续弱化，并逐渐演化为面向复杂任务的流程设计、上下文组织与专业知识嵌入，并与知识库构建、RAG、工具调用深度结合，形成更加系统化的大模型任务设计方法。在这一过程中，提示词将更多地承担任务接口与规则约束的作用，负责把人类专家的判断逻辑、业务流程、专业标准与输出要求转化为模型可以稳定执行的指令体系。
需要强调的是，大模型在企业决策中的价值并不在于替代合同专家或决策者，而在于提高信息处理效率、增强风险识别的系统性，并为专家判断提供可追溯、可复核的辅助依据。因此，构建系统的关键不只是模型本身的能力，而是如何构建高质量的合同数据、稳定的风险分类体系、清晰的责任判断规则和可复核的输出机制。在这一框架下，提示词工程将继续存在，但它会以更加隐性的方式嵌入到系统流程之中，成为连接专业知识、业务场景与大模型能力的重要接口。
下一节我们将进一步讨论：提示词工程、上下文工程与驾驭工程之间的关系，以及为什么在大语言模型辅助国际工程合同风险分析这样的专业场景中，提示词与上下文工程仍然是必要的。
