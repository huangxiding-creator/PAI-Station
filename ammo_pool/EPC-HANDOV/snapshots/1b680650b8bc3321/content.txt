**现象**：用户在 Manus 界面看到多账号安排了 >2 任务、报"已达到并发上限"。

**审计（纯 token API 地面真值）**：

- 今日 23 单散在 ~13 真实账号（各 1-2，基本合规）；违规账号当前 0 在跑，无封号词命中

**双重根因**：
1. **身份核对同义反复**：ensure_login 拿"目标账号自己的 token"查 UserInfo——查回来的永远是目标账号自己（≠浏览器现役者），无 token 账号更是直接跳过核对 → 派单全落在浏览器里上一个登录者头上（用户判断"没有切换账户"完全正确）
2. **token 库污染**：110 个 token 文件实际只有 23 把真 token（bootcamp 采集时未验归属就落盘，35 个文件是同一把）——身份核对的数据源本身就是脏的

**根治五件套**：
1. `whoami_browser()`：唯一可信判据=浏览器现役 token 的 UserInfo（capture_token→urllib 实证），不符/查不到=完整登录；login() 出口同样实证+固化正确 token
2. token 库清洗：88 个错配文件隔离至 `data/tokens_quarantine_0924/`，22 个归属正确的原位保留（只增不删）
3. 账本保守重置：16 个真实受载账号今日封账（置 2=休）；名义串号账清零
4. 禁用名单：`EXCLUDE_EMAILS={51817@qq.com}`（用户个人 QQ 主账号=身份锚，不进研磨机，启用须用户明示）
5. 烟测实证：2 账号全绿（"实证 w5uo09qm56 → T053；身份不符(≠18c1iqzd2j)→切换→实证→T054"）→ 12:3x 全量重启（251 账号待派）+ 收割器 `--loop 600` 常驻
