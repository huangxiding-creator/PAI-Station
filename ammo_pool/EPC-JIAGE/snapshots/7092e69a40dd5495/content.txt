# 软件造价｜软件造价历史回顾

2026-02-04 14:31 北京

关注！

点击“赛迪时代”关注公众号获取更多精彩内容

软件造价从20世纪60年代发展至今，在软件开发过程中一直扮演着重要角色。软件造价的历史回顾反映了信息技术产业从萌芽到成熟的演进过程，其核心是从简单成本计算逐渐发展为系统化、标准化的评估体系。当历史的车轮驶入规模化开发时代后，人们发现决定造价的不再是“写多少行代码”这一单一维度，而是需求、技术、人力、工期、风险等多因子交织的复杂系统；于是，如何“算”软件造价，便从历史经验的朴素记账，升格为一门需要独立方法论的技术学科。软件造价评估方法的发展历程，核心是从主观经验估算走向客观量化分析，再演进至适应敏捷与智能化的持续校准过程。其演变与技术范式的变革紧密相连。以下是软件造价评估关键发展阶段：

· 第一阶段：早期混沌期（1970年代以前）—— 经验与类比法主导

主要方法：

专家判断（Expert Judgment）：完全依赖项目经理或技术领袖的个人经验和直觉。

类比法（Analogous Estimating）：“这个项目看起来跟去年做的那个差不多，所以预算也差不多。”

特点：

高度主观，结果因人而异，波动性大。

严重依赖组织的历史数据和个人的可靠性。

适用于信息极少、规模小或重复性强的项目。

· 第二阶段：参数化模型兴起（1970-1980年代）—— 寻求客观与公式化

这是软件造价评估科学化的开端，旨在用数学模型替代主观猜测。

里程碑方法：

1.COCOMO（构造性成本模型，1981）：由Barry Boehm提出，是划时代的模型。

核心：以源代码行数为基本规模输入，通过一系列成本驱动因子进行调整。

意义：首次系统地将技术、项目、人员、环境等数十个因素量化并纳入公式，奠定了参数化估算的基础。

2.功能点分析法（1979）：由IBM的Allan Albrecht提出。

核心：从用户视角出发，通过计数软件向用户提供的功能（如输入、输出、查询、数据文件、接口）来度量规模，与编程语言和技术无关。

意义：解决了“代码行数”在早期需求阶段无法获得、且受技术影响大的问题。催生了IFPUG等国际标准化组织。

特点：方法开始标准化、文档化，追求可重复和可比较的估算结果。

· 第三阶段：方法的标准化与多元化（1990-2000年代）—— 完善与适应

随着软件规模扩大和类型增多，单一模型无法满足所有场景，方法论进入繁荣期。

发展主线：

功能点家族的扩展：

Mark II FPA：适应实时系统。

COSMIC-FFP：专为实时、嵌入式系统设计，理念更简洁。

NESMA：荷兰标准，提供快速估算变体。

COCOMO的演进： COCOMO II 出现，以适应现代迭代开发、原型法、商用组件复用等新实践。

新模型涌现：

用例点法：面向对象分析和UML用例图流行后，通过角色和用例的复杂度来估算。

故事点估算：敏捷方法的核心估算单元，基于团队相对速度（速率），而非绝对时间。强调规划扑克等团队协作式估算。

基准数据库建立：ISBSG 等国际组织开始收集全球项目数据，建立基准数据库，使基于基准的类比估算更为可靠。

· 第四阶段：国标建立与行业深化时代（2010年代—至今）—— 从引进到建立

2010年后，中国软件造价评估方法的发展历程是一条“从引进国际标准到建立本土规范，从政府驱动到行业渗透，再与敏捷实践融合”的鲜明路径。其发展深受中国特色的政策、市场和产业环境影响。

1.引进与探索（2010-2014年）

特征：国际标准引入，行业认知萌芽。

背景：随着国内信息化建设大规模投入，软件项目“拍脑袋定价”、成本黑洞、纠纷不断的问题凸显。

主要活动：

国际方法学习：以 IFPUG功能点分析和COSMIC方法为主的国际标准被引入，主要在大型银行、电信企业和少数先行咨询机构中研究和试点。

初步标准化尝试：工业和信息化部等单位开始组织研究，筹备制定本土标准。北京软件造价评估技术创新联盟等行业组织成立，开始推广功能点方法。

2.国家标准建立与政府驱动期（2015-2018年）

特征：国标出台，政府采购成为关键推手。

里程碑事件：GB/T 36964-2018《软件工程 软件开发成本度量规范》在工业和信息化部指导下，以2013年发布的电子行业标准SJ/T 11463-2013为基础制定的于2018年正式发布。确立了以功能点为核心，基于行业基准数据进行估算的国标体系，标志着软件造价评估在中国的规范化和普及化。

核心内容：

确立了以 “功能点规模度量”为核心的方法论（兼容NESMA和IFPUG）。

提供了完整的成本构成模型（直接人力、间接人力、直接非人力、间接非人力成本）。

定义了基于基准数据的生产率调整方法。

政府强力驱动：

北京、上海、广东等地财政部门或经信部门相继出台政策，要求政府信息化项目在可研、概算、结算环节必须采用功能点法进行造价评估。

审计部门将其作为项目审计的依据。这为方法的落地提供了最强大的行政和市场动力。

行业工具涌现：一批基于国标的国产软件造价评估工具上市，支持自动化功能点计数和成本测算。

市场认知度低： 绝大多数企业和政府用户对科学的软件造价评估缺乏概念。

3.行业深化与敏捷融合（2019年-2022年）

特征：从政府向重点行业渗透，并开始应对敏捷开发的挑战。

行业标准细化：

金融行业：央行、银保监会推动下，各银行纷纷建立基于功能点的内部计价体系，用于项目预算、供应商管理和绩效核算。

通信、能源等行业：大型央企开始制定企业标准，将造价评估纳入IT治理体系。

与敏捷开发的碰撞与融合：

矛盾：互联网公司和研发团队普遍采用敏捷开发，而国标基于传统功能点的评估方式显得笨重、滞后。

实践探索：

“前敏捷后功能点”：内部研发用故事点，对外报送、结算时转换为功能点。

“敏捷功能点”实践：尝试在用户故事层级进行轻量级功能点计数，或建立故事点与功能点的转换系数。

行业联盟开始研究和发布针对敏捷项目的度量指引。

专业人才体系建设：“软件造价工程师”、“功能点分析专家”等培训和认证体系逐步完善，人才队伍初具规模。

4.信创适配与AI大模型扩展（2023年至今及未来）

特征：响应国家信创战略，评估模型需适应新技术架构。

信创产业带来的新挑战：软件项目需适配国产CPU、操作系统、数据库等。这带来了额外的移植、适配、性能调优和生态兼容性成本，传统评估模型未能充分覆盖。

评估方法的新扩展：

成本因子调整：在国标基准数据中，加入“信创适配复杂度”作为新的调整因子。

云原生与微服务考量：评估重点从单一应用转向对多个微服务、容器平台及云服务费用的综合评估。

DevOps效能关联：将DORA（部署频率、变更前置时间等）效能指标与长期运维成本关联，评估研发效能提升对总成本的影响。

AI大模型软件工作量评估，需要从传统“功能实现”思维转向“目标达成”思维，综合运用类比、参数和分解方法，重点量化数据、实验和集成的复杂度，并必须通过分阶段管理和高额储备来应对不确定性。其评估成熟度高度依赖于组织内部历史数据的积累和对AI项目独特模式的深刻理解。

发展趋势：向价值评估延伸，领先企业不再仅关注“造价”，更关注“价值”。评估方法开始与业务指标（如用户增长、收入提升）结合，支持投资决策。

回顾软件造价评估方法七十余年的发展，是一条从依赖个人直觉的混沌，走向建立标准化模型的理性，再超越模型本身、拥抱变化与数据的螺旋上升之路。其演进的底层逻辑，始终是追求在更高的不确定性中，做出更可靠的经济决策。未来，随着软件定义一切的深入，软件造价必将更深度地与开发流程、企业财务和战略决策融合，成为一门连接技术、商业与数据的综合性决策科学。

国家标准

《软件工程   软件开发成本度量规范》 (GB/T 36964-2018)

国家市场监督管理总局、国家标准化管理委员会

该标准定义的软件开发成本估算过程包括软件：规模估算、工作量估算、成本估算、确定软件开发成本四个部分。规模估算作为其他部分的基础，在估算时采用功能点估算方法。工作量估算可采用方程法、类比法、类推法等方法。

行业标准

《软件工程 COSMIC-FFP一种功能规模测量方法》（SJ/T 11617-2016）

工业和信息化部

COSMIC（Common Software Measurement International Consortium，通用软件度量国际联盟）功能点测量方法起源于1997年的FFP（Full   Function Point，全面功能点）标准。之后，FFP与COSMIC组织共同合作，于1999年提出了COSMIC功能点标准。2003年该标准被ISO组织接纳，成为国际标准。国内于2016年等同采用该标准，推出了电子行业标准《软件工程 COSMIC-FFP一种功能规模测量方法》。

COSMIC的原理是通过识别“数据移动”的个数来度量软件规模，每个数据移动计为一个COSMIC功能规模单位（CFP），四种数据移动类型分别为：输入（Entry）、输出（eXit）、读（Read）和写（Write）。

COSMIC方法适用于商业应用软件和实时系统的功能规模测量。

《软件工程 MK II功能点分析计数实践指南》（SJ/T 11618-2016）

工业和信息化部

MK   II功能点方法起源于1991年英国人Charles Symons所著《Software Sizing and Estimating: MK II Function Point Analysis》一书，该书介绍了MK II操作方法。Symnos先生在为毕马威咨询公司工作期间提出了MK II功能点操作方法，在该操作方法的基础之上形成了Mark II功能点标准，该标准提出后被英国政府所采纳。后于2001年被ISO组织接纳为国际标准。该标准由英国软件行业协会维护。2016年，我国基于该国际标准，推出了国内行业标准《软件工程 MK II功能点分析计数实践指南》。

MK   II方法适用于逻辑事务能被确定的任何软件类型。

《软件工程   功能规模测量NESMA方法》（SJ/T 11619-2016）

工业和信息化部

NESMA（Netherland Software Measurement Association，荷兰软件度量协会）的功能点标准经由IFPUG标准演化而来，但在一些规则细节上与IFPUG不完全相同。NESMA 功能点估算方法已在2003年升为ISO标准。和IFPUG方法相比，该方法更着重在项目早期进行估算。此外，针对IFPUG方法分析过程较复杂、计算工作量大的不足，NESMA方法实现了快速计算。

NESMA方法包括估算法（Estimated）方法和指示法（Indicative）方法。它们使得用户可以在早期需求不完整的情况下，迅速估算出软件的功能点数。2016年，我国电子行业标准 《软件工程 功能规模测量NESMA方法》正式发布。该标准等效采用国际标准《软件工程——NESMA功能规模测量方法版本2.1——使用功能点分析的定义和统计准则》（ISO/IEC 24570:2005）。

《信息技术   软件和系统工程FiSMA1.1功能规模测量方法》（SJ/T   11620-2016）

工业和信息化部

1997年，FiSMA（Finnish Software Measurement   Association，芬兰软件度量行业协会）组织提出了Experience2.0 Function   Point Analysis(FPA)，后发展为FiSMA标准。该标准的应用主要集中在芬兰的软件开发组织中。FiSMA功能点标准突出“服务”的概念，不再强调“功能”概念，并且，将软件的典型功能分为了28种服务，使得服务类型划分较为细致，但带来了操作的不便。2016年，该标准被等效采用为我国行业标准《信息技术   软件和系统工程FiSMA1.1功能规模测量方法》。

团体标准

《软件造价评估实施规程》 (T/CCUA 005-2023)

中国计算机用户协会

通过规范评估原则、评估时机、评估过程及评估活动要求等8个章节的体系化框架，明确了预算编报、过程造价控制、结决算审计三种应用场景，并引用SJ/T   11463及T/CCUA 004-2023等标准，建立了从评估准备、评估策划、评估实施到评估报告的全过程管理规程，实现方法、模型、因素和过程的统一规范。

《软件及信息服务产品价值评估规范》 (T/SIA 048-2024)

中国计算机用户协会

该标准针对软件定价混乱、评估依据缺失等行业痛点，构建了"属性分析—方法选择—实施评估—结果输出"的完整技术路线，创新性地设立成本法（适用于一次性销售产品）、收益法（适用于订阅/多次销售产品）、分成法（适用于软硬件组合中的软件组件）及市场比对法（基于参照物对比）四类评估模型，为软件企业自评、政府及第三方机构评估提供了统一的价值度量尺度和规范化操作指南，推动建立透明、可信的软件产品市场价格体系。

《系统与软件工程   信息化项目 造价评估》 (T/BSCEA 005-2025 / T/CCUA 060-2025)

北京软件造价评估技术创新联盟、中国计算机用户协会

该标准规定了信息化项目建设资金及运行维护经费的完整费用构成（涵盖基础设施环境、软硬件采购、资源租赁、定制开发、信创适配改造、数据建设、集成实施、运维、安全服务等十大类费用），确立了"确认范围—明确分类—选择方法—评估费用"的四步评估流程，提供经验法、类比法、类推法和方程法四种评估方法，适用于新建、升级改造、运维及购买服务类信息化项目在立项、设计、招投标、实施、监理、验收及审计等全生命周期的造价评估，有效消除地区和组织间的造价差异，提升信息化项目造价的可比性、透明度与专业性。
