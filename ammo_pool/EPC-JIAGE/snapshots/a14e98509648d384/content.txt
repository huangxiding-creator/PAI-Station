而让这个大脑能去外面跑腿的，是滴滴出行的MCP

效果怎么样呢

简单说就是：**员工点一下，审批完自动叫车，晚上自动算账**

别看运行失败那么多次，是真的踩了很多坑，下面给大家详细说说是怎么配置的

完全不用人脑子去记那些鸡毛蒜皮

而且这里面藏着一个让兄弟们最爽的细节

大家再也不用自己先掏腰包垫钱了

以前打车，那是真金白银先从自己微信里出去

月底还得求爷爷告奶奶等着财务打款

现在这套系统可以直接用公司的账户，但是还得看公司愿不愿意这样干

行程一结束，直接扣公司的预存账户

咱们只管坐车，钱的事儿系统自己和公司结算

咱们先看看**地基**怎么打

其实只需要在多维表格里建三张表就能搞定

第一张是**项目现场信息表**

这里就是导航的A点和B点

你需要把项目现场的坐标和员工宿舍的地址都填进去

这相当于给AI一张地图，让它知道大家都在哪儿活动

做过现场调试的兄弟都懂

咱们经常是这个项目干两三天

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/4d011150-bd82-41e8-b0aa-4a51f8b28905)

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/238ced36-43c8-4027-9136-cdc65f4ffb69)

转头就得拎着电脑去下一个场子救火

所以专门建这张表 就是为了应对这种频繁变动的节奏 不用每次都重新输地址，选一下就行

第二张是**现场人员信息表**

这是白名单

把员工的**姓名**和的**手机号**放进去，这样滴滴司机就可以给你打电话了

这里有个细节要注意

手机号必须是**纯数字**，也可以直接用**电话号**字段因为Agent要靠这个号码去滴滴那边摇人

第三张是**用车调度信息表**

这也是所有数据的汇总中心

但对于干活的兄弟们来说，他们甚至都不用看这张表

我直接建了一个极简的**用车申请表单视图**

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/bab48e1b-cc4e-4854-a8b0-814ba46a0a81)

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/c18a76c0-4150-468e-ab54-7ceb7073a3ac)

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/0e0de632-c5d5-47e8-a914-06121ba69717)

大家手机上扫码点开，界面特别干净

选一下自己的名字，点一下是**去现场**还是**回住所**

再选个车型，点提交就完事

这背后的逻辑其实特别像咱们写PLC程序

那个表单的提交按钮，就是一个**启动信号**

信号一给到，后台的自动化流程立马接管

当**添加新记录**时 就会触发工作流，然后就像走梯形图一样，进入那个**条件判断**环节

它会判断你刚刚填的行程类型是不是**去现场**

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/52353c28-5269-40bc-9f8f-565fd25e7a29)

如果是，它就发送去现场的消息，把那个带按钮的审批卡片

直接推送到项目经理那里

上面写着谁要走、去哪儿、坐快车还是特惠

经理点个同意，系统状态就自动变更为已同意

背后的逻辑也是通过工作流实现的

以前用车申请得追着经理签字

现在我在工作流那里把交互逻辑都配置好了

**如图所示**，我在消息卡片里埋了两个按钮

一个是同意，一个是驳回

并设置了一个很简单的触发动作，只要经理手指一点**同意，**系统后台就会自动把这条记录的审批状态修改为**已同意**

重头戏来了，就是那个会思考的**AI Agent节点**

这也是这套方案最性感的地方

普通的自动化只能按死板的规则跑

但我在工作流里加了个Agent节点，并挂载了**滴滴出行MCP**

当审批通过，记录被修改的那一刻，真正的**派单工作流**就触发了

这里我没有把压力全扔给AI，而是用了一个**条件判断（If/Else）节点**来做分流

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/2b03d76e-046a-4c9b-835c-f937a2823fb8)

**第一条：去现场**

如果流程判断出你的行程类型是**去现场**

它就会走左边的分支，自动把你的**住所**塞进Agent的**起点**参数，把**现场**塞进**终点**参数

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/22e1e0d7-c516-47bd-98f9-ac0cc0133033)

**第二条：回住所**

如果判断结果是否定的（也就是不满足“去现场”这个条件）

流程就会自动切换到右边，把**起点和终点瞬间反转** 起点变成了现场，终点变成了住所

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/6e4a864c-5e6a-4756-b780-1129327f980f)

这样一来，Agent根本不需要去猜你要去哪

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/1accf0b9-a7fd-40e3-b6cb-427144e3c7c6)

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/7eb70c7e-9f6c-448d-ab33-7fc377bc585a)

它只需要拿着流程喂给它的精准坐标，去调用**滴滴出行MCP**

你想坐特惠它就帮你找便宜的，你想坐快车它就找快的

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/82684b9f-7a4f-490d-963c-3bf981b35d59)

最妙的是它还能处理财务闭环

我设了个定时任务，每天晚上八点

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/d718f85e-89da-40a0-87b6-94e9c10b95a3)

那个结算Agent节点就会像个勤劳的小会计一样爬起来

通过**MCP接口**去滴滴那边查每一笔订单的状态

如果订单完成了，它就把实际费用抓回来填进表里 如果取消了，就自动归零

哪怕你以前完全没写过代码 照着我下面整理好的这个提示词抄作业 也能让Agent跑得飞快

**派单Agent的配置逻辑是这样的**

它的角色就是个智能调度员，你要告诉它，先用地图工具去查精准坐标，然后根据我们选的车型和用车类型去找最匹配的那个ID，最后调用下单接口，记得把那个**call\_car\_phone**参数填对，也就是那个电话号码，不然司机找不到人

**结算Agent就更简单了**

它的任务就是查单，看到实际金额状态是为空，就把钱数记下来，这一步虽然简单，但它是把咱们从贴发票地狱里救出来的关键

Agent的数据会调用**多维表格MCP**写入相关的数据表中

![Feishu Docs - Image](blob://https://waytoagi.feishu.cn/abc780b8-9062-4ce2-84eb-56326433e436)

这一套下来 我再也不用月底对着一堆票据抓狂了

团队的小伙伴也能把心思花在更重要的调试工作上

毕竟咱们的大脑是用来解决复杂问题的

不是用来做加减法的
