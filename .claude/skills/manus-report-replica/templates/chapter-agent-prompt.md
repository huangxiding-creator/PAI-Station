# 章节子代理契约模板（Claude Code Mode A 用）

> 骨架源自 Manus workflow/run 实测契约（逐字级复刻, 映射为 Claude 子代理 prompt）。
> 用法: 主会话生成 {{N}}/{{标题}}/{{focus}} 后, 一波 3-6 个 Agent 并行派发。
> 子代理类型: general-purpose; 长章可指定更高 effort。

```markdown
你是{{行业领域}}研究专家。请独立完成第{{N}}章《{{标题}}》的研究与撰写。
研究重点：{{focus}}

硬性要求：
1. 使用简体中文写作，章节正文不少于{{4500}}个中文字符，至少包含6个
   一级以下小节、至少2个Markdown表格；每个正文段落不少于150个汉字，
   避免碎片化短句。
2. 事实、法规、统计数据和案例必须来自可公开访问且可靠的来源，优先：
   政府部门、全国人大/国务院、国家标准公开信息、{{行业主管部委}}、
   国家统计局、最高人民法院、国际组织和项目业主/官方报告；至少使用
   8个来源，关键事实尽量多渠道交叉验证。
3. 正文相关句子后使用编号引用[1]、[2]，章节末尾给出"## 本章参考资料"
   并按"[1]: URL "标题""列出可访问网址；不得编造网址、数据、案例或
   标准编号。无法核实的资料不要写入。
4. 解释分析逻辑、因果链、机制、适用边界与判断依据；以可审计的论证、
   假设、公式、评价矩阵和证据说明替代空泛结论。
5. 与其他章节错开：只围绕本章主题展开，必要的跨章内容仅作接口说明，
   不重复长篇定义。不得出现"待补充""TODO""占位"等字样。
6. 检索纪律：先宽后精确；打开原文读不信摘要；发现即存档到工作目录
   notes/；搜索词用「地域×细分×主题×时间窗」拼装并点名权威源。

工作目录：{{reports/课题/}}
- 章节文件写入 chapters/{{NN}}.md，文件第一行使用"# 第{{N}}章 {{标题}}"
- 中间发现落 notes/ch{{NN}}_*.md（防丢，但不作为交付物）
- 边写边回读校对；对同文件做增量编辑，不新建版本

完成后返回如下结构化摘要（JSON 块，供主会话验收）：
{"chapter": N, "title": "…", "path": "chapters/NN.md",
 "summary": "本章核心结论3-5条", "char_count": 实测CJK字符数,
 "sources": ["url1", "…"], "status": "done|partial+原因"}
```

## 主会话验收动作（收到子代理结果后）

1. 核 `char_count`（实测复核, 数字零造假）与 `sources`（抽检可访问性）
2. `status=partial` → 记入 state.json 缺口清单, 决定补跑或调整结构
3. 跨章查重（新章 vs 已完成章的关键概念段）
4. 章节齐后: 生成/更新 报告结构.md → 合并终稿 → L6 六项✅自检
