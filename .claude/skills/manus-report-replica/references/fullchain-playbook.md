# Manus 研究报告生成全链方法论 PLAYBOOK（三源合流版）

> 三源: S1 桌面端 asar 静态逆向 | S2 网页端 Live 实测 | S3 存量语料统计 (870 会话/26372 工具调用)
> 每条断言标注 [S1/S2/S3] 出处。版本: 2026-10-21 v1（Live 完成后升 v2）

## 〇、引擎总览（三句话）

1. **Manus 报告不是"生成"出来的，是"长"出来的**：一个确定性 JS 编排器把报告
   分解为 N 个独立章节子代理并行研究+写作，每章独立完成 搜→读→写→自检 闭环，
   最后主代理合并、质检、交付。[S2+S3]
2. **写作是绝对主体**：text_editor 占全部工具调用 77%（40k/52k），搜索只是
   弹药补给（4.5%）；写读比 1.5:1，一份报告迭代 51 次（中位）。[S3]
3. **上下文即文件**：任务清单、章节、规范、中间发现全部落沙箱文件
   （todo.md / 报告结构.md / chapters/NN.md），上下文烧完靠 contextTransfer
   新会话继承全部文件续跑，用户只需说"继续"。[S2+S3]

## 一、L1 指令接收与硬条款内化

**用户 prompt 的结构范式**（生产实证，可复用模板）[S3+Auto_Manus config]:
- 清单式硬条款（编号 1-11）：结构定义/字数下限/格式禁令/数据可靠性/
  脱敏要求/版本控制/最终交付/质量复检/自动决策授权
- 关键条款类型: ①结构条款(报告结构.md+六配件) ②数量条款(≥15章/30万字/段落≥200字)
  ③质量条款(三重交叉验证/标出处/禁待补充) ④语言条款(专业严谨/去AI味/表格化)
  ⑤流程条款(直接更新原文件/不建多版本/自主决策无需确认)

**内化机制**：主代理把 prompt 硬条款转译为计划步骤与子代理契约 [S2]:
```
实测链条: 接任务 → 读三份内部规范(研究报告规范/办公文档规范/结构规范)
→ 确认工作流接口(mcp server.list + tool.search workflow)
→ 章节分解(12章各有 title+focus) → 硬条款注入子代理 prompt
(≥4500字/≥6小节/≥2表格/段落≥150字/≥8来源/引用格式/跨章去重/文件路径/返回schema)
```

## 二、L2 计划树与 Cascade 编排（核心架构）

**计划树**: planUpdate.tasks[]{doing/todo/done/failed, title, startedAt} [S1]
- 存量 256 条计划链: 步数中位 8, P90=13 [S3]
- 报告工程五步法（计划链逆向）[S3]:
  ①盘存量(检查当前报告状态) ②立骨架(创建报告结构文件)
  ③整合去重(按新结构整合去重) ④补缺失(六配件撰写)
  ⑤冲量保质(确保≥15章≥30万字)

**Cascade 编排（Live 实测全参数捕获）**[S2]:
```
workflow/run (mcp 工具, manus-workflow 服务):
- 确定性 JS 编排脚本, 无 IO, 禁 Math.random/Date.now
- 断点重放: journal 记录已完成 agent 调用, 重启只补跑未完成件 (积分刷新后续跑实证!)
- 原语: agent(prompt, {brief≤120字, schema, input_files, sandbox:'shared', effort_level})
       parallel(brief≤80字, factory, {schema})  log(message)
- 使用判据: ≥5 个各自需独立研究/浏览/判断的条目才 fan-out;
  同一命令跑多输入=单脚本有界并发, 不开子代理
- 子代理返回 schema: {chapter, title, path, summary, char_count, sources[], status}
- 主代理终态: toolUsed(agent, 等待N章任务完成) → 收集结果 → 合并
```

**章节分解模式**（12 章实测）[S2]:

招标合同计价索赔 → 设计管理技术接口 → 施工组织进度质量安全 → 生态移民社会 →
地质水文极端天气 → 融资投资经济 → 分包供应链数字化 → 评价预警应急案例
（= 理论框架→环境→识别→分域展开→方法→案例 的专业域通用骨架）

## 五、L5 增量写作引擎

**多文件工作区** [S3]: 每任务中位 22 文件; 写操作 58% 中间章节 md、15% 终稿。
**章节分开写最后合并**——绝不单文件硬写。
**标准布局**（Live 实测）[S2]: /home/ubuntu/epc_report/chapters/01.md…12.md
+ 报告结构.md + 合并终稿。

**单文件增量编辑**: 反复读写同一文件增改, 从不开新版本文件; 多版本以字数多者为准。 [S3]

**增量节奏**: 小批搜→立即落稿→再搜→再写→终批长写收尾; 边写边回读校对。 [S3]

**中间笔记禁交付**: 发现即存文件(防丢), 但最终稿必须重写为信息密集可读文档。 [S1 deep-research 军规]

## 七、L7 交付与续跑

**成品六配件**: 严正声明、内容摘要、研究方法说明、报告价值说明、推荐序、术语表 [S3]

**断点续航**: 
- Cascade 层: journal 重放, 完成章节不重跑 [S2]
- 会话层: contextTransferFlag/Result — 上下文烧完自动换会话继承文件; 
  用户侧只需「继续」两字 [S1+S3]

  故障三态: 积分不足(可续) / 沙盒暂停(须重置) / 内部错误(重试) [S3]
