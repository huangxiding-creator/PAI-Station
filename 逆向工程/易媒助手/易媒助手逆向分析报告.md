## 二、多账号管理的实现（复刻要点 1）

### 2.1 账号即 Cookie 集，SQLite 存储

WEMedia.exe 内嵌 CEF 标准 Cookie 库建表语句（字符串证据）：

```sql
CREATE TABLE cookies(creation_utc INTEGER NOT NULL, host_key TEXT NOT NULL,
  top_frame_site_key TEXT NOT NULL, name TEXT NOT, ...);
CREATE UNIQUE INDEX cookies_unique_index ON cookies(host_key, top_frame_site_key, name, path);
```

- `CookieHelper.cpp`（调试路径字符串在案）：`GetCookie FilePath:%s` / `ResetCookie FilePath:%s`
  → **每个账号一个独立 cookie 文件**，按文件路径隔离。
- `MediaChoiceAndCookieWnd`（DuiLib 窗口类，RTTI 字符串在案）：账号选择与 cookie 管理窗口。
- `WebCookieData` 结构体（`_Ref_count<U WebCookieData>` RTTI）：账号 ↔ cookie 集绑定实体。
- 全局配置：注册表 `SOFTWARE\WEMedia\config`。
- CefBrowser.dll 内见 `cef_cookie_manager_get_global_manager`、`CefCookieVisitor/CefSetCookieCallback/CefDeleteCookiesCallback`、`\globalCache` —— 支持程序化 set/delete/visit cookie，即**切换账号 = 向 CEF 重放该账号的 cookie 集**。

### 2.2 登录捕获：内嵌浏览器打开平台登录页

WEMedia.exe 内置每平台登录 URL 表（部分证据）：

| 平台 | 登录入口 |
|---|---|
| 百度系 | passport.baidu.com/v2/api/?login、baijiahao.baidu.com/builder/theme/bjh/login |
| 头条/西瓜 | mp.toutiao.com/profile_v4/index |
| 抖音 | creator.douyin.com/?enter_from=publish |
| 快手 | cp.kuaishou.com |
| B站 | member.bilibili.com（nav API 拦截见 §3.3） |
| 小红书 | edith.xiaohongshu.com/api/sns/web/v2/user/me（登录态探测） |
| 搜狐 | v4.passport.sohu.com/i/sso/proto/cross |
| 360系 | login.360.cn |
| 微博/网易/知乎/豆瓣/汽车之家/虎牙/优酷/宝宝树/美篇/快手电商… | 各自 sso/login URL（全表在 WEMedia.exe 字符串区） |

流程 = 用户在 CEF 内扫码/账密登录 → cookie 落盘为账号文件 → 之后所有操作（取数/发布/评论）复用该 cookie 文件。

### 2.3 多账号并行

每 (平台, 账号) 组合独立 cookie 文件 + 独立任务上下文；`MediaChoiceAndCookieWnd` 做切换。发布任务按账号排队（MediaTaskMgr 管理任务队列）。

## 三、多平台分发的实现（复刻要点 2）

### 3.1 双引擎

**引擎 A —— C++ 直连平台 API**（MediaTaskMgr.dll，每平台一个适配类）：

API 端点证据（字符串区，节选）：

- 网易：`mp.163.com/wemedia/video/publish.do`、`publishreader/publish.do`、`upload/batchUploadImgUrl`
- 秒拍：`creator.miaopai.com/video/asynPublish`、`video/mutiCreate`、`video/videoTransNew`（异步转码轮询模式）
- 凤凰大风：`fhh.ifeng.com/publish/article`、`api/video/add`
- 小红书：`creator.xiaohongshu.com` + `/api/galerie/large_file/v1/video/upload_init → upload_part → upload_complete`（**分片上传协议完整在案**）+ galaxy 数据 API
- 现金头条：`content.wemedia.cashtoutiao.com/video/upload` + `article/content/uploadImg`
- 抖音：`creator.douyin.com/aweme/v1/creator/...`（走远程签名，见 §3.2）

**引擎 B —— CEF 内嵌网页 + JS 注入自动化**（用于 API 难以直连的平台，如公众号后台）：

`data/comment_media_js.json` 定义注入规则引擎：

```json
"<平台ID>" : {
  "BeforeResourceLoad": [ {"url": "...", "exactmatch": bool} ],   // 请求拦截点
  "LoadEnd":            [ {"url": "...", "jspos": N} ],           // 页面加载完成点
  "LoadStateChange":    [ ... ],
  "js": [ "var x=document.getElementById(...)..." ]               // 注入的 JS 数组
}
```

实测样本：在公众号/头条/百家/知乎/B站/微博/快手/抖音/小红书/视频号后台页面注入 JS，隐藏平台自身导航栏/侧边栏，把平台创作者后台"裁剪"成易媒助手的嵌入面板（同一技巧天然可用于表单填充自动化）。

## 四、动态行为（部分）

- 提取的 payload 免安装直接运行会秒退：主程序依赖注册表 `SOFTWARE\WEMedia\config` 安装信息（自校验）。完整动态观测需正常安装后进行（列入实施阶段，在隔离环境做）。
- 安装器为皮肤化 NSIS 类自解压（XML 皮肤 + 7z BCJ2 载荷 + 30+ 渠道号 OEM 图标，说明有大量贴牌分销渠道）。

## 五、复刻结论（给自媒体永动机的蓝本）

1. **多账号管理 = 每账号独立 cookie 库（SQLite/JSON）+ 内嵌浏览器登录捕获 + 账号切换重放**。复刻用 Playwright `storage_state`（每账号一个 state 文件 + 独立 browser context 指纹）可等价实现，且更干净。
2. **多平台分发 = 双引擎**：官方/半官方 API 直连（能签名的直连）+ 浏览器 DOM 自动化（难签名的走页面驱动）。签名层插件化、可外置。
3. **类目映射表是现成数据资产**，直接转化为复刻件的 `platform_registry`。
4. **数据回流同样双引擎**（API 取数 + 页面 URL 嵌入），可接入选题雷达。
5. 风险对齐：滑块/验证码（快手滑块、Google 签名）与账号风控是长期对抗面，需要熔断与告警机制。
