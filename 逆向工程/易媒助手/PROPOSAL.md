# 提案：总包智库·全网传播引擎 OPE（Omnichannel Propagation Engine）

> 状态：**待批准**（Proposal Approval Gate）· 2026-10-19
> 依据：易媒助手深度逆向（本目录逆向报告）+ OSS 选型调研（RESEARCH_DOCKET/）
> 一句话：把永动机产出的每一份文章/视频，**无人值守地以平台原生形态铺满你已注册的全部自媒体平台**，统一以「总包智库」出品，并把传播效果回流进选题雷达——不是复刻一个易媒助手，而是造一台它没有的「内容变体 × 全网铺设 × 效果闭环」机器。

---

## 一、为什么不是「复刻易媒助手」而是高一个维度

易媒助手的本质是「**人工点选 → 工具代发**」：人排版、人选平台、人点发布，工具只解决多账号切换和表单代填。你的真实意图是「永动机产出 → 全网自动铺开 → 品牌传遍全网」，中间不应该有人。

| 维度 | 易媒助手（已逆向证实） | 本提案 OPE |
|---|---|---|
| 内容形态 | 一份内容原样搬运到 N 平台 | **平台原生变体工厂**：一份报告 → 公众号长文/头条爆标题版/知乎答主体/小红书卡片图文/微博短文长图/B站横版视频/抖音·快手·视频号竖版切片，各自最优形态 |
| 触发方式 | 人点发布 | **永动机 S8 环节直连**：报告/视频验收完成即自动生成「发布包」入队 |
| 账号 | CEF cookie 文件 + 手动切换 | **账号保险库**：storage_state 加密库 + 每日心跳 + 失效企微告警 + 扫码台批量补登 + 每账号独立指纹 |
| 可靠性 | 无度量 | **回执制**：每平台发布凭证（链接+截图）归档，成功率/重试/断点续传全量度量 |
| 效果 | 平台数据看板（人工看） | **数据回流闭环**：各平台阅读/播放/粉丝日增量 → 选题雷达 radar_signals → 反哺下一条内容选题 |
| 品牌一致 | 无 | 「总包智库」统一署名/头像/简介/水印/首发评论文案模板 |

## 二、能力架构（五层，全部有实证蓝本或 MIT 底座）

```
┌─ L5 守门与熔断 ── 成熟度门T0-T3 · 账号红线R3 · 速率天花板 · 企微告警 · 只增不删 ─┐
├─ L4 回执与数据回流 ── 发布凭证库 · 平台指标采集 → radar_signals · 品牌传播总看板 ┤
├─ L3 分发执行器(双引擎，学易媒) ── 引擎A:官方/半官方API直连(公众号草稿箱API等)     ┤
│                                   引擎B:Playwright浏览器自动化(千帆云递19平台底座)  ┤
│                                   签名插件层(本地JS引擎跑sign库,可替换服务)         ┤
├─ L2 内容变体工厂 ── 平台模板×AI改编(标题/封面/标签/首评钩子) · 类目映射注册表      ┤
├─ L1 账号保险库 ── storage_state加密库 · 独立指纹profile · 心跳校验 · 扫码登录台    ┤
└─── 触发: 永动机 S8 发布环节 → 生成发布包(manifest: 内容+变体规格+目标账号矩阵) ──┘
```

**底座选型（OSS-first 铁律，全部实测核实）**：
- 主底座：**千帆云递 social-auto-upload-web-ui**（MIT · 318★ · 当日活跃 · Vue3+Flask+SQLite+Playwright · 19 平台）——fork + 本地镜像（防猝死）
- B 站：**biliup**（MIT · 5.5k★ · 活跃）协议投稿
- 公众号图文：**官方草稿箱+发布 API**（iamzifei 蓝本 · 零风控 · 这是易媒都没走通的正规路）
- 长尾平台（搜狐/网易/企鹅/微博图文等）：自研适配器，**蓝本=易媒 MediaTaskMgr 逐平台类 + data/ 类目映射表（40+ 文件，直接转为我们的 platform_registry 数据资产）**
- 签名对抗：易媒 sign2/ 签名农场资产已在手（字节 ugc_monorepo/百度 gtk），做成可插拔签名服务接口

**平台分层**（先深后广）：
- 一梯队（灰度期打通，8 个）：微信公众号、视频号、抖音、快手、B站、小红书、知乎、今日头条
- 二梯队（接产线后滚动扩）：百家号、搜狐号、网易号、微博、西瓜、搜狐视频、优酷、腾讯视频、一点、趣头条、雪球、豆瓣等（易媒 40+ 平台枚举表全在案，按需逐个开）

## 三、成熟度硬门（你要求「非常成熟、完美运行才接入产线」的制度化）

| 阶段 | 内容 | 晋级门槛（量化） |
|---|---|---|
| **T0 干跑** | 真实驱动到各平台发布表单最后一屏，**不点发布按钮**，截图留证 | 8 平台 × 全账号 表单填充成功率 100% |
| **T1 测试账号** | 每平台 1 个测试账号真发布 | 连续 3 天批次成功率 ≥95% |
| **T2 双轨并行** | 现有人工发布链照常跑，OPE 同步另发（或错峰跟发），对比凭证 | **连续 7 天 ≥99% 成功率 · 零账号风控事件 · 断点恢复 ≤5min** |
| **T3 接管产线** | 永动机每报告的 S8 自动调用 OPE，人工链退役为备份 | T2 门槛 + 你明示批准 |

红线熔断：任一账号出现验证码连续失败/异常提示 → 该账号自动停发并企微告警；绝不自动绕过平台的二次验证/实名环节（需人工处理）；同账号发布频率天花板按平台保守设定。

## 四、与现有体系的缝合（缝合契约）

- **上游**：永动机 S-1→S7 产出（报告 md/PDF + 视频 mp4 + 宣传文）→ S8 环节产出「发布包 manifest」（约定 schema：内容路径+平台×账号矩阵+变体规格+排期）；OPE 消费 manifest 并回写发布凭证。DoD：manifest 落盘即视为 OPE 准入。
- **下游**：发布凭证归档到报告目录（对齐现有发布链回执习惯）；平台指标日更入 `radar_signals.jsonl`（现有格式不动，新增 engine=ope 维度）。
- **基础设施铁律**：浏览器自动化统一走独立端口（9339+）与独立 profile 目录，**绝不碰 9222**；账号 cookie/state 加密存储密钥外置（gitignored）；全程只增不删；发布结果字数/数据以实测为准（数字零造假）。

## 七、风险与对策（调研实证）

1. **平台改版选择器失效**（kebenxiaoming README 自认）→ 选择器集中配置 + 截图断言 + 失败即熔断告警，24h 内热修。
2. **账号风控**（多账号同机同指纹）→ 每账号独立 context+指纹、速率天花板、行为拟人化（滚动/停留），灰度期逐账号验证。
3. **法律红线**：B 站协议文档仓已被律师函 → 只用 MIT 独立实现（biliup），不抄协议文档；MediaCrawler(非商用)/MatrixMedia(GPL) 只借鉴 pattern 不抄码。
4. **底座猝死**（lecepin 仓已 404 实锤）→ fork+本地镜像+离线 vendor 一步到位。
5. **签名演化**（抖音 ABogus 等）→ 签名层独立插件，可本地 JS 可远程服务，坏了单独换不影响主链。
