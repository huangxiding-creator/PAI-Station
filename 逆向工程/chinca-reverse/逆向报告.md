> 2026-10-24 | 方法：REA 实弹抓包(真 Chrome 155 对照) × Node vm 沙箱执行原版挑战 JS × 差分拟合
> 产物：`replica/chinca_api.py` + `replica/solver.js`（纯 HTTP 复刻件，**5 次独立会话全链贯通 5/5 PASS**）
> 授权：`work/scope.md`（用户 1024 全渠道 API 化令；全程只读 GET，无浏览器在役）

## 一、战果一句话

**chinca.org 的 acw_sc__v2 挑战 = 单段 JS 挑战 + 本地沙箱执行站点自带算法即可过闸**：
requests GET → 挑战页（`renderData` 内 `arg1` 50 位 HEX + 自校验混淆 VM）→
**Node vm 原样执行该 VM**（关键坑：沙箱不得注入宿主 `Function/Error/RegExp` 等，须用 vm 自身 intrinsics 保持 realm 一致）
→ 捕获 `reload(M)` 写入的 `acw_sc__v2` → 带 `acw_tc`+`acw_sc__v2` 重放 → 真实页面。
一次求解全站有效（实测 9+ 连续请求不再挑战），挑战 JS 部署内字节级不变（三样本归一化哈希一致）。

## 二、挑战体系鉴定

- 现状描述「加速乐(acw_sc__v2)」**实际是阿里云 WAF**（页面 meta `aliyun_waf_aa`/`aliyun_waf_bb`、script name `aliyunwaf_*`、Server: Tengine），cookie 名 `acw_sc__v2` 与经典加速乐体系同名同源。前缀 `aliyun_waf_aa` 为本站挑战版本标记。
- 响应：200 + `Set-Cookie: acw_tc=<hex>` (HttpOnly, Max-Age=1800) + `acw_sc__v2=` (清空) + 23670 字节挑战页。
- 挑战页三部件：① `<textarea id="renderData">{"l1":"var arg1='<50HEX>';"}` ② 明文 loader（`getRenderData/setCookie/reload`）③ 18.8KB 混淆 VM（自校验+环境探测+PRNG 混排）。

## 三、挑战算法原理（实测逆向结论）

VM 对 `arg1`（50 位 hex）做**列式转置混排 + 前后端定位符 + PRNG 字符交织**生成 cookie 主体，
并全程校验自身未被篡改与环境像真：

1. **自校验（防美化/防改源码）**：`vy()` 对 `xXRQBR.toString()`（函数自身源码）去掉内嵌数字常量后做 xxHash 型哈希 `v()`，减去源码里烘焙的常量得 `vL`（本部署实测 **vL=239**，代码内 `+vL` 项全部设计为补到整数值）。改一个字符 → vL 漂移 → 字符串数组轮转校验永不收敛/解码错位。**因此复刻件不改源码、原样执行**（这也带来版本免疫：站点换算法，复刻件自动跟随）。
2. **字符串解码**：轮转数组 + 自定义 base64 字母表 + LCG(48271, 2^31, seed=175) 异或流；实测 149 个唯一字符串（含 `1234cf0d46` 前缀常量、`SVGAnimate`+`String` 环境探针名、`debugger`/`active code` 反调试、`nothing2reload10ba` 诱饵、正则 `\b[\w/:­­\-\[\]<]{4,}[^\d:@]\b` 等）。
3. **环境探测（决定分支——本次战役最大坑）**：VM 调 `globalThis.SVGAnimateString()`（现代 Chrome 已移除 → 必抛 TypeError）→ 用 `j.name+' '+j.stack` 喂上述正则取 token 哈希 → 进 PRNG 种子链；另有 `navigator.webdriver`、`Math.random` 原生性（`[native code]`）、`globalThis===window`、`; debugger;` 计时等检查。
4. **关键分叉（Node vs Chrome）**：早期沙箱把宿主 `Function/Error/RegExp/Math` 等全注入 vm → **realm 混杂** → VM 走了另一条分支，输出结构完全不同（45 位定长主体+'48'分隔，Chrome 为 ~50 位交织体）→ 服务器**直接清 cookie 重挑战**（拒绝证据：`Set-Cookie: acw_sc__v2=; expires=1970`）。**去掉宿主构造器注入、只用 vm intrinsics 后，分支与 Chrome 一致**：对同一 arg1=5df63044...，本机输出 `1234cf0d46-439554356d56edc507dffafa018b62584488d8806...` 与真 Chrome 实弹（REA 抓包，headless 155）输出**前 45 位逐位一致**，仅尾部随机段不同（Chrome 自己两次运行也不同 → 服务器不校验随机段，实测任意尾段可过）。
5. **cookie 结构**：`<常量前缀 1234cf0d46>-<主体~50位：arg1 转置字符 × PRNG 交织字符>-<10位原生随机尾>`。服务器校验 = 前缀 + arg1 可还原的确定性主体（结构绑定会话 arg1，实测换 arg1 重放旧主体被拒、模板/随机主体均被拒、正确主体任意尾段通过）。

### 已证伪的假说（排雷清单）
- ❌ TLS/JA3 绑定：curl_cffi chrome131/124/safari17 三档模拟均同样被拒 → 不是 TLS 问题。
- ❌ 经典 40 位 posList/mask 算法：本站是新版 50HEX 体系，不适配。
- ❌ 请求头指纹：补全 sec-fetch/sec-ch-ua 后依旧被拒 → 与头无关。
- ❌ 二段挑战（aliyun_waf_bb blob）：拒绝时服务器重发同构 aa 挑战，blob 未参与首段校验。

## 七、失效模式与边界（如实记录）

- **算法版本变化**：挑战 JS 若换版本（arg1 长度/结构变化、script hash 变化），solver.js 按新页面原样执行，**自动免疫**；仅当站点改用非 JS 挑战（如验证码/行为分析）时失效。
- **失效特征信号**：重放响应仍含 `renderData` 且 `Set-Cookie: acw_sc__v2=; expires=1970` = 求解被拒；连续 2 次即抛 `GateError`。
- **执行环境要求**：solver 依赖 Node vm 的 intrinsics 一致性；若未来 Node 版本改变 vm realm 行为（极小概率），回退方案=REA 实弹对照校准（本报告方法可复现）。
- **频率**：单次求解≈0.5s、一次过闸后全站免挑战；建议会话级复用（复刻件已内置），避免高频开新会话触发更严风控（未观察到，防患于未然）。
