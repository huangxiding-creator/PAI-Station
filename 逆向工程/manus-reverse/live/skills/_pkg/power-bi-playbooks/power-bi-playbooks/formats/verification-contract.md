# Verification contract

Verify the state that was promised, not a convenient proxy.

## Portable source data

- record input and output hashes;
- reconcile accepted, quarantined, and rejected row counts;
- rerun the transform and prove the chosen business key does not duplicate;
- reconcile the requested control totals;
- keep credentials and absolute private paths out of outputs.

## Timing analysis

- preserve the raw source file and a separate normalized copy;
- record the field map used to normalize it;
- reject missing, negative, or internally inconsistent durations;
- rank by total duration and state the dominant reported component;
- label unreported time rather than inventing a component;
- do not claim that a normalized fixture proves real-export compatibility or capture success.

## Project or model source

- preserve the original hash and use a copy or branch;
- inventory only supported and intended files;
- exclude local settings, credentials, caches, and secrets;
- distinguish parse/schema success from model calculation and rendered acceptance;
- do not report an edit complete without an app or model-aware round trip appropriate to the retained state.

## Desktop Bridge evidence

- record the target process, intended file path, bridge manifest, client/CLI identity, and authorized host-local route;
- read unsaved-change state before open or reload and stop on an ambiguous or unintended target;
- keep source mutation, reload receipt, screenshot capture, semantic-model validation, and rendered judgment as separate checks;
- a screenshot proves only the captured pixels for that moment; it does not prove interaction, accessibility, calculation, refresh, or save/reopen;
- mark the branch `not run` when the bridge client, manifest, method, or target identity is absent.

## Service state

- identify tenant, workspace, report, semantic model, and caller with immutable identifiers where exposed;
- record the exact current-session tool and authentication state;
- for mutations, preview target and impact and obtain immediate approval;
- verify authorization under intended and denied identities when permissions or RLS matter;
- do not treat an owner or privileged identity as a user-scoped permission test.

## Completion report

State the workflow card, route, authoritative retained state, inputs, outputs, objective checks, consequential approvals, and unresolved handoffs. Use `blocked` or `not run` when that is the truth.
