# Card Route Contract

Use this table before loading a card reference. `O1` means a live-observed procedure on the exact Word or Word-on-the-web product, OS, version, locale, and retained state with a saved postcondition. Without that evidence, UI execution remains guidance or hold.

| Card | Primary route | Escalation trigger | Hybrid handoff | Fallback | Verification contract | CU display and reason |
|---|---|---|---|---|---|---|
| A1 Structure | Documents runtime | Current Word-evaluated TOC, PAGE, or NUMPAGES results are required for Microsoft Word layout | Build and inventory the DOCX natively; an O1-qualified Word tail may evaluate only the layout fields | Deliver a structurally valid DOCX with field status disclosed, or guide | Heading/bookmark/link graph, numbering and sections, field inventory, every rendered page, and Word-evaluated results if used | Conditional after O1: only Word's layout-field evaluation is app-native; structure authoring is not |
| A2 Multi-source merge | Documents runtime for a rebuild or compatible body-only append | Media, relationships, headers/footers, notes, revisions, sections, numbering, or other retained package state must survive | Inventory all sources, choose rebuild versus compatible append, and hold any unproved complex tail | Deliver a merge plan or separate normalized sources | Source manifest and order, content counts, declared retained parts, relationship integrity, field report, and every rendered page | No closed CU route: complex retained merge has no Word O1 procedure |
| B1 Formatting rescue | Documents runtime | Approved scope cannot protect load-bearing formatting, or the user asks for an in-app lesson | Lint, approve a bounded patch, apply to a copy, then render and diff | Deliver the audit and proposed patch without mutation | Approved-scope style/text diff, intentional exceptions, page-count delta, and every rendered page | No for transformation; H1 may teach a separately closed procedure |
| B2 Brand restyle | Documents runtime | Rich controls, style collisions, or layout-sensitive state exceed the native helper | Distill authority, approve mappings, apply the native tier, and use only an O1-qualified app tail | Deliver a compliance matrix and mapping plan | Style/control inventory, collision report, pagination delta, package integrity, and every rendered page | Conditional after O1 for one named Word object that the native helper cannot author |
| C1 Template system | Documents runtime for styles, layout, and plain-text controls | A named rich control or Word-specific template behavior is required | Build and test the native tier first; use one O1-qualified rich-control operation at a time | Deliver the plain-text template tier and unsupported-control list | Unique tags/titles, short/long/blank/Unicode fill and reopen tests, output behavior, and every rendered page | Conditional after O1 for the specific rich-control state only |
| D1 Data-driven documents | Documents runtime plus spreadsheet tooling | The user must retain an existing Word merge main document, labels, envelopes, or merge-to-email state | Spreadsheet route cleans data; Documents creates files; D2 owns only the native merge tail | Produce one-file-per-row DOCX/PDF artifacts without native merge state | Input/output counts, unique safe names, placeholder completeness, edge-record values, and representative full renders | No: deterministic batch file generation is the retained result |
| D2 Native mail merge | Guidance/HOLD; Word CU only after exact O1 | Native labels, envelopes, merge preview, or an existing merge main document is indispensable | Prepare and validate synthetic data natively; Word owns only the proved merge state; Outlook owns any send | Route to D1 or provide a merge plan | Field mapping, first/middle/last preview, stock/alignment, separate saved and reopened output, and zero unapproved sends | Yes only after O1: the required durable state is Word's native merge configuration or preview |
| E1 Revision report | Documents runtime | Residual Word-specific revision/comment constructs remain or a Word cross-check is explicitly required | Extract and classify natively; an O1-qualified Word check handles only the residual | Report supported and unsupported constructs without changing them | Counts, authors, locations, XML inventory, residual list, source hash, and every rendered page of any cleaned copy | Conditional after O1 for a named residual construct; not for ordinary reporting |
| E2 Compare | Documents runtime for text/render analysis | The durable output must be Word's semantic Compare/Combine document | Analyze natively; an O1-qualified Word route creates semantic markup; E1 summarizes it | Deliver a clearly labelled analytical diff or guide | Both inputs unchanged, reconciled text/page diffs, and reviewer/revision state for any Word result | Conditional after O1: Word semantic Compare/Combine state cannot be substituted by a file diff |
| F1 Convert | PDF/OCR tooling plus Documents runtime | OCR is uncertain or exact Microsoft Word layout is the acceptance target | Extract/OCR, rebuild structure, render all pages, then use only an O1-qualified Word comparison tail | Deliver a reflowable DOCX with a fidelity and uncertainty report | Source coverage, sampled text accuracy, tables/notes/columns, every rendered page, and uncertainty log | No for conversion; conditional after O1 only for exact Word-layout comparison |
| F2 Batch replacement | Documents runtime only for a fixture-tested simple or Manus-generated structure; HOLD otherwise | Tokens cross runs or occur in fields, revisions, controls, stories, links, or protected state | Build a story-aware dry run and sample copy before any batch | Deliver occurrence inventory and a safe implementation plan | Exact per-story counts, excluded-state preservation, formatting, renders, source hashes, and skipped files | No: Word CU has not been proved safer for arbitrary retained batches |
| F3 Extract | File reading/Documents runtime plus spreadsheet tooling | OCR is required or the requested content is unavailable in readable file state | Extract with source locators, validate a sample, then format through the spreadsheet route | Deliver a locator-backed report instead of a spreadsheet | Coverage count, locator per row, duplicate/conflict report, and source reconciliation | No: this is a scalable read/extract workflow |
| G1 Recovery diagnosis | Forensic file diagnosis on a verified copy | Bounded salvage fails and an exact Word recovery procedure has O1 evidence | Inventory intact/lost state natively; an O1-qualified Word route may test one copied fixture | Deliver diagnosis, salvage options, or specialist guidance | Original hash unchanged, package checks, loss inventory, recovered-copy validity, and every rendered page | Conditional after O1: only a proved Word-native recovery routine may justify CU; repair is not advertised |
| G2 Performance diagnosis | Documents runtime audit | A named reversible Word action has O1 evidence and file-native remediation cannot address the measured cause | Measure, rank causes, apply one approved change to a copy, and remeasure | Deliver diagnosis and bounded recommendations | Before/after size, timing, page count, image fidelity, revision/field integrity, and every rendered page | No until a specific app-side action passes O1 |
| H1 In-app lesson | Guidance by default; Word CU only for an underlying card with O1 | The requested procedure, surface, or saved postcondition is not independently closed | Prepare a synthetic fixture natively, replay only the proved app tail, then verify outside Word | Explain the procedure without operating the user's file | Underlying card assertions, saved/reopened state, recording privacy, recovery, and unseen-fixture replay | Yes only after O1: the app interaction is the requested experience, not a substitute for an unproved workflow |
