# Repair and Teaching (Cards G1 and H1)

## G1: diagnose or recover a damaged `.pptx`

Treat repair as forensic work, not a generic recipe.

1. hash and preserve the original; operate only on copies;
2. test whether the problem is reproducible and whether a previous version or autosave exists;
3. inspect package integrity, relationships, content types, slide parts, notes, and media;
4. identify the smallest suspected fault and test a surgical repair against a planted or equivalent fixture;
5. if full repair is not supported, salvage text, notes, and media rather than pretending the deck is restored;
6. render the candidate and, when PowerPoint is installed, open the copy in real PowerPoint, step through it, and report losses slide by slide.

Do not generalize a community anecdote such as deleting one XML part into a universal repair procedure. Do not run a destructive first-party repair against the only copy.

## H1: teach or demonstrate in PowerPoint

Use guidance when the user wants an explanation. Use CU only when they explicitly want the action demonstrated in their installed PowerPoint and the operation is already verified for that OS/version.

Demonstrate on a copy or disposable fixture. Detect the current UI instead of reciting a memorized menu path, narrate the purpose of each action, verify the outcome, and leave a concise step card that names the user's actual objects. If the operation lacks current evidence, say so and provide guidance without pretending to have performed it.
