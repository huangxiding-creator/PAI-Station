# Card Route Contract

Use this table before loading a card reference. Connector handlers in checked code are code-shipped evidence, not proof that a connector is enabled, authenticated, exposed, or successful for the current account. A connector route requires current-session exposure/auth plus an operation-specific invocation receipt. `O1` is reserved here for a live-observed Outlook web or desktop UI operation on the exact product surface with an objective retained-state postcondition.

| Card | Primary route | Escalation trigger | Hybrid handoff | Fallback | Verification contract | CU display and reason |
|---|---|---|---|---|---|---|
| A1 Inbox triage | Outlook Mail connector search/read plus sandbox report, after current-session exposure/auth and a scoped invocation receipt | Mailbox mutation, unavailable intended account, or scope outside the default user's mailbox | Connector identifies selected messages; sandbox builds the read-only report; any mutation becomes a separate O1-proved B2 workflow | Ask for a supplied export or produce a route plan without reading mail | Query/cap, requested versus returned IDs, attachment outcomes, report rows, privacy scope, and zero mailbox writes | No: the retained result is a report and CU adds exposure without connector coverage |
| A2 Default-mailbox search | Outlook Mail connector against the default user's mailbox, after current-session exposure/auth and a scoped invocation receipt | Mail exists only in a local archive, the target is shared/delegated, or the request exceeds the checked schema | Connector returns stable IDs; sandbox builds an index; a UI may open a selected hit only after exact O1 | Use C1 for a supplied archive, narrow scope, or explain the unsupported mailbox | Exact query, tested partitions, cap state, deduplicated IDs, re-identifiable hits, and explicit completeness limits | No: server search is code-bounded and the desktop search is the pain source |
| A3 New draft or send | Outlook Mail connector for a new plain-text message; save as draft by default | Preserved reply thread, HTML, existing draft, client template/add-in, or campaign intent | Connector read supplies context; sandbox prepares attachments; an O1-qualified UI owns only unsupported compose state | Deliver reviewed message text and attachment set without creating Outlook state | Exact preview, per-item draft/send result, IDs/errors, attachment reconciliation, and zero sends on cancellation | Conditional after O1 for Word/Outlook-owned rich, threaded, template, or add-in state only |
| A4 Calendar operations | Calendar connector for default-calendar search, get, create, and delete after current-session exposure/auth and an operation-specific invocation receipt; connector update is blocked | Secondary-calendar search, update, free/busy, rooms, responses, reminders, sharing, or another absent operation | Connector reads known event state; an exact O1-qualified web/client route may own one unsupported operation | Guidance or stop; never call blocked update | Query/cap for search; event IDs and item results; re-read after create; confirmed absence after delete; zero update execution | Conditional after O1: only a missing scheduling state proved on the selected Outlook surface can justify UI control |
| A5 Preservation package | Outlook Mail connector plus sandbox for a labelled derivative package | Original MIME, exact message files, archives, or authoritative Outlook rendering are required | Connector IDs and metadata seed the index; an exact O1-qualified UI may produce client-owned files | Deliver the derivative package with fidelity limits or explain the exact-export gap | One-to-one source/output manifest, attachment omissions, every file open, and explicit derivative-versus-exact label | Conditional after O1: exact Outlook-owned export state is not available in the checked connector |
| B1 Signatures | Guidance and sandbox specimen preparation; My Browser or CU only after exact O1 by retained state | Organization-wide deployment, policy enforcement, missing feature, or absent reversible test object | Sandbox defines approved assets; the O1-proved web/client surface stores the signature; admin owns centralized deployment | Deliver the approved specimen and deployment specification | Exact account/surface assignment, new/reply contexts, rendering, links/images, and rollback | Highlight only after O1 for desktop-profile signature state; server/web state should use My Browser when O1-proved |
| B2 Organization | Guidance and connector read-only impact model; My Browser or CU only after exact O1 for one object type | Shared/admin scope, policy dependency, missing feature, or unsafe reversal | Connector estimates the default-mailbox set; the O1-proved web/client surface creates one disposable object | Deliver dry-run counts, object specification, and rollback plan | Authoritative object state, harmless test behavior, cleanup, and no unrelated overwrite | Highlight only after O1 for Quick Steps or client-only rule/profile state; server-visible objects belong in My Browser when O1-proved |
| B3 Print and PDF | Connector reads plus sandbox PDF for a derivative | Authoritative Outlook rendering or native attachment rendering is required | Connector IDs define the set; sandbox creates the derivative; an O1-qualified client renders only the exact subset | Deliver derivative PDFs with a manifest and fidelity statement | Count/index, visible sender/date/body, attachment treatment, output open, and derivative-versus-exact label | Conditional after O1: authoritative client rendering can be app-native but no current path is closed |
| C1 Local archives | If the mailbox remains accessible, prefer the Mail connector; otherwise HOLD until the exact PST or OST parser passes an O3 fixture, then use sandbox on a verified copy | Unsupported format/version, damage, encryption, parser mismatch, or a need to import/open in Outlook | Copy and hash first; run only the fixture-qualified parser; an O1-qualified client may verify a separately supported export/import/open tail | OLM stays unsupported; provide export/import guidance or specialist handoff | Original hash, folder/message/date counts, Unicode/HTML handling, attachment hashes, reopened samples, and explicit gaps | No: the retained state is a local archive copy and derived files; CU is not a parser and has no proved archive route |
| C2 Damaged archive guardrail | Guidance plus a verified file copy; not an advertised repair card | No second copy, unique/encrypted data, missing version-specific first-party procedure, or unacceptable loss risk | User may run a first-party utility only after explicit approval; any surviving extraction later re-enters C1 | Stop and recommend backup restoration or specialist recovery | Original remains unchanged; copy/result hashes and losses recorded; no recovery guarantee | No: repair risk does not become a CU showcase |
| D1 Product-version guidance | Evidence-dated guidance | The answer depends on a live build, tenant policy, or feature flag | An O1-qualified read-only My Browser/CU inspection may supply current state; connector routes replace only checked operations | Mark the feature unknown and give a verification plan | Every named workflow has product/build/date, status, route, and explicit unknowns | No: the retained result is a decision; read-only UI inspection is evidence collection, not the workflow |
| D2 Platform routing | Guidance plus current runtime probe | Required state belongs to an unavailable account/product or lacks operation proof | Carry stable IDs/files between the exact bounded connector, browser, desktop, or sandbox routes | Ask, guide, or stop at the first failed gate | Enabled tool/account/product and selected route match the observed retained postcondition | No: this is routing infrastructure rather than a user-facing CU workflow |
| E1 Campaign-style bulk send | Refusal plus consent-aware campaign guidance | The request is actually a small, expected, individualized set | Sandbox may prepare consented artifacts; compliant campaign infrastructure sends; A3 may create individually reviewed drafts | Provide compliant preparation without distribution | Zero campaign sends; any legitimate small-set item remains draft unless explicitly approved | No: CU would not make campaign delivery safe or supported |
