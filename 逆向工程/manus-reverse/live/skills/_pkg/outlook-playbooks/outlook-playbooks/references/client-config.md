# Mailbox and Client Configuration (Cards B1-B3)

These are high-value candidate workflows, not automatically executable routes. My Browser and Computer Use prove transport only. Resolve an exact O1 procedure for the Outlook product/version before mutation.

Current Microsoft guidance is O2, not execution proof. It documents separate signature procedures for new Outlook/web, classic Windows, and Mac; classic Windows signatures may be local to the device. Use those facts to choose the retained state and build a test, but do not transfer a procedure between surfaces.

## Card B1: Signatures

**Outcome**: an approved signature assigned to the intended account and compose contexts.

**Route selection**: My Browser for O1-proved web-account state; Computer Use for O1-proved installed-client/profile state; administrator guidance for organization-wide deployment.

**Primary channel**: guidance and sandbox specimen preparation; product-specific My Browser or Computer Use only after exact O1 operation proof.

**Escalation trigger**: organization-wide scope, policy enforcement, missing product feature, or absence of an O1 procedure.

**Hybrid handoff**: sandbox assets define the approved specimen; the selected Outlook surface stores the signature; guidance handles centralized deployment.

**Workflow contract**
1. Detect web, Mac, new Windows, or classic Windows Outlook; record account and deployment scope.
2. Prepare a visual specimen and assets outside Outlook.
3. Resolve an O1 procedure for that exact surface. If unavailable, deliver the specification and guidance only.
4. Capture before state, install the smallest approved variant, and assign new/reply contexts only when supported.
5. Compose disposable new and reply messages, inspect text, links, image, spacing, and account assignment, then reverse test objects.

**Verification**: exact target surface, assignments, rendering, links, images, and rollback are observed. No connector mutation is claimed.

## Card B2: Organization objects

Folders, categories, server rules, client-only rules, Quick Steps, profiles, and send/receive settings are different retained objects. Never treat them as one feature.

Microsoft's current feature matrix marks Rules and Quick Steps as only partially available in new Outlook, and its rules guide says new Outlook does not support rules for third-party accounts such as Gmail, Yahoo, and iCloud. Those are O2 routing constraints, not proof of any Manus mutation path.

**Primary channel**: guidance and connector dry-run; product- and object-specific My Browser or Computer Use only after exact O1 operation proof.

**Escalation trigger**: shared/admin scope, policy dependency, missing product feature, or no safe reversible test object.

**Hybrid handoff**: connector search/read can estimate a default-mailbox message set; the authoritative web/client surface creates and tests one specific object.

**Workflow contract**
1. Identify the exact object, target account/mailbox, whether it must run with the computer off, and the Outlook variant.
2. Use connector search/read only for a dry-run count when its schema covers the source.
3. Resolve an O1 object-specific procedure on the selected web/client surface. If absent, guide or stop.
4. Preview name, conditions, actions, affected sample, collisions, and reversal.
5. Create one disposable object with a reserved test name and prove it on a harmless message.
6. Remove the test object and verify no existing object was overwritten.

**Verification**: authoritative product state and actual test behavior both pass; dry-run counts are not presented as mutation success.

## Card B3: Print and PDF

**Primary channel**: connector reads plus sandbox PDF for derivatives; Computer Use only for O1-proved Outlook-exact rendering.

**Escalation trigger**: a legal/process requirement needs authoritative Outlook rendering, native attachment rendering, or a foreground batch beyond the proved recovery envelope.

**Hybrid handoff**: connector IDs define the set; sandbox creates the index/derivative; a proved Outlook UI renders only the exact subset that requires it.

**Derivative route**: connector reads the selected messages and the sandbox creates an indexed readable PDF/report. Use this when Outlook-exact rendering is unnecessary.

**Outlook-exact route**: Computer Use only after an O1 product/version-specific print/export procedure, batch recovery, and rendering oracle have passed. Do not promise resumable UI processing without that proof.

Microsoft documents a single-message PDF procedure through the selected Outlook surface and the operating system's PDF printer. That O2 procedure is a fixture candidate only. It does not establish bulk selection, deterministic naming, attachment rendering, resume behavior, or cross-platform parity.

**Verification**: count and index reconcile; samples preserve visible sender/date/body/attachment treatment; output states whether rendering is derivative or Outlook-exact.
