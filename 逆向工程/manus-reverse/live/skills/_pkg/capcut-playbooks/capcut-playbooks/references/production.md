# Production (Cards 3, 4, 6, and 7)

## Card 3 — Short-video edit

**Use when:** multiple clips, audio, captions, graphics, transitions, and exact pacing must form a finished short. Typical cases include commerce, creator content, event recaps, product launches, education, and local-business marketing.

**Primary channel:** F1 for a fully specified deterministic assembly with no retained project; M1 as an accepted user-editable Manus scene handoff; W1/C1 for editable CapCut timeline state.

**Escalation trigger:** use W1/C1 for exact editable clip order, captions, effects, keyframes, track relationships, or continued work in CapCut. Several clips alone do not prove CapCut is required.

**Hybrid handoff:** T0/F1/G1 prepares transcripts, normalized assets, or short generated shots; W1/C1 integrates them when CapCut state is required; M1 remains a distinct Manus handoff.

**Workflow:** inventory sources; freeze brief/references/cut plan; create copied project if retained; build and approve fifteen seconds; complete; verify beginning/middle/end and output state.

**Verification:** source slate/order, timing, synchronization, sample approval, duration, streams, save/reopen, media-online state, and export specs.

**Failure and recovery:** checkpoint the manifest; stop on missing media/resources or ambiguous style rather than silently substitute.

**Record as skill:** record only a live-proved import-to-delivery trunk; culling, pacing, music, and taste remain decisions.

**CU display:** yes for C1 retained Desktop timeline; no for F1/G1/M1/W1.

## Card 4 — Batch production

**Use when:** many clips must share a style, structure, or delivery contract. Typical cases include product catalogs, creator series, localized ads, real-estate listings, and recurring campaign content.

**Primary channel:** F1 for repeated deterministic transforms; G1 for independent short generated outputs within limits; W1/C1 for a reusable project, visible Auto Cut feature, or per-item retained editorial state.

**Escalation trigger:** use W1/C1 only when project templates, caption tracks, layer structure, or reviewable editorial state must survive. Auto Cut requires current account/region/version visibility.

**Hybrid handoff:** F1 builds manifest/normalizes sources; G1 creates approved source shots; W1/C1 creates one approved master project and retained series state; F1 validates outputs.

**Workflow:** define manifest/naming/style; produce one representative item; record feature gate; approve; scale with outlier queue; reconcile outputs and any retained master project.

**Verification:** expected/actual count, file integrity/specs, sampled style/duration/audio, feature-state record, and save/reopen of requested master.

**Failure and recovery:** resume by manifest; do not universalize an observed Auto Cut path or retry absent features via stale controls.

**Record as skill:** only a stable feature/client path after live replay; manifest/output validation remains parameterized.

**CU display:** conditional for C1 reusable Desktop state or visible Auto Cut workflow.

## Card 6 — Delivery variants

**Use when:** an approved master must become platform-specific aspect ratios, codecs, resolutions, or editorial versions.

**Primary channel:** F1 for mechanically equivalent derivatives; W1/C1 when subjects/captions need sequence-aware repositioning or each version must remain editable.

**Escalation trigger:** use retained project state when mechanical crop harms subjects/captions, versions differ editorially, or the user requests separate editable projects/drafts.

**Hybrid handoff:** W1/C1 exports an approved master or sequence-aware versions; F1 creates mechanical derivatives and machine-readable verification.

**Verification:** dimensions, duration, frame rate, streams, codec, names/count, caption safe areas, representative frames, and retained project reopen when promised.

**Failure and recovery:** keep the delivery matrix and rerun only missing/invalid outputs; never infer safe reframing from dimensions alone.

**Record as skill:** delivery matrix is parameterized; one exact client export branch only after live replay.

**CU display:** conditional for C1 sequence-aware Desktop versions.

## Card 7 — Template workflow

**Use when:** the user wants to find, apply, adapt, or faithfully recreate a CapCut template/effect.

**Primary channel:** discover and evaluate in the actual client that exposes the template; use My Browser for CapCut Web, guidance for mobile-only state, and C1 only for a proved Desktop rebuild/finish.

**Escalation trigger:** move to C1 when a Desktop draft is required and the template/effect is actually available or a measured reconstruction is approved. Web/Mobile discovery never proves Desktop loadability.

**Hybrid handoff:** browser research identifies client/region/account availability; native/F1 prepares replacement assets; W1/C1 applies or reconstructs the approved effect in its real client.

**Workflow:** identify exact template; record client/platform/region/account; test load with disposable assets; choose supported use or explicit reconstruction; approve a short fidelity sample; finish and verify.

**Verification:** actual client loads/resolves assets, sample meets approved fidelity, final export opens, and requested Web/Desktop project state reopens.

**Failure and recovery:** unavailable templates trigger an honest alternate-client or reconstruction proposal, not fake cross-client compatibility.

**Record as skill:** decision tree may be shared; each template/client procedure remains evidence-bound and parameterized.

**CU display:** only a proved Desktop reconstruction/finishing workflow qualifies.
