# Draft Care and Guidance (Cards 8 and 9)

## Card 8 — Draft and media care

**Use when:** the user needs a read-only inventory, missing-media diagnosis, relink plan, naming plan, or safe cleanup of CapCut work.

**Primary channel:** file tooling for inventory, sizes, duplicates, paths, and proposed manifests; W1/C1 for proved in-client dependency/relink/organization state.

**Escalation trigger:** use W1/C1 only when a change must be reflected inside a project/draft or moving assets would break known links.

**Hybrid handoff:** file tooling proposes a reversible move/rename plan; the actual client confirms dependencies and performs proved relinks; file tooling reconciles final state.

**Workflow:** inventory without mutation; identify projects/media/missing paths; propose changes and rollback; obtain separate approval; apply one bounded class; reopen affected state.

**Verification:** file counts and hashes, no unapproved deletion, save/reopen, media-online state, and exact relink/move reconciliation.

**Failure and recovery:** do not reverse-engineer or mutate draft files directly. Stop when dependencies are ambiguous; keep backups and rollback map.

**Record as skill:** inventory is parameterized; client-specific relink needs fixture and live proof.

**CU display:** conditional for C1 retained Desktop relink/organization state.

## Card 9 — CapCut lessons

**Use when:** the user wants to learn or see one operation in the actual CapCut client.

**Primary channel:** My Browser for one live-proved Web lesson; Desktop CU for one live-proved Desktop lesson; conceptual guidance otherwise.

**Escalation trigger:** use the app only for learning a visible control/object. Reroute file-only completion to T0/F1/G1.

**Hybrid handoff:** T0/F1/G1 creates safe practice assets; the selected client performs the lesson; guidance captures variables and recovery.

**Verification:** exact client/OS/version/account/region, visible feature, observable start/end state, saved disposable project, repeat checklist, and missing-control fallback.

Priority lesson candidates are editable captions, deterministic chroma key, a minimal retained timeline, safe delivery settings, and one currently visible feature gate. Launch each independently; an old menu path or broad feature catalog is not a validated lesson.

**Record as skill:** one lesson per recording; parameterize files, region/account state, project, language, and destinations.

**CU display:** yes only after the specific Desktop lesson passes live replay. Web lessons are not CU.
