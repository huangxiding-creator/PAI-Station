# Cards 2 and 3: Editing, Presets, Export, and Share

## Card 2: Apply a look or reusable preset

- **Primary channel:** Use native image tools for approved standalone semantic derivatives, Sandbox for deterministic file transforms, My Browser for observed web-supported cloud edits, and Desktop CU only for retained Classic or verified cloud-desktop state under exact O1.
- **Escalation trigger:** Escalate to a Lightroom client when the deliverable must retain preset, history, mask, catalog, or library state that the current non-app route cannot preserve.
- **Hybrid handoff:** Approve a representative look outside the app when useful, then apply only the retained-state portion through the chosen Lightroom surface and validate the resulting derivatives separately.
- **Verification:** Compare the approved reference set, affected count, protected regions, outliers, and the exact retained state; a derivative alone never proves Lightroom state.

| Requested outcome | State | Route | Status |
|---|---|---|---|
| Approved flattened visual derivative | `S1` | Native image generation or refinement | `READY` after capability and quota preflight |
| Resize, format, rename, or compress existing derivatives | `S2` | Sandbox file processing | `READY` after codec preflight |
| Reversible Classic preset, history, mask, or synchronized settings | `C1` | Lightroom Classic through Desktop CU | `CONDITIONAL-O1` |
| Web-supported cloud edit or mask | `L1` | My Browser | `CONDITIONAL-WEB` |
| Verified desktop-only cloud editing feature | `L2` | Cloud Lightroom desktop through Desktop CU | `CONDITIONAL-O1` |

Approve a representative reference set before batch scale. Separate lighting and file-type groups, quarantine outliers, and define protected regions such as identity, skin, product color, or documentary truth. A native derivative never proves that a Lightroom preset, mask, history entry, or library state exists.

## Card 3: Export, download, or share

- **Primary channel:** Use Sandbox for existing standalone masters, My Browser for live web-supported cloud download/share, and Desktop CU for catalog-aware or verified desktop-only export under exact O1.
- **Escalation trigger:** Escalate when the source selection, reusable preset, watermark, installed plugin, or export behavior exists only inside the required Lightroom client.
- **Hybrid handoff:** Resolve and export the authoritative Lightroom selection in the app, then run deterministic renaming, format conversion, packaging, and file-level QA in Sandbox.
- **Verification:** Reconcile source and output counts, names, dimensions, format, metadata policy, isolated destination, permissions, and retained preset when requested.

| Source state | Route | Required proof |
|---|---|---|
| Existing standalone masters | Sandbox | Complete output inventory and field-level file assertions |
| Classic selection, collection, watermark, naming rule, plugin, or reusable export preset | Classic CU | `CONDITIONAL-O1`; source selection and retained preset must be observed |
| Supported cloud download or album share on web | My Browser | `CONDITIONAL-WEB`; target, permission, download, and reload/revocation checks |
| Verified desktop-only cloud export requirement | Cloud desktop CU | `CONDITIONAL-O1` |

Define each output specification separately:

- source selection and expected count;
- file format, dimensions, quality, alpha behavior, and color policy;
- metadata inclusion or removal;
- filename rule and isolated destination;
- share identity and permission, if applicable;
- whether a reusable Lightroom preset is part of the deliverable.

Validate every output row, not only a visual sample. A generic “check color profile” statement is insufficient; assert the exact property the deliverable requires. Revoke disposable shares after verification.
