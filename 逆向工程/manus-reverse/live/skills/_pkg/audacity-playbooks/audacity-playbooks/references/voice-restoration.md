# Card 3 — Noisy Voice Restoration

**Use when:** the user wants a noisy interview or voice recording made more intelligible and accepts that a defensible result may be a bounded improvement, limitation disclosure, or safe stop.

**Primary channel:** G0 establishes provenance, preservation, noise classification, and a testable A/B oracle. F0 may create protected excerpts and technical inventories through available tools. Use P1 only after O1 for a bounded listening-led Audacity trial. M1 is inappropriate unless one exact fixed operation is separately reproduced and the source class supports it.

**Escalation trigger:** move to an app trial only when the original is protected, the current route is verified, a representative excerpt exists, and the user has defined acceptable speech damage and artifacts.

**Hybrid handoff:** preserve and hash the source, create distinct test excerpts, run one bounded verified trial, compare A/B, then keep or reject the result. Store settings and provenance with every accepted derivative.

**Inputs:** untouched source, source context, any noise-only sample, restoration goal, artifact tolerance, provenance constraints, and alternate-source or rerecording options.

**Workflow:**

1. Establish whether the recording is evidentiary or otherwise provenance-sensitive.
2. Preserve the original and create a separate working excerpt.
3. Classify the noise and define an explicit intelligibility-versus-artifact oracle.
4. Probe the available route; do not invent a processing chain.
5. Run at most a bounded trial on a copy, then compare A/B.
6. Accept only a result that meets the oracle without misleading provenance; otherwise stop.
7. Deliver the untouched-source receipt, tested settings, A/B result, and explicit limitations.

**Failure and recovery:** stop when noise overlaps speech, the result damages speech, provenance is uncertain, the route is unavailable, or qualified review is required. Do not stack untracked trials on one copy or claim clean source separation.

**Record as Skill:** record only a protected-copy P1 A/B mainline after O1. The recording never owns the semantic keep/stop decision, provenance policy, or artifact threshold.

**CU display:** not an onboarding highlight. The workflow is sensitive, listening-heavy, and a correct outcome may be a safe stop.
