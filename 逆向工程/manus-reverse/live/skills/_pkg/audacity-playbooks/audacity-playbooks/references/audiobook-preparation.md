# Card 1 — Audiobook Preparation

**Use when:** the user has self-recorded narration or an existing chapter set and wants an audiobook prepared for a named delivery standard while preserving sources and any requested Audacity project.

**Primary channel:** F0 protects, inventories, names, and technically checks portable chapter files through tools that are present and probed. Use M1 only for a fixed chain reproduced on the installed Audacity build. Use P1 after O1 for listening-led edits, waveform judgment, plug-in UI, recording state, or retained project state.

**Escalation trigger:** move beyond F0 when the requested acceptance requires listening, per-segment editorial judgment, or an editable Audacity project. Do not promote a vendor guide into an executed GUI route.

**Hybrid handoff:** F0 creates the protected working set and technical manifest. M1 may apply an observed fixed chain. P1 handles only the judgment or project-state branch. F0 then reconciles every chapter and validates portable outputs.

**Inputs:** source narration, chapter/order rules, named delivery requirements, editorial brief, listening oracle, and retained-project requirement.

**Workflow:**

1. Freeze the source set and output contract; identify every expected chapter and derivative.
2. Inventory technical properties using only available, verified tools.
3. Separate deterministic packaging from mistakes, retakes, pacing, breaths, mouth noise, room tone, and other listening decisions.
4. Test one representative copy; preserve before/after identities and a listening comparison.
5. Obtain approval before scaling judgment-sensitive treatment.
6. Process only through the selected verified route and preserve exceptions.
7. Reconcile chapters, names, technical results, listening issues, and source hashes.
8. Save and reopen any promised Audacity project after current-build O1.

**Failure and recovery:** stop on unclear delivery rules, missing chapters, clipping, damaged speech, unavailable tools, or an unapproved listening result. Resume by chapter identity; never reprocess completed outputs blindly.

**Record as Skill:** record only a short P1 chapter-review and project-save mainline after O1 and unseen-fixture replay. Parameterize chapters, markers, requirements, paths, and outputs.

**CU display:** eligible after O1 because the app-specific value is listening/waveform judgment and retained Audacity project state. Portable checks are not a CU story.
