# Route Contract

The table records the current package route. `Future CU` explains where app-native state could justify Computer Use after operation-specific O1; it is not permission to execute now.

| Cards | User outcome | Current primary route | Escalation trigger | Hybrid or fallback | Verification | Future CU reason |
|---|---|---|---|---|---|---|
| SET-M01 / SET-W01 | Find and explain | Guidance | Version, hardware, policy, or naming ambiguity | User opens the supported surface; interpret a non-secret state | Correct surface and zero state change | Read a client-only visible control after current-build O1 |
| SET-M02 / SET-W02 | Personalize appearance or shell behavior | Guidance | User requires app-native preference state | Use a proved official runtime if exposed; otherwise user action | Named preference and visible shell state; inverse value retained | App-native preference lacks a proved current Manus mutation route |
| SET-M03 / SET-W03 | Improve readability | Guidance | Display, sign-out, multi-monitor, or control-loss risk | User takeover with a recovery plan | Requested surfaces remain readable and controllable | Only a bounded non-disruptive control after recovery O1 |
| SET-M04 / SET-W04 | Notifications or Focus | Guidance | Critical-alert inventory or test oracle is incomplete | Produce a scoped plan; user performs the change | Benign and critical alert paths both behave as intended | Visible state may be client-only, but risk gates precede UI use |
| SET-M05 | Diagnose Mac power behavior | Conditional host-local read, else guidance | Host runtime absent, root, policy, hardware, or a broad power request | Interpret a qualified local read or minimized user-supplied output | Cause category and effective state; zero writes during diagnosis | One finite consumer timeout only after current O1 and behavior rollback |
| SET-W05 | Diagnose Windows power behavior | Guidance | Missing minimized state, elevation, policy, hardware, or a broad power request | Interpret user-supplied read-only output; do not claim host execution | Cause category and supplied effective state; zero Manus writes | A future proved local read should precede any CU mutation |
| SET-M06 / SET-W06 | Tune input behavior | Guidance | Hardware absent, OEM ownership, or no backup input | User action or OEM support | Physical behavior and control state agree; backup input works | Input preference is app-native but hardware-specific |
| SET-M07 | Diagnose missing or reverting Mac state | Conditional host-local read, else guidance | Host runtime absent, policy, defect, sensitive output, or admin boundary | Join qualified minimal diagnostics with user-observed labels | Evidence-backed cause category and zero writes | Read managed or disabled labels after current-build O1 |
| SET-W07 | Diagnose missing or reverting Windows state | Guidance | Missing minimized state, policy, driver, defect, or admin boundary | Interpret user-supplied diagnostics and labels | Evidence-backed cause category and zero Manus writes | Future local read or UIA needs Windows O1 |
| SET-M08 / SET-W08 | Plan a managed baseline | Guidance and planning | No approved tenant, pilot, owner, or rollback | Produce a payload mapping and pilot plan only | Plan names scope, authority, pilot, verification, and rollback | CU is not the managed-policy state owner |
| SET-M09 / SET-W09 | Sensitive settings | User-owned guidance | Consent, secret, network, security, reset, UAC, or elevation | Stop before secure action; user completes it | User confirmation plus non-secret status | CU cannot authorize itself or cross secure boundaries |

## Route precedence

1. Use guidance when runtime or operation evidence is absent.
2. Use a verified read-only host route before opening a GUI for diagnosis.
3. Use an approved management plane for managed state; consumer Settings is not authoritative.
4. Use Computer Use only for a named app-native residue after all O1 and rollback gates pass.
5. Stop at the first missing permission, authority, hardware, policy, or verification gate.
