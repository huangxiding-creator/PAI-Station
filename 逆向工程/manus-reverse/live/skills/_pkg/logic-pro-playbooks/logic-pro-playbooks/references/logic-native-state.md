# Logic-native state gate

Load this reference for every L1 branch. It defines admission and verification, not a current UI procedure.

## Current package status

This package has no live-observed procedure for a current Logic Pro build. Do not infer menus, controls, key commands, accessibility behavior, timing, or save semantics from first-party documentation alone. Do not replay coordinates from another recording.

## Required O1 preflight

Before any Logic mutation, capture all of the following from the target session:

1. the exact canonical installed app record returned by the current Desktop runtime;
2. Logic version, macOS version, edition or distribution variant, and writable test location;
3. Computer Use permission and session status;
4. a disposable synthetic fixture or separately approved project copy;
5. an audible monitoring path suitable for the requested judgment;
6. the semantic controls and current state needed for one representative action;
7. a save, close, reopen, and state read-back oracle;
8. recovery and a single finish receipt for the Computer Use session.

If any item is missing, keep the L1 branch blocked and return the portable preparation or guidance handoff.

## Native state oracles

- Arrangement: expected named tracks and regions exist, media resolves, tempo/meter assumptions are recorded, and state survives reopen.
- Comping: every source take remains reachable; the comp map and editable correction state survive reopen; listening checkpoints are recorded.
- Mix/export: routing and automation survive reopen; exported files match an external manifest and listening rubric.
- Handoff: the source remains unchanged; the staged copy reopens; dependencies and losses are itemized.
- Scripter: exact input/output MIDI vectors match, every note-on has a corresponding note-off, no runaway events occur, and the selected persistence container survives reopen.
- Troubleshooting: tests use a copy, change one variable, restore state, and never overstate cause confidence.

Screenshots, an existing export, a file extension, or a project that opens once are not sufficient proof of retained state.

Project alternatives and automatic backups are app-native recovery state, not portable interchange. Do not flatten, replace, or select an alternative on the user's behalf without an observed disposable workflow and task-specific approval. A future handoff run should preserve the intended alternative and verify the relevant backup state independently.

For collaboration or archive, prefer a separately saved project copy with required assets consolidated into that copy after O1. A file inventory can identify candidate dependencies, but it cannot prove that Logic copied every external audio file, sampler instrument, impulse response, video, loop, or asset used by every project alternative.

## Consequential boundaries

Require immediate task-specific approval before overwriting a project or master, flattening takes, replacing source media, moving preferences or plug-ins, resetting settings, reinstalling Logic, deleting caches or media, or publishing audio. A research or packaging request does not authorize any of these actions.
