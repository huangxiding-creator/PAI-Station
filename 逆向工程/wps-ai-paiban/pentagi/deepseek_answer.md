# WPS 本机攻击面研判清单（按风险降序）

## P0 · wpscloudsvr.exe 监听 0.0.0.0:46608 —— 未认证远程攻击面（最高风险）

**判定依据**
- 绑定 `0.0.0.0` 意味着对所有网卡/所有网段可达，不再局限于本机。只要 Windows 防火墙对该进程放行（或处于共享网络），**同一局域网/受限网络内的任意主机都能直连 46608**。
- "私有协议、不吃明文 HTTP" 说明是自研二进制/序列化协议。这类自定义协议解析器历来是内存破坏（缓冲区/整数溢出）、反序列化、长度字段校验缺失的高发区，且几乎不被外部安全研究覆盖。

**攻击路径**
1. 未认证握手 → 构造畸形报文触发解析器漏洞 → RCE / 崩溃 DoS。
2. 若协议明文传输且无认证 → 同网段可 MITM 窃取云同步内容或凭据。
3. 作为横向移动入口：一个内网失陷点可批量探测并利用所有装有 WPS 的机器。

**缓解建议（按优先级）**
1. 非必要直接**禁用/卸载该云服务组件**；若业务必需，改绑定 `127.0.0.1`（46608 不应监听公网网卡）。
2. 在 Windows 防火墙建立**入站拒绝规则**（专用/公用/域全 profile），仅放行本机回环。
3. 强制升级到最新版本；对私有协议做**语法级加固**（长度/类型边界校验、握手认证、传输加密）。
4. 若持续暴露，纳入**协议 fuzz 与渗透测试**范围，作为重点整改项。

## P1 · Copilot 侧边栏注入链 kcopilotentry.dll → kwpsaitypeset.dll → KSOLITE.DLL —— 内容到原生的特权边界（高风险）

**判定依据**
- `kwpsaitypeset.dll` 向侧边栏 Webview 注入 JS API，形成一条 **JS(Webview) → 原生(DLL)** 的桥接边界。这是典型的 "JS bridge" 高危面：一旦 Webview 渲染了不受信任内容，注入的桥对象即可被脚本调用进入原生层。
- `KSOLITE.DLL` 负责 AES：密钥若硬编码在 DLL 内、或由固定字符串弱派生，加密的 token/配置可被离线还原，直接支撑下方会员门禁伪造。

**攻击路径**
1. 若侧边栏加载远程内容（wps.cn / AI bus）或任何用户可控 HTML，且 bridge 未按 **origin 白名单 + CSP** 隔离 → XSS 可直接调用桥接的原生 API → 文件读写、进程启动、凭据窃取。
2. 逆向 `KSOLITE.DLL` 提取 AES 密钥 → 解密本地加密数据，进一步伪造权益/会话。

**缓解建议**
1. 对注入的 JS bridge 做**严格 origin 白名单**，仅允许可信域调用；落地 CSP、禁用 `eval`/内联脚本。
2. **审计并最小化暴露给 JS 的原生方法**（白名单化，禁止任意文件/进程/网络能力直接透传）。
3. 密钥改走 **DPAPI/TPM 安全存储**，杜绝硬编码与固定派生。
4. 默认关闭远程内容加载，或对第三方内容做沙箱隔离。

## P2 · 本地模板容器固定 IV AES-128-CBC —— 确定性加密导致的信息泄露与可篡改（中高风险）

**判定依据**
- AES-128-CBC 使用**固定 IV** → 加密退化为**确定性加密**：
  - **相等预言机**：同一明文 → 相同密文，可判定两份密文是否同源；
  - **内容指纹泄露**：通过密文可识别具体模板/版本、检测内容是否变化；
  - **无完整性保护**（CBC 无 MAC）：密文可被按块篡改；若解密时错误可区分，还引入 padding oracle 面。

**攻击路径**
1. 本地窃取/观察模板密文 → 指纹识别在用模板，泄露使用行为/版本信息。
2. 篡改模板密文（块翻转/重放）→ 诱导加载恶意模板内容，配合 P1 的 Webview 链放大危害。

**缓解建议**
1. **每次加密使用随机 IV**（安全随机源，禁止固定/计数器 IV）。
2. 改 **AEAD（AES-GCM / ChaCha20-Poly1305）**，或 AES-CBC + HMAC-SHA256 提供完整性与认证。
3. 密钥通过 KDF（如 PBKDF2/scrypt/Argon2）派生，与数据解耦、密钥隔离。
4. 对解密失败统一返回不可区分的错误，消除 padding oracle 信号。

## P3 · 会员门禁 personal-ai-bus.wps.cn + VAS pay-counter —— 权益客户端信任问题（中风险）

**判定依据**
- 会员/付费门禁若在**本地**维护"已付费"标志、或 pay-counter 为客户端计数，则存在越权空间；权益 token 若由 KSOLITE 弱密钥加密且无签名，可被伪造。

**攻击路径**
1. 篡改本地"会员状态"字段 / 重置 pay-counter → **绕过付费门槛**使用会员功能（业务越权，非直接 RCE）。
2. 伪造未签名/弱签名权益 token → 骗取服务端认定会员身份。
3. 对 `personal-ai-bus.wps.cn` 做 MITM（若无证书校验/固定）→ 窃取会话或注入伪造响应。

**缓解建议**
1. 权益判定**强制在服务端**完成，客户端仅缓存展示态、不可信。
2. 权益凭证采用**签名 token（JWT，强密钥 + 过期 + 绑定设备）**，服务端验签，杜绝本地伪造。
3. 对关键域名启用**证书固定（pinning）**，防止中间人。
4. pay-counter 等计数逻辑服务端化，客户端上报仅做参考。

## 补充 · 127.0.0.1:4709 回环服务（跨项风险）

回环端口虽然不跨网段，但**任何本地进程、乃至浏览器（DNS rebinding / 恶意网页）都可能尝试连接**。若协议无认证、无 Origin/来源校验，可被本地低权限进程或网页滥用去触发云操作/功能调用。

**缓解建议**：绑定到仅必要进程可访问、增加握手认证、校验请求来源（Origin/进程身份），隔离不必要的回环端口。

## 研判总结

| 风险 | 目标 | 性质 | 首要缓解动作 |
|---|---|---|---|
| **P0** | wpscloudsvr.exe `0.0.0.0:46608` | 未认证远程面 | 改绑回环 + 防火墙拒绝 + 禁用 |
| **P1** | Copilot JS bridge + KSOLITE 密钥 | 内容→原生边界 | origin 白名单 + 密钥 DPAPI |
| **P2** | 固定 IV AES-CBC 模板容器 | 确定性加密/可篡改 | 随机 IV + 改 AEAD |
| **P3** | 会员门禁 + pay-counter | 客户端信任越权 | 服务端强校验 + 签名 token |
| 补充 | `127.0.0.1:4709` | 回环滥用 | 认证 + 来源校验 |

**总体建议**：这是一条典型的"云服务 + Webview 桥接 + 弱加密 + 客户端门禁"复合链，危害可被互相放大（如 P1 提取的弱密钥 → 伪造 P3 会员权益）。优先按 P0→P1 顺序整改，同时把 KSOLITE 密钥管理与 CBC 固定 IV 作为密码学债一并偿还。以上均为基于授权测绘事实的静态研判，未做任何对外扫描或联网验证，落地整改前建议在授权范围内进行协议 fuzz 与 JS bridge 审计以确认实际可利用性。
