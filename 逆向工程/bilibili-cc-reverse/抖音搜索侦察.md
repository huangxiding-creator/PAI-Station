# 抖音搜索端点侦察报告（261024，只侦察不破解）

## 1. 端点
`https://www.douyin.com/aweme/v1/web/search/item/`（GET）
标准 query 面（web 端全量 ~40+ 参数）：`device_platform=webapp&aid=6383&channel=global&keyword=<kw>&search_source=normal_search&query_correct_type=1&is_filter_search=0&offset=0&count=10&need_filter_log=1&browser_language=zh-CN&browser_platform=Win32&browser_name=Chrome&browser_version=<ver>&webid=<id>&msToken=<tok>`

## 2. 实弹证据（本机 2026-10-24 09:48，curl 无 cookie 无签名）
- HTTP 200，body 127B：
  `{"log_pb":{"impr_id":"202610240948568F389B34C8420A8825A6"},"status_code":2483,"status_msg":"请先登录，再继续搜索吧"}`
- **结论：登录墙在签名墙之前**。先要登录态 cookie（sessionid_ss / t_sso 等），之后才轮到 a_bogus/X-Bogus/msToken 签名校验。

## 3. 本机登录态盘点（261024 实测）
| 浏览器 | douyin.com cookies | 可解性 |
|---|---|---|
| Edge Default | 仅 `ttwid`（v20-appbound），无登录 cookie | 无登录态 |
| Chrome Profile 2 | 文件被运行中 Chrome 独占锁（err 32）+ Chrome 155 全量 v20 | 不可读 |
| Chrome Guest Profile | 0 cookies | 无 |

→ 本机当前**无可读 douyin 登录态**。

## 4. 签名要求（公开生态知识，非本机实证）
- 新代签名 `a_bogus`（搜索/详情现行），旧代 `X-Bogus` 仍部分端点兼容；均需与 UA+全量 query 派生。
- `msToken`：滑块/环境行为签发，服务端校验有效性，纯算复刻难度最高。
- 现成 OSS：`JoeanAmier/TikTokDownloader`（内含纯 Python ABogus 实现，走 web 签名链）等。
- 「不硬做签名破解」（任务令）：本报告止于侦察。

## 5. 建议路径（与 B 站同班次）
1. 受控浏览器（带调试口）扫码登录 douyin.com → CDP `Network.getAllCookies` 取明文登录 cookie（免疫 v20/锁，同 bilibili 方案）。
2. 或走 app 端 `access_key`（需账号密码/APP token，另案）。
3. 拿到登录态后再评估 a_bogus 引用现成 OSS 实现（revenue-engine OSS-first 铁律）。
