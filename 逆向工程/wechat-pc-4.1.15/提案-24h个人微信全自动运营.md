# 提案：24 小时不停的个人微信全自动运营（v1，2026-10-17）

> 依据：微信 4.1.15.55 逆向（[自动化情报](自动化情报.md)）+ 识流逆向成果合流 + WeChat-Report
> 实作参考 + 本轮 GitHub 四轨调研 ~100 仓实测（2026-10-17，api.github.com 逐一验证）
> 红线继承：tier-② 事实级边界 / UIA 唯一发送车道 / 主力号零封号目标

## 一、目标与红线

**目标**：单台 Windows 机 7×24 无人值守运营个人微信——群消息自动回复、定时内容分发、
朋友圈日更——主人随时用电脑时自动化自动让路。

**五条红线（全程不可越）**：
1. 不注入微信进程、**不改写 Weixin.dll 内存**（含 accessibility gate 的运行时改写——见 §六决策2）
2. 不伪造 micromsg 协议流量、不碰 127.0.0.1:140xx 内部服务
3. 不用无 license / AGPL / GPL 传染件的代码（自部署 GPL 整机除外，不分发无碍）
4. 主力号只跑低频高价值动作；频控参数（同群日3/全局日20/冷却/熔断）恒生效不可绕过
5. 一切「更激进」的变通必须先过用户批准

## 二、研究基线（三方证据链，30 字版）

微信客户端带 VMP+Detours 钩子（wcprobe）→ 软件合成输入可观测（本仓 mouse_supervisor
已实锤 LLMHF_INJECTED 判别）→ 识流商业产品以驱动/硬件输入应对 → 开源社区用脚投票
收敛于 UIA 车道 + 硬件 HID（本轮调研再证）。

## 三、调研总览（四轨 ~100+ 仓，关键结论）

### 轨1 微信本体（~40 仓）
- **WeChatAuto.SDK**（278★ MIT，当日活跃）：4.1.x UIA+本地 OCR 混合 SDK，多实例+MCP，
  **朋友圈组件（@好友/标签分组可见）在 MIT 目录**——主干候选
- **wechat-moments-automation**（1★ MIT）：全 GitHub 唯一完整 PC 朋友圈发布件，
  版本无关（OCR 语义+SIFT/ORB）+风控退避+类人行为，44 测试
- **wechat-uia-keepalive**（4★）：**4.x UIA 硬前提情报**——CPU 软件渲染+无障碍客户端
  持续附着双条件才暴露完整树（预热 6-15 分钟），零侵入可自研
- pywechat（2021★ 纯 UIA 4.x，license 待确认）/wx4py（AGPL 仅参考）/xiaoli（4★ MIT
  纯视觉降级通道，4.1.15.13 标定）
- 旁证：WeChatFerry 已归档实证 hook 路线 4.x 失活；协议族（Gewechat/PadChat 等）全部
  落后 4.1.15 或无 license——**无一个存活项目用驱动注入碰 4.1.15**

### 轨2 输入反检测层（35 仓，命门层）
- **用户态全家覆没**：pyautogui/pynput/keyboard/AHK/enigo/pydirectinput（含扫描码模式）
  全部 SendInput 系=带注入标志，在 wcprobe 面前裸奔（测试环境专用）
- **Interception 驱动死路**：停更 5 年、Win11 普遍装不上（issue #215/#176）、无 EV+WHQL
  签名无解（#207）、被反作弊拉黑（#44）、卸载灾难（#206）
- **CH9329 硬件主路线成立**：CH9329_COMM（89★ **MIT，pip 直用** Python 协议库）+
  模块 ¥15-30 = 物理 USB HID，低级钩子无从标注入；识流商业验证同芯片
- 开源 IP-KVM 整机：NanoKVM（6556★ GPL，**识流同款**）/PiKVM（10390★ 当日活跃），
  自部署 GPL 无碍
- 拟人轨迹：WindMouse（重力+风场算法，MIT 版可移植）——反检测社区公认标配
  （sunone 圈三件套=WindMouse+KMBOX+MAKCU，与识流栈同构）
- 佐证：deskflow/Synergy（29772★）开源代码含同款 LLMHF_INJECTED 判别

### 轨3 UIA 框架与 24h 运行时（30+ 仓）
- **后台投递实证**：PersonaMorph（74★）证明微信 4.x 上 UIA pattern（Invoke/Value）
  可后台调用——窗口被盖/最小化照跑、不产生输入事件
- pywinauto（BSD-3，在役底座）官方文档：RDP 断开=桌面锁死=自动化全灭，**VNC 是标准解**
- 运行时栈定型：WinSW（14372★ MIT 守护）→ APScheduler（7656★ MIT 调度+jitter）→
  healthchecks（10425★ BSD-3 死人开关）→ watchdog（7421★ 断点监视）
- 自愈编排开源空白=自建（任务粒度 checkpoint）；Supervisor 官方不支持 Windows；
  Docker 化 GUI 不可行（官方指南）

### 轨4 编排与内容（32 仓）
- B 栈自研频控**不替换**（limits 仅多进程场景补）；human-cron 空白=自研 ~60 行高斯作息峰
- 内容源：DailyHotApi（MIT 热榜）+ we-mp-rss（部署不抄码，license 非标需人工核）+
  wechat-article-exporter（13074★ MIT）+ agents-radar（MIT 日报骨架）+ doocs/md（排版）
- **朋友圈文案腿开源空白**=自研 prompt 腿；看门狗告警=wecomchan 直推函数（MIT）

## 六、三大工程决策

**决策1 输入三级跳**：UIA pattern 主档（后台+零输入事件）→ CH9329 硬件档（需真鼠标的
动作：拖拽/滚动长列表/朋友圈选图）→ pyautogui 仅测试。**生产默认零 SendInput**。

**决策2 UIA 激活零侵入**：微信 4.x 树断裂用 keepalive 式双条件（渲染模式+持续附着）
解决——这改的是**我们调用无障碍 API 的方式**，不改微信任何字节；replica 的 Weixin.dll
内存改写法即使有效也踩红线 1，弃。

**决策3 会话保活**：24h 腿活在 VNC 会话（TightVNC/TigerVNC 服务端），禁 RDP 断开直连；
锁屏策略改为「VNC 虚拟会话常驻 + 物理屏可锁」。

## 九、风险声明（如实）

1. UIA pattern 后台投递的单项目实证（PersonaMorph 74★）未经第三方复核——W1 实测是硬门
2. WeChatAuto.SDK 20% VIP 边界需逐文件核（朋友圈组件经 code search 确认在开源目录）
3. 微信版本升级仍是最强外扰：版本守门腿（6h 检测→停发）为最后防线
4. 「24h 不停」与「拟人」存在本质张力：方案以作息模拟+克制频控折中，不承诺绝对安全
5. CH9329 对微信的实际效果（识流商业验证同芯片）待我方接入实测

## 十、与在役件的关系

wxrpa 不废：human_input 拟人层（贝塞尔/正态延迟/剪贴板协议）被三档共用；B 栈队列/
audit_log/proactive 原样在役；本提案=把「发送执行器」从 pyautogui 单档升级为三档，
读/决/监督层零改动。
