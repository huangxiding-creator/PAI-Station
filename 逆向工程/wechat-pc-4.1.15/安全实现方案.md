# PC 微信本机 24h 自动化运营——安全实现方案（详细版）

> 2026-10-17 | 依据：[自动化情报.md](自动化情报.md)（4.1.15.55 逆向结论）+ revenue-engine B 栈在役件
> 目标功能：**发消息（群/私）、发朋友圈、群消息自动回复**，7×24 本机运行，主力号零封号
> 车道铁律（情报结论 §二）：**UIA 是唯一发送车道**；rion-cli 是唯一读车道；140xx/micromsg/hook 三面全禁

## 一、总体架构

```
┌─ 读车道（零风险）─────────────────────────────┐
│ rion-cli 本地DB直读 → 群消息流 → SignalDetector │
│ （意图识别/JTBD，在役）→ 线索/触发词命中         │
└──────────────┬───────────────────────────────┘
               ▼
┌─ 决策与安全网（B栈队列，在役+本方案补强）────────┐
│ auto_responder：同群日3 / 全局日20 / 冷却30min   │
│ / 群间隔60-180s / md5去重 / 熔断 / 审计落盘      │
│ + 朋友圈频控器（新增，§四）+ 作息窗（新增）        │
└──────────────┬───────────────────────────────┘
               ▼
┌─ 发车道（唯一出口：wxrpa UIA）──────────────────┐
│ 群消息：定位会话→Ctrl+V→Enter（在役，实战验证）   │
│ 朋友圈：SNS UIA 流（新增，§三）                  │
│ 全部经 human_input 拟人化节奏                    │
└───────────────────────────────────────────────┘
```

### 2.x 识流对策表全量吸收（§6 复核清单）

随机点击落点（bbox 内侧随机）/ 拟人滚动 3-8 步 / 画面 pixelmatch diff（>0.2% 判变化
才走后续）/ 行动-验证 0/1 后验 / OCR 预检标题区再点击 / 红点导航随机落点 / 剪贴板
短占用+读回校验（已在役）/ 未读检测 2.5s×4 次间隔抖动重试。

## 三、功能二：朋友圈（新增腿，UIA 流详细设计）

### 3.1 发表流程（文字朋友圈）

```
1. 主窗侧栏「发现」页 → 朋友圈入口（Qt 控件: 名含"朋友圈"）
2. 朋友圈窗右上角相机按钮 —— ⚠️ 文字朋友圈=长按相机（单击=拍照/选图弹窗）
   UIA 实现长按：human_input 按住 800-1200ms 随机
3. 「发表文字」弹窗 → 文本框 human_input 键入（打字节奏 80-200ms/字符随机+偶尔停顿）
4. 可选插图：点「+」→ 文件对话框 → 输入绝对路径 → 回车（不遍历目录树）
5. 右上角「发表」→ 等待朋友圈窗刷新（新条目出现在流首=成功锚点）
6. 全程截图落盘审计（audit_log 扩展 leg="sns"）
```

### 3.2 选择器固化

- 控件定位优先级：AutomationId > Name 精确 > Name 含关键字 > 坐标兜底（坐标仅最后手段）
- 全部选择器集中进 wxrpa 选择器注册表（json 配置，非硬编码），版本升级只改注册表
- 首次实施：用 wxrpa dump 朋友圈窗全树 → 人工标定 8-10 个锚点控件 → 固化

### 3.3 频控（自定保守值，识流无此功能无参数可抄）

| 参数 | 值 | 理由 |
|---|---|---|
| 日发表上限 | 1-2 条 | 真人商务号典型频率 |
| 发表时段 | 7:30-9:00 / 12:00-13:00 / 20:00-21:30 三窗随机取一 | 拟人作息 |
| 同内容重复 | 永不（md5 全文去重，跨日亦拒） | 朋友圈无「重发」概念 |
| 图:文 | ≥1/3 条带图 | 纯文字连发是营销号特征 |
| 失败处理 | 连续 2 次流程失败 → 当日停发朋友圈（不强试） | 反指纹 |

### 3.4 内容源

自媒永动机产线（3 公众号+1 视号）文摘→钩子文案→朋友圈；与 proactive 推送内容错开（不同素材池）。

## 四、功能三：群消息自动回复

```
rion-cli 轮询群消息（30s 级）→ 触发词/意图命中（SignalDetector 在役）
→ 命中白名单群且该群当日回复 <3 → 工程大脑生成回答（带规范出处）
→ B栈队列 priority=1（问答>推荐>推送）→ wxrpa 发送 → 审计
```

- **白名单制**：默认全静默，逐群开启（先开 3 个测试群跑 1 周，再扩）
- **@提及优先**：被 @ 的群消息优先回复（社交义务性回复最拟人）
- **不答场景**：纯表情/红包/接龙/他人对话中段——宁可漏答不硬答

## 五、作息模拟（24h 安全的核心新增件）

| 时段 | 行为 |
|---|---|
| 08:00-22:00 | 正常运营（B栈在役参数） |
| 22:00-23:30 | 减频（只答 @，不推送不发圈） |
| 23:30-07:30 | **全静默**（队列冻结不入不出；紧急告警腿除外） |
| 每周随机 1 天 | 「休息日」总量减半（真人有淡日） |

实现：auto_responder 加 business-hours 双档 + 军团 schtasks 夜间冻结/晨间解冻腿（复用在役让路机制代码）。

## 六、监控 / 应急 / 降级

1. **审计**：audit_log（在役）扩 leg=sns；朋友圈截图独立目录留 90 天
2. **风控信号分级**（与 REQ-021 同口径）：
   - 客户端弹「操作频繁」→ 当日减半配额
   - 弹「环境异常」/要求验证 → 双栈同停 + 人工
   - 掉线重登失败 → 停发保号（账号安全 > 当日运营）
3. **降级序**（任何故障只向更保守降，永不向更激进变通）：
   UIA 失效→停发；频控参数异常→回默认保守值；内容源断→静默不发空文
4. **禁区重申**（情报 §二 B/C/D 面）：不碰 140xx、不构 micromsg 包、不注入、不挂第三方协议端

## 八、验收（五轴口径）

- 账号安全轴：试运行期主号零封号零验证弹窗（弹窗哨兵日志为证）
- 克制自研轴：新增面全部落在 wxrpa/auto_responder 自有件，零新依赖
- 审计轴：每条发送（消息/朋友圈）可回溯：时间/群/内容摘要/腿/频率快照
- 无人值守轴：72h 零人工介入（含一次自愈：窗口丢失重启客户端）
- 合规轴：tier-② 边界零违例（无注入/无协议伪造/无第三方协议端）

## 九、输入后端分级与升级路线（识流×微信逆向互证后的关键新增）

**依据**：微信客户端 wcprobe.dll = VMProtect 加壳 + Detours API 钩子（情报 §五点五）
→ 软件合成输入（SendInput/keybd_event 系，**含 pyautogui**）在客户端侧可观测
（LLMHF_INJECTED 标志）；识流以驱动级/硬件 HID 后端应对——「操作系统与应用层均无法
与真人区分」。

| 级 | 后端 | 可观测性 | 成本 | 判定 |
|---|---|---|---|---|
| L0 | pyautogui（现状） | **INJECTED 标志可辨** | 0 | 短期过渡：日3/全局20 克制频率下可运行（实战无事故记录），但为已知暴露面 |
| L1 | 驱动级键鼠（wyhkm 类商业驱动） | 驱动层注入，无 INJECTED 标志 | ~百元级授权 | 备选（引入第三方闭源驱动需过 tier-②审） |
| L2 | **CH9329 硬件 HID**（串口 USB 芯片） | **物理设备输入，理论不可辨** | ¥10-30/片 + USB 口 | ✅ **推荐终态**：识流已解码全套帧协议（§5.4：0x57AB 帧/绝对相对鼠标/boot 键盘/校验和），按协议事实自写串口驱动层（clean-room，非抄码） |

**实施建议**：B 栈保持 L0 跑低频高价值动作（朋友圈+@回复）；采购 1 片 CH9329（淘宝
现货）做 L2 试点——wxrpa 的 human_input 抽象成 backend 接口（pyautogui/ch9329 双实现，
识流同构的后端优先级架构），两周内可切换验证。**硬件到位前不扩频**。

### 朋友圈分组可见（SnsPost WithChatroom 字段 → UIA 同路可达）

情报确认协议层支持群维度可见性；UIA 发表流中「谁可以看」控件同路驱动——运营价值
（按群画像定向发圈）+ 安全面（缩小受众=缩小风控暴露）。进 P2 选择器标定清单。

## 十、风险声明（如实）

UIA 车道的固有风险**不为零**：微信用户协议禁自动化，客户端侧 wcprobe（加壳）行为遥测
不可审计——本方案的一切参数以「最保守拟人」对冲，但不承诺绝对安全。封号损失边界：
主号承载核心私域（100 群），**建议主号只跑低频高价值动作（朋友圈+@回复），
高频推送继续由小号（A 栈存活门实验中）或企微腿分担**。
