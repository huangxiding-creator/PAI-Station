# METHODOLOGY · PAN-HUNTER 本役方法论沉淀（W0-W4，2026-10-30/31）

> 六大判例，均出自实测+事故复盘，可直接复用于同型战役（资源发现/逆向复刻/多源聚合类）。

## 1. 配方库 vs 运行时裁决法——TLS 指纹能力是分水岭

**问题**：开源引擎（pansou，15k★）整仓在手，跑它的运行时还是只摘它的配方？

**裁决法**（不问星数问能力）：看「运行时本身是否带来你缺的能力」。pansou 运行时=裸 Go net/http
（util/http_util.go 全仓无 utls/ClientHello 定制），对 CF TLS 指纹墙与 curl 同样无解；而本站已证的过墙武器
是 curl_cffi impersonate（W0 四象限对照：yunso requests 直连死/curl_cffi 直连 200，铁证）。
运行时买不来过墙能力 → 只作**配方库**（122 插件=122 份 endpoint/参数/头/解析的单文件配方，逐行翻译成
Python，零猜测），运行时自建。附带义务如实记账：上游月度增量合并。

**推广式**：引入任何开源引擎前先问三句——它独有的能力是什么？我现有栈能否等价？不跑它的代价是什么？
答案「无独有能力/能等价/只省翻译工」即配方库路线。

## 2. 真件门纪律——端点活≠能力

**教训**：115 skip_login_downurl 端点活、光鸭匿名链全通到列表——按「端点活」口径早该报绿。
真件门（真实分享链→列表→直链→**≥10MB 真文件落盘+sha1**）把两盘都拦下：115 一律 errno=4100054、
光鸭一律 code=207（分享者未开免登下载）。**端点活只是链路证据，真件落盘才是能力证据**；
对外能力声明只认后者（5/10 绿而非 9/10）。

**推广式**：一切「能力声明」必须绑定端到端真件门（真实输入→产物落盘→可校验指纹）；中间层全通的
「就绪态」与「能力态」分栏声明（绿?≠绿）。

## 3. owner 开关型盘定性法

新盘型：**链路我方全通，卡点在分享者侧的一个开关**（115 的免登下载开关/光鸭的免登下载选项）。
定性法=三问：①失败码是否稳定指向 owner 侧（4100054「该链接不支持免登下载」×N 链、207「分享者未开启」
×7 链）？②官方文档是否印证开关存在（两盘官网功能均=分享者可选）？③是否存在任何我方可修参数？
三问成立 → 定「绿?·owner 开关型」：不转绿（无真件）、不标红（非我方墙）、写明转绿条件（猎到开链即绿）。
同理「绿?·无当活链」（wss：配方在位，公开链全过期+收件码制不入索引）——**定性要指名等待的随机事件**。

## 4. 源半衰期与健康轮

实测漂移：melost 响应结构**同日**变更（search_result→list）、aipanso 同日被 CF 升级为质询、
pan666 站变形（Flarum→Discuz+520）、kkmao 疑关站（首页=Farewell）。38 源实测仅 9 活（23.7%）。
结论：**聚合源的活源名单是易腐品，半衰期按天计**——覆盖叙事必须从「N 配方」改成「实测 N 活源+日期」；
健康轮周期≤7 天（探针≈9-12 发），死源摘牌=矩阵更新而非救火（弃养政策）。
另：首页过墙≠端点过墙（W3：5 质询源首页 5/5 可开、搜索端点 0/5——CF 对 API 路径单独设防，
turnstile 交互墙下「浏览器过首页→导 cookie→curl 复放」路径不成立，无 clearance 可导）。

## 5. 模造链与臆造盐——两起自纠事故的教训模式

- **模造链**（W1 门链狩猎）：w1_gate_extra.json 初版后半段系**按模式编造的链接**（长得像真链），
  当场销毁重写为仅实见链。
- **臆造盐**（W2 迅雷签名）：凭记忆写 captcha_sign 算法=九轮**短盐**连拼 → 15 链全 captcha_invalid；
  病根不是盘墙是代码病。回 engine/pansou 本地仓 L1305 逐行核对→真算法=首轮即 content+**长盐**连拼九轮 md5
  +timestamp 必须字符串 → 一次修通（14 次 init 全通零 invalid）。

**教训模式**：**记忆≠证据，本地仓源码才是**。签名算法/参数名/响应结构这类「可查证事实」，
禁止凭记忆产出——先回冻结副本/上游源码逐行核对，再动手；产物自检时对「过于顺手的规律性内容」
（链接成串、签名一次过）保持怀疑，宁可当场销毁重写，不留给下游当证据用。

## 6. 免登三态分级（绿/黄/红）+ 口径纪律

三态不是评分是**承诺口径**：绿=免登全链可交付（真件门为证）；黄=免登可发现可列表可探活，
交付走本地凭据插件且默认关（发现/交付两栏强制分列）；红=仅发现不承诺。
配套纪律：①对外两栏分列（交付层/发现层），黄盘永不写「可下载」；②计数口径注明「链次 vs 独立链」
（W2 迅雷 6 链次=3 独立链的教训）；③台账只追加不覆写（unlink 毁档事故→run-id 追加制）；
④数字零造假——一切数字出自 JSONL 台账行计，报不出台账的数字不报。
