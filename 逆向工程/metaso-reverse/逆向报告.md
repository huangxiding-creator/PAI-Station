## 一、战果一句话

**秘塔AI搜索 = 一次纯 HTTP POST SSE 流**：预热 GET 首页取 `meta-token`（服务端签发、SSR 直出）+
三个可复刻 Cookie（`tid`=客户端uuid4、`_nb_ioWEgULi`=空、`aliyungf_tc`=响应下发），
然后 `POST /api/search/chat` 以 `text/event-stream` 流式收「AI综述 + reasoning + 逐条来源（含学术论文元数据）」。
学术scope = 请求体里 `engineType:"scholar"` 一个字符串，**无独立端点、无额外门票**。

## 二、API 交互规约（三段全链）

### 段 1 — 预热（token + Cookie 面）

```
GET https://metaso.cn/                     # curl_cffi impersonate=chrome
→ 200 (SSR HTML)
   <meta id="meta-token" content="wr8+…=="/>   # ★ 152B 服务端签发token，正则即取
   Set-Cookie: aliyungf_tc=<HEX>; Path=/; HttpOnly
自设 Cookie: tid=<uuid4>(domain=.metaso.cn)     # sha256实证==浏览器telemetry里的tid
            _nb_ioWEgULi=                      # 空值（sha256("")实证）
GET https://metaso.cn/api/search-template   # 浏览器同构预热（可省，建议保留）
   → Set-Cookie: JSESSIONID=<HEX>; Path=/api
```

**关键实证**：瘦请求（只有 aliyungf_tc、无 token）服务器仍会建会话但立刻
`data:{"msg":"Too Many Requests","code":429}`（captures/rea_chat_search_capture1.json 对照
probe_http1 实测×2）；补齐 tid+token+预热链后同一 IP 连发全绿——429 是 bot 评分不是配额。

### 段 2 — 检索主端点（SSE 流）

```
POST https://metaso.cn/api/search/chat
Headers: accept: text/event-stream          # ★ SSE
         content-type: application/json
         metaso-pc: pc                       # 自定义头
         origin/referer: https://metaso.cn/…
Body:
{
  "model": "fast_thinking", "stream": true,
  "messages": [{
    "id": "temp-<uuid>", "key": "temp-<uuid>", "conversationId": "temp-<uuid>",
    "role": "user", "content": "<关键词>", "markdownContent": "<关键词>",
    "engineType": "",            # "" = 全网 | "scholar" = 学术（唯一机关）
    "filter": "all", "contentType": 0, "outputHtml": false,
    "mode": "detail", "model": "fast_thinking", "outputStyle": "正常"
  }],
  "engineType": "",              # 与 message 内一致
  "mode": "detail", "filter": "all", "outputHtml": false,
  "outputStyle": "正常", "darkMode": false, "outputLanguage": "中文",
  "htmlNoDisplayEnable": true, "metaso-pc": "pc",
  "token": "<段1 meta-token>"    # 可省（实测过闸）但带上=浏览器同构
}
→ 200 text/event-stream;charset=UTF-8
```

### 段 3 — SSE 事件契约（解析器据此写）

| 事件 | 载荷 | 用途 |
|---|---|---|
| `conversation_init` / `user_message_init` / `response_message_init` | `{"data":{"id":"<雪花id>"}}` | 会话/消息 id；`chat_url=https://metaso.cn/chat/<conversation_id>` |
| `heartbeat` | 空 | 保活（本次 46 事件中 11 个） |
| `chat.completion.qa_with_agent` chunk | `choices[0].delta` | 增量拼装：`action`（如"搜索"）、`reasoning_content`（思考）、`content`（综述正文，含`[[N]]`引用标）、`citations[]`（来源对象数组）、`total_cite_num`（总数） |
| `data:[DONE]` | — | 流终止 |

`citations[]` 单条字段（全网/学术同构，学术多 populated）：`title/orig_title, link, site[], date/publish_date_str, snippet, authors[], institution, article_type(学术论文/期刊/会议论文/Working Paper…), engine, score_base, rank_policy_score, file_uuid, publish_date…`。

**学术scope独立端点验证**：无。`engineType:"scholar"` 同端点同门票，来源即切为
万方/DOI/semanticscholar/期刊 PDF（probe_http3 实测：14 引用全学术论文含作者+机构）。
学术子筛选（中文库/英文库/PubMed/北大核心/中科院分区）走 `filter` 字段，
合法值由 `GET /api/meta-config/by-key?configKey=scholarScope` 下发（all/zh/en/pubmed/北大核心/中科院1区…）。

## 五、剩余墙与边界（如实记录）

1. **开放API key墙**：`POST https://metaso.cn/api/v1/search` 无 key 返回 `errCode:2005`（战役采集腿旧线索）。按 scope.md 不破解，本件走匿名 chat 面等效替代。
2. **匿名日配额未知**：今日本 IP 累计 ~10 次搜索无阻；旧浏览器腿 6 次/日常态。流控纪律（间隔≥5s、单会话≤6 次、429 不硬刚如实上报）已内建复刻件。
3. **model 字段**：`fast_thinking`（免费档）实测可用；其他模型（深度研究等）可能要登录态——未测，超出匿名面授权边界。
4. **chat_url 仅 SSR 壳**：`GET /chat/<id>` 200 但答案为客户端拉取（与侦察一致）；复刻件的 JSON/MD 即最终产物，chat_url 供人复核。
5. **token 生命周期**：meta-token 每次 GET 首页刷新，单值有效期未压测（复刻件每次 warmup 现取，规避过期问题）。
