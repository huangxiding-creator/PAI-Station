[T] CH9329 串口帧格式与校验和算法
[D] lib/protocol.js 定义固定帧 [0x57, 0xAB, ADDR=0x00, CMD, LEN, payload..., SUM]，HEAD1=0x57、HEAD2=0xAB、ADDR=0x00。SUM 为单字节累加和：sum = (0x57+0xAB+0x00+CMD+LEN+Σpayload) & 0xFF，由 buildCmdPacket(command,data) 生成。接收侧 isValidPacket/readPacketFromBuffer 在缓冲区内扫描 0x57AB 帧头、按 LEN 定长，校验和覆盖帧头到 payload 的前 5+LEN 个字节，与 packet[5+LEN] 比对。
--------------------------------------------------------------------------------
[T] CH9329 命令码表与应答帧规则
[D] 主机侧只使用 4 个命令码：CMD_GET_INFO=0x01（获取模块信息，兼作连通探测）、CMD_SEND_KB_GENERAL_DATA=0x02（普通键盘 HID 报文）、CMD_SEND_MS_ABS_DATA=0x04（绝对鼠标）、CMD_SEND_MS_REL_DATA=0x05（相对鼠标）。应答帧命令字节规则：GET_INFO 应答=0x81（RESPONSE_GET_INFO 常量）；普通命令成功应答 = CMD|0x80（如 0x02→0x82），错误应答 = CMD|0xC0（如 0x02→0xC2），waitForCommandResponse 中 okCommand=command|0x80、errorCommand=command|0xc0。NanoKVM 对 GET_INFO 的应答 payload[1]!=0 判为 'HID mount is not ready'。
--------------------------------------------------------------------------------
[T] 相对鼠标 payload 位域（5 字节）
[D] buildRelativeMousePayload(buttons,dx,dy,wheel) 返回 [0x01, buttons, dx, dy, wheel]：首字节 0x01 为相对鼠标报告 ID；buttons 为位掩码 left=0x01 / right=0x02 / middle=0x04（index.js normalizeButton：'right'→2、'middle'→4、其余→1）；dx/dy/wheel 各钳位 ±127，负数经 toUnsignedByte 转补码（value<0 时 256+value）。buildMouseClickPayload(buttons) 即 buttons 置位且 dx=dy=wheel=0 的特例。
--------------------------------------------------------------------------------
[T] 绝对鼠标 payload（12 位 HID 坐标，小端）
[D] buildAbsoluteMousePayload(buttons,x,y,screenW,screenH,wheel) 返回 7 字节 [0x02, buttons, hidX&0xFF, hidX>>8, hidY&0xFF, hidY>>8, wheel]：首字节 0x02 为绝对鼠标报告 ID；hidX=round(x*4096/screenW)、hidY=round(y*4096/screenH)，各钳位 [0,4096]，坐标按小端拆低/高字节（HID 绝对鼠标 0-4095 量程，4096 为钳位上限）；wheel 仍为 ±127 补码。demos 中 absolute-zero 变体以 4096x4096 量程示例。
--------------------------------------------------------------------------------
[T] 键盘 HID 报文结构（8 字节 boot 协议）
[D] buildKeyboardPacketData(modifierMask,keyCodes) 生成 8 字节 [modifierMask, 0x00(保留字节), k1..k6]：标准 HID 键盘 boot 报告，最多 6 个并发普通键码，不足补 0x00（slice(0,6) 后补齐）。keyTap 实现为：发送 (mask,[keyCode]) 报告 → 固定 sleep(50ms) → 发送全零报告 [0,0,0,0,0,0,0,0] 松键。keyToggle 在 JS 侧维护 pressedModifierMask 与 pressedKeyCodes 集合，每次变更调用 syncKeyboardState 整帧重发，保证任意组合键状态一致（AtomS3U 同构：KEY <mask> <k1>..<k6>）。

[T] HID 键码表与修饰键掩码
[D] lib/keycodes.js：字母 a-z = 0x04+(c-'a')；数字 '1'-'0' = 0x1E-0x27；enter=0x28、escape=0x29、backspace=0x2A、tab=0x2B、space=0x2C、'-'=0x2D、'='=0x2E、'['=0x2F、']'=0x30、'\\'=0x31、';'=0x33、"'"=0x34、'`'=0x35、','=0x36、'.'=0x37、'/'=0x38；方向键 up=0x52、down=0x51、right=0x4F、left=0x50。修饰键掩码（HID 位图）：ctrl/control=0x01、shift=0x02、alt/option=0x04、command/cmd/meta=0x08。getKeyCode/getModifierMask/isModifierKey 三个查表函数。

[T] 拟人化随机点击默认参数（60-120ms 随机按住）
[D] index.js normalizeClickOptions：holdMs 未指定时默认 60+Math.round(Math.random()*60) → 60-120ms 随机按住时长；intervalMs 默认 30+Math.round(Math.random()*40) → 30-70ms 连击间隔；repeat 默认 1；nudgePx（钳位 ±127）可选实现'按下时位移 nudgePx、松开时回移 -nudgePx'的微移点击。CH9329/NanoKVM click 流程：发按下帧（CMD_SEND_MS_REL_DATA 带 buttons）→sleep(holdMs)→发松开帧（buttons=0）→连击间 sleep(intervalMs)，整个循环结束后再补一次 sleep(intervalMs)。这是总体结论'点击按住 60-120ms 随机'的确切代码出处。

[T] 串口 moveTo 相对位移闭环与停滞检测
[D] CH9329/NanoKVM 的 moveTo(targetX,targetY,getCursorPos) 为闭环步进：读宿主光标→算 dx,dy→buildRelativeStep 每轴独立 clamp(round(dx),±maxStepPx=25)（轴激活阈值 tolerancePx=2px，取整后为 0 但轴激活时强制 ±1）→发送单步→sleep(stepDelayMs=8/20ms)→再读。停滞检测：本帧距离相对上帧减少不足 0.25px 连续 stallThreshold 次抛 'movement stalled before reaching target'；总时长超 moveTimeoutMs 抛超时。options.onMoveStep 回调逐帧输出 {phase:step/done/timeout, iteration, elapsedMs, target, point, delta, distance, step, stallCount}，供上层做贝塞尔轨迹拟人与审计。

[T] AtomS3U 行文本协议全表（115200 波特）
[D] AtomS3U（M5Stack ESP32+TinyUSB HID 固件）走 115200 波特、'\n' 结尾 ASCII 行协议，命令/应答严格成对：`PING`→`OK PONG`（探测与连接握手，probeTimeoutMs=1200、commandTimeoutMs=800）；`MOVE <dx> <dy>`→`OK MOVE`（钳位 ±127，0,0 直接跳过）；`CLICK <left|right|middle> <holdMs>`→`OK CLICK`（holdMs 由固件侧按住，钳位 0-5000，默认 clickHoldMs=70；另有 clickPreDelayMs=20、clickPostDelayMs=30、clickIntervalMs=80）；`DOWN <btn>`→`OK DOWN`；`UP <btn>`→`OK UP`；`KEY <modifierMask> <k1> <k2> ... <k6>`→`OK KEY`（整键盘状态帧，6 槽补 0，mask/keyCode 语义同 keycodes.js）；`KEYTAP <mask> <keyCode> <holdMs>`→`OK KEYTAP`（默认 keyHoldMs=50）；`RELEASE_KEYS`→`OK RELEASE_KEYS`（急停全松）。错误应答行以 `ERR` 开头，直接作为异常抛出。所有命令经 commandQueue promise 链串行化防交错。

[T] AtomS3U 自适应轨迹步进与增益自校准
[D] 默认 adaptiveMove=true 走 buildAdaptiveRelativeStep：缓动因子 easing=clamp(distance/slowRadiusPx=90,0,1)——距目标 90px 内线性减速；期望逻辑步长=targetStepPx(20)×easing，下限 minTargetStepPx=2；再除以 logicalPxPerHidCount（HID 计数→逻辑像素增益，默认 1）并钳位 [minStepPx=1, maxStepPx=18]。updateLogicalMoveEstimate 用实测比值（逻辑位移/HID 位移，钳位 0.05-8）做 EMA 在线自校准，adaptiveSmoothing=0.35。每步 sleep(stepDelayMs=14ms)；stallThreshold=18 次、moveTimeoutMs=5000ms。legacy 模式（adaptiveMove=false）步长=clamp(ceil(distance/10),1,18)。设备识别：对 path/manufacturer/serialNumber/vendorId/productId/friendlyName 拼串匹配 /atoms3u|m5stack|tinyusb|esp32|espressif|usbmodem|modem|cdc/i；若枚举为 Espressif USB-Serial/JTAG（VID 303a+PID 1001）给出'未刷 TinyUSB HID 固件'的明确提示。macOS 下 /dev/tty.* 自动改用 /dev/cu.* 可呼叫路径。

[T] 鼠标轨迹 generateBezierPath 算法公式(三次贝塞尔+时间缓动+末端抖动)
[D] steps = clamp( floor(dist/40)+floor(random*3), minSteps=5, maxSteps=15 );dist<1 直接跳终点。控制点(每分量独立随机):ctrl1 = start + d*U(0,0.5) + U(-0.5,0.5)*dist*0.2;ctrl2 = start + d*(0.5+U(0,0.5)) + U(-0.5,0.5)*dist*0.2(d 为位移向量)。每步 i=1..steps:t=i/steps → easedT=easeInOut(t) → 代入标准三次贝塞尔 B(easedT)(P0=start,P1=ctrl1,P2=ctrl2,P3=target),即曲线在缓动后的时间轴上取样。easeInOut(t)= t<0.5 ? 2t² : 1-(-2t+2)²/2(二次 ease-in-out)。每点加抖动 jitter=(random-0.5)*1.5 即 ±0.75px(两轴独立),四舍五入取整。轨迹结束后强制 moveMouse(finalX,finalY) 精确落点(抖动不污染终点,保证点中 YOLO 检出的按钮中心)。

[T] 不规则延迟 generateIrregularDelay:Box-Muller 正态 + 停顿/加速双尾巴
[D] z0 = sqrt(-2·ln u1)·cos(2π·u2)(Box-Muller);normalDelay = baseDelay + z0·baseDelay·0.4,即 N(baseDelay, σ=0.4·baseDelay)。再叠两个尾部:10% 概率长停顿 ×(2+U(0,3)) 下限 10ms(模拟人类'看内容');5% 概率快速 ×0.3 下限 5ms;其余 max(5, normalDelay)。鼠标移动 baseDelay 默认 10ms、滚动 15ms。

[T] 滚动 generateScrollSequence:进度递增方差分步+Fisher-Yates 打乱+微移+长停顿
[D] stepCount = clamp( floor(|distance|/10)+floor(random*5), minSteps=8, maxSteps=20 )。步长分配:for i in 0..stepCount-2:variance = 0.3 + (i/stepCount)·0.4(越靠后方差越大);stepSize = (remaining/(stepCount-i))·(1+U(-0.5,0.5)·variance),floor 后 max(1,·);最后一步补满剩余。随后 Fisher-Yates 全打乱步长顺序。每步:scrollY = step·sign(distance)·directionMultiplier;delay = round(irregularDelay(15));30% 概率 microMove=true(执行时鼠标在原位 ±1px 内微移,(random-0.5)*2 两轴);15% 概率(非末步)附加停顿 round(50+U(0,100))ms。directionMultiplier 来自 ScrollDetector:DEFAULT_CONFIG={directionMultiplier:-1, pixelsPerUnit:40, initialized:false},持久化在 electron-store key 'scroll_calibration_config'(用户校准滚轮方向/像素比,校准等待超时 120000ms);humanLikeScroll 每次调用自动合并该系数,默认 -1 表示 Windows 滚轮 deltaY 与内容移动方向相反。

[T] 打字机 typeStringWithDelay:码点分段+均匀延迟+Shift+Enter 软换行,无退格模拟
[D] 分段规则:Array.from(String(text)) 按 Unicode 码点切分(中文单字、代理对 emoji 保持完整;但 ZWJ 序列/组合符会被拆开逐字 typeString,是潜在破坏点)。延迟分布:每字符后 sleep(round(min + random()·(max-min))),默认 min=35ms/max=55ms 均匀分布(biz 侧同名常量 DEFAULT_TYPEWRITER_MIN_DELAY_MS=35/DEFAULT_TYPEWRITER_MAX_DELAY_MS=55 与 helper 端默认一致)。换行:character==='\n' 时改发 keyTap('enter',['shift'])(Shift+Enter=微信软换行,避免误触发送)。isCancelled 在每字符输入前后各检查一次(客户端断连/停止信号即中断)。无退格模拟、无纠错——typewriter.js 全文无 backspace;唯一的 backspace 出现在 mac 输入准备流程(keyTap('space')+30ms+keyTap('backspace')+50ms,用途是唤醒 mac 输入法而非纠错)。biz 调用侧 typeMacTextTypewriter 校验返回值:completed && charactersTyped===Array.from(text).length,不完整则取消发送。超时预算:timeoutMs = max(5000, 字符数·(maxDelayMs+10)+5000)。
