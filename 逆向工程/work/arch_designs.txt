SUBSYSTEM: 数据与画像子系统（总包私域运营台 · zb-data，单机本地 SQLite，本地优先/数据主权）
OVERVIEW: 定位：为"企微官方API为主体 + 个人微信精简版RPA为补充"的混合架构提供统一的数据底座——消息/联系人/群/商机/素材/动作的存储、联系人画像计算、商机台账、频率账本与导出，并内置个保法对齐的治理层（脱敏写入、保留期、删除开关、出网审计）。存储布局：双 SQLite 库（WAL 模式）——core.db 承载长周期台账与审计（contacts/groups/leads/actions/content_assets/quota_ledger/治理表），msg.db（ATTACH 挂载）承载高体量、可整体清洗的内容数据（messages/contact_events/ai_interactions + FTS5 全文索引）；拆双库的原因：保留期清理和"删除开关"可以按文件级完成（redact 后直接 detach/轮换），core.db 备份小而稳定。写入路径唯一：better-sqlite3 跑在 Electron 主进程，RPA helper 与企微连接器一律经 IPC 提交，不直开数据库（单写者，busy_timeout=5000，foreign_keys=ON）。写入即脱敏：手机号/身份证/银行卡在落库前正则替换为占位符，不可逆。逆向参照与差异：识流（E:\AI-Station\逆向工程\extracted\app64\resources\biz\index.js）为云端中心架构——本地只有 ReplayLogger 审计截图（userData/replay）、布局缓存与 hot-versions.json，没有本地业务库；本设计反其道而行（本地优先），但借鉴其 replay 式逐步取证，落到 actions.evidence_path（每个对外动作存 before/after 截图目录）。ER 述（mermaid）：CONTACTS ||--o{ GROUP_MEMBERS }-- GROUPS；GROUPS ||--o{ MESSAGES；CONTACTS ||--o{ MESSAGES；MESSAGES ||--o{ AI_INTERACTIONS（触发）；AI_INTERACTIONS ||--o| ACTIONS（产出）；CONTACTS ||--o{ LEADS；LEADS ||--o{ LEAD_EVENTS（阶段流转留痕）；CONTACTS ||--o{ CONTACT_EVENTS（画像证据，指向 evidence_message_id）；CONTENT_ASSETS ||--o{ MOMENTS_SCHEDULE（排期）；ACTIONS 多态弱引用 trigger_message_id / related_lead_id / related_asset_id / target_contact_id / target_group_id（允许 NULL，审计不因外键缺失断链）；QUOTA_LEDGER 独立按 (日期,类别,scope) 计数，被动作网关在读侧消费。身份模型：contacts 唯一键为 (channel, ext_id)，同一人双通道暂为两行（merged_into_id 支持人工合并，见 open_questions）。与既有资产呼应：用户已有"微信情报库/商机雷达"（本地微信聊天只读检索）——本子系统提供只读导入适配器作历史回填与对账源（只用本人可见数据），商机台账字段（待回复/待复联/承诺跟进）沿用商机雷达的心智模型。

  选型: 夜算 cron（node-cron，每日 03:00）跑聚合 SQL 产出 facets；分类用'规则优先、LLM 抽样复核'降成本（识流的视觉分类整层被砍掉，分类只作用于文本）
  接口: contact_tags(id, contact_id FK, facet('activity'|'domain'|'engagement'|'stage_suggest'|'risk'), value, confidence, basis_json 证据计数与消息id样本, computed_at, expires_at 如 activity 7天/ domain 半衰期90天)；汇总快照写回 contacts.profile_json。产出定义：activity=近30天发言频次+趋势→active/normal/quiet/silent；domain=taxonomy(造价|招标投标|EPC管理|施工技术|资质|材料价格|其他) top3；engagement=被回复后是否再回应/是否私聊过（企微侧含链接点击）；stage_suggest 规则示例：问价或要方案→qualified，多轮追问→nurturing；risk=广告号/竞对启发式

[FLOW] 历史回填（情报库数据源）：import_sources 登记 → 只读遍历本人可见聊天（rion-wechat-cli/情报库能力）→ 走同一 scrub 管道以 backfilled=1 写入 messages → 事后触发一次全量画像重算；该源亦用于周期性对账（发现 UIA 漏读的消息）
[FLOW] 治理流：每日 04:00 retention job 按策略 redact 过期内容 → 月度 VACUUM；用户在面板触发删除开关 → deletion_requests → 执行器事务内（匿名化联系人+redact 消息+清 FTS+写 actions(action_type=data_deletion)）→ 标记 executed_at
[FLOW] 导出流：每周一 08:00 生成商机周报（新增/变阶段/待跟进/互动Top/我方动作效果/建议动作）→ exports/YYYY-Www.xlsx；每日 09:00 刷新朋友圈 14 天排期表 → exports/moments_plan_14d.csv；两者均记 actions 审计
[RISK] UIA 读取没有服务端消息 ID，dedupe_key（分钟桶+内容哈希+发送者）是启发式：同分钟同内容不同消息可能误并、跨分钟重读可能漏并——需 scan_cursor 前移保守化 + 借情报库源周期对账兜底
[RISK] actions 先写 attempt 再执行的两段式：执行进程崩溃会留下 outcome 为空的行——语义上可接受（审计如实），但报表需区分'尝试'与'成功'计数
[RISK] FTS5 中文检索默认分词不可用：必须 trigram 或外置分词，且 rebuild 在大库上有耗时窗口（安排在保留期 job 之后低峰执行）
[RISK] 脱敏正则存在变体漏检（带空格/分隔符的手机号、位数变形）：二次扫描任务只是兜底不是根治，残余 PII 风险要在文档明示
[RISK] msg.db 无界增长：若用户关闭保留期（retention_policy.enabled=0），一年行业群量级约百万行仍可控，但截图/附件目录必须单独限额（30天硬清理）
[RISK] better-sqlite3 是原生模块，Electron 升级需按 ABI rebuild，版本锁死要与发布流程绑定
[RISK] 画像 taxonomy 若与总包智库目录不一致会导致 domain 标签返工：taxonomy 变更需触发 contact_events 的 domain 重映射（成本可控但要有迁移脚本）
[RISK] 同一自然人双通道（个人微信 wxid + 企微 external_userid）在 contacts 是两行：画像与商机暂不自动归并，merged_into_id 仅人工——统计口径可能出现重复计数
[RISK] LLM 出网 unavoidable（问题摘录发往云端模型）：outbound_excerpt 审计列让出网可查，但若用户要求零出网需切本地 GLM，成本结构改变

SUBSYSTEM: 部署与运维子系统（总包私域运营台 · 单机 Windows 常驻）
OVERVIEW: 单机 Windows、双会话边界是本子系统的第一设计约束：凡需要读写微信桌面客户端 UIA 树的进程（主服务、RPA worker、托盘看护）必须运行在用户交互式桌面会话（Session 1+），绝不能注册为 Windows 服务——服务会话（Session 0）无桌面访问权，UIA 直接失能，这条必须写进部署文档并作为验收项；唯一适合装成 Windows 服务（nssm 托管）的是纯网络转发进程：企微回调隧道（cloudflared 或 frpc），它不需要桌面。进程模型 3+1：zp-supervisor（托盘看护）→ zp-core（Node 主服务）+ zp-rpa（Python UIA 工作进程）+ cloudfrp（隧道服务）。RPA worker 与主服务的隔离通信直接复刻逆向出的识流 helper-win 契约（127.0.0.1 HTTP + Bearer token + ppid 2 秒看门狗，见 E:\AI-Station\逆向工程\extracted\app64\resources\helper-win\main.js）；升级策略刻意不抄识流 electron-updater 的 autoDownload+autoInstallOnAppQuit 全自动热更（见 E:\AI-Station\逆向工程\extracted\app64\resources\app-update.yml），改为维护窗口+版本目录+junction 切换+双版本回滚，因为单机系统要的是可回滚而非无人值守。端口规划（全部仅本地监听）：58560=supervisor 控制口、58561=core 健康口、58570=RPA 工作口（token 鉴权）、58080=企微回调端点（隧道对外）。目录统一 C:\zp-ops\{app,config,data,logs,versions,backup,config_history}。会话与电源：专用标准用户+sysinternals Autologon（凭据入 LSA）+永不锁屏永不休眠+BIOS 来电自启+任务计划"仅当用户登录时"启动 supervisor；主理人经远程桌面完成朋友圈人工确认与扫码类处置。告警只经"运维专用企微群机器人 webhook"单向发出，绝不走个人微信 RPA 通路（结构上杜绝递归），失败降级邮件+本地 toast+alerts.log 兜底。敏感信息（API key/webhook/隧道凭据）用 Windows DPAPI 按用户加密存 secrets.dat，非密配置 config.yaml 明文+每次变更快照可回滚。微信客户端关闭自动更新并锁版本，UIA 选择器适配层独立成热更模块。自愈目标：断电重启后无人干预 5 分钟内全链路回到就绪；RPO≤1h、RTO≤30min。

[COMP] zp-supervisor（托盘看护进程）
  职责: 进程树总管与安全开关。开机按序拉起 zp-core、zp-rpa、探测 cloudflared；子进程存活/心跳监控，崩溃按指数退避重启（30s→2min→10min），连续5次失败自动转只读降级并告警；承载一键熔断三入口：全局热键Ctrl+Alt+F12、托盘菜单、磁盘开关文件 C:\zp-ops\KILL.switch（任何人创建该文件即全系统2秒内停止RPA动作）；编排升级drain→staging→切换→回滚；触发日志轮转与备份。必须运行在交互式桌面会话。
  选型: Node.js 22 LTS 打包单exe（Node SEA）；托盘用systray轻量库；由任务计划程序拉起（触发器=用户登录、勾选仅当用户登录时运行、失败1min后重启），不用HKCU Run键也不用Windows服务。
  接口: 入口：任务计划（登录触发、延迟30s）；本地控制API 127.0.0.1:58560（token鉴权，start/stop/status/drain/rollback）；监听 KILL.switch 文件与全局热键；出：按序spawn子进程并注入token；托盘菜单与状态色。

[COMP] zp-core（主服务，Node）
  职责: 业务编排中枢：企微回调事件接入并先持久化再处理（防隧道重投丢事件）；RPA上报的个人微信消息进同一管线；AI答疑与智库推荐调用总包AI顾问；出站动作统一频控、排队、审计打点；朋友圈素材定时生成任务；维护窗口与降级态管理；健康指标暴露。
  选型: Node.js 22 LTS，Fastify（本地监听）；better-sqlite3；node-cron做内部调度；无头运行在用户会话（supervisor子进程），绝不装成服务。
  接口: 入：127.0.0.1:58080 企微回调（先落库再ack）；127.0.0.1:58561 本地health/metrics/drain；出：调zp-rpa 58570、调总包AI顾问HTTP API、发运维告警webhook、读写SQLite(WAL)。
------------------------------------------------------------------------------------------
[COMP] zp-rpa（UIA工作进程，Python）
  职责: 个人微信侧唯一执行体：UIA无障碍树直读会话列表与消息文本（新消息事件化上报）；响应式回复输入（剪贴板写入→Ctrl+V→恢复剪贴板，动作间随机化间隔）；朋友圈半自动辅助发布（素材core生成、主理人远程桌面人工确认后辅助执行，设计为幂等三段：贴→停→人工点发，系统永不自动点发）；微信客户端健康探测（主窗存在性、掉线二维码识别）；每动作记录审计上下文。单实例锁。
  选型: Python 3.12 + uiautomation/pywinauto（wxaco已验证的UIA3路线）+ mss截图；进程间通信复刻逆向出的识流helper-win契约：127.0.0.1 HTTP + Bearer token + ppid看门狗每2秒（参照 E:\AI-Station\逆向工程\extracted\app64\resources\helper-win\main.js）。不做驱动级输入、不做硬件HID。
  接口: 入：127.0.0.1:58570，POST {action,args}，Authorization: Bearer <token> 或 x-helper-token 头；出：消息/健康事件上报zp-core、动作审计写rpa-audit.jsonl、必要截图存data/replay/{date}/。

[COMP] cloudfrp（企微回调隧道，唯一Windows服务）
  职责: 把单机动态IP后的本地端点暴露为固定公网HTTPS地址，满足企微自建应用回调的可信域名要求；隧道故障不影响个人微信RPA侧（两通路独立）。纯网络转发、无桌面依赖，是全系统唯一允许注册为Windows服务的进程。
  选型: 首选Cloudflare Tunnel（cloudflared，需一个自有域名，免公网IP免端口映射）；备选frp+便宜VPS；经nssm注册为服务并配自动重启。
  接口: 入：公网 https://回调域名/ → 本地127.0.0.1:58080；nssm负责崩溃自动重启；连通性探测结果上报supervisor。

[COMP] 配置与密钥管理
  职责: 分层：非密配置config.yaml（功能开关、频控参数、会话白名单、维护窗口、UIA选择器适配层定义）；敏感凭据secrets（企微corpid/secret、AI key、隧道凭据、RPA token）单独存放；一切变更全量留痕、可回滚到任意历史版本。
  选型: secrets用Windows DPAPI（CryptProtectData，当前用户scope）加密为secrets.dat（Node用win-dpapi、Python用win32crypt），文件ACL仅本用户；config.yaml明文+每次变更快照带sha256清单。不用明文.env存密。
  接口: core各模块经统一config库读取（启动加载+监听变更热生效）；secrets解密仅发生在进程内存；每次变更复制到config_history/{ts}-{sha256}.yaml；备份任务对config目录整体快照。

[COMP] 监控告警中心
  职责: 指标采集（进程心跳、微信在线、隧道连通、磁盘水位、动作成功率滑窗、SQLite完整性周检）；告警分级P1熔断/微信掉线、P2隧道断/连续动作失败、P3磁盘与备份异常；防风暴：同主题15分钟聚合去重、每小时上限N条超限只发摘要；与个人微信RPA通路物理隔离，杜绝告警触发被自己处理的递归。
  选型: core内嵌告警模块（不独立成进程，减少守护面）；出口：企微群机器人webhook（专用运维群，单向）→ 失败降级SMTP邮件 → Windows toast + alerts.log兜底。
  接口: 入：core/rpa/supervisor的告警事件（本地HTTP或日志钩子）；出：企微群机器人webhook、SMTP、Windows toast、C:\zp-ops\logs\alerts.log兜底持久层。

[COMP] 日志与审计
  职责: 三类分离：app.log运行日志（INFO起可调DEBUG）；rpa-audit.jsonl追加式审计（每个RPA动作记录时间/目标会话/动作类型/触发原因/结果/关联消息id，文本脱敏）；replay截图仅排查期按需开启；轮转按日+大小双限，app留90天、审计压缩留180天，磁盘水位85%时加速清理。
  选型: Node侧pino + pino-roll；Python侧loguru（rotation内建）；审计jsonl统一schema两端共用；截图JPEG按日期目录。
  接口: core/rpa/supervisor经统一logger写入；审计jsonl双写SQLite索引表供台账查询；备份任务按计划打包logs与data。

[COMP] 数据存储与备份
  职责: 单文件业务库zp.db：联系人/群/消息索引/线索台账/画像/审计索引，WAL模式；三级备份：每小时在线热备、每日03:30全量+zstd（滚动保留7日+4周）、配置每次变更即时快照；每周一次人工触发异地备；每季度真实恢复演练（目标RPO≤1h、RTO≤30min）。

  接口: core经better-sqlite3同步访问；备份器用SQLite在线backup API读不阻塞写；恢复用documented脚本restore.ps1+演练清单。

[COMP] 升级管理（双轨）
  职责: 轨道A数据热更新免重启：话术/SOP/知识库引用/频控参数/UIA选择器适配层均为数据文件，改动即热生效——适配层单列因为微信版本升级主要破坏的就是选择器，必须能不动代码快速修补；轨道B整体更新：仅维护窗口（默认04:00-06:00）且无在途RPA动作时执行，下载→sha256+签名校验→解到versions/v{ts}/→drain排空在途回复→切换current junction→滚动重启→冒烟自检，保留最近2版本一键回滚。
  选型: 版本目录+NTFS junction指向current（原子切换、秒级回滚）；升级包sha256+签名校验；刻意不用识流的electron-updater autoInstallOnAppQuit全自动热更（见 E:\AI-Station\逆向工程\extracted\app64\resources\app-update.yml），单机要可回滚不要无人值守。
  接口: 读versions/目录与manifest；切换后经supervisor滚动重启进程树；适配层热更只触发rpa worker模块重载，不重启微信。

[COMP] 健康检查体系
  职责: 四层探活：进程层（supervisor对子进程pid+心跳，2s粒度）；依赖层（微信客户端：进程存活+UIA主窗可见+无掉线二维码，60s粒度，掉线属P1需人工扫码，系统只告警暂停不自动处理）；网络层（隧道出口探活、企微API可达性，5min粒度）；资源层（磁盘水位、库完整性周检）。微信不在线时RPA自动进入静默等待而非反复重试。

  接口: 对core/rpa的/health探测；对cloudflared服务状态探测；对微信的UIA探测经rpa worker代理执行；结果驱动托盘状态色与告警中心。

[COMP] 会话与电源管理（开机自启链）
  职责: 固化UIA运行的会话前提：专用标准用户+sysinternals Autologon（凭据入LSA非注册表明文）实现断电重启后无人干预回到桌面；永不锁屏、永不休眠、显示器可关（UIA不需要亮屏但需要未锁桌面）；BIOS设置来电自启；远程管理通道（ToDesk或RDP）供主理人异地确认朋友圈发布与处置扫码。物理安全由BitLocker+可控环境补偿。
  选型: Autologon for Windows（sysinternals）；powercfg锁定电源计划；组策略/注册表钉死Windows活动时间到凌晨与维护窗口重合，避免白天强制重启；ToDesk/RDP开二步验证。
  接口: 构成开机到全链路就绪的入口链：BIOS/电源策略→自动登录→任务计划→supervisor→子进程；远程桌面通道供主理人完成朋友圈人工确认与扫码类处置。
[FLOW] 开机到就绪链路：BIOS来电自启→Windows自动登录→桌面加载→任务计划延迟30s启动zp-supervisor（微信自身开机自启已在跑）→supervisor依次探测cloudflared服务、拉起zp-core、zp-rpa→rpa上报微信在线→core发就绪心跳到运维群→托盘转绿色。全程目标：无人干预5分钟内自愈到就绪。
[FLOW] 崩溃自愈流：子进程心跳丢失→supervisor分类（可重启崩溃vs配置/权限类致命错）→可重启类按30s/2min/10min指数退避重启并计数→连续5次失败：停止重启、系统转只读降级（RPA停、企微侧只收不发）、P1告警→人工经托盘或远程桌面处置后一键恢复并清零计数。
[FLOW] 微信离线处置流：rpa健康探测发现UIA主窗消失→三分支：进程崩溃（自动重启微信进程并等窗口回归，最多2次）；账号掉线出现二维码（不自动扫码：P1告警+RPA暂停，主理人手机确认或远程桌面扫码）；仅失焦（不处理）→恢复在线后自动回到工作状态，全程审计留痕。
[FLOW] 告警递送流：任意子系统产生告警事件→告警中心分级+同主题15分钟聚合→经运维企微群机器人webhook单向发出（与个人微信RPA通路物理隔离，结构上不可能递归）→3次投递失败降级SMTP邮件+Windows toast→兜底永远先写alerts.log（出口全挂仍有本地凭据）→每小时上限熔断防风暴。
[FLOW] 一键熔断流：人工按热键/托盘菜单/创建KILL.switch文件→supervisor广播停机令→zp-rpa 2秒内停止一切输入并退出当前会话操作→zp-core转只读（继续收消息入台账但不回）→熔断状态托盘置顶红色+P1告警通知主理人→恢复需托盘菜单二次确认防误触→全程状态变化写审计。
[FLOW] 升级流双轨：轨道A（适配层热更）——替换选择器数据文件→rpa worker重载模块→对当前微信窗口做一次只读UIA树校验→通过即生效，失败自动回退旧适配层并转只读告警。轨道B（整体更新）——维护窗口到期或人工触发→检查无在途RPA动作（有则顺延）→下载升级包→sha256+签名校验失败即中止告警→解压到versions/v{ts}/→逐进程drain排空在途回复→切换current junction→滚动重启→冒烟自检（微信在线探测、回调自ping、RPA dry-run）→失败自动切回上一版本并告警。
[FLOW] 备份与恢复流：每小时整点在线热备zp.db→每日03:30全量备份+zstd→配置每次变更即时快照config_history→每周主理人手动触发异地备（百度网盘通道或外置盘）→季度恢复演练：停core→以最近好备份还原zp.db→用config_history对齐配置→起core→核对台账计数与审计流连续性→记录RTO/RPO实测值。
[FLOW] 首次部署清单：(1)机器与账户：专用标准用户+强口令、BitLocker开、Autologon、电源计划永不休眠永不锁屏、BIOS来电自启、Windows活动时间钉到凌晨；(2)目录与权限：建C:\zp-ops\七目录结构、ACL限本用户；(3)微信客户端：装锁定版本、关闭自动更新、设开机自启、登录一次并勾选记住；(4)装nssm并注册cloudflared服务、配隧道域名；(5)写config.yaml与secrets（DPAPI加密）；(6)任务计划建supervisor登录触发项；(7)企微管理后台：自建应用回调URL与可信域名、运维群机器人webhook；(8)验收测试：熔断测试（建KILL.switch→RPA 2秒内停）、断电重启演练（来电→5分钟自愈）、备份恢复演练、告警全链路测试（含webhook失败降级邮件）、升级回滚演练；(9)交付runbook文档（含故障预案表、恢复脚本用法、各目录说明）。
[RISK] 微信客户端自动升级破坏UIA选择器（最高频故障源）｜症状：树校验失败率突增或找不到控件｜预案：部署时关闭微信自动更新并锁版本；适配层为独立热更模块，微信升级必须走先更适配层再升微信的受控流程；适配层校验失败自动回退旧层并转只读。
[RISK] RPA相关进程被误装成Windows服务（Session 0隔离）｜症状：服务显示运行中但UIA全部超时失败｜预案：部署文档以红字写明supervisor/core/rpa只能跑在交互式桌面会话，全系统唯一服务是cloudflared；验收清单含UIA冒烟测试必过。
[RISK] 微信账号掉线出现二维码（无法也不应自动处理）｜症状：UIA探测到登录二维码｜预案：P1告警+RPA自动暂停，主理人手机确认或远程桌面扫码；期间企微侧不受影响继续服务；恢复后自动续跑并审计留痕。
[RISK] Windows强制更新重启打断在途动作｜症状：动作半途中断、会话可能停在输入框状态｜预案：活动时间钉到凌晨与维护窗口重合；Autologon+任务计划保证重启后5分钟内全链路自愈；审计流标记中断动作，恢复后不自动重发（宁可漏发不重发骚扰）。
[RISK] 告警递归或风暴｜症状：告警触发更多事件形成回环或单点故障刷屏｜预案：告警唯一出口是运维企微群机器人webhook（单向、RPA永不操作该群）；同主题15分钟聚合+每小时上限+超限摘要；alerts.log兜底确保出口全挂时仍有本地凭据。
[RISK] SQLite库损坏（断电/磁盘错误）｜症状：database disk image is malformed｜预案：WAL+常规检查点；小时级热备链；恢复脚本取最近好备份还原，缺口窗口用审计jsonl重放补台账；季度演练保证恢复流程真实可用。
[RISK] 磁盘写满（日志/截图/备份堆积）｜症状：写入失败、微信客户端卡顿｜预案：日志按大小+天数双限自动清理；replay截图默认关、排查期限额；85%水位告警+自动加速清理；备份目录滚动保留。
[RISK] 隧道中断（企微回调失联）｜症状：企微侧停收、个人微信侧不受影响｜预案：nssm自动重启cloudfrp隧道；3次失败P2告警；事件先落库设计保证隧道恢复后企微重推不丢不重；极端情况临时切手机热点出口。
[RISK] 自动登录凭据暴露（物理接触机器）｜风险：单机含客户数据与微信会话｜预案：BitLocker全盘加密；机器置于可控物理环境；Autologon凭据存LSA非注册表明文；远程通道开二步验证；审计日志记录本地登录事件。
[RISK] 熔断开关误触发｜症状：KILL.switch被误建、系统静默停｜预案：熔断状态托盘置顶红色+P1告警（不会unnoticed）；恢复需二次确认防误操作；开关文件路径写入runbook便于人工排查。
[RISK] 备份从未验证不可恢复（最隐蔽风险）｜症状：出事才发现备份损坏或流程不会用｜预案：季度真实恢复演练列入运维日历并记录RTO/RPO实测；备份完成时做zstd测试解压+SQLite integrity_check。
[RISK] 朋友圈辅助发布中途失败（半自动流断在输入半途）｜症状：文案粘贴了但未发出｜预案：该流程本就人工确认制，设计为幂等三段（贴→停→人工点发），系统永不自动点击发布；中断即告警提示主理人手动收尾。
[RISK] 主服务内存泄漏长期运行劣化｜症状：core RSS缓慢上涨、响应变慢｜预案：supervisor每日维护窗口主动优雅重启core（drain后重启，RPA无感）；内存水位超阈值即时告警提前重启。

SUBSYSTEM: 个人微信精简版RPA子系统（总包私域运营台 · wx-rpa）——最敏感子系统，护栏优先，分级放权
OVERVIEW: 定位与总原则：本子系统是运营台中唯一触碰个人微信桌面客户端的执行器，设计立场是"感知强、执行弱、人工可介入"：只做响应式动作（被@/关键词求助/白名单私聊），低频+可一键熔断+全量审计；与主台（企微官方API路线）进程隔离，本子系统崩溃或被熔断不影响主台。落地采用三阶段放权：Phase 0 影子期（只读感知+生成草稿+审计，零输入动作，跑2周基线）→ Phase 1 辅助期（人工逐条批准后才执行粘贴；朋友圈半自动填充）→ Phase 2 受限自动期（仅@提及与私聊白名单免批自动答，收紧限额）；任何阶段可一键降级回上一阶段。

关键实测证据（2026-10-12本机，Weixin 4.1.8.107，安装于 C:\Program Files\Tencent\Weixin，正在运行，主窗口 pid=17340 class=Qt51514QWindowIcon name=微信）：用 System.Windows.Automation 分别以 ControlViewWalker 与 RawViewWalker 遍历主窗口，两种视图均只返回1个不透明Window节点、零子节点、无AriaRole——即该版本主窗口当前不向UIA暴露任何会话列表/消息内容。这推翻"4.x直接UIA直读"的乐观假设，但不推翻架构：感知层做成适配器（UIA为主选，微信3.9.x全树可用；4.x降级为本地OCR固定区域识别；另配只读本地DB做台账补充），启动自检自动判定后端并上报，禁止静默假装可用。4.x下Phase 2自动发送默认关闭，直至感知+校验可靠。

技术选型对比（worker语言）：① python uiautomation/pywinauto——微信自动化社区事实标准（wxauto生态围绕其维护3.9.x选择器），COM直调UIA，低频场景性能足够，PyInstaller打包，LLM栈亲和；② C# UIA——UIA事件性能与COM控制力最强，适合事件驱动高频场景，但开发成本高、与现有栈割裂；③ node+windows-foreground——与Electron主台同语言、可直接复用逆向出的粘贴流程代码，但微信选择器社区积累在Python侧。结论：worker用Python（uiautomation+pywin32+pillow+本地PaddleOCR），IPC照抄逆向验证过的 helper-win/main.js 模式（127.0.0.1随机端口+Bearer token+ppid看门狗2s自杀），即"主台 ⇄ localhost HTTP+token ⇄ RPA worker(Python)"。UIA事件vs轮询：选轮询（3-8s抖动），理由：Qt/mmui类框架几乎不发可靠UIA事件、COM事件回调在Python有死锁风险，参照产品同为轮询+红点检测（biz/index.js的unread_detected/poll循环）。

对参照产品（识流，逆向产物位于 E:\AI-Station\逆向工程\extracted\app64\resources\）的取舍：不继承——wyhkm.dll/wyhr.dll驱动级输入（lib/wyhkm-dll.js的FFI全套）、CH9329/AtomS3U/NanoKVM硬件HID四后端（robot/index.js）、云端YOLO布局检测与豆包视觉后验、整套拟人军备；保留借鉴——剪贴板粘贴闭环（biz/index.js的pasteTextViaClipboard：备份→写入→readText回读校验→300-500ms随机延时→Ctrl+V→恢复并校验，支持中止信号）、"不前台拉起"原则（其代码注释：忽略前台拉起调用以避免触发截屏风控）、reply_mode可切换（auto/人工）、ReplayLogger式逐步事件审计（但默认不存截图，仅失败可选存并限期清除）、发送键模式探测（单Enter/Ctrl+Enter兼容）。

"永不做"清单（硬编码进GuardrailCore，任何配置不可解锁）：1) 不自动点赞/评论/回复他人朋友圈；2) 不做未经人工确认的全自动朋友圈发布（系统最高权限是"填充后停在发表按钮前"，发布点击永远归人）；3) 不主动私聊陌生人、不群发批量营销；4) 不自动加好友/拉群/改群公告；5) 不对白名单以外会话做任何动作（读取也仅限白名单群）；6) 不绕过或自动处理微信风控验证（验证码/滑块/短信一律停机转人工）；7) 主理人正在用机时（GetLastInputInfo近120秒有键鼠输入）不抢焦点不抢键盘，动作推迟；8) 20:30-08:30不执行任何输入动作；9) 重启后不回放积压消息批量补发；10) 不向云端LLM发送真实昵称/手机号等身份字段（编号化）；11) 不伪装人类——被问是否AI必须承认（写入Advisor提示词）。

SUBSYSTEM: 合规护栏子系统（Guardian）— 横切企微官方API / 个人微信UIA-RPA / 朋友圈半自动辅助三条通道的统一强制层
OVERVIEW: 设计原则：护栏不是散落在业务代码里的检查集合，而是一个独立的 Policy Decision Point——名为 Guardian 的独立本地进程，持有全部对外动作的唯一放行权。三条通道（企微API、个人微信RPA执行器、朋友圈辅助发布）的每个对外动作必须先取得 Guardian 签发的一次性 permit（HMAC 签名，绑定内容哈希+通道+对象+epoch+短TTL），执行器逐动作验签、并在不可逆步骤（回车/点击发送）前复核熔断 epoch。固定决策管线顺序：①急停状态检查→②免打扰/节流日历→③内容审核闸门→④频率限制扣减→⑤人工确认路由→⑥落审计intent并fsync后才签发（no log no permit 不变式）。架构取舍直接取自本次逆向结论：继承识流已验证的 helper-win 进程隔离模式（127.0.0.1+token+ppid双向看门狗，见 extracted/app64/resources/helper-win/main.js）与每动作留痕的 ReplayLogger 思路，但修复其四个结构性缺陷——bundle内敏感词/审核/过滤词零命中（无内容闸门）、reply_mode默认auto（无人审默认）、ReplayLogger可一键清理且非append-only（审计可篡改）、stop为散布全码的协作式软停（非fail-closed）。进程拓扑附加一条结构性保证：RPA执行器进程被OS防火墙完全禁外网，唯一socket是Guardian loopback——输入路径在结构上不可能外传数据。诚实边界：单机单操作者场景下，护栏的设计目标是防bug、防行为漂移、保证留痕可追责，不是对抗机器所有者本人；所有配置修改均版本化+审计留痕以提高可见性，而非技术阻断。

[COMP] Guardian 护栏网关(permit 机制, 强制基座)
  职责: 全系统唯一对外动作放行口与决策管线编排者。对外动作定义 = 任何经由三条通道发出的消息/请求/发布。决策管线固定顺序①至⑥不可重排; 每步判定写入 decision_path 随 intent 记录落盘。permit 一次性(nonce防重放)、短TTL默认90秒、绑定 sha256(最终发送内容)。【强制点】编排器到执行器之间物理上无第二条通路; 执行器除心跳与outcome上报外无任何被允许的写操作。
  选型: 独立 Node.js 进程(WinSW 注册为 Windows 服务, 开机自启); 127.0.0.1 HTTP+token(继承逆向出的 helper-win 模式但反转信任方向: 不是 helper 信任调用方, 而是执行器必须持 Guardian 签发的 permit 才动作); 状态存 SQLite(better-sqlite3); HMAC-SHA256 密钥仅 Guardian 与执行器持有。
  接口: REST(仅loopback): POST /v1/permit/request, /v1/permit/revoke, /v1/risk-signal, /v1/heartbeat, /v1/audit/outcome, GET /v1/state。【绕过难度: 高】绕过需改执行器代码或伪造HMAC签名; 每分钟对账任务(outcome无对应intent即视为绕过信号, 自动熔断告警) + 审计哈希链断链检测使静默绕过必然留痕; 对机器owner不设防(明示边界)。

[COMP] G1 频率限制器(令牌桶, 四维)
  职责: 四层维度: 通道级(个人微信默认每小时30条、每天150条; 企微按官方接口限额镜像)、对象级(每群每小时2次回复且仅响应式触发)、会话级(同一会话两条回复最小间隔约120秒加jitter, 克制不刷屏)、动作类型级(加好友/主动私信/朋友圈协助发布各自独立桶)。桶状态 SQLite 持久化, 重启不清零, 封死重启即绕过的口子; 配置热加载且变更本身写审计。【强制点】决策管线第④步, 同步扣减, 扣减失败即拒绝; permit 一次性防重放。

  职责: 发送前全量过闸(文本/表情包文案/朋友圈文案; 图片仅允许注册过的模板资产, 用户提供图片一律转人工)。三级词库: 一级硬阻断(涉政涉法涉黄暴恐、诈骗推广、广告法绝对化用语如 最/第一/国家级/100%); 二级工程行业承诺类禁用语(保证中标/包过/包验收/终身免费/绝对安全零事故/资质挂靠/围标串标话术, 阻断或强制人工); 三级提示级(报价/工期/责任表述、夸大修辞, 转人工确认)。词库本地、版本化、SHA-256清单固化。逆向已验证: 识流 bundle 内敏感词/审核/过滤词零命中且 reply_mode 默认 auto —— 这是本系统与参照物的核心差异点。【强制点】决策管线第③步, 先于频率扣减(被拒内容不消耗令牌); LLM 二审只允许升严、永不放行硬阻断。

[COMP] G4 审计日志(append-only 哈希链)
  职责: JSONL 按天分片 + SQLite 索引。每个对外动作两条记录: intent(Guardian 签发 permit 前 fsync 落盘, 含时间/通道/对象/动作类型/全文内容/决策依据=各护栏判定明细/permit_id)与 outcome(执行器回报成败+发送后UIA回读校验结果)。对账任务巡检 有outcome无intent 即绕过信号, 自动触发熔断告警。防篡改: 记录间哈希链(每条含 prev_hash), 每日锚定根哈希导出; 启动验链, 断链即告警。保留: 内容全文90天后转哈希+元数据, 索引180天, 事故事件截图30天。对比逆向产物: 识流 ReplayLogger(MAX_SESSIONS=5/EVENTS_PER_SESSION=200/JPEG60)每步双截图且可一键清理 —— 留其每动作留痕思路, 去其可篡改与PII超采。【强制点】无日志不签发: intent 先于 permit 写盘是签发前置条件; outcome 是执行器除心跳外唯一被允许的写操作。

  接口: append(type,payload), verifyChain(), reconcile(), retention sweeper; 控制台审计检索UI(按通道/对象/时间/结果过滤)。【绕过难度: 高(对进程内逻辑)/中(对文件系统)】owner 可删文件但验链会在下次启动检出断链; 可选异机备份根哈希(仅哈希不含PII, 可上云)。

SUBSYSTEM: 企业微信主通道子系统（总包私域运营台·合规主干）
OVERVIEW: 【核实方法说明】WebSearch 后端配额耗尽（2026-10-26 重置），改用更强的方式：直读企业微信开发者中心官方文档正文（通过文档站 docFetch API 拉取 18 篇现行文档，含 2025-08 更新的"消息推送"与 2026-10-11 更新的"智能机器人长连接"），以下所有能力/限制均出自官方文档原文，非二手记忆。

【已核实的 2025-2026 关键现状】
1. 群机器人 webhook（已更名"消息推送"，2025-08 更新）：只发不收；每机器人 ≤20条/分钟（超限 errcode 45009）；支持 text(≤2048字节)/markdown(≤4096字节)/image/news/文件(upload_media，media_id 3天有效)；text 支持 @成员。API 文档树中不存在"客户群机器人"原语——客户群不能挂 webhook 机器人。
2. 智能机器人（2025-2026 最重要的新能力，长连接文档 2026-10-11 仍在更新）：支持"API 模式"，两种接入——Webhook 回调（需公网 URL+加解密）或 WebSocket 长连接 wss://openws.work.weixin.qq.com（无需公网 IP、无需加解密、官方 aibot-python-sdk/aibot-node-sdk）。触发方式：群里@机器人 或 单聊发消息（群聊支持 text/图文混排/引用；image/语音/文件/视频仅单聊）。支持流式回复（stream.id+finish=true，10分钟内完成）——天然适配 LLM 流式输出。频率：每会话 30条/分钟、1000条/小时；收到消息后 24 小时内可回复；用户发过消息后可 aibot_send_msg 主动推送(markdown/模板卡片)。每机器人同时仅 1 条长连接（新连接踢旧连接，有 disconnected_event），心跳 30s。from.userid 可能是密文 open_userid，需自建应用 batch/openuserid_to_userid 转明文。发送者身份均为企业成员（是否可进客户群未见任何 API 迹象，待实测）。API 模式机器人还内置 MCP 文档/智能表格工具并可接 OpenClaw。
3. 自建应用回调：URL/Token/EncodingAESKey(43位)；GET echostr 验证（1秒内回明文）、POST 签名+AES 密文；access_token 按应用独立、7200s、须缓存。
4. 客户联系：新客户欢迎语 send_welcome_msg 的 welcome_code 仅 20 秒有效且只能调一次（多应用竞速 41096/41051）；入群欢迎语素材库全企业 ≤100 条（%NICKNAME% 变量）；企业群发 add_msg_template 不直接发送、须成员客户端确认，每客户/每客户群每月接收上限=当月天数（可在群发助手调整为每周7条/每天1条），仅推给最后互动成员；JS-SDK shareToExternalChat 同一成员每日对同一客户群最多 1 条。
5. 客户朋友圈：企业发表 add_moment_task（text≤2000字/4000字节；9图 或 1视频≤30s/10MB 或 1链接；visible_range 按成员/部门/客户标签；异步 jobid→get_moment_task_result；企业侧 10次/分钟、10万次/月；任务推给成员在客户端确认发表）；JS-SDK ww.shareToExternalMoments 拉起发表框预填内容由成员手动点发（半自动）。前提：自建应用配进"可调用应用"、成员在客户朋友圈使用范围、具备客户联系与外部沟通权限。
6. 会话存档：官方 C SDK v3.0（2025-02-13，openssl3.0，Linux x86/arm+Windows）；流程 init→按 seq 分页拉取→RSA 解密 random_key→AES 解密→拉媒体；外部客户需同意（"同意会话聊天内容"消息类型+同意事件回调）；开通需付费订阅（价格未写在文档，以后台为准）。
7. 微信客服：回调 kf_msg_or_event→sync_msg 读消息→kf/send_msg 发送；仅当微信客户主动发消息后 48 小时内可发、最多 5 条（用户再发重新计数）；自建应用须配入「微信客服-可调用接口的应用」（2023-12 起系统应用 secret 不可用）；微信客服用户是微信侧客户（EXTERNAL_USERID）——这是官方接收微信用户消息的唯一正道。

【场景映射结论】A 群聊守护：企业内部群/员工单聊→智能机器人长连接(AI 答疑+流式回复)；企微客户群(微信客户可入)→入群欢迎语+关键词自动回复+克制的企业群发+(可选)会话存档辅助；行业大群(个人微信群)→不归企微，留给个人微信 RPA 子系统。B 朋友圈：企微侧走 add_moment_task 企业任务(成员客户端一键确认) 与 JS-SDK 半自动双路；个人微信朋友圈素材由本子系统素材库供给、发布由 RPA 子系统人工确认执行。C 客户沉淀：客户联系+客户群 API 全量/增量拉取→本地 SQLite 台账，AI 会话中抽取商机线索。

  选型: 向量库 sqlite-vec（嵌入SQLite单文件，单机零运维，量级<百万chunk足够）；embedding首选智谱 embedding-3 API（中文强、免运维），涉密/敏感内容备选本地 BGE-M3（Ollama 跑，CPU可接受）；重排可选 bge-reranker-v2-m3 本地或省略（top_k小+大模型自带抗噪）。知识入库侧用PyMuPDF解析规范PDF，条款级切分（按'第X.X.X条'结构切，保留标准号头）。
  接口: 输入: retrieve(query: str, top_k=6, filters{std_no?, domain?}) → List<CitedChunk>。输出给答疑生成器与引用校验器；求资源类直接映射为 LibraryCard{title, doc_type, summary, share_ref}。库构建侧接口: ingest(文档/PDF) → chunks+embeddings（离线管线，与在线检索解耦）。

[COMP] 答疑生成器 · 总包AI顾问 (Answer Composer)
  职责: 大模型生成群聊体量的工程答疑：system prompt定义'总包AI顾问'人设——工程师口吻、群聊场景下先给结论再给依据、默认120字以内（复杂问题分段）、不确定就说不确定；硬约束：所有规范性表述只能基于检索到的CitedChunks生成，引用条款必须内联标注'依据GB/T xxx-2020 第x.x.x条'，chunk未覆盖的问题如实说明并建议查阅正式版规范或私聊详聊；禁止输出报价、资质承诺、法律责任判断。超长答案自动提议'转私聊/企微全文'。
  选型: 网关T2档路由：首选 claude-sonnet-4-5（经LiteLLM的Anthropic渠道，开prompt caching——system+智库固定导语缓存命中可省大半成本），GLM glm-4.6 为成本/可达性兜底与超时fallback；max_tokens按场景限死（群答400/私聊2000）；流式输出仅用于运营台审核员实时预览（群消息整条发出，不做假流式）。
  接口: 输入: AnswerContext + CitedChunks + PromptTemplate(v)。输出: DraftReply{body, citations[]{std_no, clause, quote_range}, confidence, needs_review: bool, model_used, prompt_version}。输出给引用校验器与合规护栏。

[COMP] 引用校验器 (Citation Verifier)
  职责: 对DraftReply里的每处规范引用做事后校验：①条款号必须存在于本次检索命中的CitedChunks元数据中（杜绝编造条款号）；②引文内容与chunk原文做编辑距离/包含性比对，防止张冠李戴；③检查标准现行状态（库内版本字段），若引用了即将废止/被替代标准则触发重检索或加免责声明。校验失败→打回生成器重试一次（附失败原因），再失败→转人工审核。这是对抗幻觉的最后一道机器闸门。
  选型: 纯代码：difflib相似度+条款号字符串匹配（零模型成本、确定性）；标准时效数据来自智库元数据表，不联网核查（版本信息入库时人工/半自动维护）。
  接口: 输入: DraftReply。输出: VerifyResult{pass: bool, failed_citations[], verdict}；fail→打回生成器重生成(带失败原因，最多1次)或降级人工审核。审计: VerifyResult全量落决策审计追踪。

[COMP] 推荐决策与克制度治理器 (Recommendation Governor)
  职责: 决定'这条消息回什么、要不要顺带推荐'——全部确定性规则，零LLM：①配额制：每群每日产品/服务主动提及上限默认1次、每联系人7日1次，配额耗尽自动只推智库内容或纯答疑；②触发条件：产品提及仅当 商机信号明确（求方案/求供应商）或 对方主动询问，绝不无触发硬推；③冷却期：同群两次机器人发言间隔≥10分钟（被@除外），避免刷屏；④响应式优先：非@消息且群活跃时段消息密集时降级为'记录线索不发言'；⑤智库内容推荐限每次答疑最多附1张资料卡片且与问题强相关（检索相似度阈值）；⑥读取全局熔断开关，熔断状态下一律只收不发。
  选型: 纯Python规则引擎 + policies.yaml 声明式配置（阈值/配额可由主理人在运营台改，改即生效、留痕）；计数器与冷却状态存SQLite（quotas表，按 chat_id×date 主键，原子更新）。
  接口: 输入: IntentResult + DraftReply + PolicyState + 熔断开关状态。输出: ActionPlan{action∈[send_direct, send_with_knowledge_card, mention_product(受限), enqueue_review, silent_hold], product_quota{used, cap}, cooldown_remaining}。读: 发送执行子系统的全局熔断状态；写: quota计数。策略配置: policies.yaml（人工可改，改动留审计）。

[COMP] 合规话术护栏 (Compliance & Style Guard)
  职责: 双向护栏——生成前把合规守则注入system prompt（不做资质/报价/工期承诺，不贬低同行，不使用'保证通过''最低价''包过审'类表述，涉法律问题引导咨询专业人士）；生成后对DraftReply做输出校验：禁词/承诺句式regex扫描（报价数字+服务类动词、'保证''承诺''肯定能'、资质代办话术）、长度与格式检查（群聊≤200字、emoji≤2个）、称呼与语气抽检；命中即改写为合规模板句（'具体要结合项目情况，方便私聊详聊吗'）或直接拦截转人工。个保法护栏：输出中不回显他人手机号/身份证等敏感字段。
  选型: 主检测纯代码（禁词表+regex模板库，版本化随prompt资产一起管理）；每周用小模型T1对已发消息抽样复核话术一致性（离线质检，不在线路）。
  接口: 输入: DraftReply(生成后)。输出: GuardResult{pass|sanitized|block, applied_rules[], sanitized_body?}。sanitized/block均落审计。与意图识别器共享禁词表（单一数据源 prompt-assets/guardlists/）。

[COMP] 人工审核队列 (Human Review Queue)
  职责: 五类必入队：①意图置信度<0.6；②涉报价/商务条款（risk_flags命中）；③涉法律/事故/质量安全责任；④产品提及类动作（首次每群首次提及永远人工确认，之后按配额可直发）；⑤引用校验二次失败。队列项展示完整决策上下文（原消息、意图、检索引用、草稿、护栏意见），主理人可 批准/编辑后发/拒绝/转私聊；审核结果回流为few-shot样本与prompt迭代依据；积压超SLA（4小时）桌面+企微双重提醒。
  选型: SQLite review_queue 表 + 状态机（pending/approved/edited/rejected/expired，行级锁原子流转）；通知走 Windows toast（win10toast/pywin32）+ 企微自建应用消息（复用企微官方通道，合规）；运营台UI归属运营台前端子系统，本组件只提供REST接口（本地FastAPI）。

[COMP] Prompt资产注册表 (Prompt Registry)
  职责: 所有prompt（意图分类、答疑system、摘要、护栏禁词表、朋友圈文案模板、审核话术）作为带版本的资产而非硬编码字符串：目录化管理+manifest登记（版本号、内容hash、changelog、生效状态、评测报告指针）；运行时按 name+version 解析，线上每条请求记录所用版本；新版本必须先过固定评测集（含合规红线用例、幻觉陷阱用例——故意问库里没有的条款看是否编造、以及风格用例）达标才能 set_active；支持双版本灰度（新版本只对10%流量生效对比审核通过率）。
  选型: 文件形态 prompts/<name>/v<N>.md + manifest.json，纳入git版本控制（diff天然可见）；registry为纯Python加载器（启动预载+热重载manifest）；评测集 evals/datasets/*.jsonl（约100条黄金用例），跑批走网关T1+T2，结果存 evals/reports/。
  接口: 加载: render(name, version='active', vars) → messages[]。管理: register(new_version, changelog) / set_active(name, version, 依据=评测报告id) / list_versions(name)。评测: run_eval(name, version, dataset) → EvalReport{accuracy, citation_pass_rate, style_pass_rate}。所有生成请求携带 prompt_version 写入审计。

[COMP] 决策审计追踪 (Decision Trace & Audit)
  职责: append-only记录每条消息的完整决策链：msg_id→意图结果（含模型与prompt版本）→检索引用清单→草稿与校验结果→治理器动作与配额状态→护栏裁决→最终去向（直发/审核/静默/熔断）+token用量与成本。审计日志是熔断事后核查、prompt迭代归因、以及'可向群主解释机器人为什么说话'的唯一事实源。保留策略默认180天，可整段删除（个保法'可删除'要求），删除动作本身留痕。
  选型: JSONL追加写（audit/YYYY-MM-DD.jsonl，按日轮转）+ SQLite trace索引表（msg_id主键便于回查）；写入与业务解耦（内存队列异步落盘，掉电最多丢秒级）；敏感字段（手机号等）落盘前掩码。
  接口: 输入: 各组件埋点（装饰器/显式调用）。查询: query_trace(msg_id) / export_range(date)。输出: 审计记录 + 周度量指标（意图分布、答疑直发率、审核通过率、平均成本/条、引用校验通过率）。对齐消息采集子系统的全局熔断开关（同一开关表）。
[FLOW] 群消息答疑主流程（响应式核心链）: 消息采集子系统→NormalizedMessage→规则预筛（闲聊/无关节流，不调模型）→意图识别器T1分类→[工程疑问]→上下文构造器（20条窗口+群摘要+画像+去重）→智库RAG检索top6→答疑生成器T2（流式仅运营台预览，带内联条款引用）→引用校验器（条款号必须来自命中chunk，fail打回1次）→合规护栏（禁词/长度/语气）→治理器终审（配额/冷却/熔断）→置信度≥0.6且无risk_flags→SendTask直发；否则→人工审核队列。全链每个环节写决策审计。
[FLOW] 求资源流程: 意图=求资源→智库文档卡片匹配（不走片段检索）→命中→生成≤80字说明+1张LibraryCard→护栏→治理器（资料卡片不计产品配额但受发言冷却约束）→直发或轻审核；未命中→话术'智库暂时没有这块，我记下来了，也可以私聊我详细说说需求'→同时登记内容缺口到智库运营清单。
[FLOW] 商机信号流程（默认不自动推销）: 意图=商机信号→治理器检查：写入客户沉淀子系统线索台账（必做）+桌面/企微通知主理人（必做）；仅当 求方案/求供应商明确 且 该群产品配额未耗尽 且 群首次提及已人工背书过 → 生成一句克制价值提示（'这类我们做过一些项目，需要的话私聊'级别）→必进人工审核→批准后随答疑附带发出；配额耗尽或任何条件不满足→只答问题+记线索。
[FLOW] 朋友圈半自动文案流程: 选题日历（运营台维护）+本周产品/知识主题→T2大模型按朋友圈话术模板批量生成3-5条候选（含配图建议）→100%进人工审核队列（此流程无直发路径）→主理人编辑确认→交辅助发布子系统（系统只生成素材+走人工确认的发布通道，永不自动发圈，也永不做点赞/评论他人能力——不在任何组件的能力清单内）。
[FLOW] 成本控制与降级链: 每次模型调用→网关计量UsageEvent→预算检查器实时累计（群/日/月三层）→月预算>80%运营台预警；触顶→T2自动切glm-4.6→再触顶→意图与生成全面转T1→最终态'仅审核队列模式'（机器人只出草稿不直发任何内容）→恢复窗口（次日/次月）自动回升，升降级全部落审计并通知主理人。
[FLOW] 人工审核回流与迭代闭环: 审核动作（编辑后发/拒绝）→样本入库 samples/（脱敏）→每周离线批跑：小模型抽检已发消息话术一致性 + 引用抽检复核 + 高频编辑模式总结→形成prompt改进提案→Prompt Registry登记新版本→评测集回归（含幻觉陷阱与合规红线用例）→达标灰度10%流量→对比审核通过率后 set_active；不达标自动退回。
[FLOW] 熔断联动: 运营台一键熔断（或治理器检测到异常，如单群被投诉关键词/发送连续失败）→全局开关置位→本子系统所有出口动作收敛为 silent_hold+审核队列，采集侧照常收消息记台账（只读不受影响）→解除需主理人显式操作并留审计记录。
[RISK] 规范条款幻觉是最大技术风险：大模型可能编造'GB xxx第x.x.x条'。缓解=引用只能来自检索chunk元数据+引用校验器事后比对+幻觉陷阱评测用例，但无法归零，需在话术层保留'以现行正式版规范为准'免责声明兜底。
[RISK] UIA侧消息质量问题反噬意图识别：消息分片、表情包、引用链解析不全会导致上下文残缺、误判闲聊或答非所问。需与消息采集子系统约定NormalizedMessage契约（含reply_to与分片合并标识），并在低完整度时主动降置信度转审核。
[RISK] 标准时效风险：智库中规范被废止/替代后若未及时标记，AI引用旧规范可能造成工程误导（工程行业这不是小事）。需库内版本字段+入库时人工确认现行状态+答案免责声明三重缓解。
[RISK] 群聊体感风险：即使有克制度，'AI感'过重的回复仍可能引发反感或被群主移出。缓解：@优先响应、非@高密度时段静默、回复人设口语化、每群可单独配置aggressiveness等级（默认最低）。
[RISK] 成本失控与可用性双风险：GLM免费档限流（仓库经验：需1.5s全局节流+账号池）与Claude中转通道不稳定的叠加可能导致答疑链路降级频繁；预算降级链末端'仅审核队列模式'体验差，需主理人知晓并预设月度金额上限的合理值。
[RISK] 个保法合规风险：群消息天然含第三方个人信息。缓解：本地存储、敏感字段落盘掩码、180天保留期+可删除工具、审计日志本身可整段清除且清除留痕；但'群友不知情被AI分析'的伦理边界需主理人自行把握话术透明度（如群公告声明有AI助手）。
[RISK] 人工审核积压风险：早期置信度阈值未校准时审核队列可能爆炸，机器人'看起来坏了'。缓解：SLA提醒+首月重点调阈值+审核动作回流加速校准；极端时一键放宽为'全部直发纯答疑类'模式（产品类仍人工）。
[RISK] prompt资产与代码漂移风险：prompt迭代快，若绕过Registry直接改文件会导致线上版本不可追溯。缓解：启动时校验manifest hash与git状态，未登记变更打警告；评测报告与set_active绑定强制留痕。

OVERVIEW: 【定位】让"总包私域运营台"在一台用户自己的 Windows 机器（以现有 Windows 10 Home 为基线，兼容 Pro）上 7x24 无人值守常驻，且所有个人微信动作可控、可熔断、可审计、可恢复。设计原则：看门狗极简可靠、监督分层、数据面与控制面分离、任何组件死了都能被更低层拉起、任何状态都能一键停。【进程与端口模型】三层监督树：①计划任务看门狗（Task Scheduler，2条任务：ZB-Start 登录触发启动主服务；ZB-Health 每5分钟检查主服务进程存活+心跳哨兵文件超时则拉起，用全局命名互斥量 Mutex 防双开）。②主服务 zb-supervisor（Python 3.11 打包，跑在用户会话）：调度中枢+子进程监督者，自身不做 UIA；管理 rpa-worker 子进程（崩溃指数退避重启 5s→30s→5min，每小时崩溃预算5次，超限停 RPA 动作保观测+P1告警）。③rpa-worker（独立进程，uiautomation/comtypes 直读微信桌面客户端 UIA 树）：独立进程因 UIA COM 调用栈易崩需隔离、可单独熔断与升级；与主服务经命名管道 \\.\pipe\zb-rpa-ipc（JSON 行协议，token 鉴权）通信，消息先落盘队列再处理，断续容错。wecom-gateway（FastAPI）监听 127.0.0.1:8440：/wecom/callback 企微回调（经 frp 内网穿透到达）、/healthz 健康探针、/breaker 熔断端点；本机管理台（含朋友圈素材人工确认页）静态托管于 127.0.0.1:8441，仅 loopback。nssm 仅可选用于无桌面依赖组件（如 frpc），文档铁律：任何需要 UIA 的进程严禁注册为 Windows 服务。【登录会话要求（硬前提，必须写清）】UIA 的读写与输入注入要求进程运行在交互式桌面会话（Session 1+）；Windows 服务运行在 Session 0（无桌面、UIA 完全不可用），所以本系统不走 nssm 服务化主链路，而走"BIOS 来电自启 → Sysinternals Autologon 自动登录（凭据存 LSA，优于注册表明文）→ 登录后计划任务拉起全链"。屏幕可关闭休眠（不影响 UIA），但会话不得锁定/注销：关闭"离开时锁定"与睡眠（电源计划：永不睡眠、可关显示器、无唤醒密码）。远程运维禁用直接断开 RDP（断开=锁会话→RPA 输入立即失效）：Win10 Home 本就无 RDP 主机，统一用向日葵/ToDesk/RustDesk 类镜像会话远控；若临时用 RDP，退出前执行 tscon <会话id> /dest:console 重定向回控制台。Windows Update 设活跃时间+定期检查，防强制重启打断会话。【微信客户端健康检查（3层）】L1 进程存在（WeChat.exe）；L2 主窗口与登录态（UIA 树出现"登录"按钮=掉线，或窗口类名探测）；L3 功能探针（每10分钟读一次会话列表，统计 UIA 调用成功率）。降级阶梯：读失败→只记录不动作→自动重启微信客户端（每日限2次，重启后若需扫码登录则 P0 告警"需人工扫码"）→全局熔断。【配置管理】C:\zb-ops\config\ 下 defaults.yaml（随版本发布的只读基线）+ config.yaml（本机覆盖）+ secrets\（不进 git）：敏感项（企微 corpid/secret/token/aesKey、LLM keys、frp token）用 Windows DPAPI（CryptProtectData，CurrentUser）加密为 secrets.dat，CLI 提供 zbctl secret set/get；每次变更写前快照到 config\history\（时间戳版本化，非敏感部分纳入本地 git），审计日志记录，支持热加载信号或标记需重启。【监控告警（防递归是核心）】通道分离：A=告警通道用企微"群机器人 webhook"（自建仅含主理人的群+一个机器人，webhook 只能发不能收，物理上不可能递归）；B=命令通道用企微自建应用回调或仅限本机（托盘/管理台/桌面"熔断.bat"），A/B 严格分离。风暴抑制：同类告警15分钟聚合1条+每日摘要；分级 P0（SQLite损坏/磁盘<5%）P1（微信掉线/UIA失效/RPA熔断/回调不可达）即时推，P2（LLM超时/单任务失败）聚合，P3 进日报；兜底通道为本地 Windows Toast+可选 SMTP 邮件（企微 webhook 失效时启用）。指标：心跳戳、UIA成功率、消息处理时延、动作日预算消耗、磁盘水位、最近备份成功时间。【日志】loguru JSONL，按模块分目录 logs\{main,rpa,wecom,audit}\；轮转每日+50MB；运行日志留30天，审计日志（全部 RPA 动作/外发内容/配置变更/熔断记录）≥180天并 zip 归档、单独磁盘配额；手机号/wxid 审计中哈希化脱敏；磁盘>80% 告警。【升级策略】双层：数据型模块（提示词/推荐规则/朋友圈文案模板/知识库索引/微信UIA选择器适配 yaml）文件监视+原子替换+热重载；代码型整体更走版本目录：app\releases\YYYYMMDD-N\ + current junction，启动固定走 current\zb-supervisor.exe，升级=新 release 落地→SHA256校验+冒烟脚本→维护窗口（如周二07:00主理人值守）先熔断 RPA→停进程→切 junction→启动验证→失败自动回切上一版（保留最近5版）。微信适配层版本化：adapters\wechat-4.x\selectors.yaml 绑定微信版本，检测到微信自动升级后先探测版本找适配包，无适配则降级只读+P1告警。【备份】SQLite(WAL) 每日 03:30 VACUUM INTO backup\db\YYYYMMDD.sqlite（在线安全），GFS：日7+周4+月12；每周日自动对最近日备做恢复演练（restore 到 temp+PRAGMA integrity_check）；副本先写第二物理盘/USB，云副本默认关闭，开启时先 7z AES-256 加密（密钥主理人离线持有）；secrets.dat 是 DPAPI 绑本机的，必须另备一份明文封存（密码管理器/纸质信封）供换机恢复，RESTORE.md 步骤化：装机→运行时→git 还原 config→secrets→恢复 sqlite→冒烟。【部署清单】A 硬件/系统：①专用机器≥8G内存+256G SSD+第二块物理盘或定期插的USB盘 ②BIOS 设"来电自启" ③电源计划永不睡眠/关显示器/无唤醒密码 ④关闭锁屏（Home 用注册表 DisableLockWorkstation）⑤Windows Update 设活跃时间 ⑥安装向日葵/ToDesk 供远程运维（禁用断开式远程）。B 账号/凭据：⑦企微管理员权限与自建应用（corpid/secret/回调token+aesKey）⑧主理人个人微信已登录且记住登录 ⑨LLM API keys（Claude/GLM）⑩建"告警专用"企微群并添加群机器人取 webhook ⑪（如需公网回调）frp 服务端或 cpolar 账号。C 安装：⑫装 Python 3.11/运行时与 releases\current ⑬Autologon 配自动登录 ⑭导入两条计划任务（ZB-Start/ZB-Health）⑮secrets 经 zbctl 写入 DPAPI ⑯装微信客户端目标版本并锁定 ⑰（可选）nssm 装 frpc。D 验证：⑱重启整机验证自动登录→全链自起→收到"系统上线"企微心跳 ⑲手工杀 rpa-worker 验证退避重启 ⑳手工杀主服务验证计划任务5分钟内拉起 ㉑执行一次熔断.bat 验证 RPA 动作全停+企微收到确认 ㉒跑一次备份与恢复演练。【故障预案表（故障|检测|自动处置|人工处置）】微信客户端崩溃|L1进程检查|重启微信（日限2次）→仍失败熔断|需扫码则扫码，次日重置计数；微信掉线/被踢登录|L2登录态探测|停止动作+P0告警|手机扫码重登；微信版本升级致UIA失效|L3成功率骤降+版本探测|切对应适配包，无则只读降级|等适配包发布；rpa-worker崩溃循环|监督者崩溃预算|退避重启→超预算停RPA保观测+P1|按日志定位，可整版回滚；主服务死亡|计划任务心跳哨兵|5分钟内拉起|若反复死看日志/回滚；整机重启/断电来电|BIOS自启+自动登录+ZB-Start|全链自动恢复|收到上线心跳即可，异常则远程查看；SQLite损坏|备份演练integrity_check+运行时报错|切最近好备份（可能丢1日内数据）|按RESTORE.md重建；磁盘满|水位监控|轮转日志紧急清理非审计文件+P0|人工清理/换盘；frp/回调断|gateway自检外部探针|降级轮询可轮项+P1|修复穿透或转纯本机模式；企微token过期|API报错码检测|P1告警|企微后台刷新secret并 zbctl 更新；LLM API失效/超时|调用失败率|降级备用模型→关闭AI外发只记录|检查配额/换key；触发微信风控（账号功能受限）|发送失败/账号提示|立即全局熔断+P0|主理人自查账号，评估后手动恢复；Windows更新强制重启|计划任务重启后|同整机重启流程|调整活跃时间。

[COMP] watchdog-scheduler（计划任务看门狗）
  职责: 全链最底层守护：Windows 计划任务两条——ZB-Start（用户登录时启动主服务）与 ZB-Health（每5分钟检查主服务进程存活与心跳哨兵文件，死了就拉起）；只做'进程不存在则启动'这一件极简可靠的事，不做复杂逻辑；全局命名互斥量防双开。
  选型: Windows 任务计划程序（schtasks 导出 XML 随版本发布），'仅用户登录时运行'+交互式触发；不依赖第三方。
  接口: schtasks /create 导入的 ZB-Start.xml / ZB-Health.xml；读取 C:\zb-ops\runtime\heartbeat.json 哨兵（含各模块心跳戳）；启动目标 C:\zb-ops\app\current\zb-supervisor.exe。

[COMP] zb-supervisor（主服务/监督者）
  职责: 调度中枢：定时任务（朋友圈素材生成、台账整理、备份触发）、AI 调用编排、企微官方 API 客户端（合规自动化主体）、商机台账写入、告警发出、子进程监督（rpa-worker 崩溃退避重启与崩溃预算）、心跳哨兵写入、熔断总开关持有者。自身绝不触碰 UIA。
  选型: Python 3.11 + asyncio，loguru 日志，APScheduler 调度；打包为 releases 目录形式（venv 或 PyInstaller 单 exe），跑在交互式用户会话。
  接口: 命名管道 \\.\pipe\zb-rpa-ipc 与 rpa-worker 双向 JSON 行协议（token 鉴权）；读 config/ 下 yaml；写 SQLite（WAL）；HTTP 调企微开放 API 与 LLM API；经 wecom-gateway 的内部端点下发控制命令。

[COMP] rpa-worker（个人微信 RPA 工作进程）
  职责: 唯一拥有微信桌面客户端依赖的进程：UIA 直读消息文本、执行保守频率的响应式动作、上报消息与执行结果；独立进程以隔离 UIA COM 崩溃，可被单独熔断/暂停/升级；崩溃由 supervisor 退避重启。
  选型: Python + uiautomation/comtypes（备选 pywinauto；如需更稳可换 C# FlaUI 子进程），选择器适配层 yaml 版本化绑定微信版本。
  接口: 命名管道 \\.\pipe\zb-rpa-ipc 接收指令/上报消息（先落盘队列再处理，断续容错）；UIA 操作微信客户端窗口；执行动作前检查全局熔断开关文件 runtime\breaker.on；写 logs\audit\ 动作审计。

[COMP] wecom-gateway（回调与控制面 HTTP 服务）
  职责: 承接企微官方回调（URL 验证+事件解密）、暴露 /healthz 健康探针与 /breaker 熔断端点；可选挂载 frp 内网穿透以获得公网可达回调地址；全部仅监听 loopback（frp 场景由 frpc 出站连接建立通道，不开放入站端口）。
  选型: FastAPI/uvicorn，绑定 127.0.0.1；企微回调签名验证与 AES 解密按官方 SDK；frp/frpc 或 cpolar 作为可选穿透组件（可用 nssm 或计划任务托管，因无桌面依赖）。
  接口: 127.0.0.1:8440/wecom/callback（GET 验证 + POST 事件）、/healthz、/breaker（POST）；127.0.0.1:8441 本机管理台静态页（含朋友圈素材人工确认工作流）；上游转发主服务。

[COMP] session-keeper（开机自启与会话保持）
  职责: 落实 UIA 硬前提：交互式桌面会话。BIOS 来电自启 + Sysinternals Autologon 自动登录（凭据存 LSA）+ 关闭睡眠/锁屏 + 远程运维规范（镜像式远控或 tscon /dest:console，禁断开式 RDP）；文档明示：任何需要 UIA 的进程严禁注册为 Windows 服务（Session 0 隔离无桌面）。
  选型: Autologon for Windows（LSA 存储）；电源计划与注册表 DisableLockWorkation/无唤醒密码；向日葵/ToDesk/RustDesk 任一做远程运维通道。
  接口: 部署清单与 RESTORE.md 中的装机步骤；tscon <sessionId> /dest:console 应急脚本置于 tools\。

[COMP] health-checker（健康检查）
  职责: 三层微信客户端健康检查（L1 进程存在 / L2 主窗口+登录态 / L3 每10分钟功能探针统计 UIA 成功率）+ 系统面检查（磁盘水位、SQLite 可写、frp 通道、LLM 可用性、备份新鲜度）；输出分级状态驱动降级阶梯与告警。
  选型: 主服务内调度线程；psutil 查进程；UIA 探针复用 rpa-worker 通道；外部探针经 gateway 自检。
  接口: 写 runtime\health.json（管理台与看门狗共用）；状态变更事件进告警总线；触发熔断器与微信重启流程。

[COMP] alerter（监控告警，防递归设计）
  职责: 分级告警：P0 即时、P1 即时、P2 聚合、P3 日报；防递归核心=告警通道用企微群机器人 webhook（只能发不能收，物理单向），命令通道与之严格分离；风暴抑制（同类15分钟聚合、每日摘要）；兜底 Windows Toast 与可选 SMTP 邮件。
  选型: 企微群机器人 webhook（主理人专属群）；python-win10toast/plyer 本地通知；可选 smtplib。
  接口: 内部告警总线（级别+类别+去重键）；HTTP POST webhook；每日 21:00 日报（心跳/消息量/动作量/预算消耗/备份结果）。

[COMP] breaker（全局熔断器）
  职责: 一键停：写入 runtime\breaker.on 哨兵文件后，rpa-worker 在每个动作前检查并立即停止一切个人微信主动动作（观测与台账保留，企微官方通道不受影响）；三个触发入口：桌面'熔断.bat'/托盘菜单、管理台按钮、（有公网回调时）企微自建应用命令；微信风控信号自动触发；解除需人工显式确认。
  选型: 哨兵文件+主服务广播+审计记录（谁/何时/为何熔断）。
  接口: C:\zb-ops\runtime\breaker.on；gateway /breaker 端点；熔断与解除均发企微确认消息并写审计日志。

[COMP] config-manager（配置与密钥管理）

  选型: yaml 分层合并 + Windows DPAPI（CryptProtectData，CurrentUser）+ 本地 git 仓库管配置版本。
  接口: config/ 目录约定；zbctl CLI；reload 命名事件；审计日志记录全部变更。

[COMP] backup-agent（备份与恢复演练）
  职责: SQLite 每日 03:30 VACUUM INTO 到 backup\db\（在线安全），GFS 保留（日7+周4+月12）；每周日自动恢复演练（restore 到 temp + PRAGMA integrity_check，失败 P0）；配置与 DPAPI secrets 一并入备份；第二物理盘/USB 副本；云副本默认关闭，开启时先 7z AES-256 加密且密钥离线保存；配套 RESTORE.md 换机重建手册与个保法'可删除'数据清理工具（含备份副本处理）。

[RISK] UIA 会话硬约束被误配：任何把主链路注册成 Windows 服务（Session 0）、或远程运维用断开式 RDP 导致锁屏，都会让个人微信 RPA 立即失能且表象是'静默假死'——必须靠部署清单固定 Autologon+镜像远控，并在健康检查中加入'会话锁定状态'探测项。
[RISK] 自动登录的物理安全风险：机器开机即进桌面且存有微信登录态与密钥，机器失窃=数据面全失——缓解：专用机器不放无关敏感数据、机器物理上锁、secrets 云备份密钥离线保存；Windows 10 Home 无完整 BitLocker（仅部分设备有 Device Encryption），磁盘加密能力弱是明确短板。
[RISK] 微信客户端版本升级是最高频破坏源：UIA 选择器随版本漂移；自动更新难以彻底禁用，只能'检测版本→适配包匹配→无则只读降级+告警'的补偿策略，存在功能静默退化窗口。
[RISK] 账号风控残余风险：即便低频+响应式+可熔断，个人微信自动化仍可能被平台判定异常（限功能/封号）；熔断与审计只能降低损失不能消除概率，需在运营上保留'人工值守时段'与降级预案（企微官方通道承接全部合规动作）。
[RISK] 企微回调需要公网可达地址：单机无公网 IP 时依赖 frp/cpolar 穿透，引入第三方可用性与安全面；若完全不开公网，企微侧部分实时能力降级为轮询/半离线，功能边界需在产品层明确。
[RISK] 告警通道自身故障（webhook 失效/群被删/网络断）会让'系统病了但没人知道'：兜底 Toast+邮件也依赖本机在场；需把'连续N小时未发日报'视作异常信号（外部视角的心跳缺失检查，如主理人手机端每日21:00没收到日报即人工介入）。
[RISK] 单盘故障与 SQLite 损坏：备份在第二物理盘才有效，若只有单盘则 GFS 形同虚设；恢复演练若不跑，备份可用性存疑；最坏丢最近1日数据（日备粒度）。
[RISK] DPAPI secrets 换机不可解：secrets.dat 绑定本机用户，若无离线明文封存，整机灾难恢复时所有凭据需全部重申请（企微 secret 重置、LLM key 重录），恢复时间显著拉长。
[RISK] Windows Update 强制重启与断电：重启后链路可自愈，但正在进行的 RPA 动作与当日备份可能中断；活跃时间设置只能缓解，需接受偶发中断并靠'开机到就绪'流程兜底。
[RISK] LLM/API 依赖失效：Claude/GLM 超时或配额耗尽会让 AI 答疑停摆——降级为'记录问题+稍后统一回复'而非硬重试；企微 token 过期需人工刷新 secret（无法全自动）。

SUBSYSTEM: 个人微信精简版RPA子系统（WeChat-Lite-RPA，护栏优先/能力分级架构）
OVERVIEW: 定位：总包私域运营台的"手和眼"——独立进程运行在常驻Windows机上，用UI Automation直读微信桌面客户端做【低频+响应式】群聊应答与【半自动】朋友圈辅助；所有业务判断（AI答疑、内容生成、台账）留在主台，本子系统不含任何LLM密钥与数据库写权限。核心架构决策是"能力分级门控（capability-gated）"：因为已有2025年实测文献（cnblogs.com/zhaoweiwei/p/19731420）证实微信4.x改用跨平台自绘Canvas渲染，Inspect.exe看不到内部控件、pywinauto/uiautomation无法定位按钮——"UIA直读"这一前提在4.x上不成立或仅部分成立（3.9.x时代UIA树丰富，yinkaisheng/uiautomation正是以微信3.x为示范场景）。因此Phase 0必须先跑本机UIA探针，按探针矩阵（会话列表可读/消息项可读/输入框可写/发送按钮可Invoke四项能力）把系统锁定在三种模式之一：全自动响应模式（四项全过）、只读建议模式（可读不可写：消息照读、答案只在主台确认面板显示+一键复制、人工手发）、纯辅助模式（探针全挂：仅剩朋友圈素材生成+剪贴板辅助，零微信自动读取）。绝不在能力不足时退回视觉栈/OCR/硬件HID（路线已砍，不复活）。技术选型结论：主栈Python 3.11 + yinkaisheng/uiautomation（comtypes直连UIA COM，与主台同语言、中文社区成熟、以微信自动化著称），pywinauto(UIA backend)作为窗口级操作与对话框断言的副库；C#方案（cswin32+IUIAutomation）仅在需要STA事件泵或事件Handler稳定性不佳时作为≤200行的sidecar可执行文件保留，不作主栈；Node+windows-foreground否决——它只解决SetForegroundWindow一个子问题，无UIA树访问能力，Node侧UIA需经edge-js二次桥接.NET，链路长无收益。新消息检测默认轮询（2-5s抖动扫描会话列表未读角标），UIA结构变更事件因微信是否触发无实证、降级为可选优化项。回复执行仅文本：剪贴板备份→写入→Ctrl+V→点击"发送"按钮（优先Invoke而非回车，规避用户发送键配置差异）→读取消息列表末条做后置校验，失败即熔断计数。护栏三层：进程内守门（每次动作前限额校验，SQLite持久化计数防重启洗白）+ 主台侧总量核验 + 物理熔断（本地pause旗标文件+全局热键，主台挂了也能停）。朋友圈半自动为两级：L0默认级仅"复制文案+打开图片文件夹+唤起微信主窗"；L1配置级额外代开朋友圈编辑器并粘贴文案与选图，但"发表"按钮选择器写入代码级FORBIDDEN选择器清单，ReplyActor在动作目标命中该清单时直接拒绝执行——不自动发布是代码约束而非流程约定。熔断触发词（"操作过于频繁/账号异常/验证/重新登录"等）+选择器连续失配+后置校验失败+心跳丢失多路触发，触发即停机、树文本快照留证（默认不截屏，最小采集）、Windows Toast+主台横幅告警、人工两步恢复（点恢复+选原因码）。进程隔离：worker经Job Object纳管，崩溃由独立supervisor按"30分钟冷却内最多重启1次"处理，绝不影响主台；worker与主台仅经127.0.0.1 HTTP+命名事件通信，事件信封内发送者一律加盐哈希假名化，AI调用仅携带脱敏最小上下文。"永不做"清单硬编码于worker常量与选择器denylist双层强制。

[COMP] message-parser（消息读取与结构化）
  职责: 进入目标群后读取新增消息项，解析出发送者显示名（→加盐哈希假名）、文本正文、@我检测（'有人@我'预览标记+正文前缀@昵称/@所有人双路）、方向判断（自身消息启发式）；非文本降级为类型占位符[图片][语音][文件][视频][链接][引用:截断]不提取内容；消息去重用(群绑定+发送者哈希+文本+分钟桶)指纹。
  选型: Python正则+结构解析；占位符降级策略（无OCR、无语音转写——最小采集铁律）
  接口: 产出 MessageEnvelope{msg_hash, binding_id, sender_pseudo, type, text?, at_me, quote_ref?, ts} → POST console /api/messages

[COMP] trigger-engine（响应式触发规则）
  职责: 在console侧运行（worker只送信封不含判断）。三级触发：T0被@（强）；T1关键词/句式（标准号regex：GB/JGJ/JTG/JTS/DL\/T/NB/CECS+年份，求助句式'请问|怎么处理|求助|有没有…规范'）；T2廉价模型语义分类（批量、仅对白名单新消息）。'先让人答'延迟：T1/T2等待90-150s无真人回复才生成答案；同群24h内相同归一化问题去重或引用早前答案。生成答案交给人工可配的'高敏群先审'开关。
  选型: Python规则引擎+GLM/Claude小上下文调用（仅传问题文本+脱敏上下文，不传全群记录）
  接口: 消费/api/messages流；产出ReplyTask{binding_id, text_segments[≤3段,每段≤500字], priority} → worker /task/reply

[COMP] reply-actor（回复执行器）
  职责: 执行文本回复：激活微信窗口→点击输入框→剪贴板协议（备份→写入→Ctrl+V→5s后恢复）→点击发送按钮（Invoke优先）→后置校验（列表末条与所发文本一致，5s窗口）→失败重试1次→再失败计熔断分。FORBIDDEN目标拒绝。夜间/限额/停机旗标硬拒。
  选型: uiautomation动作原语+win32clipboard；不使用SendMessage/WM_SETTEXT（4.x无HWND控件）；不使用驱动级键鼠
  接口: 内部消费ReplyTask；产出ActionResult{ok, post_verified, err_class} → 审计JSONL + console回填

[COMP] guardrail（频率护栏）
  职责: 三层：进程内守门（每动作前查SQLite计数：默认每群≤3条/小时、每群≤20条/天、全局≤30条/天、任意两次发送间隔≥120s±抖动、22:30-07:30全停只排队）；主台侧总量核验（防worker状态被污染）；物理熔断（pause旗标文件+注册的全局热键，主台失联仍可停）。计数持久化，重启不清零。
  选型: Python + SQLite WAL（本地单文件）+文件旗标+global-hotkey库
  接口: worker内部canAct(binding_id)->Decision；暴露/console API /api/guardrail/stats 给主台仪表盘

[COMP] moments-assist（朋友圈半自动流）
  职责: 消费主台已生成且人工批准的素材包。L0（默认）：复制文案到剪贴板+打开配图文件夹+唤起微信主窗，人手动发。L1（配置显式开启）：额外自动打开朋友圈编辑器、粘贴文案、经文件对话框选图，止步于发表前——'发表'按钮在FORBIDDEN清单，代码层不可触达。发布节奏护栏：≤2条/天、间隔≥4h、仅08:30-21:00。
  选型: uiautomation导航+剪贴板协议（与reply-actor共用）；确认面板在主台Web UI（逐条强制停留阅读防'一键全批'）
  接口: 消费主台批准件MomentsDraft{id, text, images[], level:L0|L1}；产出执行回执（不含是否已发表——发表事实由人工回执勾选）

[COMP] circuit-breaker + supervisor（熔断器与看门狗）
  职责: 熔断触发：风控提示词命中（'操作过于频繁|账号存在异常|请输入验证|重新登录|扫码验证'）/必选选择器连续失配≥3/后置校验失败×2/微信窗口消失或登出/滚动10次回复成功率<80%/心跳丢失。动作：立即置pause、清空待发队列、留存UIA树文本快照、Toast+主台横幅+可选邮件告警、要求人工两步恢复（恢复按钮+原因码）。supervisor独立小进程：心跳超时杀worker进程树（Job Object），30分钟冷却内最多重启1次，再崩即保持停机+告警。
  选型: Python监督进程+Windows任务计划程序托管；告警走Windows Toast+console webhook
  接口: 状态文件breaker_state.json（ paused|running|down + reason_code ）；console轮询+worker每次动作前读取

[COMP] audit-log（审计日志）
  职责: append-only JSONL逐动作记录：ts、action_type、binding_id、selector_fingerprint、耗时、结果、err_class；消息正文仅存'已触发应答的白名单问题文本'（假名化），默认90天保留+一键清除工具（个保法可删除义务）；默认零截屏、零图片/语音落盘。
  选型: 本地JSONL+SQLite索引；清除工具提供按群/按日期/全量三档
  接口: worker本地写入+镜像POST console /api/audit；清除工具CLI: audit_purge --binding --before

[COMP] bridge（主台↔worker IPC）
  职责: 127.0.0.1单端口token鉴权HTTP+命名事件；schema校验所有跨界载荷；worker侧无LLM密钥、无DB直连、无外网域名白名单之外访问。
  选型: FastAPI(主台) + 内置http.server最小面(worker，攻击面最小化)

[FLOW] 启动自检流：supervisor拉起worker→探测微信进程与登录态→跑uia-probe能力矩阵→与selector-registry指纹比对→能力分级(全自动响应/只读建议/纯辅助)上报console→按级进入运行模式；指纹不匹配=降级+告警，绝不带病硬跑
[FLOW] 消息监听流：session-monitor轮询会话列表→白名单+未读角标判定→三元组身份核验(名+规模+锚点)→导航进群→message-parser读新增消息→结构化信封(假名化)→POST主台→恢复原会话焦点→trigger-engine三级判定(T0@/T1关键词/T2语义)→'先让人答'延迟窗→主台AI生成答案→(高敏群先经人工审)→下发ReplyTask
[FLOW] 回复执行流：worker收task→guardrail.canAct校验(群/时/天/间隔/夜间/pause旗标六查)→reply-actor剪贴板协议粘贴→Invoke发送按钮→后置校验消息落列表→审计落盘+限额计数递增→失败路径：重试1次→计熔断分→连续失败走熔断流
[FLOW] 朋友圈半自动流：主台排程生成文案+配图→人工确认面板逐条审改批准→按级别执行L0(复制文案+开图夹+唤起微信)或L1(代开编辑器+粘贴+选图,止于发表前)→人手动点击发表→人工回执勾选已发→台账回填；'发表'按钮选择器在FORBIDDEN清单，actor层物理拒绝
[FLOW] 熔断流：任一触发条件命中→置pause旗标+清队列→UIA树文本快照留证→Toast/主台横幅/邮件告警→worker进入只心跳状态→人工两步恢复(点恢复+选原因码)→恢复后先重跑探针再复级
[FLOW] 崩溃恢复流：heartbeat.jsonl超时→supervisor经Job Object终结worker进程树→读最近审计定位崩溃点→冷却判定(30分钟内已重启过则不再拉起)→重启或保持down+告警→主台全程不受影响，消息信封在重连后续传
[RISK] 【最高风险·路线前提】微信4.x为跨平台自绘Canvas UI，已有2025年实测文献（cnblogs.com/zhaoweiwei/p/19731420）证实Inspect.exe看不到内部控件、uiautomation/pywinauto无法定位——'UIA直读'在4.x上可能整体不成立或仅部分成立；若探针判DEAD，本子系统降级为只读建议/纯辅助模式，绝不退回截屏OCR/驱动级输入/硬件HID（路线已砍，复活即违背用户确认的路线）
[RISK] 3.9.x版本锁定受侵蚀：老版本可能被强制升级或限制登录，锁定方案有半衰期；需探针+版本监控双保险
[RISK] 群名可被任意成员修改且可重名：白名单误绑→误读非目标群（合规与信任双重风险）；三元组绑定只能缓解不能根除，歧义即拒读
[RISK] 账号风控不可免疫：即使低频+响应式，机器行为特征仍可能被识别为自动化；熔断只能止损，不能保护账号不被处置——主理人须知情接受此残余风险
[RISK] 剪贴板是全机共享可变全局：与同机人用冲突、被剪贴板管理器/同步工具（如输入法云剪贴板）外泄的次生风险；缓解=备份恢复协议+动作瞬间完成+禁用云剪贴板建议，但非零风险
[RISK] 前台要求冲突：UIA写动作需交互式桌面，锁屏/断开会话即阻断；常驻机须保持登录态——物理安全与操作连续性互相拉扯（无人值守机房vs不锁屏）
[RISK] 图片/语音/引用内容不可读→语义遗漏导致答非所问或漏接需求的体验风险；只能靠降级提示('图片消息我看不了,麻烦文字描述')兜底
[RISK] 确认疲劳滑变：朋友圈确认面板用久后人工滑向'无脑批'，半自动事实漂移为全自动；需逐条强制停留+随机抽检提醒，但属流程性防御非硬约束
[RISK] 本地台账含个人信息（假名化不彻底时的显示名残留）：删除工具与保留期必须先于采集上线，否则违反自定个保法铁律
[RISK] UIA树遍历的COM跨界开销：大群消息列表轮询的CPU/延迟；缓解=限定深度+只读增量+白名单收窄，但Windows低配机上仍可感
[RISK] UIA事件不可用性：若微信不触发结构变更事件，轮询是唯一路径，检测延迟与扫描频率此消彼长
[RISK] 单机单号单点：无冗余无故障转移，机器/微信号任一不可用即整子系统停摆（可接受，但需在SLA预期里写明）
