# GAP_REPORT — 我方 vs 20 顶级源：诚实缺口（1005 Arc O 第二波）

> 判定基准：BEST_PRACTICES.md 66 条主题化最佳实践 × 我方现状
> （RQS 21 门十一机检引擎 / conductor 统一调度 / 证据饱和引擎 / ammo_pool
> 三态+GRADE / Jev 判断层主影双轨 / 28 渠道舰队 / domain_blocklist /
> keyword_engine / hypothesis_redteam 零LLM腿 / SuperSkillWeekly 达尔文环）。
> 缺口按「不补的后果」排序，最疼的排最前。已补的明确写「已闭环」防重复建设
> （G-001 纪律）。

## 一、执行证据 vs 主张正确性分离 —— 最大的洞

**现状**：渠道腿是 Python 确定性执行有日志，但 **Jev 三腿 / Manus 军团 /
写作链的 LLM 自报（「已核验」「confirmed12」）没有回执账本可对账**。
**差距**（对标 DeerFlow 三层验证栈 + ARIS Type-A/B）：
- 无工具回执账本——「结算 0 假阳」目标缺证据底座；
- 无 Type-A/Type-B 二分类——质量判定没有强制路由到不同模型家族；
- done≠accepted 未分离——军团任务「写完」与「验收通过」共用一个状态。
**后果**：LLM 谎报「已抓取/已核验」时 RQS 无法区分真执行与幻觉。

## 二、提示注入防御缺一层工程

**现状**：无任何围栏机制。抓取内容直接进 Jev 裁判/写作链上下文。
**差距**（对标 last30days 围栏+defang / anysearch 横幅 / Scrapling 净化）：
- 判断腿提示词无 untrusted 围栏+defang；
- 渠道 extract 输出层无注入警横幅；
- 喂 LLM 前不剥隐藏元素/零宽字符。
**后果**：恶意网页一条「忽略以上指令」即可操纵判断层（研究工具被研究目标
反向操纵）。

## 三、信源质量层薄

**现状**：GRADE A/B/C 三级+host 独立源原则+blocklist。
**差距**（对标 LDR 四级打分 / last30days RRF / hyperresearch 独立性）：
- 无信源质量数值分（h-index 式分档）——中文信源生态无 OpenAlex，但权威度
  分层（部委>行业协会>官媒>门户>自媒体）可数值化；
- 无跨源 RRF 融合排序——多渠道收割件目前按渠道分目录存，无统一候选池打分；
- 无辛迪加转载检测——同文多站转发会被当成多源共识（对我们「≥2 独立源」
  饱和门是直接威胁）；
- 无实体接地降权——同名噪声/主题外内容混进弹药池只靠 judge 腿语义判。
**后果**：饱和门的「独立源」可能是转载链的幻觉；弹药池信噪比靠后置人工。

## 四、检索空间穷举无账本

**现状**：EEI 51 条/课题+四维查询公式+查询词回存资产库。
**差距**（对标 LDR 实体覆盖账本）：
- 无「已覆盖/未覆盖实体」记账——查询词进化靠 RUN_LEDGER 散文，无程序化
  回填未搜组合；
- 无近 5 迭代零结果→「太窄了减约束」反向适配。
**后果**：穷举完整性不可证明（我们声称「全渠道上阵」但某实体维度漏搜无门
可查）。

## 五、新鲜度无分级表

**现状**：RQS 有 12-24 个月时效校验（report-helper 融合 F4 关联），但只有
单一阈值。
**差距**（对标 node-DeepResearch 30+ 行领域分级）：金融实时 0.1 天/行业
报告 30 天/统计 180 天的领域映射缺失。
**后果**：过严（静态事实也被要求 24 个月内）或过松（价格数据用一年前的）。

## 六、引用完整性只有报告级

**现状**：引用三态门+V3-CITE 上标绑定门（1005 新增）+own_calculations。
**差距**（对标 hyperresearch）：
- 无 quote 逐字对撞——正文引号内容与源文不对撞，改写后失真不可检；
- 无撤稿/删除地板。
**后果**：引用格式全对但内容失真的报告过门。

## 七、外部技能供应链无确定性扫描

**现状**：github-to-skill / SuperSkillWeekly 大量激活上游外部技能，只有
人工红线。
**差距**（对标 scientific#2/#3 仓库级守卫+入仓扫描）：无 frontmatter 结构
校验/禁 eval 扫描/本地链接解析检查/内容哈希增量扫描。
**后果**：外部 skill 夹带 curl|bash 或硬编码 key 直接进全局技能库。

## 八、渠道探测与墙态检测零散

**现状**：各渠道自写探活；墙态四层矩阵+cli_fetcher。
**差距**（对标 career-ops 信封三态 / open-webSearch 拦截病理学）：
- 探活无副作用审查（有的探活本身会拉起 daemon）；
- 「信封变形→descriptive throw 点名实际 keys」未统一——静默改版仍可能表现
  为永远 0 条；
- 无 retrievalMethod 溯源标记（直连/带cookie/全浏览器三档）。

## 九、子进程环境变量未洗刷

**现状**：conductor/tools 下 subprocess 调用直接继承环境。
**差距**（对标 DeerFlow env_policy）：*KEY*/*TOKEN* 未洗刷——shell 里导出的
付费 API key 可被任何子进程/外部脚本读走。
**后果**：密钥面扩大（账号安全红线的工程缺口）。

## 十、已闭环项（防重复建设，G-001 纪律）

- **方法论框架**：EEI+问题树+ACH+饱和门+GRADE ≥ 各源通用框架（我们的
  METHODOLOGY.md 七步循环已是情报学界满配）；
- **中文写作纪律**：report-helper F1-F6 已全部融合（上标绑定/定量四件/禁套
  话/坑账），AI 腔黑名单 29 条规则在役；
- **并发调度**：conductor 确定性 Python 调度 ≥ 各源提示词层并发（DeerFlow
  SLR 自己承认中间件税）；资源互斥/heavy 窗/adopt 收编是我方独有；
- **确定性质量门**：RQS 21 门零 LLM 机检 ≥ 各源 lint（v3 概率词锁/GRADE
  词表/上标绑定是全行业无人机检化的）；
- **账号安全四件套**：节流/冷却/日限额/熔断已在渠道层标配（部分源根本没有
  此概念）；
- **渠道复盘**：channel_reverse+墙态登记簿 ≥ web-access 站点经验文件（我们
  按机制沉淀，他们按域名散存）。

## 结论

我方**强在骨架**（调度/质量门/方法论/安全），**弱在证据链的最后一公里**
（执行证据分离/注入防御/信源独立性/引用对撞）——恰好全部是「防自欺」层，
与 RQS「难题即标准」宪法同向。融合优先级据此排定，见 FUSION_PLAN.md。
