## 0. 一句话主张

**把「一次昂贵的专业解答」变成「一次付费解答 + 无限次免费延伸」的对话式咨询产品**——工程大脑的答案只买一次，智谱免费链以该答案为上下文接住所有追问，让每个用户从「看完一篇文档」升级为「带着一个智库往下聊」。

## 1. ten× delta 指数（可证伪）

| 维度 | 现值 (v0.5.1) | 目标 (v0.6.0) | 判据（可实测） |
|---|---|---|---|
| 单次咨询可交互轮数 | 1（一问一答） | **1 + 20 追问** | followups 表行数；答案页出现对话流 |
| 答案首屏理解成本 | 2000+字直渲 | **3 条要点速览（<15s 读完）** | digest 缓存命中率；tldr 字段非空 |
| 会话延伸路径 | 0 条 | **3 条相关问题/答案** | related 点击 → ask 提问转化（引擎可测） |
| 分享形态 | 纯文字链接 | **精美海报图（要点+品牌+码）** | poster 生成数 + 海报扫码进入 UV |
| 等待体验 | 文本事件+秒表 | 骨架屏+绘图仪式感（调研回填） | 主观体验 + 停留页行为 |
| 免费成本 | KB 3点/问 | **不变**（追问/digest/海报全免费） | KB 日积分消耗不升 |

## 2. 产品设计

### 2.1 两级产品语义（质量诚实）

```
┌─ 工程大脑 · 专业解答（KB，烧积分 ~3点/问）
│   全库检索的正式咨询 —— 现有主线一字不动
└─ 智库助手 · 快答（智谱免费链，0 积分）
    追问 / 术语 / 延伸 —— 以本篇解答全文+引用为上下文接地作答
```

**可行性已实证（0929 23:4x 实测）**：接地追问 1.9s/153字，结论先行、引用原文关键句、诚实边界话术（「建议就合同解除或重新协商条款发起新咨询」——飞轮话术自动生成）。

## 3. 架构设计（引擎腿）

### 3.1 数据库迁移（只增不删）

```sql
CREATE TABLE IF NOT EXISTS followups (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  aid TEXT NOT NULL,
  openid TEXT NOT NULL,
  question TEXT NOT NULL,
  answer TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT 'pending',   -- pending|ready|error
  error_text TEXT DEFAULT '',
  created_at REAL
);
CREATE INDEX IF NOT EXISTS idx_followups_aid_openid ON followups(aid, openid);
-- answers 表新增列（ALTER 只加不改）：tldr TEXT DEFAULT ''（JSON 数组）、
--   related TEXT DEFAULT ''（JSON 数组）、poster_png BLOB（海报缓存）
```

### 3.2 API 契约（新增四端点，全部免费）

```
POST /api/answer/{aid}/followup   {question}   → {id, status} 异步快答（智谱接地）
GET  /api/answer/{aid}/followups               → {items:[{id,question,answer,status}]}（本人+锅圈可见答案）
GET  /api/answer/{aid}/digest                  → {tldr:[..3], related:[..3]}（首次生成永久缓存）
GET  /api/answer/{aid}/poster                  → {b64}（竖版海报 PNG，首次生成缓存）
```

护栏：followup 每答案每人 ≤10 问/天 + 全局 20/天/人（防刷）；正文 ≤200 字；1301 内容审核已有熔断；digest/poster 每答案只算一次成本。

### 3.3 提示词（接地核心）

```
你是总包AI智库的咨询助手。下面是工程师的原始咨询与智库专业解答全文。
只依据「专业解答」回答追问；先核对解答中适用前提是否满足，再下结论；
信息不足时如实说明并建议就这一点发起新的正式咨询。
要求：结论先行，条理清晰，引用解答原文关键句，300 字内。
【原始问题】…【专业解答】…【用户追问】…
```
（实测后增补：先核对前提再结论——修复 flash 模型前提条件反向表述的小瑕疵）
