# 报告名→顶级研报：超级生产线框架 v1

## 一、总述

本文档是「报告名进、顶级研报出」超级生产线的框架总装版 v1：把一个报告名变成一份自带质量档案的世界级研报的全过程，固化为 S0-S6 七阶段＋四条横切层的可审计产线，每阶段有可证伪的入口/出口判据、业界模式对照表、增量件清单（最小落地形态＋验收判据）、护城河确认与不抄清单。它给研报工厂的编排层用——用户只需给报告名加一次企微呈批，产线无人值守出货；骨架 v0 定了七阶段骨架，v1 定的是往骨架里装哪些标准件、每件怎么验收。

它现在够格称世界级，靠三层事实而非设计图：其一，产线硬层全部在役且经实读复核——61 渠道注册六 lint fail=0、弹药池 23.24 亿字（塔尖 lark_zhiku_file 22.36 亿=96.2%）、judge 按字数拒率 77%（拒 77 亿字/4.4 万件，入池件均 2.8 万字 vs 拒件均 17.8 万字）、RQS 21 门零 LLM 机检全收官、conductor 7min tick 现役活、弹药门 v3 被渠道全景明断「已是世界级设计」；其二，913 项目语料扫荡把外部可抄件摸到了底（四大方法论来源见语料总账），且经三轮对抗审计——杀「编造业界」零命中（全部外部模式引用逐条对回输入件原文）、夸大在役全数降级并注差距（如 auto_dispatch 仅 3/61、完备门键名错位 7 假缺席、probe 面 3/14）、误删已有件全数回收（4 件 CONFIRMED-已有杀出增量件清单）；其三，每个增量件都有唯一归属节与可证伪验收判据，跨节去重后净增 38 件，0 件需要新基建——全部架在在役硬层上，外部标准件单向装入、绝不反向看齐。

## S0 意图解析与立项（报告名 → 战役 Charter）

**本阶段做什么**：把一个报告名解析成可执行战役——识别研究对象（企业/行业/主题）、报告类型、读者与体量目标，生成本体词表（tiers.json 三层）与弹药门参数，并对「这份报告名能不能产」做数据判级。产出口径是战役 Charter：它是 S1-S6 的唯一事实源，框架、派单、完备门分母、验收条款全部从 Charter 派生。本阶段新增件全部是「装进骨架的标准件」——判级数据源、弹药门参数、渠道账本全部来自在役硬层，不另起第二套账。

**入口/出口判据**：
- 入口：用户给出报告名或需求单（两档：L1 详单 / L2 仅报告名，见增量件 3）；产线侧=战役目录未建、tiers.json 不存在。多战役并行允许，上一战役不阻塞本阶段。
- 出口（逐项可验证，缺一不算完成）：
  1. 战役目录落盘，沿用 EPC100 结构（01 需求/02 原料/04 网络调研/05 根基对标/09 生成指令——骨架 v0 S0 已有件）；
  2. Charter.md 定稿：六栏范围卡 + 研究对象/类型/读者/体量目标（章×节×字显式字段）+ 设问式核心问题；
  3. tiers.json 三层词表（T1 本体/T2 同业/T3 行业）且每词带槽位溯源；
  4. 弹药门参数写入（T1≥300万 ∧ T1+T2≥3000万 / T3 封顶 / 机动补弹 0.5 亿——骨架 v0 S0 已有件）；
  5. 完备门分母=该战役适用渠道清单，生成时必须过 engine_aliases 键名归一（输入件1 §3 实锤：完备门 13 渠道裸缺席中 7 个实有正产量，分母被键名错位污染过）；
  6. 门卫判级 PASS 留痕，或 RETREAT 附缺口清单退回；
  7. 用户呈批回执落盘（结构化批/改标签，批准前 S1 不动工）。

## S1 初步框架（骨架 + 弹药路由表）

**本阶段做什么**：基于 S0 charter 与存量先验（共性库/先前战役/05 根基对标/弹药池水位）+ 免费侦察面快扫，生成初版章节骨架。核心产出不是大纲文本而是**框架即路由表**——framework.json 每章预标 tier 词表映射、目标渠道组合、证据密度预估与弹药预算档，作为 S2 Channel Grid 派单的直接输入契约；框架生成层用 LLM（推理级单报告内），派单层保持零 LLM 确定性（进程级），两层判定同源不同权。

**本阶段做什么**：把 S2 到位的弹药回灌进 S1 初版框架——用章节×证据矩阵把「哪章弹药饱和、哪章贫血」从人脑判断变成机读账，据此强扩弱并：证据强的章节扩写升权、证据弱的合并/降级/标注，锁定终版大纲为写作合同（章节树+每章字数预算+图表数+章级 tier 路由），贫血章自动生成补扫单交回 S2 定向补弹。本阶段是调研与写作之间的产前门：框架一旦锁定即合同，后续变更须走 diff 留痕，不许静默改。

## S4 边写边收集（章级缺口定点补弹）

**本阶段做什么**：逐章初稿生成与采集交替进行——写作腿按 S3 锁定的章节合同逐章起草；初稿中的证据缺口（[待证] 标记、低置信论断、单一来源撑起的结论）由章级缺口检测器自动抽成补弹任务，经 tier_router 派单定点补弹（可派面以当期真出粮渠道为实——auto_dispatch 现 3/61，全渠道自动派单属 v3 接线清单，见护城河2差距注），judge 过门回填后续写。本质是把「达标战役的转产+定点补弹」逻辑从战役级降到章级，让「77% 写增量生长」（搜×5→写×1、写读比 1.5:1）从方法论认知变成可编排的产线节奏。

**入口/出口判据**：

- 入口（三条全满足）：① S3 出口达成——最终框架锁定（outline 即合同），章节×证据矩阵已标出哪章弹药饱和/哪章贫血（epc-deep-research 阶段5 覆盖度分析四权评分）；② 战役级弹药门已结算——tier_report `gate_ok`（T1≥300万∧T1+T2≥3000万）进转产态，或走机动补弹 0.5 亿窗（豁免留痕）；③ 写作腿提示词三件套（增量件 3）在位——没焊反幻觉条款不开笔。
- 出口（全部机检可验）：① 大纲合同章节数 100% 有初稿文件（manifest 对账无缺章）；② gap_extractor 复扫终稿：[待证]/单源论断零未处置——清零或显式转 uncertain 账本，豁免须留痕（不静默）；③ 补弹任务全闭环：gap→job→回填全链在 board 三方总表可对账，无孤儿任务；④ 反损耗门：终稿字数 ≥ Σ分章稿（编译零损耗）；⑤ 每章自报「N out of M 章引用已核」与 RQS 引用门复核一致；⑥ 反面判据：写作腿因等弹药空转的时间窗 ≤1 个 conductor tick（7min）——写章 N 时采章 N+1 的并发编排真活。

### 护城河确认（我们有而业界没有或更强）

1. **弹药预算经济学（转产 204 卷+机动补弹 51 卷章法）**：业界无人做「字数当量弹药预算」级的章级补给纪律——AutoSurvey 的预算是检索篇数（1500/60），ODR 是 token 上限，均无「达标即转产、缺口定点补」的战役级账户体系。实证：骨架 v0 S4 已有件、NB MD 资料库规矩（单本 280 源/2.5 亿、补弹机动 0.5 亿=51 卷）。
2. **补弹 query 的三层去处（供给面在役，派单面待接线）**：61 渠道注册+23.24 亿字存量仓+五层调度地基构成供给面碾压——但按渠道全景真相，机器派单面刚起步：auto_dispatch=true 仅 3/61（media_group/website/registry），主力产粮=OS 级班次腿双轨，29 渠道在册不出粮、12 真缺口待接线；「存量仓收割/当期增量班次/按需单查」三类分层派单逻辑是 §5.2 的设计要求而非已接线调度器。章级补弹的实际可派面=当期真出粮渠道（A 桶 7+B 桶 22），缺口任务「不愁供给」但「派单接线」是 v3 前置工。对比 AutoSurvey 单库、ODR 单一搜索 API、WebThinker 单引擎。实证：channel-landscape §1/§2 四桶/§4 五层组件/§5.1-5.2。
3. **judge 真过滤器保证回填质量**：按字数拒率 77%（拒 77 亿字/4.4 万件）、入池件均 2.8 万字 vs 拒件均 17.8 万字——章级补弹回填的弹药天然过分层门，外部项目（WebThinker/ODR/deer-flow）无内容级入池过滤。实证：channel-landscape §1「judge 是真过滤器」。
4. **全程落盘+断点续跑**：O_EXCL 锁+tmp+os.replace 原子写+adopt 收编在役——边写边收集的多轮循环里任何一环崩溃都可续，两个 Manus clone 的无持久化（planning 进程内 dict/无 checkpointer）恰是它们完全空白。实证：manus-clones-fusion §4 N2/N8。
5. **免费判断层底盘**：judge_heuristic 免费为主、Jev 只占免费做不到的原语位——77% 写增量生长的写读循环在我们这里成本底盘是免费的，ODR 同型循环单轮 $45.98。实证：骨架 v0 横切层判断层、免费模型优先铁律。
6. **完备门思想可降粒度到章**：「静默缺席不许收官」推广为「章级缺口不静默」——豁免须留痕（waivers 机制 FAIL→WARN），与 0930 用户裁决豁免机制同构。实证：channel-landscape §5 第4条、RQS 收官记录。

### 不抄清单

1. **ODR 单轮 $45.98/5800 万 token 纯付费重炮**（输入件5）：写读循环每章跑一遍的边际成本我们承受不起，且违反免费模型优先铁律；其压缩层垫终稿前是为付费 token 省钱的形态，我们素材走落盘仓不进上下文。
2. **AutoSurvey 封闭单库**（预建 530k arXiv 摘要、无活网调研，输入件5）：章级缺口千变万化，单库检索会饿死定点补弹；我们 61 渠道活网+23.24 亿字存量仓是碾压性供给面。
3. **WebThinker 单体思考流**（无多 agent 并行、非工厂化，输入件5）：写作决策锁进单一模型的思考流，与 7min tick 确定性产线相斥；其质检纯 LLM 主观排序，无字数/引用/完备客观门。
4. **deer-flow 默认深度浅+火山引擎绑定**（1 轮规划×3 步、Doubao/InfoQuest 推荐，输入件5）：离「顶级研报」差数量级；供应商绑定违反渠道中立原则。
5. **BettaFish GPL-2.0 传染**（输入件5 明示严禁商用）：license 传染性直接排除引进；其 word_budget 前置思想（P21）可自由借鉴，代码与形态不碰。
6. **两 clone 的进程内存储形态**（OpenManus PlanningTool 类属性 dict、LangManus 无 checkpointer，输入件3 §4 N2/N8）：抄其提示词件（双槽/计数/诚实收尾），不抄其存储形态——多线程产线必串，状态一律落盘。
7. **委托 Manus 执行写作侧**（输入件4·M62 三用途铁律+§4.4 边界令）：反损耗编译、增量生长等写作侧模式只借鉴模式、必须落自己管线（laya/成稿链/promotion）——借鉴其打法 ≠ 扩大其用途，防外部军团反噬产线纪律。
