## S0 意图解析与立项（报告名 → 战役 Charter）

**做什么**：解析报告名 → 研究对象（企业/行业/主题）、报告类型、读者、体量目标；生成战役目录 + tiers.json（T1 本体/T2 同业/T3 行业词表）+ 弹药门参数 + 完备门分母。

- 已有件：EPC100 战役目录结构（01 需求/02 原料/04 网络调研/05 根基对标/09 生成指令）；tiers.json 词表工艺；弹药门 v3 参数（T1≥300万∧T1+T2≥3000万/T3 封顶/机动补弹 0.5 亿）。
- 缺件：**报告名→词表的自动生成器**（现在词表是人工+战役经验写的；需「研究对象本体词表归纳」管线：企业名/母公司/曾用名/核心子公司/旗舰项目/竞争对手 自动展开）。
- 待扫荡验证：业界 report-planning 阶段怎么做 query decomposition / entity expansion。

## S1 初步框架（骨架 + 弹药路由表）

**做什么**：基于存量先验（共性库/先前战役/05 根基对标）+ 快速免费侦察（zh-search-pro/anysearch/opencli 免费面）生成初版章节骨架；**框架即路由表**——每章预标 tier 词表与目标渠道组合、预估证据密度。

- 已有件：十维度框架（企业基本面/EPC 战略/组织人才/项目管理体系/设计/采购/施工/风险/技术/市场对标——epc-deep-research config/topic_dimensions.json 50-80 主题生成工艺）；共性库先验（多本架构：共性库+战役本各吃各的 2.5 亿）。
- 缺件：**框架生成的模型化**（现在偏模板化；报告名千变万化时框架要能适配：企业研究/行业研究/主题研究/政策研究四类框架族）。
- 待扫荡验证：STORM 式「多视角提问→大纲演化」、outline-driven retrieval 的业界做法。

## S2 定向调研（Channel Grid v2 调度 + 弹药门 + 饱和引擎）

**做什么**：按框架路由表派单全渠道；边收集边判断；双门准入（弹药门+饱和门）。

- 已有件（世界级，直接复用）：
  - **五层调度**：L0 注册 61 渠道 → L1 tier_router 六闸+辛迪加闸（≤40%∧≥3源）+并发预算 → L2 conductor tick 7min → L3 完备门四态 → L4 探活周腿
  - **分层派单**（渠道全景报告启示）：存量仓收割 / 当期增量班次 / 按需单查（积分制永不自动派）三类渠道不同逻辑
  - **judge 真过滤器**：字数拒率 77%，件均 2.8 万字
  - **证据饱和引擎**：字数门∧饱和门 + ACH 假设对抗；元门=调研不达世界顶级不生产
  - **权威度分级**：source_authority + GRADE_MAP + 辛迪加折叠
- 缺件（渠道全景报告点名）：12 真缺口接线（search_library/engopp/ebook_library/wechat_local/rion/govlist/giiisp/factory_registry/localfiles/baidu_netdisk/anysearch/quark_pan）；**键名归一**（完备门 7 渠道假缺席根因）；probe 面 3→14。
- 待扫荡验证：多智能体分工采集（planner-worker-judge）vs 单 conductor 的边界；query 变体生成策略。

## S3 最终框架（证据回灌）

**做什么**：弹药到位度回灌框架——证据强的章节扩写、证据弱的章节合并/降级/标注；覆盖度评分定薄弱维度。

- 已有件：epc-deep-research 阶段5 覆盖度分析（数量30%/深度30%/多样性20%/时效20% 四权评分+薄弱维度补采）。
- 缺件：**框架-证据双向对账器**（章节×证据矩阵，自动输出「哪章弹药已饱和/哪章贫血」），现在靠人脑。
- 待扫诡验证：dynamic outline / evidence-aware outlining 业界做法。

## S4 边写边收集（章级缺口 → 定点补弹）

**做什么**：逐章初稿生成时发现证据缺口 → 自动生成补弹 query → 派单 → 回填再续写（达标战役的「转产+定点补弹」逻辑推广到章级）。

- 已有件：转产触发器（204 卷）+补弹机动（51 卷）章法；「77% 写增量生长」（写的过程长出新问题——Manus 方法论学走成果）；Jev 判断层（免费启发式为主）。
- 缺件：**章级缺口检测器**（初稿里的 [待证] 标记/低置信论断自动抽取成补弹任务）；写作与采集的并发编排（写章 N 时采集章 N+1 的缺口）。
- 待扫荡验证：write-while-retrieve 的业界编排（longform writing 工作流）。
