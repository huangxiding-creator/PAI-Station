> 用途：Phase 5 API_DESIGN 支付腿与 Phase 6 引擎实现的唯一契约依据。所有断言可溯源，标注（源：deep_pay Qn / WIZARD）。

## 1. 为什么是虚拟支付（唯一合规判定）

- 官方判定标准：小程序内向用户提供虚拟商品（虚拟代币、解锁功能、订阅内容、付费功能、打赏等），购买与支付均须接入小程序虚拟支付 wx.requestVirtualPayment（基础库≥2.19.2）。（源：deep_pay Q1.1）
- 研报售卖明确落入典型形态一「付费数字内容」：官方运营指南原文列举「课程视频、小说章节、专栏文章、数字藏品等」——「¥498 解锁一份研报 PDF+在线阅读」与之同构 → 必须走虚拟支付，不得用标准商户号 JSAPI 收款。（源：deep_pay Q1.2）
- 禁止外流支付：官方原文「不得引导至 app、公众号、h5、个人号、网站完成支付」。小程序内放「去官网购买」按钮=违规。（源：deep_pay Q1.3）
- 2026-04-01 全终端强制已生效：iOS/安卓/Windows/鸿蒙须完成接入，到期未接入判违规，处置阶梯=风险提醒→功能限制（限流）→下架。今天 2026-09-28，此为现行有效规则。「安卓 JSAPI + iOS 不卖」旧行业做法现为违规项。（源：deep_pay Q1.4）
- 历史沿革：2023 微短剧类目试点（当时无 iOS）→ 2025-11-14 苹果腾讯协议 iOS 开放（分成 15%，后「小程序合作伙伴计划」降至 12%）→ 2026-04-01 全终端强制。（源：deep_pay Q1.5）

## 2. 开通 6 步（用户人工位，30-60 分钟）

前置四件套：管理员微信（可扫码登录 mp.weixin.qq.com）、营业执照、对公账户三要素（开户名=公司全称/开户银行/银行账号）、小程序简称（iOS 端虚拟支付前置，后台「设置→基本设置」配置）。（源：WIZARD 开通前准备）

| 步 | 动作 | 要点 |
|---|---|---|
| 1 | MP 后台【功能（或「支付与交易」）→虚拟支付】入口 | 若提示「类目不支持」：先到「设置→服务类目」调整到虚拟支付开放清单内（教育/知识付费/工具方向）再回来 |
| 2 | 阅读并同意《虚拟支付服务协议》 | 承诺即合同义务的起点 |
| 3 | 提交商户资料 | 系统开通**虚拟支付专用独立新商户号**——与普通微信支付商户号是两回事，不用已有的 |
| 4 | 账户状态查询与资料审核 | 时长以官方提示为准；对公账户填错可在审核阶段重新提交 |
| 5 | 账户验证 | 打款验证或信息核验 |
| 6 | 扫码签约 | 管理员微信扫码签署协议；随后进商户管理后台配置道具 |

（源：deep_pay Q2 开通入口与流程 6 步｜WIZARD 官方 6 步）

主体要求：企业、事业单位、个体工商户等（非个人）。本项目已确认企业主体（2026-09-28 用户答复，PROPOSAL 假设1）。个人主体路径（2026-09 新开，仅工具类目+月支付限额 10 万元）对本项目不可行，作废。（源：deep_pay Q2）

## 3. 道具直购模式（本项目唯一采用）

三种官方模式（API 参数 mode 区分）：

| 模式 | mode 值 | 机制 | 本项目判定 |
|---|---|---|---|
| 道具直购 | `short_series_goods` | 用户直接以人民币金额购买指定道具（productId+goodsPrice 必填），支持 Android/鸿蒙+iOS 双端 | **采用**：一份报告=一个道具，定价直给 |
| 代币充值 | `short_series_coin` | 先充代币包再扣减消费，配套余额/扣减/退款/赠送 API | 不采用：过度设计（PROPOSAL v1 不做） |
| 会员订阅 | 签约入参亦用上两值 | 周期扣费；准入=已接入虚拟支付+首次发布≥90天+认证备案+近30天日均 DAU≥1万 | 远期 P2 后再评估 |

（源：deep_pay Q3｜PROPOSAL 六 v1 不做）

道具配置（WIZARD 开通后清单，先只建 1 个跑通全链）：
- 道具名称「研报单篇解锁」；productId 例如 `xy_report_unlock`；价格 ¥498.00 = **49800 分**。
- iOS 价格：若后台强制双端分价，¥498 保持同价（推荐）；不允许同价则按官方允许档位就近。
- 设计要点：所有报告统一定价 → **一个通用道具**即可；解锁哪份报告由我方订单系统（outTradeNo）绑定，不需要 40 个道具。后续分报告定价再逐个加道具。
- 用户回传 3 个值：offer_id（虚拟支付发售单元 ID）、product_id（道具 ID）、iOS 实际价格 → 我方落 `data/secrets/virtual_pay_xueyuan.secret` → 引擎重启生效。（源：WIZARD 开通后/最后）

## 4. signData 结构与签名链

wx.requestVirtualPayment 关键参数（客户端组装+服务端签名下发）：
- `mode: 'short_series_goods'`、`signType: 'SHA256'`、`paySign`。（源：deep_pay Q1.6 官方 API 参考）
- zongbao 现役封装实样（utils/pay.ts）：`env`（**0=正式环境，1=沙箱环境**）、`currencyType: 'CNY'`、`platform`、`buyQuantity: 1`、`orderId/outTradeNo`（幂等键，`${reportId}_${Date.now()}`）、`goodsPrice`（单位分）、`signData`；`paySig` 与 `signature` 由服务端签名后下发——协议要求支付链路由服务端供给签名，本地不持密钥。（源：WeAppForge projects/zongbao/utils/pay.ts 实读）
- 服务端签名腿 = qianwen-engine 已在役的 **pay_sign 双签名**（签名单测 5 向量 PASS，ECS 公网 401@78ms），xueyuan-engine 换 appid/appsecret 即用。（源：FEASIBILITY 1.1｜PROPOSAL 十一）

## 5. 价格规则

- 道具单价以「分」为单位传入（goodsPrice）。官方体系内实证锚点：扣费金额「不超过 5000 元」→ **¥498（49800 分）远低于上限，处于允许区间**（置信度 0.8，建议开通后在 MP 道具后台以 49800 分实测确认）。（源：deep_pay Q3）
- 优惠价：可传 activitySellingPrice；**优惠价最低为道具价格的 40%（最高打 4 折）**（行业文档转述，建议后台实证）。（源：deep_pay Q3）
- 平台技术服务费（微信侧）：工具/知识付费类目预期 Android 侧 1%~10% 区间，**以签约协议为准**；微短剧类目专属 20% 不适用本项目。（源：deep_pay Q3）

## 6. iOS Apple 通道（12%）

- 苹果渠道费率 **12%**：2025-11 开放时 15%，后苹果「小程序合作伙伴计划」降至 12%（个人版官方文档明文「iOS 将收取 12% 渠道佣金（苹果代收）」）。注意：deep_refund 引旧闻 15% 为沿革注记，以 12% 为准。（源：deep_pay Q3｜RESEARCH_DIGEST 交叉验证1）
- 双端差价配置：MP 后台道具管理支持 Android/iOS 分别定价（iOS 调高覆盖 12% 是行业通行做法）；API 层 goodsPrice 为单值，差价在后台道具维度配置。二手信源 cred 0.5，开通后实证。（源：deep_pay Q3）
- 本项目首期决策：**双端统一 ¥498，iOS 差价我方吸收**（叙事干净，PROPOSAL 假设2）；iOS 订单占比监控进日报，若 iOS 占比>50% 且净利率跌破 80% → P2 再评估调价（RISK R-13）。
- iOS 端额外条件：已开通虚拟支付 + 已配置小程序简称 + 微信客户端 8.0.68+。（源：deep_pay Q2/Q3）

## 8. 退款能力与 refund_order API

- 两条退款路径：① MP 商户后台手动退款；② 服务端 **refund_order API**（官方服务端 API 族「启动订单退款任务」+ 回调 `xpay_refund_notify` 推送退款结果）。（源：deep_pay Q4）
- 终端差异（关键）：
  - **Android/鸿蒙**：开发者可主动发起退款（全额语义为订单级退款）；**「按比例部分退款」参数级语义官方未公开明文——degraded，须开通后实测**。本项目批评退款按分退 50%-100% 是否能单笔 API 完成，开通后第一周实测验证；实测不通则以「全额退+差额转书券」或分单设计兜底。（源：deep_pay Q4｜RESEARCH_DIGEST 交叉验证2）
  - **iOS**：开发者无法主动退款；用户向 App Store 申请，走苹果流程，结果异步通知开发者 → 主动权在苹果/用户侧。（源：deep_pay Q4）
- 手续费规则（官方原文）：**支付成功后 180 天内退款的，平台返还已收手续费；超过 180 天退款，手续费不退**。（源：deep_pay Q4）
- 结算后退款：Android T+3/iOS 45-60 天；结算后退款从后续应结资金/保证金扣回；虚拟支付体系未公开商户号式「垫付回补」细节（degraded）。（源：deep_pay Q4）
- 对比基准（不可用但作参照）：商户号 v3 退款支持 1 年内多次部分退+垫付，但数字内容不允许走商户号收款。（源：deep_pay Q4）

## 9. 合规义务（官方硬要求，全部进产品）

1. 须向用户提供**退款界面入口**。
2. **24 小时投诉处理机制**。
3. 支付前明示「**付费内容不支持无理由退款、未成年人购买限制及使用范围**」。
4. 退款须走商户平台/接口规范操作，不得私下处理。

（源：deep_pay Q4 官方合规要求｜PROPOSAL 4.2 发票入口前置为 B2B 刚需补充）

## 10. 503 降级模式（offerId 未到位期间）

- 引擎行为：offerId/secret 缺失时支付腿返回 **503 降级**——可试读、可收藏，支付入口灰置；已验证不阻塞开发与提审（harness D 场景实测：已解锁 409/幂等 200）。（源：FEASIBILITY 1.1｜PROPOSAL 六 P0）
- 前端行为：featureFlags.virtualPay=false 或 wx.requestVirtualPayment 不存在时，返回「支付通道开通中，敬请期待。试读章节持续免费开放」，不抛错。（源：zongbao utils/pay.ts 实读）
- 凭证到位即插：填 secret → 引擎重启即生效（biaoxun 同款流程，RUN_LEDGER #45 同款插入点）。（源：PROPOSAL 假设8｜FEASIBILITY 调度图 F）

## 11. Plan B（虚拟支付不可行时的合规替代，按可行性排序）

1. **实体商品交付（最稳）**：纸质精装版+邮寄，电商类目+普通商户号 JSAPI（费率约 0.6%，v3 退款一年内多次部分退）；主商品是实物，赠阅在线版作赠品。¥498 可覆盖印刷邮寄。（源：deep_pay Q6.1）
2. 人工咨询服务定位（灰色，不推荐主路径）：挂咨询之名行付费解锁现成 PDF 之实仍属形态一违规。（源：deep_pay Q6.2）
3. PC/官网独立售卖+小程序零支付入口（灰色对冲）：小程序内只要出现「去官网购买」引导即违规；纯自然流量官网成交可被平台综合判定，只作第二收款端。（源：deep_pay Q6.3）
4. 会员订阅（远期）：DAU≥1万+90天门槛，初创不可行。（源：deep_pay Q6.4）
