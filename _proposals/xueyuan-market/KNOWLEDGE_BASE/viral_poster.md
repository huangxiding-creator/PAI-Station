# 海报与裂变（viral_poster）

> 浓缩自：RESEARCH_DOCKET/deep_viral/_all.md、PROPOSAL.md 4.4
> 交叉引用：AI_NATIVE_OPTIONS.md #2、RISK_REGISTER.md R-11、KNOWLEDGE_BASE/refund_criticism.md 第 9 节（利益-分享因果链）
> 用途：海报服务端生成（P1）+ 归因三表 + 裂变双引擎的设计契约。所有断言可溯源，标注（源：deep_viral Qn / PROPOSAL）。

## 1. 情报卡=社交货币（产品定位）

海报不是广告，是**社交货币**：报告封面 + 最狠的 1 个数据（大字）+ 1 句结论 + 品牌条 + 小程序码（右下规范位）+「长按识别 免费读前 20 页」。转发者有面子（「我在研究江苏水网商机」）而非「我在卖课」。（源：PROPOSAL 4.4）

## 2. 服务端 PIL 路线（三理由）

选定路线 A：服务端生成（PIL 模板+码预生成池+图片 URL 直出，CDN 出图）；端侧 wxml-to-canvas 仅留「用户实时换头像昵称」轻量补充位。（源：AI_NATIVE_OPTIONS #2｜deep_viral Q2）

三理由：
1. **渲染结果与设备无关（千机一面）**：高分辨率导出，无 canvas 缩放模糊、无多机型 dpr 坑；对比端侧 wxml-to-canvas 仅支持 view/text/image 三标签+仅 flex 布局（官方文档 1.0 实读），复杂版式做不了。（源：deep_viral Q2.2/Q2.4）
2. **模板改动不发版**：模板改服务端即生效；服务端是重内容平台的收敛选择（知乎排版引擎文章为证）。（源：deep_viral Q2.1）
3. **码可预生成缓存，不撞 5000 次/分限频**：官方明确建议预生成。（源：deep_viral Q1.1）

代价（诚实计入）：服务器 CPU/内存开销（puppeteer 截图尤重，PIL 较轻）、字体文件管理、长图内存、需自建或买 CDN。（源：deep_viral Q2.1）

三路线对比速记（deep_viral Q2.4）：A 服务端=加载速度/清晰度/布局能力三星，个性化实时性二星；B 端侧=实时性三星但布局一星；C 云函数=免运维但冷启动+裂变峰值期按量计费成本反超自备服务器。

## 3. scene 32 字符契约（官方接口实读，cred 1.0）

核心接口：`getUnlimitedQRCode`（POST `https://api.weixin.qq.com/wxa/getwxacodeunlimit`），「获取不限制的小程序码」，适用于码数量极多的业务场景——每张海报一个邀请人专属码正是目标场景。（源：deep_viral Q1.1）

- **scene 参数：最大 32 个可见字符**；仅支持数字、大小写英文以及 `!#$&'()*+,/:;=?@-._~`；**不支持 %**（不能 urlencode 中文，参数必须用短 ID/短码）。
- **page 参数：不能带参数**（query 参数只能放 scene 里）；不能带前导 `/`；须本小程序已发布页面（check_path 默认 true；false 可用于未发布页）。
- env_version：release（默认）/trial/develop。
- width：默认 430px，范围 280-1280；海报印刷位建议 600-800px 保证扫得动；官方返回的码是方形 buffer，四周留白自加。
- 数量与频率：B 码数量**无限制**（对比 A/C 合计 10 万上限）；调用频率 **5000 次/分钟**，官方建议预生成。
- scene 到达方式：作为 query 参数传给指定 page；开发工具模拟编译时需手动 encodeURIComponent（真机自动）——最常见的「本地好好的真机解析失败」坑。
- 关键错误码：40129 scene 非法；41030 page 不存在/未发布；40169 长度非法；45009 调用超限；47001 body 非 JSON；89300 无效 signature（未发布时）。

（源：deep_viral Q1.1）

## 4. 短码映射表（溢出兜底+天然 tracking 落地点）

- **直拼短参数**：`r=Ab3xK9&i=U8mQ2z`（r=报告短 ID，i=邀请人短 ID），约 18 字符，余量充足；分隔符 `&`/`=`/`-` 均在合法字符集内。（源：deep_viral Q1.2）
- **溢出兜底=短码映射**：参数放不进 32 字符时，服务端先落库 `scene_code → {report_id, inviter_uid, channel, poster_version}`，scene 只存短码（如 `s=Xk29fA`），扫码端查映射表还原——同时天然成为 tracking 落地点。（源：deep_viral Q1.2）
- **ID 必须短化**：openid 28 字符直接塞必爆，须用自增 uid/Base62 短 ID。（源：deep_viral Q1.2）

扫码解析标准链（onLoad）：`decodeURIComponent(options.scene)` → split('&') → split('=') 得 params.r/params.i；官方仅保证 scene 作为 query 传入，解析、校验、兜底全部自己写。（源：deep_viral Q1.3）

**兜底三板斧**（转化损失>归因损失原则）：
1. scene 缺失/解析失败 → 降级为无邀请人进入（report_id 用页面默认值，inviter 置空，不做归因）。
2. onLoad 参数丢失（冷启动被系统回收）→ 落地页把 scene 写入本地缓存，onShow 再校验一次。
3. 短码映射查不到 → 同①降级，不阻塞用户看免费部分——**免费内容兜底优先于归因**。

（源：deep_viral Q1.3）

## 5. 归因三表（首触归因 first-touch）

| 表 | 关键字段 | 作用 |
|---|---|---|
| `poster_code`（码映射表） | scene_code, report_id, inviter_uid, poster_version, created_at | scene 短码→业务参数还原；预生成码池 |
| `share_event`（分享事件） | share_id, uid, report_id, channel(海报/会话/朋友圈), poster_version, ts | 谁在何时分享了哪份研报的哪版海报 |
| `invite_relation`（邀请关系） | inviter_uid, invitee_uid, report_id, scene_code, status(扫码/注册/解锁/付费), ts | **邀请归因主表，首触归因(first-touch)** |
| `scan_visit`（扫码访问，第四度量环） | scene_code, openid/uid, entry_page, ts | 漏斗第一环：曝光→扫码落地的度量 |

说明：微信官方不规定 tracking 表结构；上表为技术社区实战文与神策归因模型的综合收敛（cred 0.65，设计参考而非硬证据）。**K 因子（人均邀请数×邀请转化率）可直接由 invite_relation 聚合**。（源：deep_viral Q1.4）

## 6. 尺寸与布局规范

| 场景 | 推荐尺寸 | 说明 |
|---|---|---|
| 朋友圈海报（本项目主战） | **1080×1440（3:4 竖版）** | 信息容量更大（小红书同规格）；PROPOSAL 4.4 定为安全线 |
| 方形备选 | 1080×1080 | 适配手机屏居中 |
| 全屏竖版长图 | 1080×1920（9:16） | 信息最全，注意朋友圈会压缩；信息多再用 |
| 关键约束 | **宽度控制在 ~1080px** | 超大分辨率（3000px+）发朋友圈反被强制压缩变模糊；1080px=「清晰又不触发二次压缩」安全线 |
| 小程序码 | 官方 width 默认 430，海报印刷位 600-800px | 右下角+预留白边 |

（源：deep_viral Q4.2）

布局分区（社区方法论收敛，cred 0.5-0.6）：顶部主标题（大字号直击利益点，研报最强结论句，3 秒抓眼）→ 副标题（「免费看全文」类强化）→ 中部信任背书（品牌/数据源权威性「基于 XXX 份一手数据」/销量）→ 中下部产品展示（封面大图+3 条核心数据摘要，数字大写醒目）→ 右下角小程序码（行业惯例右下+留白，配行动指令「长按识别 免费读第 X 章」）。研报场景定制：封面顶部约 40%+品牌条底部+数据摘要中部+码右下。（源：deep_viral Q4.1/Q4.3）

## 7. 裂变双引擎（安全区玩法）

**引擎一：邀请解锁**——邀 2 位新用户扫码 → 自己解锁完整免费部分+50 元书券。安全要素：分享是解锁**路径之一而非唯一路径**（也可付费直接解锁）；激励物为**产品内虚拟权益非现金非实物**；不强制发朋友圈、不要求截图验证、不搞打卡返现。（源：PROPOSAL 4.4｜deep_viral Q3.2）

**引擎二：3 人组队读研报**——组队价 ¥998/3 人，全队各得阅读权（微信读书「组队抽无限卡」同款，多年在役=安全样本，cred 0.7 在役事实可自证）。（源：PROPOSAL 4.4｜deep_viral Q3.1）

书券内循环：邀请/批评/iOS 补偿都发书券（非现金），攒券换报告——合规且锁客。（源：PROPOSAL 4.4）

安全区判据（微信读书活样本）：激励物=虚拟权益；分享=路径之一非唯一；不强制、不截图、不打卡返现。（源：deep_viral Q3.2）

## 8. 红线清单（绝不碰）

| 红线 | 依据 |
|---|---|
| 砍价（拼多多式） | PROPOSAL 4.4 红线；公开量化数据 thin（deep_viral Q3.1 诚实标注） |
| 晒单返现/打卡返现 | 微信安全中心 2019《利诱分享朋友圈打卡处理公告》批量处理；晒单返现=高危（cred 0.85） |
| 二级及以上分销 | 新世相二级 3 小时 96,741 份后被封（cred 0.75）；网易戏精课当日被封；《禁止传销条例》三级及以上计酬涉传销 |
| 强制分享解锁（分享为唯一路径） | 诱导分享违规；「邀请 X 人解锁」若设计为强制分享触达即违规 |
| 利益-分享因果链 | 《微信外部链接内容管理规范》2.1.2：给付以「完成分享」为前提=违规（含虚拟奖品诱导） |
| 无依据划线价 | 划线价须真实存在过（有销售记录），否则价格欺诈（deep_competitors 表③） |

（源：PROPOSAL 4.4 红线不碰｜deep_viral Q3.2｜deep_competitors 表③）

诱导分享处罚阶梯（运营规范 3.3）：删文→删粉→封禁分享能力→封号（四级）。售卖「诱导分享裂变程序+防封系统」已被法院认定不正当竞争——平台态度司法化。（源：deep_viral Q3.2）

## 11. 限频风险与处置（R-11）

- 触发信号：errcode 45009 调用超限；40129/40169 scene 非法。
- 处置：码预生成池（官方明确建议）；scene 直拼 `r=短ID&i=短ID`≈18 字符余量充足；放不下走短码映射表；生成请求入队削峰；映射查不到时降级无邀请人进入。（源：RISK R-11｜deep_viral Q1）
