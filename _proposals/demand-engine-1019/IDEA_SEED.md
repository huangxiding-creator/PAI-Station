# IDEA_SEED — 群众需求引擎（Demand Engine）

## 原始想法（用户三段原话精髓）

1. **从群众中来到群众中去**：研报产线目前销售给群众，但需求尚未系统来源于群众。需求源=微信群聊+微信私聊+微信朋友圈聊天记录的真实用户需求洞察。
2. **自媒体评论矿**：借鉴自媒体永动机与公众号/视频号的交互做法，访问 3 个公众号（总包之声/总包说/工程行业大脑）+ 1 个视频号的后台，抓取全部文章/视频**评论**，做用户需求洞察，从中选出工程总承包研报选题 + JTBD 需求分析。
3. **稳定自动 API**：用 REA 逆向或浏览器自动化破解评论访问，形成稳定的自动 API 访问方式，持续稳定获取自媒体平台用户评论。

## 真实意图揣摩（用户令：比原想法好 100 倍）

用户要的不是三个采集脚本，而是一条**永不枯竭的需求飞轮**：

- **本质**：把产线的「选题」环节从拍脑袋/单信号升级为**群众需求驱动的持续系统**——需求→选题→成书→销售给同一群人→他们的反馈/评论再成为下一轮需求（真正的闭环，不是单向采集）。
- **隐含痛点**：现有 topic-signals 管线已有骨架但信号薄（2 条）；81 群全史 860 信号已证价值（司法鉴定 226 热度→第 7 份在售报告）；缺的是（a）私聊面（b）自家阵地评论面（公众号后台留言+在看+视频号评论=**付费意向最强的人群**）。
- **100× 方向**：不只采评论，而是建**需求资产台账**（Demand Ledger）——每条需求带 JTBD 结构+来源面+频率+紧急度+专家面板评分（已有 schema！），跨面聚合去重，热力榜自动生成，选题即从台账 Top 出，且与 radar_topics 桥接直通 S-1。评论抓取只是喂料腿之一。
