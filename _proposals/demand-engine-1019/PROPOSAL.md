# PROPOSAL — 群众需求引擎 v2（Demand Engine 2.0）

> 比「三个采集脚本」好 100 倍的形态：**需求资产飞轮**——从群众来（三面采集），到群众去（成书卖给同一群人），他们的评论/反馈再回流为下一轮需求。

## 一、真实意图还原（揣摩）

| 用户说的 | 真实要的 |
|---|---|
| 微信群/私聊/朋友圈洞察 | **面A：私域需求矿**（已在跑：rion-cli 81 群 860 信号；缺私聊面+调度固化） |
| 抓 3 公众号+1 视频号评论 | **面B：自家阵地需求矿**（评论区=付费意向最强人群：他们已读我们的内容） |
| REA/浏览器破解成稳定 API | **面B 的技术路线**（实测结论：API 正道优先——`comment/list` 权限两号 48001 未开通、一号通但需群发回执 article_id；**网页后台 CDP 是已验证稳定通道**，非破解） |
| JTBD 需求分析 | **统一需求台账**（已有 JTBD schema+专家面板，扩展为全项目需求资产库） |
| 「从群众中来到群众中去」 | **闭环**：面A/B/C 采集 → 台账 → 选题 → 成书 → 发布回同渠道 → 评论再入台账（飞轮而非管道） |

## 二、100× 提案：Demand Engine 2.0 架构

```
┌─ 面A 私域矿 ────────────────────────────────┐
│ A1 群聊深扫（rion search 词表轮换+分页）      │ 已跑通, 固化调度
│ A2 私聊面（rion timeline p2p 会话）           │ 新增
│ A3 朋友圈面（rion sns-feed --offset 全量翻页）│ 新增
├─ 面B 自家阵地矿 ────────────────────────────┤
│ B1 公众号评论（合法 API: 总包说 comment/list  │ 权限实测: 1号通/2号48001
│    article_id ← material/news→publish 回执链）│ 新建回执链补齐
│ B2 公众号留言/私信（mp 后台 CDP 9336 通道）   │ 新增（网页后台稳定通道）
│ B3 视频号评论（channels 后台 CDP 9337）       │ 新增
├─ 面C 交易回流矿（已在跑，接进台账）──────────┤
│ C1 小程序语音/文字反馈（feedback 飞轮 MySQL） │ 已在跑, 接台账
│ C2 咨询问答日志（ask 全史=用户主动问题！）    │ 已有库, 接台账
│ C3 购买/退款行为（最强付费意向信号）          │ 已有库, 接台账
└──────────────┬──────────────────────────────┘
               ▼
    ┌─ 需求资产台账（Demand Ledger）──────────┐
    │ 统一 JTBD schema（沿用 topic-signals）   │
    │ +来源面标记 +频率 +紧急度 +专家面板      │
    │ 跨面去重（语义聚类）· 热力周报           │
    └──────────────┬─────────────────────────┘
                   ▼
    选题直通车（topic_signals_to_radar → demand_radar
    → 评分卡 → 呈用户批准 → S-1 全链）
```

**比原想法强的六点**：
1. **闭环非管道**——面B/C 让买过/读过的人的需求回流，选题命中率从「猜测群众」升级为「已知付费人群的下一本书」
2. **三面互补去重**——群聊热词（司法鉴定226 实证）× 自家评论（付费意向）× 交易行为（真金白银），单一面噪音被交叉验证过滤
3. **合法稳定优先**——API 正道（1 号已通）+ 官方后台 CDP（自家账号后台，非破解第三方）；REA 逆向仅作 fallback 不作主路
4. **复用巨人**（C4）——rion-cli/JTBD schema/雷达桥/feedback 飞轮全部在役，新建件 <30% 
5. **需求资产复利**（C0）——台账跨报告积累，越用越厚；热力周报让「下一本」永远有据
6. **JTBD 直通选题**——每条需求带 job_statement/forces/outcome，选出的选题自带「给谁写/写什么/怎么卖」

## 三、技术路线（实测依据）

| 面 | 通道 | 实测状态 | 稳定性 |
|---|---|---|---|
| A1 群聊 | rion search（词表+翻页） | ✅ 860 信号 | 高（本地库只读） |
| A2 私聊 | rion timeline --chat p2p | CLI 在役 | 高 |
| A3 朋友圈 | rion sns-feed --offset | 1086 条已采 | 高 |
| B1 评论 API | comment/list | 总包说通（需 article_id 链）；另两号 48001 未开评论权限 | 中（回执链新建） |
| B2 后台留言 | mp 后台 CDP 9336 | Chrome 在役（小程序后台登录态） | 高（自家后台） |
| B3 视频号评论 | channels 后台 CDP 9337 | 登录态在役 | 高（自家后台） |
| C1-C3 | feedback MySQL / ask 库 / pay log | 全在役 | 高 |

## 四、范围与里程碑

**M1（当日）**：Demand Ledger 台账统一（三源汇入）+ A2 私聊面 + C2/C3 接入 → 首份跨面热力周报
**M2（次日）**：B1 article_id 回执链 + B3 视频号评论 CDP 采集器 → 面B 首批评论入账
**M3（第三日）**：B2 公众号后台留言 CDP + 语义去重聚类 + 全自动调度（夜班窗）→ 飞轮全速
**每里程碑**：台账计数+样例+周报呈报；**不跳任何 super-skill 阶段**（本件=Phase 0 提案，批准后走 1-12 全链）

## 五、红线（不跨）

- rion 只读契约（无发送/无 UI/无密钥获取）——微信本地库安全
- CDP 仅自家账号后台（9336/9337 合法口），不碰第三方平台反爬
- 账号安全四件套沿 We-AIPO 纪律（限流/熔断/日帽/凭证外置）
- 评论数据只作需求洞察，不做用户画像外传
