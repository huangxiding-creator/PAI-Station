# 用户反馈驱动的报告质量改进+部分退款提案

## 核心思路

> 买家在小程序里直接反馈意见 → 我们根据反馈改进报告 → 改进后的版本回馈买家（含不满意时的部分退款）。
> 这不是客服——这是把买家变成我们的质量校准器。

---

## 一、小程序内反馈系统设计

### 1. 读者阅读页内嵌反馈入口

在报告阅读页（reader.html）每章末尾添加反馈组件：

```
┌─────────────────────────────────────────────┐
│  📝 本章反馈                                │
│                                             │
│  [👍 有用]  [👎 没用]  [🐛 有错误]          │
│                                             │
│  具体意见（选填）：                           │
│  ┌─────────────────────────────────────┐   │
│  │ 例：第3页的合同金额数据与判决书原文不符   │   │
│  └─────────────────────────────────────┘   │
│                                             │
│  [提交反馈]                                  │
└─────────────────────────────────────────────┘
```

### 2. 反馈分类（自动+手动）

| 类型 | 触发 | 处理 |
|------|------|------|
| **数据错误** | 读者指出某数字/日期/金额有误 | 24h内核验→修正→全站更新 |
| **内容缺失** | 读者认为缺了某个重要话题 | 评估→补充到下一版 |
| **分析深度不足** | 读者认为某章分析太浅 | 定向补采→重写该章 |
| **实用性不足** | 读者觉得看了不知道怎么用 | 增加行动清单+案例 |
| **整体不满意** | 读者觉得不值这个价 | **部分退款流程启动** |

### 3. 技术实现

```
小程序端：
  每章末尾 → 反馈按钮 → 弹出反馈面板
  → 收集：章节号 + 反馈类型 + 具体文字 + 截图(选填)
  → POST /api/report/{sku}/feedback

引擎端（qianwen-engine）：
  POST /api/report/{sku}/feedback
  → 存储：data/feedback/{sku}_{timestamp}.json
  → 分类：AI 判断反馈类型（数据错误/内容缺失/深度不足/不满意度）
  → 通知：企微推送给产线
  → 触发：根据类型自动进入改进流程
```

## 二、反馈驱动的质量改进流程

### 流程图

```
读者反馈 → 分类 → 路由
                        │
        ┌───────────────┼───────────────┐
        │               │               │
    数据错误         内容缺失         不满意
        │               │               │
    核验源文件      评估补采         退款审核
        │               │               │
    修正→全站更新   下版补充         部分退款
        │               │               │
    回复读者        通知读者         退款到账
```

### 改进机制

| 反馈类型 | 改进动作 | 时间线 | 回馈买家 |
|---------|---------|--------|---------|
| 数据错误 | 逐字核验源文件→修正→勘误公告 | ≤48h | 免费获得修正版 |
| 内容缺失 | 评估→定向补采→新增章节 | ≤7天 | 免费获得新版 |
| 深度不足 | 定向补采→重写该章 | ≤14天 | 免费获得新版 |
| 实用性不足 | 增加行动清单+实操案例 | ≤7天 | 免费获得新版 |
| 不满意 | 审核→部分退款 | ≤72h | 按梯度退款 |

## 三、部分退款机制

### 退款梯度（按满意度和使用时长）

| 条件 | 退款比例 | 说明 |
|------|---------|------|
| 购买≤7天 + 阅读进度<30% + 反馈「不满意」 | **50%** | 犹豫期保护 |
| 购买≤7天 + 阅读进度≥30% + 反馈「不满意」 | **30%** | 已使用部分不退 |
| 购买≤30天 + 发现数据错误（经核验属实） | **20%** + 免费修正版 | 质量补偿 |
| 购买≤30天 + 反馈「深度不足」+ 采纳建议 | **10%** + 免费新版 | 共建激励 |
| 购买>30天 | 不退款 | 但可享受新版折扣价 |

### 退款流程

```
读者提交「不满意」反馈
       ↓
系统自动检查：购买时间 + 阅读进度
       ↓
符合退款条件 → 企微通知产线审核
       ↓
产线审核（≤24h）：确认是否恶意/滥用
       ↓
通过 → 原路退回（微信支付退款API）
       ↓
不通过 → 回复理由 + 改进承诺
```

### 防滥用机制

| 规则 | 说明 |
|------|------|
| 单份报告限退 1 次 | 不允许反复退款 |
| 阅读进度>80% 不退 | 已充分使用 |
| 退款后失去该报告访问权 | 退款=退回商品 |
| 恶意反馈记录 | 影响后续退款资格 |

## 四、反馈数据的商业价值

### 1. 质量校准（Brier 回写）

每条反馈都是校准信号：
- 「数据错误」→ 修正锚点门阈值
- 「深度不足」→ 调整该话题的采集深度
- 「实用性不足」→ 改进行动清单质量

### 2. 选题雷达（喂入 S-1）

```
反馈「缺了XX内容」
       ↓
提取关键词 → 匹配需求信号框架
       ↓
纳入 radar_topics.md 排行
       ↓
如果同类反馈≥3次 → 新报告候位
```

### 3. 定价校准

- 高退款率 → 定价过高或质量不足 → 降价或提质
- 低退款率 + 高复购 → 定价过低 → 可以提价
- 反馈「值这个价」+ 复购 → 定价合理

### 4. 营销素材

- 买家好评 → 截取放入报告详情页
- 「反馈后24h修正」→ 写入营销文案（「我们24h响应读者纠错」）
- 退款承诺本身 → 信任营销（「不满意可退」）

## 六、ROI 分析

### 成本

| 项目 | 成本 |
|------|------|
| 开发 | 4-5 天 |
| 退款支出（预估） | 售价的 5-15%（初期） |
| 运维 | 企微通知+定期审核 |

### 收益

| 收益 | 价值 |
|------|------|
| 买家信任 | 「不满意可退」→ 提高转化率（预估 +30-50%） |
| 质量信号 | 每条反馈=免费质量审计 |
| 选题雷达 | 直接从买家获取下一份报告的需求 |
| 复购率 | 积极响应反馈→买家愿意买下一份 |
| 口碑传播 | 「他们真的根据我的反馈改了」→ 自然传播 |

### 净效果

假设月售 100 份 × ¥698：
- 退款支出：~10 份 × ¥698 × 40% = ¥2,792
- 转化率提升：+30 份 × ¥698 = ¥20,940
- **净收益：+¥18,148/月**
