## 三、系统架构

```
素材池（合作伙伴企微投喂 / 网盘 / 本地目录）
      │  intake：Excel 计划表 → 结构化战役单（场次/主题/时间/伙伴/素材链接）
      ▼
┌─ SPH-COMMAND 引擎（事件驱动状态机，每场一个 campaign.json）─────────┐
│  S1 预告   : POST live/create_live_prepare（API）→ 预约码            │
│  S2 海报   : 预约码+主题 → 合成海报 ×N → 企微                        │
│  S3 宣传文 : super-skill 写文 → 三号发表链（gzh-autopublish）        │
│  S4 T-2h   : 推流码 API（update_stream_URL 族）→ 主题封面生成 → 伙伴包 │
│  S5 分发   : 伙伴包 → 企微（推流码+封面+开播清单）→ 回执             │
│  S6 开播   : check_live_status 轮询 → 开播确认 → 实时数据落账        │
│  S7 收播   : 自动触发高光链（已验证 API 化）→ 闸门发布               │
│  S8 归档   : bdn 上传 → 分享链接 → 企微 → 复盘报告（峰值/GMV/转化）  │
└──────────────────────────────────────────────────────────────────┘
      │            │             │            │
   视频号 HTTP    公众号3号     企业微信      百度网盘
  (mmfinderassistant-bin)  (gzh-autopublish) (wecom)   (bdn CLI)
```

**技术底座**（全部在役、零新建）：
- `sph.py` 纯 HTTP CLI（1124 收官，22 命令全绿）+ 478 端点地图 + 写协议逆向（在飞）
- 保险库 cookie 会话（S367 链，6h 快照，API 与浏览器解耦）
- live-campaign-autopub / wevideo-highlights / gzh-autopublish / wecom-unified / bdn 五大在役技能
- 浏览器兜底：仅当 API 被场景锁死时启用（DrissionPage@9337，最小化纪律）

## 五、风险登记册（如实）

1. **推流码协议未验证**（最大不确定）：7 个串流端点静态已定位，但 T-2h 窗口协议可能需要一次真实开播抓包。对策：W1 探针先行，锁死则 W3 绑定下次真实战役窗口（不制造假直播）。
2. **写操作账号安全**：发布/删除全部加 `--confirm` 门+测试片回环验证（1124 已验证此打法），永不触碰 13684 条真实内容。
3. **频控**：API 化后请求量可控可审计；高峰期(14-18 点)避让纪律沿用 token-peak-hour-rule。
4. **伙伴素材质量**：intake 解析遇到烂素材→企微退回清单，不硬造。
5. **依赖锁死项**：rawKeyBuff×4 端点为账号场景限制（已定谳），绕行路线在案，不阻塞主线。
