## 一、搜索词生成器（用户点名核心）

**四维拼装公式**：`地域 × 行业细分 × 主题 × 时间窗`

实证序列（四川省任务）：
```
四川省 建筑业统计数据 2020-2024          ← 基础盘: 统计+时间窗
四川省 教育设施 EPC项目案例 政策          ← 行业矩阵扫描①
四川省 文化旅游设施 EPC项目案例 政策      ← 行业矩阵扫描②
四川省 现代物流设施 EPC项目案例 政策      ← 行业矩阵扫描③
四川省 电子信息产业 EPC项目案例 政策      ← 行业矩阵扫描④
四川省 大型医院建设项目 EPC模式 2023 2024 ← 行业矩阵扫描⑤
```

**漏斗式改写**（泛→点名权威源）：
```
江苏省EPC总承包市场规模 历史数据 来源
  → 江苏省EPC总承包市场规模 官方数据
    → 江苏省统计年鉴
```

**权威源直捣**：省政府官网/发改委/住建厅/统计年鉴/公共资源交易平台——不靠搜索引擎碰运气，直接点名官方站点。

搜索词画像：中位 34 字（长而具体），P10=17 P90=60。

## 二、工作结构反转：77% 写 / 10% 搜

| 工具 | 次数 | 占比 | 含义 |
|---|---|---|---|
| text_editor | 20522 | 77% | **写作是绝对主体** |
| terminal | 2951 | 11% | 文件操作/格式转换 |
| browser | 1664 | 6% | 深读信源 |
| search 族 | 1185 | 4.5% | 定向补给 |

结论：**报告是「长出来的」不是「生成出来的」**。搜索只是弹药补给。

## 三、增量写作节奏

实测节奏（四川任务）：`搜×5 → 写×1 → 搜×4 → 写×1 → 搜×5 → 终×2 → 写×14`

- 小批搜→**立即落稿**→再搜→再写→**终批长写收尾**
- 写读比 1.5:1（write 8931+update 2621 vs read 7743）——边写边回读校对
- 每任务写操作中位 **51 次**——一份报告迭代 51 遍

## 四、多文件工作区（软件工程式）

每任务涉及文件中位 **22 个**；写操作目标：58% 中间章节 md、15% 终稿、13% 报告主体。

**章节分开写，最后合并**——不是单文件硬写。

## 五、报告工程五步法（从计划链逆向）

实证（广西任务计划全链）：

```
① 盘存量    「检查当前报告状态和内容」        terminal+text_editor 混读
② 立骨架    「创建并完善报告结构文件」          1 次写 (报告结构.md)
③ 整合去重  「按新结构整合、去重、优化现有章节」 11 次 text_editor
④ 补缺失    「撰写严正声明/摘要/研究方法/推荐序/术语表」 terminal13+text_editor16
⑤ 冲量保质  「确保≥15章，总字数≥30万汉字」    terminal50+text_editor165
```

**关键行为：把用户 prompt 里的质量硬条款（字数/章节数）内化成计划步骤，逐步验收。**

## 六、成品配件清单（报告完整性标准）

从「补缺失」步骤反推，Manus 的完整报告=核心章节 + 六配件：
严正声明、内容摘要、研究方法说明、报告价值说明、推荐序、术语表。
