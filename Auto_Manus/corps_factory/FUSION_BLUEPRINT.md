## 三、骨架核心：七环研究流水线 × 三方能力矩阵

把「调研→撰写」全生命周期拆成七环，每环三方各司其职、显式交接：

```
 ①选题定向 → ②谋划拆解 → ③采集执行 → ④判断核验 → ⑤撰写成稿 → ⑥发布反馈 → ⑦复利进化
    └──────────────────── 每环三方咬合，中央对象一单到底 ────────────────────┘
```

| 环节 | 现有能力体系 | Jev 判断层 | Manus 军团 |
|------|-------------|-----------|-----------|
| ①选题定向 | 缺口分析器/盯梢雷达/EPC100 榜单推进 | **价值判断**：这课题值得投入多少产能（P0/P1/P2 裁决） | 参谋预扫：新领域 15 分钟快侦察 |
| ②谋划拆解 | 四维查询矩阵生成器（8412 搜索词语料） | **可证伪性检查**：任务拆得对不对、验收标准硬不硬 | 参谋会话：需求单→任务矩阵 JSON |
| ③采集执行 | 渠道广度收割（日常增量·定向扫描） | **路由判断**+S2 实时预筛（采回来的先粗筛再入库） | 深度钻探（渠道外找源·单主题钻透） |
| ④判断核验 | 溯源率统计/信源打分/URL 归一去重 | **核心主场**：关键数据点 confirmed/refuted/unverifiable 三态判定 | dual 双跑交叉验证（分歧即红旗） |
| ⑤撰写成稿 | EPC100 成稿链（终稿整合+排版+发布，质量主权） | **论断级终审**：每个关键句必须挂已核验数据点 | **分析输出主力**：分析性章节撰写/数据洞察/专题深钻（小任务增量生长聚合） |
| ⑥发布反馈 | 发布链（docx/推广三档/渠道分发） | 反馈分类判断：用户纠错→判断规则库 | — |
| ⑦复利进化 | 方法论逆向管线（corpus→growth_miner） | 判断规则自身进化（误判案例→新判据） | 事件流语料周反哺（contextTransfer 传承） |

**每格都是显式交接契约**：上游产出必须带 DoD（验收字段），下游有准入闸门——没有判断的单不派发，没有溯源的数据不入库，没有核验的论断不成稿。

## 四、中央对象谱系：ResearchTicket 一单到底

「理想的交接是没有交接」——同一对象从选题到成稿全程流转，三个阶段同一个 ID：

```json
{
  "ticket_id": "RT-20260922-001",
  "stage": "intake | planning | collecting | verifying | drafting | published",
  "north_star_ref": "P5独立源缺口#123",

  "①选题": { "need": "...", "value_verdict": {"jev": "P0", "reason": "..."} },
  "②谋划": { "task_matrix": [{"id":"T01","question":"...","acceptance":"..."}],
             "falsifiability_check": "jev_pass" },
  "③采集": { "ammo": [{"engine":"own|manus|dual","route_reason":"...",
              "context_pack":["库内已有资料指纹"],   // 防重复扫描
              "sources":[{"url":"...","credibility":"official|media|unknown"}]}] },
  "④核验": { "datapoints": [{"claim":"...","value":"...","source_url":"...",
              "jev":"confirmed|refuted|unverifiable"}],
             "traceability": 0.85 },
  "⑤成稿": { "chapters": [{"title":"...","grown_from":["T01","T03"],
              "assertions_audited": 42, "assertions_failed": 0}],
             "golden_score": 91 },
  "账本":   { "credits": 120, "own_tasks": 6, "manus_tasks": 3, "dual": 1,
             "jev_calls": 11, "wall_hours": 6.5 }
}
```

**三个关键设计**：
1. `context_pack`：派发前先查我方库，已有资料指纹随单注入——Manus 不重扫我方已有的，积分只花在缺口上
2. `assertions_audited/failed`：成稿终审的硬指标——failed>0 的章节退回重写，零未核验论断发布
3. `账本`：engine/jev_calls/耗时全记录——复利账本是路由规则达尔文进化的数据底座

## 九、风险登记（Top 3）

1. **Jev 滥用漂移**（什么都问 Jev，成本失控）→ 原语位纪律硬编码：Jev 调用必须在账本登记「免费模型为何做不到」，周审计
2. **双跑成本翻倍** → 只对关键事实开 dual（每课题≤3 题）
3. **七环流水线过重**（小任务被流程拖死）→ 分级通道：弹药单（≤60 积分）走快车道（环③④直达），完整 ResearchTicket 只用于成稿级课题
